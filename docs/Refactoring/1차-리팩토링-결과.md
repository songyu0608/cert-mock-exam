## 1. 현재 동작의 기준 확보

### 결과

애플리케이션 코드를 변경하지 않고 기존 검사 결과와 코드 규모를 확보했다. 환경 문제를 정리한 후 format, lint, 타입 검사, 단위 테스트, 빌드, E2E가 통과했다. 이번 단계에서 기능 회귀는 관측되지 않았으며, 모든 기능의 무결성을 보장하는 의미는 아니다.

### 실행 환경 및 검사 결과

- Windows, Node.js `v24.18.0`, pnpm `10.28.0`.
- `.nvmrc` 지정값은 `24.19.0`이다. 로컬 Node는 package.json의 최소 요구사항을 만족하지만 CI와 정확히 같은 버전은 아니다. 기준 기록 커밋 `bde54a0`의 [CI](https://github.com/songyu0608/cert-mock-exam/actions/runs/45918767941)는 통과했다. 이후 문서 수정 커밋의 CI는 별도로 확인한다.
- 실행 시 `npx --yes pnpm@10.28.0 run <명령>`으로 저장소 지정 pnpm을 사용했다.

| 검사                | 결과 | 근거                                            |
| ------------------- | ---- | ----------------------------------------------- |
| `pnpm format:check` | 통과 | Git 원본과 동일한 LF 기준 검사                  |
| `pnpm lint`         | 통과 | 경고 허용 수 0                                  |
| `pnpm check`        | 통과 | TypeScript project build                        |
| `pnpm test`         | 통과 | 6개 파일, 79개 테스트                           |
| `pnpm build`        | 통과 | 실제 시험 12개와 견본 시험 1개 데이터 검증 포함 |
| `pnpm test:e2e`     | 통과 | 50개 통과, 2개 의도적 생략, 56.6초              |

E2E는 Desktop Chrome과 Pixel 7 설정을 사용했다. 생략된 2개는 `tests/sync.spec.ts`의 모바일 동기화 테스트이며, 같은 로컬 D1을 공유하므로 저장소 설정에서 생략한다. 대응하는 데스크톱 동기화 테스트는 통과했다.

### 실행 중 환경 문제와 처리

1. 기본 pnpm `11.25.0`은 기존 `node_modules`를 다시 준비하려다가 `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY`로 중단됐다. 지정 pnpm `10.28.0`으로 실행해 해결했다. lockfile과 의존성 정의는 변경하지 않았다.
2. Git의 `core.autocrlf=true`에 따른 CRLF 때문에 첫 포맷 검사에서 79개 파일이 실패했다. 텍스트 파일의 줄바꿈을 Git 원본과 같은 LF로 맞춘 후 전체 검사가 통과했다. Git 기준 소스 diff는 없고, Git 전역 설정도 변경하지 않았다.
3. 첫 E2E 실행은 브라우저 준비 전 즉시 실패했다. `pnpm exec playwright install chromium` 실행 후 전체 E2E가 통과했다.
4. Windows에서는 `e2e:server`의 `rm -rf`를 그대로 사용하지 않고 동일한 준비 작업을 수행했다. `.wrangler/e2e`의 절대 경로를 확인해 테스트 DB만 초기화하고, 아래 명령으로 서버를 먼저 실행했다. Playwright는 설정된 `reuseExistingServer`로 이 서버를 사용했다. 운영 DB와 배포 사이트에는 변경하지 않았다.

```sh
pnpm build:e2e
pnpm exec wrangler d1 migrations apply DB --local -c wrangler.e2e.jsonc --persist-to .wrangler/e2e
pnpm exec wrangler dev -c wrangler.e2e.jsonc --ip 127.0.0.1 --port 4173 --persist-to .wrangler/e2e
pnpm test:e2e
```

빌드는 성공했지만 JS chunk 크기 경고와 빌드 플러그인 처리 시간 안내가 있었다. 성능 개선이나 번들 분할은 이번 단계에서 수행하지 않았다.

### 코드 규모 기준

측정 대상은 `git ls-files src worker scripts tests`에 포함된 `.ts`, `.tsx`, `.css`이다. PowerShell의 `[System.IO.File]::ReadAllLines(path).Length`로 빈 줄과 주석을 포함한 물리적 줄 수를 셌다. 생성 파일, 설정 파일, Markdown, 시험 JSON, 학습 자료, SVG는 제외했다. 파일 이동 후에도 동일한 분류로 합계를 비교한다.

| 분류                                   | 파일 수 | 줄 수  |
| -------------------------------------- | ------- | ------ |
| 앱: `src`, `worker`의 테스트 제외 코드 | 35      | 8,318  |
| 도구: `scripts`의 테스트 제외 코드     | 2       | 279    |
| 테스트: `*.test.ts` 및 `tests` 코드    | 9       | 2,285  |
| 합계                                   | 46      | 10,882 |

| 주요 검토 파일                    | 줄 수 |
| --------------------------------- | ----- |
| `src/styles.css`                  | 2,036 |
| `src/pages/ExamHome.tsx`          | 652   |
| `src/components/SplitSession.tsx` | 651   |
| `src/components/QuestionView.tsx` | 532   |
| `src/pages/SessionPage.tsx`       | 440   |
| `src/lib/session.ts`              | 433   |
| `src/lib/storage.ts`              | 360   |

프로덕션 빌드의 주 JS 파일은 593,935 bytes, 주 CSS 파일은 526,029 bytes였다. 압축 전 값이며 전체 배포 용량이 아니다. 줄 수 감소가 번들 크기 감소를 뜻하지는 않는다. 주 CSS에는 `src/styles.css` 외에도 `src/main.tsx`에서 import하는 `@fontsource/*`의 폰트 선언이 포함된다. 따라서 주 CSS 전체 크기를 `styles.css` 자체 크기로 해석하지 않는다. 폰트 선언별 번들 기여도는 측정하지 않았으며, 스타일 정리의 효과는 동일한 빌드 조건에서 별도로 비교한다.
