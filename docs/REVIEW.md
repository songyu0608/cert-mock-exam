# REVIEW — AI 교차 리뷰 절차

PR 구현·리뷰 절차의 원본. 협업 규칙 전체는 `AGENTS.md` §2를 따른다.

## 기본 원칙

- Claude가 구현한 PR은 Codex가 리뷰한다.
- Codex가 구현한 PR은 Claude가 리뷰한다.
- AI 리뷰와 자동 검사(CI)를 함께 쓴다. AI의 승인만으로 merge하지 않는다.
- 최종 merge는 사용자(choi)가 결정한다.

## 진행 순서

1. **구현과 자체 검증**: 구현 AI가 `AGENTS.md` §3의 검사를 모두 돌리고, PR 본문에 변경 내용·검증 결과·남은 일을 적는다.
2. **리뷰 요청**: Claude가 구현했으면 PR에 `@codex review` 코멘트를 남긴다. Codex가 구현했으면 사용자가 Claude에게 리뷰를 맡긴다.
3. **교차 리뷰**: 리뷰 AI는 PR 설명만 믿지 않고 실제 변경 코드와 검사 결과를 직접 확인한다. 화면 변경이 있으면 가능한 환경에서 실제로 실행해 본다.
4. **수정과 재확인**: 구현 AI가 지적 사항을 고치고 검사를 다시 돌린다. 리뷰 AI는 수정과 그 영향을 다시 확인한다. 최종 결과는 PR 최신 커밋 기준으로 남긴다.
5. **사용자 확인과 merge**: CI 통과와 주요 지적 해결을 확인하고, 확인하지 못한 항목은 사용자에게 밝힌다. merge는 사용자가 한다.

## 리뷰 확인 항목

| 항목        | 확인 내용                                                            |
| ----------- | -------------------------------------------------------------------- |
| 요구사항    | PR 목적 충족, 누락, 불필요한 범위 확대                               |
| 채점 정확성 | 정답 판정, 유형별 채점 규칙(`docs/data-format.md`), 도메인 비중 출제 |
| 문항 데이터 | 형식 검사 통과, 정답·해설 내용 오류, 기존 문항 id 변경 여부          |
| 동작        | 정상 흐름, 예외 상황(새로고침, 시간 종료, 기록 없음), 기존 기능 영향 |
| 구조        | `AGENTS.md` §4 준수, 중복, 불필요한 복잡성                           |
| 화면·접근성 | 모바일, 키보드 조작, 다크 모드                                       |
| 보안        | 비밀 값 노출, 외부 입력 처리 — 해당할 때                             |
| 검증        | CI 결과와 실제 실행 확인 여부                                        |

해당 없는 항목은 "해당 없음"으로 표시한다.

## 리뷰 결과 작성 기준

- **수정 필요**: 발생 조건, 영향, 파일·위치, 판단 근거
- **개선 제안**: merge를 막지 않지만 개선할 수 있는 사항
- **확인 완료**: 직접 확인한 코드·동작과 실행한 검사
- **미확인**: 환경이나 정보 부족으로 확인하지 못한 항목과 이유

문제가 없어도 "문제없음"만 남기지 않고 확인 범위와 한계를 적는다. 추측성 지적은 확인된 결함과 구분한다.
