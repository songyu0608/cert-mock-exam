## 01.01 CCAR-Fで問われる設計者の仕事とは

[이 절을 한국어로 읽기](01-ko.md#s1)

> 「明日引っ越すのですが、注文A-104は今日届きますか。今日なら、お届け先は今の住所のままで大丈夫です」

ここで「新しいご住所をお知らせください」と答えたら、何が早すぎるのでしょうか。お客様はまだ住所変更を申し込んでいません。まず今日受け取れるかを知り、その答えを聞いてから届け先をどうするか決めたいのです。では「今日届きます」と即答したらどうでしょう。質問には答えていますが、配送記録を一度も確認していません。

**CCAR-F**は _Claude Certified Architect – Foundations_ の試験コードです。ここでいう設計者（architect）は、このような問い合わせを受けたときに、サービスがどう動くかを決めます。お客様の言葉を読み、何を確かめる必要があるかを判断する役目はClaudeに任せられます。実際の配送状況を調べるには、記録を持つシステムとの接続も必要です。誰の注文をいつ照会してよいのか、結果が返ってこなければどこまで案内できるのかも、設計者が考えることです。

### お客様、Claude、アプリはそれぞれ何をするか

この架空の通販サイトでは、本人確認を済ませたお客様だけが、自分の注文を照会できます。開発者は、注文番号を受け取って配送記録を読み出す機能をアプリに用意しました。このように、アプリが提供し、Claudeが実行を依頼できる機能を**ツール**と呼びます。

| 担当               | この問い合わせでの役目                                                                                   | 理由                                                                                 |
| ------------------ | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| お客様             | 配送情報を聞いて、今の住所のままにするか、届け先を変えるかを決める。                                     | 「今日なら」という条件を付けており、新住所への変更を依頼したわけではない。           |
| Claude             | まず到着予定日を調べる必要があると判断し、照会を依頼する。結果が届いたら、お客様に分かる言葉で説明する。 | 発言の意図は読み取れても、メッセージに書かれた注文番号だけでは配送状況は分からない。 |
| 通販サイトのアプリ | 本人確認が済み、その注文を閲覧する権限があることを確かめる。配送システムに照会し、実際の結果を返す。     | 注文記録と、それを閲覧する権限は通販サイトが管理している。                           |

照会結果が**「配送中・到着予定日未定」**だったとします。お客様には「ご注文A-104のお荷物は現在配送中です。配送記録に到着予定日が出ていないため、本日お受け取りになれるかはまだ確認できません」と案内できます。お届け先には手を加えません。ここでは、確認できた配送状況と、まだ分からない到着日を分けて伝えることが、お客様の判断に役立ちます。

条件を一つ変えてみましょう。配送会社から到着予定日が**本日**と返ってきたら、「配送会社の記録では、本日到着予定です」と案内する根拠ができます。この場合も「到着予定」と「到着を保証する」では意味が異なります。また、お客様がまだ住所変更を依頼していない点は同じです。

### 設問で確かめる

> 本人確認を済ませたお客様から「注文A-104は今日届きますか。今日なら住所はこのままで大丈夫です」と連絡があった。配送状況はまだ照会していない。最初に取る対応として最も適切なものはどれか。
>
> A. 今日届くと伝え、住所をそのままにする。
>
> B. 注文の配送情報を照会し、確認できた内容を伝える。
>
> C. 引っ越しに備えて新住所を聞き、変更手続きを始める。

**正解はBです。**「まだ照会していない」ので、到着日について答える根拠がありません。「今日なら」は、お客様が付けた条件です。Aは到着日を推測で決めており、Cは条件付きの発言を変更の申し込みと受け取っています。最後に、**お客様が決めること、Claudeが判断すること、アプリが実行すること**を一行ずつ書き出してみてください。

## 01.02 一つのサービスに五つの試験分野はどう関わるか

[이 절을 한국어로 읽기](01-ko.md#s2)

同じ通販サイトで「配送中なので今日届きます」という誤案内が続いたとします。調べてみると、ある応対では注文照会を飛ばしていました。別の応対では、正しく照会したのに、記録にない日付を答えていました。お客様の目には同じ誤りに見えますが、直す場所は異なります。試験ガイドの五つの分野を、この店で実際に決めることに当てはめてみましょう。

| 試験分野                                                | 通販サイトを設計するときに決めること                                                                                                                                                                                                                                                                                                                           |
| ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. エージェントアーキテクチャとオーケストレーション** | **どんな順序で仕事を終えるか。** 依頼を読み、ツールを呼び、結果に応じて次の行動を選ぶ仕組みを、ここではエージェントと呼びます。注文照会を依頼した時点では、まだ仕事が残っています。アプリから実際の結果が届いて初めて、それに基づく回答が書けます。こうした手順や役割の調整がオーケストレーションです。                                                        |
| **2. ツール設計とMCP統合**                              | **どの機能を、どんな条件で使えるようにするか。** 「配送照会」は注文番号で行えますが、「住所変更」には新しいお届け先も要ります。二つのツールの名前、入力、戻り値を区別すると、配送について聞かれただけで住所を変えてしまう危険を減らせます。MCPは、アプリと外部サービスがこうした機能や資料を決められた形式でやり取りするための共通の取り決めです。             |
| **3. Claude Codeの設定とワークフロー**                  | **開発チームは誤案内が再発していないか、どう確かめるか。** Claude Codeは、開発者がプロジェクトのファイルを読み、コードを修正し、テストを実行するときに使うツールです。チームは「到着予定日のない注文」のテストを用意し、アプリを変更するたびに実行する手順を決められます。これは、お店がお客様に応対する場面から一歩戻って、開発チームの仕事を考える分野です。 |
| **4. プロンプトエンジニアリングと構造化出力**           | **どんな基準に従い、どんな形式で答えてもらうか。** モデルへの指示をプロンプトといいます。「予定日が空欄なら日付を推測しない」という基準を、回答例とともに示せます。別のプログラムが結果を読むときは、「配送状況」と「到着予定日」を別々の項目にして返します。このように、あらかじめ項目を定めた結果が構造化出力です。                                          |
| **5. コンテキスト管理と信頼性**                         | **次の回答に必要な根拠をどう残すか。** コンテキストとは、モデルが今回の回答を作るときに参照できる情報です。応対が長引いても、注文番号、最後に照会した時刻、確認済みの配送状況、未確認の到着予定日を区別して渡します。そうすれば、担当が替わっても「未確認」を「本日到着」と取り違えずに済みます。                                                              |

### 同じ誤案内でも、どこを直せばよいか

回答を書く**直前の段階で、どの情報が届いていたか**を見てください。照会結果は正しく届いているものの、予定日が未定のときの答え方が決まっていないなら、分野4の課題です。一方、指示と回答例は適切でも、会話を要約したときに「予定日未定」という情報が落ちたなら、まず分野5を見ます。前者では根拠の使い方、後者ではその根拠が今も届いているかを確かめます。

### 設問で確かめる

> 注文システムは「配送中・到着予定日未定」と正しく返し、その結果は回答時にもモデルに渡っている。指示には「質問に簡潔に答える」としか書かれていない。モデルが到着日を推測して答える問題に対し、最初に試す改善はどれか。
>
> A. 到着予定日が未定の場合の回答基準と具体例を指示に加える。
>
> B. 注文照会ツールをもう一つ追加する。
>
> C. すべての会話履歴を毎回送り直す。

**正解はAです。**「正しく返し」から照会は成功しており、「回答時にもモデルに渡っている」から根拠も届いています。Bはすでに成功した照会を増やし、Cはすでに届いた情報をもう一度送る対応です。予定日が不明なときの案内を具体的に示すAが、設問の条件に合います。

最後に、表を隠して次の五つを分類してみましょう。**① 予定日が未定のときの回答例を書く　② 照会ツールの入力を決める　③ 長い応対でも最後の照会時刻を残す　④ コードを変更したらテストする　⑤ 照会が終わってから答える。** 答えは順に分野4、2、5、3、1です。それぞれ誰が何を決め、どんな失敗を防ぐのか、自分の言葉で説明できるか試してみてください。

## 01.03 日本語の設問では何を先に読むか

[이 절을 한국어로 읽기](01-ko.md#s3)

「昨日買った靴はいつ届きますか」と聞かれました。昨日の注文に靴が一足だけあれば、その到着予定日を案内できます。では、二足あって、それぞれ別の日に届くとしたらどうでしょう。設問に出てくる言葉がすべて分かっても、どちらの靴を指しているかが分からないうちは、日付を一つに決められません。

### 選択肢を隠し、まだ分からないことを一行で書く

> 本人確認はすでに済んでいる。お客様は「昨日注文した靴の到着予定日を知りたい」と話している。注文一覧には、昨日購入した靴が2件あり、到着予定日はそれぞれ異なる。次に取る対応として最も適切なものはどれか。
>
> A. 本人確認をもう一度行い、注文一覧を再取得する。
>
> B. 2件のうち注文時刻が新しい方を選び、その到着予定日を伝える。
>
> C. 商品名や注文番号を尋ね、対象の注文を特定してから到着予定日を伝える。

まず、最後の文の**「次に取る対応」**に印を付けます。求められているのはサービス全体を作り直す方法ではなく、今この応対で取る行動です。続いて、前の文から三つの手掛かりを拾いましょう。

| 読み取ること       | 設問の表現                                | そこから判断できること                                                                                      |
| ------------------ | ----------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| お客様の目的       | 「到着予定日を知りたい」                  | 案内するのは、いつ届く予定かということです。                                                                |
| すでに取った対応   | 「本人確認はすでに済んでいる」            | 誰からの問い合わせかは確認済みです。Aのように本人確認を繰り返しても、どの注文を指しているかは分かりません。 |
| 答えを左右する条件 | 「靴が2件」「到着予定日はそれぞれ異なる」 | どちらもお客様の説明に当てはまり、案内する日付は異なります。先に対象の注文を特定する必要があります。        |

**正解はCです。** Bがもっともらしく見えるのは、注文時刻という実在の記録に基づいているからです。ただし、お客様は「一番最近買った靴」とは言っていません。記録そのものが正しくても、それをお客様の意図と結び付ける根拠がなければ、別の注文を選んでしまいます。Cなら、二足を区別できる商品名や注文番号だけを尋ねれば済みます。

**条件を変えて考えてみましょう。** お客様が「二つのうち、後で注文した方です」と付け加え、二つの注文時刻が異なるなら、Bの基準にはお客様の発言という根拠ができます。「最新の注文を選ぶのはいつでも誤り」とだけ覚えると、この違いを見落とします。

## 01.04 演習の後、どこを復習するか

[이 절을 한국어로 읽기](01-ko.md#s4)

先ほどの設問でBを選んだとします。「配送の問題を間違えた。正解はC」と記録すると、数日後に覚えているのは選択肢の記号だけかもしれません。次に出会う問題では、選択肢の順番も商品も変わります。そのとき役立つのは、**自分が何を根拠にし、その根拠から実際にはどこまで判断できたか**という記録です。

### 間違えた理由を一行で書き、復習する節を探す

01.03の誤答なら、こう書けます。「注文時刻が遅いことを、お客様がその注文を指している根拠にした。実際には二つとも条件に合い、どちらかは指定されていなかった」。この記録を手に、30項目のタスク一覧で **5.2** を開きましょう。「複数の結果が一致した場合、追加の識別情報を尋ねる」が今回の判断に当たります。この教材では **07.04「いつ聞き返し、いつ担当者に引き継ぐか」**で学ぶ内容です。[日本語のチェックリスト](<../../exams/anthropic-ccar-f/theory/ja/00 ダッシュボード/公式タスクステートメント30件チェックリスト.md>) · [タスク5.2の解説](<../../exams/anthropic-ccar-f/theory/ja/01 理論/5.2 エスカレーションと曖昧さの解消.md>)

同じ「注文照会」の設問でも、判断を誤った箇所によって復習先は変わります。

| 間違いを振り返ると                                               | 見落としたこと                                               | タスク一覧 → 教材の節                        |
| ---------------------------------------------------------------- | ------------------------------------------------------------ | -------------------------------------------- |
| 二つの注文が一致したのに、推測で一つを選んだ。                   | 照会には成功したが、お客様が指す注文は特定できていなかった。 | 5.2 曖昧さの解消 → 07.04                     |
| タイムアウトで結果を受け取れず、「注文がありません」と答えた。   | 照会の失敗を、正常終了で0件だった場合と取り違えた。          | 2.2 ツールのエラーレスポンス → 05.01         |
| 応対の冒頭で確認した注文番号が要約から抜け落ち、もう一度尋ねた。 | 確認済みの事実が次のリクエストに引き継がれなかった。         | 5.1 長いやり取りでのコンテキスト管理 → 08.02 |

### 設問から復習先を選ぶ

> 注文照会がタイムアウトしたとき、ツールが空の一覧を正常な結果として返していた。その記録を読んで「該当する注文はない」と答えてしまった。まず復習すべき設計上の判断はどれか。
>
> A. 複数の注文が見つかったとき、どの情報を追加で尋ねるか。
>
> B. 照会できなかった場合と、照会に成功して0件だった場合を、ツールの応答でどう区別するか。
>
> C. 長い会話を要約するとき、どの注文情報を残すか。

**正解はBです。**「タイムアウトしたとき」から、照会が完了していないと分かります。「正常な結果として返していた」は、失敗を示す情報がどの段階で失われたかを示します。したがって、まずタスク **2.2** に戻ります。Aが必要なのは照会に成功して候補が複数見つかった場合です。Cが必要なのは、受け取っていた事実が後の会話から抜け落ちた場合です。[タスク2.2の解説](<../../exams/anthropic-ccar-f/theory/ja/01 理論/2.2 MCPツールの構造化されたエラーレスポンス.md>)

復習したら、条件を一行だけ変えて自分に問い直してください。「今度は照会が**正常に完了し、一致する注文は0件**だった。どう案内するか」。今度は「この条件に当てはまる注文は見つかりませんでした」と伝えられます。**なぜ答えが変わったのか**まで説明できれば、別の商品や違う言い回しの設問にも同じ考え方を使えます。
