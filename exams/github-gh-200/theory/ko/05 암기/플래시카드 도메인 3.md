# 플래시카드 도메인 3　액션 작성과 유지 관리

#flashcards/gh-200/d3

형식: `질문::답` (Spaced Repetition 플러그인). 플러그인이 없어도 한 줄씩 읽으면 된다.

## 개념 확인
세 OS 러너 모두에서 쓰려면 어떤 유형?::JavaScript 액션(또는 OS 중립 단계의 복합 액션)
Linux 러너에서만 실행되는 액션 유형은?::Docker 컨테이너 액션
JS 액션의 runs.using 값 예는?::node20, node24
작업이 끝난 뒤 정리 코드를 실행하는 키는?::runs.post
Docker 액션에 입력을 전달하는 방법은?::runs.args
Docker 액션 Dockerfile에서 피해야 할 지시어는?::USER
복합 액션 run 단계에 반드시 필요한 키는?::shell
복합 액션 출력에 필요한 키 2개는?::description, value
action.yml 필수 키 3개는?::name, description, runs
입력 이름이 my input이면 환경 변수 이름은?::INPUT_MY_INPUT
같은 리포의 ./path 액션을 쓰기 전에 필요한 단계는?::actions/checkout
액션 리포 이름이 바뀌면 기존 참조는?::실패(리디렉션 미지원)
불변 릴리스에서 잠기는 두 가지는?::Git 태그와 릴리스 자산
불변 릴리스를 게시하면 자동 생성되는 것은?::릴리스 증명(release attestation)
비공개 리포 액션을 조직의 다른 리포에서 쓰게 하는 설정 위치는?::액션 리포 Settings → Actions → General → Access
Marketplace 게시에 필요한 인증 조건은?::2단계 인증(2FA)
Marketplace 게시용 메타데이터 파일 위치는?::리포지토리 루트에 하나
호환성이 깨지는 변경을 낼 때는?::새 major 버전(v2) 태그
사용자가 받을 major 태그 v1을 어떻게 유지하나?::현재 릴리스를 가리키도록 이동

## 상황 → 판단
상황: 세 OS에서 빠르게 도는 액션 → 정답은?::JavaScript 액션
상황: 도구 버전까지 고정된 환경 → 정답은?::Docker 컨테이너 액션(Linux)
상황: 반복 단계 몇 개를 묶기 → 정답은?::복합 액션(using: composite)
상황: 작업 종료 후 정리 코드 → 정답은?::JS 액션 runs.post
상황: 입력 이름 변경 시 이전 이름 경고 → 정답은?::inputs.<id>.deprecationMessage
상황: 액션을 검색되게 공개 → 정답은?::Marketplace 게시(공개·루트 action.yml·2FA)
상황: 사용자가 버그 수정을 자동으로 받게 → 정답은?::major 태그(v1) 이동
상황: 릴리스 태그·자산 변경 방지 → 정답은?::불변 릴리스
