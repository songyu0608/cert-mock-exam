# 플래시카드 도메인 5　자동화 보안과 최적화

#flashcards/gh-200/d5

형식: `질문::답` (Spaced Repetition 플러그인). 플러그인이 없어도 한 줄씩 읽으면 된다.

## 개념 확인
검증된 작성자 배지가 의미하는 것은?::GitHub가 작성자를 파트너 조직으로 확인(안전성 보장 아님)
인라인 스크립트에서 신뢰할 수 없는 값을 안전하게 쓰는 방법은?::중간 환경 변수로 넘기고 "$VAR"로 사용
문서가 선호하는 완화 방법은?::값을 액션 입력으로 전달
GITHUB_TOKEN의 정체는?::GitHub App 설치 액세스 토큰
permissions에 일부만 적으면 나머지 범위는?::none
워크플로가 만든 PR에서 CI가 돌게 하려면 어떤 토큰?::GitHub App 토큰 또는 PAT
OIDC 토큰을 요청하려면 필요한 권한은?::id-token: write
GitHub OIDC 발급자(iss)는?::https://token.actions.githubusercontent.com
클라우드가 워크플로 출처를 확인하는 주 클레임은?::sub
가장 안전한 액션 참조 방식은?::전체 길이 커밋 SHA
SHA 고정 액션에 Dependabot 취약점 알림이 생기나?::아니요
base 리포 권한으로 실행되는 PR 트리거는?::pull_request_target
권한 분리를 위해 문서가 권하는 트리거는?::workflow_run
포크 PR의 GITHUB_TOKEN 권한은?::읽기 전용
허용 목록에서 차단을 뜻하는 접두사는?::!
허용·차단 목록 최대 항목 수는?::1,000개
증명 생성에 필요한 권한 3개는?::id-token: write, contents: read, attestations: write
재사용 워크플로로 빌드하면 도달 가능한 SLSA 레벨은?::Build Level 3
증명을 검증하는 CLI는?::gh attestation verify
비밀에서 파생된 값을 로그에서 가리는 방법은?:::add-mask:로 등록
비밀이 로그에 노출됐을 때 조치는?::로그 삭제 후 비밀 교체
같은 브랜치의 오래된 실행을 자동 취소하는 방법은?::concurrency 그룹 + cancel-in-progress: true
문서 변경만 있을 때 CI를 건너뛰려면?::paths-ignore(또는 paths) 필터
워크플로 실행 전체 최대 기간은?::35일(대기·승인 포함)
공개 리포에서 무료인 러너는?::표준 GitHub 호스팅 러너와 자체 호스팅 러너

## 상황 → 판단
상황: PR 제목을 run에서 사용 → 정답은?::중간 환경 변수 "$TITLE"
상황: 토큰 권한 최소화 → 정답은?::permissions: (작업별 최소)
상황: 워크플로가 만든 PR에서 CI 실행 → 정답은?::GitHub App 토큰 또는 PAT
상황: 클라우드 키 없이 배포 → 정답은?::OIDC(id-token: write)
상황: 타사 액션 공급망 공격 대비 → 정답은?::전체 커밋 SHA 고정
상황: 포크 PR에 라벨 달기 → 정답은?::pull_request_target(PR 코드 실행 없이)
상황: 포크 PR 결과로 댓글 → 정답은?::pull_request → 아티팩트 → workflow_run
상황: 특정 액션 버전 차단 → 정답은?::허용 목록에 !owner/repo@ref
상황: 배포 바이너리 출처 검증 → 정답은?::아티팩트 증명 + gh attestation verify
상황: 서명한 JWT가 로그에 노출 → 정답은?:::add-mask:로 등록
상황: CI 비용·시간 절감 → 정답은?::캐시·필터·concurrency·보존 단축

## 목표 번호
목표 5.1의 내용은?::환경 보호와 승인 게이트를 사용한다
목표 5.2의 내용은?::Marketplace에서 신뢰할 수 있는 액션을 식별해 사용한다
목표 5.3의 내용은?::스크립트 인젝션을 완화한다(입력 정제·검증, 최소 권한, run:에 신뢰할 수 없는 데이터 넣지 않기, 올바른 셸 따옴표, 인라인 스크립트보다 검증된 액션 선호)
목표 5.4의 내용은?::GITHUB_TOKEN 수명 주기(임시, 범위 한정)를 이해하고 세분화된 권한을 구성하며 PAT와 비교한다. 쓰기 범위를 제한한다
목표 5.5의 내용은?::클라우드 공급자 페더레이션에 OIDC 토큰(id-token 권한)을 써서 장기 클라우드 비밀을 없앤다
목표 5.6의 내용은?::타사 액션을 전체 커밋 SHA로 고정하고 호스팅 러너의 불변 액션 적용에 맞춘다. 근거 없이 떠다니는 @main/@v* 참조를 피한다
목표 5.7의 내용은?::액션 사용 정책(조직·리포지토리 허용/거부 목록, 확인되지 않은 액션에 대한 필수 검토자)을 적용한다
목표 5.8의 내용은?::아티팩트 증명·출처 정보(예: SLSA, 빌드 메타데이터)를 생성·검증하고 배포 검증에 통합한다
목표 5.9의 내용은?::효율을 위해 캐싱과 아티팩트 보존을 구성하고 REST API로 보존 정책을 프로그래밍 방식으로 적용한다
목표 5.10의 내용은?::워크플로 확장과 최적화 전략을 권한다
