# 판단 패턴 역색인

문제 속 상황에서 정답 기능을 거꾸로 찾는 표. 가운데 열을 가리고 말해 본다. 표의 상황은 이 볼트가 공식 자료를 바탕으로 만든 예다.

## 도메인 1　워크플로 작성과 관리

| 문제 속 상황 | 정답 방향 | 노트 |
|---|---|---|
| PR이 열릴 때만 실행 | on: pull_request + types: [opened] | [[워크플로 트리거와 이벤트]] |
| docs 폴더만 바뀌면 건너뛰기 | paths-ignore 필터 | [[워크플로 트리거와 이벤트]] |
| 외부 시스템이 API로 워크플로 시작 | repository_dispatch | [[워크플로 트리거와 이벤트]] |
| 매일 정해진 시각 실행 | schedule + cron(UTC) | [[예약 실행(schedule)]] |
| 버튼으로 실행하며 환경을 선택 | workflow_dispatch + environment/choice 입력 | [[수동 실행(workflow_dispatch)]] |
| 여러 리포가 같은 파이프라인을 호출 | 재사용 워크플로(workflow_call) | [[재사용 워크플로]] |
| 호출한 워크플로에 비밀 전부 넘기기(같은 조직) | secrets: inherit | [[재사용 워크플로]] |
| 앞 작업 실패해도 정리 작업 실행 | needs + if: always() | [[작업 종속성(needs)]] |
| main 브랜치일 때만 배포 단계 | if: github.ref == 'refs/heads/main' | [[조건 실행(if)]] |
| 같은 브랜치 새 푸시 시 이전 실행 취소 | concurrency + cancel-in-progress: true | [[동시성 제어(concurrency)]] |
| 로그에 파일·줄 위치 경고 표시 | ::warning file=…,line=…:: | [[워크플로 명령]] |
| 다음 단계에서 쓸 환경 변수 설정 | GITHUB_ENV 파일 | [[환경 변수와 환경 파일]] |
| 테스트에 PostgreSQL 필요 | services: 서비스 컨테이너 | [[서비스 컨테이너]] |
| 3개 OS × 3개 Node 버전 테스트 | strategy.matrix | [[매트릭스 전략]] |
| 한 조합 실패해도 나머지 계속 | fail-fast: false | [[매트릭스 전략]] |
| 한 파일 안 반복 env 블록 줄이기 | YAML 앵커(&)·별칭(*) | [[YAML 앵커와 별칭]] |
| 브랜치 짧은 이름이 필요 | github.ref_name | [[컨텍스트]] |
| 워크플로 YAML을 편집기에서 검증·자동 완성 | GitHub Actions VS Code 확장 | [[GitHub Actions VS Code 확장]] |
| 매번 패키지 설치가 느림 | actions/cache 또는 setup-* 캐시 | [[의존성 캐싱]] |
| 빌드 결과를 배포 작업에서 사용 | upload-artifact → download-artifact | [[워크플로 아티팩트]] |
| 값 하나를 다른 작업으로 | GITHUB_OUTPUT → 작업 outputs → needs | [[작업 간 데이터 전달]] |
| 테스트 결과 표를 실행 요약에 | GITHUB_STEP_SUMMARY | [[작업 요약(GITHUB_STEP_SUMMARY)]] |
| README에 CI 상태 | 상태 배지 badge.svg | [[상태 배지]] |
| 프로덕션 배포 전 사람 승인 | 환경 + 필수 검토자 | [[환경과 배포 보호 규칙]] |
