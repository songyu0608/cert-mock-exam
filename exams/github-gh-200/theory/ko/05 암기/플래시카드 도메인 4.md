# 플래시카드 도메인 4　엔터프라이즈의 GitHub Actions 관리

#flashcards/gh-200/d4

형식: `질문::답` (Spaced Repetition 플러그인). 플러그인이 없어도 한 줄씩 읽으면 된다.

## 개념 확인
비공개 리포 액션을 조직 내 공유할 때 보안상 주의점은?::다른 리포의 외부 협력자가 간접 접근·로그 열람 가능
허용 목록에서 특정 액션을 차단하는 표기는?::! 접두사
전체 SHA 고정을 강제하는 조직 설정 이름은?::Require actions to be pinned to a full-length commit SHA
공개 리포 포크 PR 승인 옵션 3가지는?::GitHub 신규 첫 기여자 / 첫 기여자 / 모든 외부 기여자
호스팅 러너 작업 최대 실행 시간은?::6시간
호스팅 Linux 러너의 관리자 권한 방식은?::비밀번호 없는 sudo
호스팅 러너에 고정 IP가 필요할 때 선택은?::정적 IP를 할당한 더 큰 러너(또는 자체 호스팅)
더 큰 러너를 쓸 수 있는 요금제는?::Team, Enterprise Cloud
자체 호스팅 러너 작업 최대 시간은?::5일
자동 업데이트를 끈 러너는 언제까지 업데이트해야 하나?::새 버전 공개 후 30일 이내
호스팅 러너 IP 범위를 얻는 API는?::GET /meta의 actions 키
사내 방화벽에 고정 IP로 허용하려면?::정적 IP 더 큰 러너 또는 자체 호스팅 러너
새 러너가 자동으로 들어가는 그룹은?::기본(Default) 그룹
러너는 몇 개 그룹에 속할 수 있나?::한 번에 하나
작업별 상세 로그 파일 접두사는?::Worker_
러너 네트워크 연결을 점검하는 옵션은?::config 스크립트 --check
ARC를 설치하는 도구는?::Helm 차트
ARC 러너로 작업을 보내는 runs-on 값은?::러너 스케일 세트 이름
실행 로그에서 설치 소프트웨어 목록을 찾는 경로는?::Set up job → Runner Image → Included Software
미리 설치된 도구 디렉터리 환경 변수는?::RUNNER_TOOL_CACHE
같은 이름 비밀의 우선순위는?::환경 > 리포지토리 > 조직
비밀 하나의 최대 크기는?::48 KB
리포지토리 비밀 최대 개수는?::100개
구성 변수를 읽는 컨텍스트는?::vars
리포지토리 변수 최대 개수는?::500개
비밀 생성 전 먼저 호출하는 엔드포인트는?::.../actions/secrets/public-key
비밀 암호화 라이브러리는?::LibSodium

## 상황 → 판단
상황: 비공개 액션을 조직 리포에서 사용 → 정답은?::액션 리포 Settings → Actions → Access
상황: 조직에서 GitHub·검증 작성자 액션만 → 정답은?::Allow OWNER, and select non-OWNER… 정책
상황: 방화벽에 고정 IP 허용 → 정답은?::정적 IP 더 큰 러너 또는 자체 호스팅
상황: 사내망 리소스 접근 → 정답은?::자체 호스팅 러너
상황: 민감 러너를 특정 리포만 → 정답은?::러너 그룹 접근 정책
상황: 러너 Offline → 정답은?::머신·앱 실행·네트워크(--check)·_diag
상황: 쿠버네티스에서 러너 자동 확장 → 정답은?::Actions Runner Controller
상황: 러너 설치 도구 버전 확인 → 정답은?::Set up job → Runner Image → Included Software
상황: 특정 Node 버전 필요 → 정답은?::actions/setup-node
상황: 비밀을 일부 리포에만 → 정답은?::조직 비밀 visibility: selected
상황: 스크립트로 비밀 대량 등록 → 정답은?::public-key → LibSodium → PUT

## 목표 번호
목표 4.1의 내용은?::재사용 가능한 구성 요소와 템플릿을 정의·관리한다
목표 4.2의 내용은?::엔터프라이즈 안에서 액션과 워크플로에 대한 접근을 제어한다
목표 4.3의 내용은?::조직 사용 정책을 구성한다
목표 4.4의 내용은?::GitHub 호스팅 러너와 자체 호스팅 러너를 구성하고 모니터링한다
목표 4.5의 내용은?::IP 허용 목록과 네트워크 설정을 적용한다
목표 4.6의 내용은?::러너 그룹을 관리하고 러너 문제를 해결한다
목표 4.7의 내용은?::GitHub 호스팅 러너에 미리 설치된 소프트웨어·도구 버전(이미지 릴리스 정보, 도구 캐시)을 확인하고, 런타임에 추가 소프트웨어를 설치한다(setup-* 액션, 패키지 관리자, 캐싱, 컨테이너 이미지, 사용자 지정 자체 호스팅 이미지)
목표 4.8의 내용은?::조직·리포지토리·환경 수준에서 암호화된 비밀과 변수를 정의하고 범위를 정한다
목표 4.9의 내용은?::워크플로와 액션에서 비밀과 변수에 접근해 사용하고, REST API로 프로그래밍 방식으로 관리한다
