# 캐시 vs 아티팩트

| | [[의존성 캐싱]] | [[워크플로 아티팩트]] |
|---|---|---|
| 목적 | 실행 간 의존성 재사용(속도) | 실행이 만든 결과물 보관·작업 간 공유 |
| 액션 | actions/cache, setup-* 내장 캐시 | actions/upload-artifact, download-artifact |
| 대상 예 | node_modules, 패키지 캐시 | 빌드 결과물, 테스트 보고서, 로그 |
| 수명 | 7일 미접근 시 제거, 리포당 10 GB | 기본 90일, retention-days |
| 변경 | 불변(같은 key 덮어쓰기 불가) | 실행 단위로 저장, 삭제 가능(되돌릴 수 없음) |
| 범위 | 현재·기본 브랜치(PR은 base 포함) | 그 실행(다운로드는 UI·API로 외부에서도) |

> [!question]- 빌드 작업이 만든 dist 폴더를 같은 실행의 배포 작업에서 써야 한다.
> 아티팩트.

> [!question]- 매 실행마다 같은 npm 패키지를 받느라 3분이 걸린다.
> 캐시.
