# 시작 워크플로 vs 재사용 워크플로 vs 복합 액션

| | [[워크플로 템플릿]](시작 워크플로) | [[재사용 워크플로]] | [[복합 액션]] |
|---|---|---|---|
| 정체 | 새 워크플로를 만들 때 복사하는 뼈대 | workflow_call로 호출하는 중앙 정의 | 단계 묶음을 담은 액션(action.yml) |
| 위치 | 조직 .github 리포의 workflow-templates/, GitHub 제공 템플릿 | .github/workflows/ 파일 | 별도 리포 또는 디렉터리의 action.yml |
| 사용 방법 | Actions 탭 → New workflow → Configure | 작업 수준 `uses: owner/repo/.github/workflows/f.yml@ref` | 단계 수준 `uses: owner/repo@ref` |
| 변경 전파 | 없음(생성 후 독립) | 있음(참조한 ref 기준) | 있음(참조한 ref 기준) |
| 작업(job) | 템플릿 내용대로 | 여러 작업 포함 | 작업 없음, 호출 작업 안의 단계 |
| 러너 | 생성된 워크플로가 지정 | 작업마다 자체 지정 | 호출한 작업의 러너 |
| 비밀 | 생성된 워크플로가 사용 | secrets 매핑·inherit로 사용 | 직접 사용 불가(입력으로) |
| 로그 | 일반 워크플로 | 단계별 실시간 | 한 단계로 표시 |
| 중첩 | — | 최대 10단계 | 한 워크플로에 최대 10개 |

**판별**: "복사 후 각자 수정" → 템플릿. "파이프라인 전체를 중앙에서 관리" → 재사용 워크플로. "몇 개 단계를 묶어 여러 작업에서" → 복합 액션.

> [!question]- 보안 팀이 배포 파이프라인 전체(빌드·스캔·배포 3개 작업)를 한 곳에서 고치면 모든 리포에 반영되길 원한다.
> 재사용 워크플로.

> [!question]- 새 리포를 만들 때 조직 표준 CI를 출발점으로 제공하되, 각 팀이 자유롭게 고치게 하고 싶다.
> 워크플로 템플릿(시작 워크플로).
