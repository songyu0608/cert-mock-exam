# 도메인 3　액션 작성과 유지 관리

**English** Domain 3: Author and maintain actions  
**한국어 공식 안내서** 작업 작성 및 유지 관리

도메인 3 (15–20%) · 목표 7개

사용자 지정 액션(JavaScript·Docker·복합)을 만들고 문제를 해결하며, action.yml 메타데이터와 디렉터리 구조, 액션 안의 워크플로 명령, 배포 모델·Marketplace 게시·버전 관리를 다룬다(15–20%). 한국어 공식 안내서는 이 도메인의 action을 "작업"으로 옮겼다.

> [!abstract] 사용자 지정 액션 만들기와 문제 해결
> Create and troubleshoot custom actions · 사용자 지정 작업 만들기 및 문제 해결

## 목표 3.1

**액션 유형(JavaScript, Docker, 복합)을 식별·구현한다. 호스팅 러너의 불변 액션 도입과 그것이 버전 고정·레지스트리 출처에 주는 영향을 이해한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Identify and implement action types (JavaScript, Docker, composite); understand immutable actions rollout on hosted runners and implications for version pinning and registry sources
>
> 작업 형식 식별 및 구현(JavaScript, Docker, 복합); 호스트된 실행기에서 변경할 수 없는 작업 롤아웃 및 버전 고정 및 레지스트리 원본에 대한 영향 이해

JS(모든 OS, 빠름), Docker(Linux만, 환경 통제, 느림), 복합(단계 묶음). 불변 액션은 안내서에 있으나 로드맵에서 제외된 상태라 버전 고정·불변 릴리스와 함께 이해한다.

관련 카드: [[사용자 지정 액션 유형]] · [[JavaScript 액션]] · [[Docker 컨테이너 액션]] · [[복합 액션]] · [[불변 액션과 불변 릴리스]]

## 요약
- Docker 액션 = Linux만 · JS = 모든 OS.
- action.yml 필수: name · description · runs.
- 복합 액션 run 단계 = shell 필수.
- Marketplace: 공개 · 루트 단일 action.yml · 2FA.
- v1.0.1 릴리스 → v1 태그 이동 → 깨지면 v2.

## 이 도메인의 카드
- [[사용자 지정 액션 유형]] — 사용자 지정 액션은 JavaScript, Docker 컨테이너, 복합(composite) 세 유형이다. 유형은 action.yml의 `runs.using`으로 정한다.
- [[JavaScript 액션]] — Node.js로 실행되는 액션이다. action.yml의 `runs.using: node20` 또는 `node24`와 `main` 파일로 정의한다.
- [[Docker 컨테이너 액션]] — 액션 코드와 실행 환경을 Docker 이미지로 묶은 액션이다. `runs.using: docker`, `image`로 정의한다.
- [[복합 액션]] — 여러 단계를 하나의 액션으로 묶은 것이다. `runs.using: composite`와 `steps`로 정의하며, 호출한 작업의 러너에서 한 단계처럼 실행된다.
- [[액션 메타데이터(action.yml)]] — 모든 액션은 루트(또는 액션 디렉터리)에 `action.yml`(또는 action.yaml) 메타데이터 파일이 있어야 한다. 이름, 설명, 입력, 출력, 실행 방식을 정의한다.
- [[액션 문제 해결]] — 액션 실패는 참조(경로·버전), 러너 OS 호환, 입력 전달, 권한, 메타데이터 오류 순으로 확인하고 디버그 로깅으로 세부를 본다.
- [[불변 액션과 불변 릴리스]] — 불변 액션은 액션을 변경 불가능한 패키지 버전으로 게시·사용하려던 기능이다. 불변 릴리스는 게시 후 태그와 자산을 바꿀 수 없게 하는 GitHub 릴리스 기능이다.
- [[액션 배포 모델]] — 액션은 같은 리포지토리 안(로컬), 조직 내 비공개·내부 리포지토리 공유, 공개 리포지토리, GitHub Marketplace로 배포할 수 있다.
- [[Marketplace 게시]] — 공개 리포지토리의 액션을 릴리스할 때 "Publish this Action to the GitHub Marketplace"를 선택해 Marketplace에 등재한다.
- [[액션 버전 관리와 릴리스]] — 액션은 시맨틱 버전 태그(v1.0.1)로 릴리스하고 major 태그(v1)를 최신 호환 릴리스로 옮겨, 사용자가 깨지지 않고 수정 사항을 받게 한다.
