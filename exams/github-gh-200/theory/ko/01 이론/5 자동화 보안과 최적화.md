환경 보호, 신뢰할 수 있는 액션, 스크립트 인젝션 완화, GITHUB_TOKEN 권한, OIDC, SHA 고정, 액션 사용 정책, 아티팩트 증명 같은 보안 모범 사례와 캐싱·보존·확장을 통한 성능·비용 최적화를 다룬다(10–15%).

## 목표 5.1

**환경 보호와 승인 게이트를 사용한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Use environment protections and approval gates
>
> 환경 보호 및 승인 게이트 사용

환경에 필수 검토자·대기 타이머·배포 브랜치 제한을 걸고, 환경 비밀은 승인 후에만 쓰게 한다.

## 목표 5.2

**Marketplace에서 신뢰할 수 있는 액션을 식별해 사용한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Identify and use trustworthy actions from the Marketplace
>
> Marketplace에서 신뢰할 수 있는 작업 식별 및 사용

검증된 작성자 배지는 신원 확인일 뿐이므로 코드를 감사하고, 전체 SHA로 고정하며, 조직 정책으로 허용 범위를 정한다.

관련 카드: [[신뢰할 수 있는 Marketplace 액션]]

## 목표 5.3

**스크립트 인젝션을 완화한다(입력 정제·검증, 최소 권한, run:에 신뢰할 수 없는 데이터 넣지 않기, 올바른 셸 따옴표, 인라인 스크립트보다 검증된 액션 선호)**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Mitigate script injection (sanitize/validate inputs, least-privilege permissions, avoid untrusted data in run:, proper shell quoting, prefer vetted actions over inline scripts)
>
> 스크립트 주입 완화(입력 삭제/유효성 검사, 최소 권한 권한, 실행 시 신뢰할 수 없는 데이터 방지:, 적절한 셸 따옴표, 인라인 스크립트보다 검사된 작업 선호)

신뢰할 수 없는 컨텍스트 값을 run의 ${{ }}에 직접 넣지 않고 액션 입력이나 중간 환경 변수("$VAR")로 넘긴다. 최소 권한, 검증된 액션 선호.

관련 카드: [[자체 호스팅 러너]] · [[스크립트 인젝션]] · [[포크 PR 워크플로 보안]] · [[비밀 유출 방지]]

## 목표 5.4

**GITHUB_TOKEN 수명 주기(임시, 범위 한정)를 이해하고 세분화된 권한을 구성하며 PAT와 비교한다. 쓰기 범위를 제한한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Understand GITHUB_TOKEN lifecycle (ephemeral, scoped), configure granular permissions, contrast with PAT; restrict write scopes
>
> GITHUB_TOKEN 수명 주기 이해(임시, 범위 지정), 세분화된 권한 구성, PAT와 대조; 쓰기 범위 제한

GITHUB_TOKEN은 작업마다 생성되는 리포 범위 GitHub App 토큰이다. permissions로 쓰기 범위를 줄이고, 다른 리포나 트리거가 필요하면 GitHub App 토큰·PAT를 쓴다.

관련 카드: [[조직 Actions 정책]] · [[GITHUB_TOKEN]]

## 목표 5.5

**클라우드 공급자 페더레이션에 OIDC 토큰(id-token 권한)을 써서 장기 클라우드 비밀을 없앤다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Use OIDC token (id-token permission) for cloud provider federation to eliminate long-lived cloud secrets
>
> 클라우드 공급자 페더레이션에 OIDC 토큰(ID 토큰 권한)을 사용하여 수명이 긴 클라우드 비밀을 제거합니다.

id-token: write로 OIDC 토큰을 받아 클라우드의 신뢰 조건(sub 등)으로 단기 자격 증명을 얻는다. 장기 클라우드 비밀이 필요 없다.

관련 카드: [[OIDC]]

## 목표 5.6

**타사 액션을 전체 커밋 SHA로 고정하고 호스팅 러너의 불변 액션 적용에 맞춘다. 근거 없이 떠다니는 @main/@v* 참조를 피한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Pin third-party actions to full commit SHAs; align with immutable actions enforcement on hosted runners; avoid floating @main/@v* without justification
>
> 타사 작업을 전체 커밋 SHA에 고정하여 호스팅된 실행기에서의 변경 불가 작업 적용과 일치시키고, 근거 없이 부동 상태를 피하십시오. @main/@v*

타사 액션은 원래 리포의 전체 커밋 SHA로 고정하고 @main 같은 이동 참조를 피한다. 조직 정책으로 SHA 고정을 강제할 수 있다.

관련 카드: [[불변 액션과 불변 릴리스]] · [[액션 SHA 고정]]

## 목표 5.7

**액션 사용 정책(조직·리포지토리 허용/거부 목록, 확인되지 않은 액션에 대한 필수 검토자)을 적용한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Enforce action usage policies (organization/repository allow/deny lists, required reviewers for unverified actions)
>
> 작업 사용 정책 적용(조직/리포지토리 허용/거부 목록, 확인되지 않은 작업에 필요한 검토자)

조직·리포 허용/차단 목록(OWNER/REPO@REF, *, !)과 SHA 고정 강제, 포크 PR 승인 정책으로 통제한다. "확인되지 않은 액션의 필수 검토자"는 문서에서 같은 이름의 설정을 확인하지 못했다.

관련 카드: [[조직 Actions 정책]] · [[포크 PR 워크플로 보안]] · [[액션 허용·차단 목록]]

**아티팩트 증명·출처 정보(예: SLSA, 빌드 메타데이터)를 생성·검증하고 배포 검증에 통합한다**

## 이 도메인의 카드
- [[신뢰할 수 있는 Marketplace 액션]] — 타사 액션은 내 리포지토리 권한·비밀로 실행되므로, 작성자 신원, 코드, 유지 관리 상태를 확인하고 버전을 고정해 쓴다.
- [[스크립트 인젝션]] — 이슈 제목, PR 제목, 브랜치 이름처럼 공격자가 정할 수 있는 값을 `run:` 안의 `${{ }}`에 넣으면, 값이 셸 스크립트의 일부가 되어 임의 명령이 실행될 수 있다.
- [[GITHUB_TOKEN]] — GITHUB_TOKEN은 작업마다 자동 생성되는 GitHub App 설치 액세스 토큰이다. 워크플로가 있는 리포지토리로 범위가 한정되고 작업이 끝나면 만료된다. `permissions:`로 권한을 줄인다.
- [[OIDC]] — OIDC를 쓰면 워크플로가 클라우드 공급자에게서 작업 하나에만 유효한 단기 토큰을 직접 받는다. 장기 클라우드 자격 증명을 GitHub 비밀로 저장할 필요가 없다.
- [[액션 SHA 고정]] — 타사 액션을 `uses: owner/repo@<40자 커밋 SHA>`로 참조하면 태그가 옮겨지거나 리포가 침해돼도 검토한 코드만 실행된다.
- [[포크 PR 워크플로 보안]] — 포크에서 온 PR은 신뢰할 수 없는 코드다. pull_request는 제한된 권한으로 돌고, pull_request_target은 base 리포 권한으로 돌기 때문에 PR 코드를 체크아웃해 실행하면 위험하다.
- [[액션 허용·차단 목록]] — 엔터프라이즈·조직·리포지토리 Actions 설정에서 어떤 액션과 재사용 워크플로를 쓸 수 있는지 허용·차단 목록으로 제한한다.
- [[아티팩트 증명]] — 아티팩트 증명은 빌드 결과물이 어떤 리포·워크플로·커밋·이벤트에서 만들어졌는지 서명해 기록한 출처 증명이다. 배포 전 `gh attestation verify`로 검증한다.
- [[비밀 유출 방지]] — GitHub는 등록된 비밀을 로그에서 가리지만, 변형된 값·구조화된 값·비밀이 아닌 민감 값은 직접 마스킹하고 노출 경로를 줄여야 한다.
- [[워크플로 최적화 전략]] — 캐싱, 필요한 경우에만 실행, 병렬화와 동시성 제어, 적절한 러너 선택, 보존 기간 단축으로 실행 시간과 비용을 줄인다.
- [[사용 한도와 과금]] — GitHub Actions에는 실행 시간·대기열·매트릭스·API 같은 사용 한도가 있고, 비공개 리포의 호스팅 러너 사용과 저장은 요금제의 포함량을 넘으면 과금된다.
