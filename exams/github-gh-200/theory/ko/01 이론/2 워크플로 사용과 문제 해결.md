# 도메인 2　워크플로 사용과 문제 해결

**English** Domain 2: Consume and troubleshoot workflows  
**한국어 공식 안내서** 워크플로 사용 및 문제 해결

도메인 2 (15–20%) · 목표 11개

워크플로 실행 결과를 해석하고 문제를 해결하며(로그·실행 기록·디버그·재실행), 로그와 아티팩트를 찾고, 워크플로 템플릿과 재사용 워크플로를 사용·구분하는 능력을 다룬다(15–20%).

> [!abstract] 워크플로 동작과 결과 해석
> Interpret workflow behavior and results · 워크플로 동작 및 결과 해석

## 목표 2.1

**구성과 로그에서 워크플로 트리거와 그 효과를 식별한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Identify workflow triggers and effects from configuration and logs
>
> 구성 및 로그에서 워크플로 트리거 및 효과 식별

실행 요약의 트리거(이벤트·커밋·행위자)와 on: 설정(필터·types), 이벤트별 실행 대상(병합 커밋 ref, base 브랜치 등)을 함께 본다.

관련 카드: [[워크플로 트리거와 이벤트]] · [[실패한 실행 진단]]

## 목표 2.2

**로그와 실행 기록으로 실패한 워크플로 실행을 진단한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Diagnose failed workflow runs using logs and run history
>
> 로그 및 실행 기록을 사용하여 실패한 워크플로 실행 진단

실패 단계 로그, 주석, 이전 성공 실행과 비교하고, 부족하면 ACTIONS_STEP_DEBUG·ACTIONS_RUNNER_DEBUG 또는 재실행의 Enable debug logging을 쓴다.

관련 카드: [[실패한 실행 진단]] · [[디버그 로깅]] · [[워크플로와 작업 재실행]]

## 목표 2.4

**매트릭스 확장을 해석하고, 작업 이름을 매트릭스 축과 대응시키며, 변형 간 실패를 분석하고, 개별 매트릭스 작업만 골라 다시 실행한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Interpret matrix expansions, correlate job names to matrix axes, analyze failures across variants, and selectively rerun individual matrix jobs
>
> 행렬 확장을 해석하고, 작업 이름을 행렬 축과 상호 연결하고, 변형 간 오류를 분석하고, 개별 행렬 작업을 선택적으로 다시 실행합니다.

작업 이름의 매트릭스 값으로 실패 조합을 찾고 그 작업만 재실행한다(30일 이내, 실행당 50회, 원래 SHA·ref).

관련 카드: [[매트릭스 전략]] · [[워크플로와 작업 재실행]]

## 목표 2.7

**조직 수준 워크플로와 재사용 워크플로를 사용한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)

## 목표 2.9

## 목표 2.10

**시작 워크플로(복사한 뼈대, 생성 후 독립) vs 재사용 워크플로(workflow_call로 호출하는 중앙 버전 정의) vs 복합 액션(캡슐화된 단계 논리)을 구분한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Differentiate starter workflows (copy scaffold, independent after creation) vs reusable workflows (central versioned definition invoked via workflow_call) vs composite actions (encapsulated step logic)
>
> 시작 워크플로(생성 후 독립적으로 스캐폴드 복사)와 재사용 가능한 워크플로(workflow_call 통해 호출된 중앙 버전 정의) 및 복합 작업(캡슐화된 단계 논리) 구분

시작 워크플로는 복사 후 독립, 재사용 워크플로는 workflow_call로 호출하는 중앙 정의(여러 작업·비밀), 복합 액션은 단계 묶음(호출 작업의 러너, 한 단계 로그).

관련 카드: [[재사용 워크플로]] · [[워크플로 템플릿]] · [[복합 액션]]

**워크플로 비활성화와 삭제를 비교한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)

>
> 워크플로 비활성화 및 삭제 비교

비활성화는 파일을 남기고 트리거만 멈춘다(gh workflow disable, 진행 중 실행 유지, 재실행 불가). 삭제는 파일을 지우는 커밋이다.

관련 카드: [[워크플로 비활성화와 삭제]]

## 요약
- 재실행: 30일 · 50회 · 원래 SHA·ref · 원래 행위자 권한.
- ACTIONS_STEP_DEBUG(단계) vs ACTIONS_RUNNER_DEBUG(러너).
- 템플릿 = 복사, 재사용 워크플로 = 호출, 복합 액션 = 단계 묶음.
- private .github 템플릿 → private 리포만.

## 이 도메인의 카드
- [[실패한 실행 진단]] — 실패한 실행은 실행 요약(트리거·주석·작업 그래프), 작업 로그, 실행 기록을 차례로 보며 원인을 찾는다.
- [[디버그 로깅]] — 디버그 로깅은 평소보다 자세한 로그를 남겨 실패 원인을 찾게 한다. 단계 디버그와 러너 진단 로그 두 종류가 있다.
- [[워크플로와 작업 재실행]] — 완료된 실행을 전체, 실패한 작업만, 또는 특정 작업만 다시 실행할 수 있다. 원래 이벤트의 커밋과 ref를 그대로 쓴다.
- [[로그와 아티팩트 찾기(UI·API)]] — Actions 탭(워크플로 → 실행 → 작업)과 REST API·GitHub CLI로 워크플로, 로그, 아티팩트를 찾고 내려받거나 삭제한다.
- [[Actions REST API(로그·아티팩트·캐시)]] — GitHub REST API로 워크플로 실행·로그·아티팩트·캐시를 조회·삭제하고 보존 설정을 바꾼다. 정리 작업과 정책을 자동화할 때 쓴다.
- [[워크플로 템플릿]] — 워크플로 템플릿(시작 워크플로)은 새 워크플로를 만들 때 복사해 쓰는 뼈대다. GitHub 제공 템플릿과 조직이 `.github` 리포지토리에 둔 템플릿이 있다.
- [[비공개 조직 워크플로 템플릿]] — 2025-09-18부터 조직의 `.github` 리포지토리가 internal 또는 private이어도 워크플로 템플릿을 쓸 수 있다. 사용 가능 범위는 그 리포지토리의 가시성에 따른다.
- [[워크플로 비활성화와 삭제]] — 비활성화는 파일을 남긴 채 트리거만 멈추고 언제든 다시 켤 수 있다. 삭제는 워크플로 파일 자체를 리포지토리에서 지운다.
