# 재사용 워크플로

> [!summary] 한 줄 정의
> `on: workflow_call`로 선언한 워크플로를 다른 워크플로의 작업(job) 수준에서 `uses:`로 호출해 파이프라인 전체를 재사용한다.

**English** Reusing workflows (workflow_call)

## 시험 트리거
- "여러 리포지토리가 같은 배포 파이프라인을 써야 한다"
- "호출한 워크플로에 비밀을 넘기고 싶다"
- "재사용 워크플로 결과를 다음 작업에서 쓰고 싶다"

## 핵심
- 파일은 `.github/workflows`에 있어야 한다(하위 디렉터리 불가).
- 작업 수준에서 호출: `uses: owner/repo/.github/workflows/file.yml@ref` 또는 같은 리포 `./.github/workflows/file.yml`. 단계(step) 안에서는 호출할 수 없다.
- ref는 SHA(가장 안전·권장), 태그, 브랜치. 같은 이름의 태그와 브랜치가 있으면 태그가 우선.
- 입력은 `with:`, 비밀은 `secrets:`로 매핑. `secrets: inherit`는 같은 조직·엔터프라이즈 안에서 호출자의 비밀을 넘긴다. 선언하지 않은 입력·비밀을 넘기면 오류.
- 비밀은 직접 호출된 워크플로에만 전달된다(중첩 시 다시 매핑). 호출자 `env`는 전달되지 않는다. 권한은 유지하거나 줄일 수만 있다.
- 출력: 재사용 워크플로의 `on.workflow_call.outputs`를 작업 출력에서 매핑 → 호출자는 `needs.<job>.outputs`로 읽는다.
- 한도: 최대 10단계 중첩, 한 워크플로 파일에서 고유 재사용 워크플로 최대 50개, 순환 호출 불가. 매트릭스로 재사용 워크플로를 호출할 수 있다.
- 과금과 러너 할당은 호출자 기준.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - 재사용 워크플로를 steps 안에서 uses로 호출한다는 선택지 → 작업(job) 수준에서만
> - 호출자의 env 변수가 재사용 워크플로로 전달된다는 선택지 → 전달되지 않는다
> - secrets: inherit가 다른 조직의 재사용 워크플로에도 비밀을 넘긴다는 선택지 → 같은 조직·엔터프라이즈 안에서만
