# 서비스 컨테이너

> [!summary] 한 줄 정의
> `services:`로 작업에 데이터베이스·캐시 같은 Docker 컨테이너를 붙여 테스트한다. 작업마다 만들어지고 작업이 끝나면 제거된다.

**English** Service containers

## 시험 트리거
- "통합 테스트에 PostgreSQL이 필요"
- "Redis에 어떤 호스트 이름으로 접속하나"
- "Windows 러너에서 서비스 컨테이너가 안 된다"

## 핵심
- Linux 러너 필요: GitHub 호스팅은 Ubuntu, 자체 호스팅은 Docker가 설치된 Linux.
- 작업이 컨테이너(`container:`)에서 실행되면 서비스 라벨이 호스트 이름(예: `postgres`), 포트 매핑 불필요.
- 작업이 러너에서 직접 실행되면 `localhost` + `ports:` 매핑(예: 5432:5432). 할당된 포트는 `job.services.<label>.ports`.
- `options:`로 docker create 옵션(예: --health-cmd 상태 검사), `env:`, 비공개 레지스트리는 `credentials:`.
- 복합 액션은 서비스 컨테이너를 만들 수 없다.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - 서비스 컨테이너가 Windows·macOS 러너에서도 동작한다는 선택지 → Linux만
> - 러너에서 직접 실행하는 작업도 라벨 이름으로 접속한다는 선택지 → localhost + 포트 매핑
