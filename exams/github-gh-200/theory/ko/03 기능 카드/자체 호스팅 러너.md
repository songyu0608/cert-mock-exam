# 자체 호스팅 러너

> [!summary] 한 줄 정의
> 직접 배포·관리하는 머신(물리·가상·컨테이너, 온프레미스·클라우드)에 러너 애플리케이션을 설치해 작업을 실행한다. 리포·조직·엔터프라이즈 수준에 등록한다.

**English** Self-hosted runners

## 시험 트리거
- "사내망 리소스에 접근해야 한다"
- "특수 하드웨어가 필요"
- "공개 리포에 자체 호스팅 러너를 붙여도 되나"

## 핵심
- 수준: 리포지토리(그 리포만), 조직(여러 리포, 그룹으로 제어), 엔터프라이즈(여러 조직).
- 러너 앱은 자동 업데이트. 끄면 새 버전 공개 후 30일 안에 업데이트해야 한다. OS·기타 소프트웨어 업데이트는 사용자 책임.
- 통신: 러너가 GitHub로 나가는 HTTPS 443 연결만 필요(github.com, api.github.com, *.actions.githubusercontent.com 등). 인바운드 개방 불필요〔해석: 문서는 아웃바운드 요건만 명시〕.
- 작업 최대 5일, 대기열 24시간 넘으면 작업 실패. Docker 컨테이너 액션·서비스 컨테이너는 Docker가 설치된 Linux 필요.
- 러너 사용 자체는 무료(머신 비용은 본인).
- 보안: 매 작업 깨끗한 환경이 보장되지 않아 신뢰할 수 없는 코드가 지속적으로 침해할 수 있다. 공개 리포지토리에서는 거의 쓰지 않는다. 임시(ephemeral)·JIT 러너로 작업마다 새 러너를 쓰는 방식이 있다.
- 라벨: runs-on에 self-hosted와 OS·아키텍처·사용자 지정 라벨을 함께 적어 고른다〔해석: 기본 라벨 목록은 이 볼트에서 원문 확인 안 함〕.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - 자체 호스팅 러너가 GitHub의 인바운드 연결을 받으려면 방화벽 포트를 열어야 한다는 선택지 → 아웃바운드 HTTPS 443
> - 공개 리포지토리에 자체 호스팅 러너가 권장된다는 선택지 → 거의 쓰지 말 것
