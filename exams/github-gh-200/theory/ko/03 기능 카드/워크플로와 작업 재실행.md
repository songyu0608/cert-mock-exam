# 워크플로와 작업 재실행

> [!summary] 한 줄 정의
> 완료된 실행을 전체, 실패한 작업만, 또는 특정 작업만 다시 실행할 수 있다. 원래 이벤트의 커밋과 ref를 그대로 쓴다.

**English** Re-running workflows and jobs

## 시험 트리거
- "매트릭스 중 하나만 일시적으로 실패"
- "재실행했는데 최신 커밋이 아니다"
- "재실행 버튼이 안 보인다"

## 핵심
- 방법: Re-run all jobs, Re-run failed jobs(`gh run rerun --failed`), 특정 작업(`gh run rerun --job JOB_ID`, 사이드바의 작업별 재실행).
- 최초 실행 후 30일 이내. 실행당 최대 50회(부분 재실행 포함).
- 원래 이벤트의 GITHUB_SHA와 GITHUB_REF를 사용 → 새 커밋을 반영하지 않는다.
- 권한은 원래 워크플로를 실행시킨 행위자의 권한을 쓴다. 재실행하려면 write 권한 필요.
- Enable debug logging 옵션. 비활성화된 워크플로는 다시 활성화해야 재실행 가능.
- 매트릭스: 작업 이름(축 값 포함)으로 실패 조합을 찾아 그 작업만 재실행할 수 있다.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - 재실행이 최신 커밋으로 실행된다는 선택지 → 원래 SHA·ref
> - 재실행 횟수 제한이 없다는 선택지 → 50회
