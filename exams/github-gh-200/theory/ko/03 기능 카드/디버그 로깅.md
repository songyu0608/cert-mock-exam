# 디버그 로깅

> [!summary] 한 줄 정의
> 디버그 로깅은 평소보다 자세한 로그를 남겨 실패 원인을 찾게 한다. 단계 디버그와 러너 진단 로그 두 종류가 있다.

**English** Enabling debug logging

## 시험 트리거
- "로그만으로 원인을 모르겠다"
- "워크플로 파일을 고치지 않고 자세한 로그를 보고 싶다"

## 핵심
- 단계 디버그: 비밀 또는 변수 `ACTIONS_STEP_DEBUG=true` → 단계 로그에 상세 정보, `::debug::` 메시지 표시.
- 러너 진단: `ACTIONS_RUNNER_DEBUG=true` → 로그 아카이브에 runner-diagnostic-logs 폴더(러너·워커 로그).
- 같은 이름의 비밀과 변수가 모두 있으면 비밀 값이 우선.
- 재실행할 때 Enable debug logging을 체크(CLI `gh run rerun --debug`)하면 워크플로 수정 없이 그 재실행에만 켜진다.
- 디버그가 켜지면 `RUNNER_DEBUG` 변수가 1로 설정된다(자체 스크립트의 상세 출력에 활용).

## 헷갈리는 개념
| 개념 | 차이 |
|---|---|
| ACTIONS_STEP_DEBUG vs ACTIONS_RUNNER_DEBUG | 단계 상세 로그 vs 러너 진단 로그(아카이브 폴더) |

## 오답 함정
> [!warning] 디버그 로깅을 켜려면 워크플로 YAML을 수정해야 한다는 선택지 → 비밀·변수 또는 재실행 옵션
