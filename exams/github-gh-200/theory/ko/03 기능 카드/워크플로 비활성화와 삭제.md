# 워크플로 비활성화와 삭제

> [!summary] 한 줄 정의
> 비활성화는 파일을 남긴 채 트리거만 멈추고 언제든 다시 켤 수 있다. 삭제는 워크플로 파일 자체를 리포지토리에서 지운다.

**English** Disabling vs deleting workflows

## 시험 트리거
- "외부 서비스 장애 동안 잠시 멈추기"
- "포크한 리포의 예약 워크플로가 필요 없다"
- "영구히 쓰지 않는 워크플로"

## 핵심
- 비활성화: Actions 탭 → 워크플로 → Disable workflow, `gh workflow disable`, REST. 다시 켜기는 Enable workflow / `gh workflow enable`.
- 비활성화해도 진행 중인 실행은 취소되지 않는다. 비활성 상태에서는 기존 실행 재실행 불가.
- 활용: 외부 서비스에 잘못된 요청을 보내는 오류, 분(minutes) 과소비, 대상 서비스 다운, 포크의 불필요한 워크플로.
- 자동 비활성: 공개 리포 포크의 예약 워크플로(기본), 공개 리포 60일 무활동 시 예약 워크플로.
- 삭제〔해석〕: .github/workflows의 파일을 지우는 커밋. 다시 쓰려면 파일을 복구해야 하고, 이력은 git에 남는다. 기존 실행 기록은 별도로 삭제할 수 있다.

## 헷갈리는 개념
| 개념 | 차이 |
|---|---|
| 비활성화 vs 삭제 | 되돌리기 쉬움·파일 유지 vs 파일 제거(커밋 필요) |

## 오답 함정
> [!warning] 워크플로를 비활성화하면 진행 중인 실행도 즉시 취소된다는 선택지 → 취소되지 않는다
