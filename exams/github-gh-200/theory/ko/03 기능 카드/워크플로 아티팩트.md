# 워크플로 아티팩트

> [!summary] 한 줄 정의
> 아티팩트는 실행이 만든 파일(빌드 결과, 테스트 보고서 등)이다. `actions/upload-artifact`로 올리고 `download-artifact`로 다른 작업에서 받는다.

**English** Storing workflow data as artifacts

## 시험 트리거
- "빌드 작업의 결과물을 배포 작업에서 쓰기"
- "테스트 보고서를 실행 후 내려받기"
- "아티팩트를 3일만 보관"

## 핵심
- 같은 실행의 작업 간 파일 공유 수단.
- 로그·아티팩트 기본 보존 90일. 리포지토리·조직·엔터프라이즈에서 조정, `retention-days`로 아티팩트별 지정.
- 실행을 삭제하면 아티팩트도 삭제된다. 아티팩트 삭제는 되돌릴 수 없고 write 권한이 필요하다.
- 저장 용량 한도(요금제별 포함량 예: Free 500 MB, Pro 1 GB, Team 2 GB, Enterprise Cloud 50 GB, 변동 정보).
- REST: 리포·실행별 목록, 조회, 삭제, zip 다운로드(302 리디렉션, 만료 시 410). 필드 expired, expires_at, size_in_bytes.
- 아티팩트 증명(attestation)은 서명된 출처 증명 → [[아티팩트 증명]].

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - 아티팩트가 영구 보관된다는 선택지 → 기본 90일
> - 아티팩트 다운로드 REST의 archive_format에 tar를 쓴다는 선택지 → zip
