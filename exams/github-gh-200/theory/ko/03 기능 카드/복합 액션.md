# 복합 액션

> [!summary] 한 줄 정의
> 여러 단계를 하나의 액션으로 묶은 것이다. `runs.using: composite`와 `steps`로 정의하며, 호출한 작업의 러너에서 한 단계처럼 실행된다.

**English** Composite actions

## 시험 트리거
- "체크아웃·설정·빌드 3단계를 여러 워크플로에서 반복"
- "공통 단계 묶음에 비밀이 필요"

## 핵심
- runs: using composite, steps(각 단계는 run 또는 uses). run 단계는 shell 필수.
- 입력은 `inputs` 컨텍스트로 읽는다(INPUT_ 환경 변수 자동 생성 안 됨). 출력은 description과 value 필수.
- 작업(job)을 포함할 수 없다. 비밀을 직접 쓸 수 없다 → 입력으로 전달.
- 로그에는 한 단계로 표시된다. 한 워크플로에 복합 액션 최대 10개 중첩.
- 서비스 컨테이너를 만들 수 없다.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - 복합 액션의 run 단계에서 shell을 생략할 수 있다는 선택지 → run이면 shell 필수
> - 복합 액션이 secrets 컨텍스트를 직접 쓴다는 선택지 → 입력으로 넘긴다
