# 워크플로 템플릿

> [!summary] 한 줄 정의
> 워크플로 템플릿(시작 워크플로)은 새 워크플로를 만들 때 복사해 쓰는 뼈대다. GitHub 제공 템플릿과 조직이 `.github` 리포지토리에 둔 템플릿이 있다.

**English** Workflow templates (starter workflows)

## 시험 트리거
- "조직 표준 CI를 새 리포에서 쉽게 시작"
- "New workflow 화면에 우리 조직 템플릿이 보이게"
- "템플릿을 고쳤는데 기존 리포에 반영이 안 된다"

## 핵심
- 사용: Actions 탭 → New workflow → 템플릿 Configure → 수정 → Start commit(기본 브랜치 커밋 또는 PR).
- 생성 후에는 리포지토리의 독립된 파일이다. 템플릿을 고쳐도 이미 만든 워크플로는 바뀌지 않는다.
- 조직 템플릿: `.github` 리포지토리의 `workflow-templates/` 디렉터리에 워크플로 YAML과 같은 이름의 `.properties.json`.
- `.properties.json`: name, description(필수), iconName, categories, filePatterns(루트 파일 정규식으로 추천).
- `$default-branch` 자리 표시자는 생성 시 그 리포지토리의 기본 브랜치 이름으로 바뀐다.
- GitHub 제공 템플릿 목록은 actions/starter-workflows 리포지토리. 템플릿 안에서 재사용 워크플로를 호출해 중앙 관리와 결합할 수 있다.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - 조직 템플릿을 수정하면 그걸로 만든 기존 워크플로도 바뀐다는 선택지 → 복사본이라 바뀌지 않는다
> - 템플릿 메타데이터 파일이 template.yml이라는 선택지 → 같은 이름의 .properties.json
