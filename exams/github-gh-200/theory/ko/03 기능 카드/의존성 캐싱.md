# 의존성 캐싱

> [!summary] 한 줄 정의
> `actions/cache`(또는 setup-* 액션의 내장 캐시)로 패키지 등 의존성을 실행 간에 재사용해 시간을 줄인다.

**English** Caching dependencies

## 시험 트리거
- "매번 npm install이 오래 걸린다"
- "정확한 키가 없을 때 비슷한 캐시라도 복원"
- "캐시가 사라졌다"

## 핵심
- `key`가 정확히 맞으면 적중. 없으면 `restore-keys`를 순서대로 접두사 일치로 찾는다. 키에 `hashFiles('**/package-lock.json')`를 흔히 쓴다.
- 복원 범위: 현재 브랜치 또는 기본 브랜치의 캐시. PR은 base 브랜치 캐시도.
- 리포지토리당 기본 10 GB(늘릴 수 있고 초과분 과금). 7일간 접근하지 않은 항목은 제거, 한도 초과 시 오래된 것부터 제거.
- 캐시는 불변: 같은 키로 덮어쓸 수 없다.
- 조직 설정 Cache retention 기본 7일·최대 365일, 크기 한도 기본 10 GB(결제 수단 필요).
- REST: 캐시 사용량 조회, 목록, 키·ID로 삭제, 보존·저장 한도 설정.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - 캐시로 같은 실행의 작업 간 빌드 결과를 넘긴다는 선택지 → 결과물은 아티팩트
> - 같은 key로 캐시를 덮어쓸 수 있다는 선택지 → 불변
