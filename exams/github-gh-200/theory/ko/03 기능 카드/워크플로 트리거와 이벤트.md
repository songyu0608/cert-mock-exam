# 워크플로 트리거와 이벤트

> [!summary] 한 줄 정의
> `on:`에 적은 이벤트(푸시, PR, 일정, 수동, 외부 웹후크 등)가 일어나면 워크플로가 실행된다. `types`와 브랜치·경로 필터로 범위를 좁힌다.

**English** Workflow triggers and events

## 시험 트리거
- "PR이 열릴 때만 실행"
- "docs 폴더 변경에는 실행하지 않기"
- "외부 시스템이 웹후크로 워크플로를 시작"
- "푸시했는데 워크플로가 안 돈다"

## 핵심
- 리포지토리 이벤트: push, pull_request, issues, release 등. 일정: schedule. 수동: workflow_dispatch. 외부 웹후크: repository_dispatch. 다른 워크플로 완료: workflow_run. 호출: workflow_call.
- `types:`로 활동 유형을 거른다. pull_request의 기본 유형은 opened, synchronize, reopened다.
- branches/branches-ignore, tags, paths/paths-ignore 필터. branches와 paths를 함께 쓰면 둘 다 만족해야 실행된다.
- 여러 이벤트는 기본 브랜치에 있는 워크플로 파일 기준으로 동작한다(이벤트별로 다름, 문서 표 확인).
- GITHUB_TOKEN으로 만든 이벤트는 새 실행을 만들지 않는다(재귀 방지). 예외: workflow_dispatch, repository_dispatch.
- 한 번에 브랜치 5,000개 초과 또는 태그 3개 초과를 푸시하면 push 이벤트가 생기지 않는다.
- 머지 큐를 필수 검사와 함께 쓰려면 `merge_group`(checks_requested) 트리거가 필요하다.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - GITHUB_TOKEN으로 푸시하면 push 워크플로가 다시 돈다는 선택지 → 새 실행을 만들지 않는다
> - branches와 paths 필터 중 하나만 맞아도 실행된다는 선택지 → 둘 다 만족해야 한다
