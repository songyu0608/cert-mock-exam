# 환경과 배포 보호 규칙

> [!summary] 한 줄 정의
> 환경(environment)은 배포 대상(production 등)을 나타내며, 보호 규칙(필수 검토자, 대기 타이머, 배포 브랜치 제한)과 전용 비밀·변수를 가진다.

**English** Deployments and environments

## 시험 트리거
- "프로덕션 배포 전에 사람 승인"
- "main 브랜치만 프로덕션에 배포"
- "배포 30분 지연"
- "프로덕션 비밀은 승인 후에만"

## 핵심
- 작업에 `environment: production`(이름, 선택적으로 url)을 지정하면 그 환경의 규칙이 적용된다.
- 필수 검토자: 사용자 또는 팀 최대 6개, 그중 1명 승인으로 진행. 배포를 시작한 사람의 자기 승인을 막는 옵션.
- 대기 타이머: 1~43,200분(30일). 대기 시간은 과금되지 않는다.
- 배포 브랜치·태그: No restriction / Protected branches only / Selected branches and tags(이름 패턴).
- 관리자 우회: 기본 허용, 환경별로 끌 수 있다. 사용자 지정 배포 보호 규칙(GitHub Apps, 공개 미리 보기), 환경당 최대 6개 동시 활성.
- 환경 비밀은 그 환경을 참조하는 작업만, 승인 후에 접근 가능. 환경 변수는 vars 컨텍스트로.
- 요금제: Free·Pro·Team의 비공개 리포지토리에서는 필수 검토자·대기 타이머를 쓸 수 없다(공개 리포는 가능). 비공개·내부 리포 전체 기능은 Enterprise.
- 환경 승인 대기 한도 30일.
