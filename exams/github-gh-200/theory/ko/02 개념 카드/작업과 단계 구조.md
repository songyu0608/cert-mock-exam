# 작업과 단계 구조

> [!summary] 한 줄 정의
> 워크플로는 하나 이상의 작업(job)으로, 작업은 같은 러너에서 차례로 실행되는 단계(step)로 이루어진다. 단계는 `run`(셸 명령) 또는 `uses`(액션)다.

**English** Using jobs and steps

## 시험 트리거
- "두 작업이 같은 파일을 공유하지 못한다"
- "특정 단계가 실패해도 계속"
- "작업이 6시간 넘게 걸린다"

## 핵심
- 작업은 기본적으로 병렬 실행, 각자 다른 러너(새 VM)에서 돈다 → 파일 공유는 아티팩트·캐시·출력으로.
- `runs-on`: 라벨 배열은 모두 만족하는 러너를 찾는다. `group`·`labels`로 러너 그룹 지정.
- 기본 셸: Linux·macOS `bash -e {0}`(bash 없으면 sh), Windows `pwsh`. `defaults.run`으로 바꾼다.
- `timeout-minutes` 기본 360분. `continue-on-error`는 단계(또는 작업)에서 실패를 허용.
- 작업 수준 `permissions`, `environment`, `concurrency`, `outputs`, `services`, `container`, `strategy`를 둘 수 있다.

## 헷갈리는 개념
| 개념 | 차이 |
|---|---|
| 작업(job) vs 단계(step) | 작업 = 러너 단위, 병렬 기본 / 단계 = 같은 러너에서 순서대로, 파일 시스템 공유 |
| 한국어 공식 안내서의 "작업" | job과 action을 모두 "작업"으로 옮겼다 → [[용어 대조표]] |

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - 같은 워크플로의 작업들이 같은 러너에서 파일을 공유한다는 선택지 → 작업마다 새 러너
> - 기본 timeout-minutes가 60분이라는 선택지 → 360분
