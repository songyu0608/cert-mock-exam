# 컨텍스트

> [!summary] 한 줄 정의
> 컨텍스트는 실행·작업·단계·러너 정보를 담은 객체로, `${{ github.ref }}`처럼 식에서 읽는다.

**English** Contexts

## 시험 트리거
- "이벤트 페이로드의 PR 번호를 읽고 싶다"
- "브랜치 이름만 필요하다"
- "작업 수준에서 어떤 컨텍스트를 쓸 수 있나"

## 핵심
- github(실행·이벤트, github.event = 웹후크 페이로드), env, vars, job, jobs(재사용 워크플로 출력), steps, runner, secrets, strategy, matrix, needs, inputs.
- github.ref = 전체 ref(refs/heads/main), github.ref_name = 짧은 이름(main).
- 키마다 쓸 수 있는 컨텍스트가 다르다. 작업 if: github, needs, vars, inputs. runs-on: github, needs, strategy, matrix, vars, inputs(env 불가). hashFiles는 단계 수준에서만.
- 없는 속성은 빈 문자열로 평가된다.
- github.event의 제목·본문·브랜치 이름 등은 신뢰할 수 없는 입력이다 → [[스크립트 인젝션]].

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - github.ref가 브랜치 짧은 이름이라는 선택지 → 전체 ref, 짧은 이름은 ref_name
> - 작업 if에서 secrets·env를 쓸 수 있다는 선택지 → github, needs, vars, inputs
