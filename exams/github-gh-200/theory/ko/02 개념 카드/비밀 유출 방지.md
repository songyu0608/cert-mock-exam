# 비밀 유출 방지

> [!summary] 한 줄 정의
> GitHub는 등록된 비밀을 로그에서 가리지만, 변형된 값·구조화된 값·비밀이 아닌 민감 값은 직접 마스킹하고 노출 경로를 줄여야 한다.

**English** Preventing secret leakage in logs and expressions

## 시험 트리거
- "JWT를 비밀로 서명해 만들었더니 로그에 그대로"
- "JSON 한 덩어리를 비밀 하나로 저장"
- "비밀이 로그에 찍혔다"

## 핵심
- 평문으로 워크플로 파일에 민감 정보를 넣지 않는다.
- 구조화된 값(JSON·XML·YAML)을 비밀 하나로 묶지 않는다 → 값마다 별도 비밀(마스킹이 부분 문자열에서 실패할 수 있음).
- 비밀에서 파생된 값(서명한 JWT, Base64·URL 인코딩 값)은 `::add-mask::`로 등록해야 가려진다.
- 비밀을 명령줄 인수로 넘기지 않는다(같은 러너의 다른 프로세스가 볼 수 있음) → 환경 변수 사용〔자체 호스팅 러너 관련 문서 서술 기반〕.
- 노출되면 해당 로그를 삭제하고 비밀을 교체(rotate)한다.
- 작업 출력에 비밀이 들어가면 가려져 전달되지 않는다. 환경 비밀은 필수 검토자로 보호.

## 오답 함정
> [!warning] Base64로 인코딩한 비밀은 자동으로 가려진다는 선택지 → 따로 등록해야 한다
