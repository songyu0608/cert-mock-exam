# 사용자 지정 액션 유형

> [!summary] 한 줄 정의
> 사용자 지정 액션은 JavaScript, Docker 컨테이너, 복합(composite) 세 유형이다. 유형은 action.yml의 `runs.using`으로 정한다.

**English** Types of custom actions

## 시험 트리거
- "Windows·macOS 러너에서도 돌아야 하는 액션"
- "특정 OS 도구와 버전을 고정한 환경이 필요"
- "반복되는 단계 몇 개를 묶고 싶다"

## 핵심
- JavaScript: 러너에서 직접 실행, 빠르다. Linux·Windows·macOS 호스팅 러너 모두 지원. 순수 JS로 작성하고 러너 이미지에 없는 바이너리에 의존하지 않는다.
- Docker 컨테이너: 환경(OS·도구·버전)을 함께 묶어 일관성이 높다. 컨테이너 빌드·가져오기 때문에 느리다. Linux 러너에서만(자체 호스팅은 Docker 필요).
- 복합(composite): 여러 워크플로 단계(run, uses)를 하나의 액션으로 묶는다.
- runs.using 값: node20·node24(JS), docker, composite.
- 모두와 공유하려면 공개 리포지토리에 둔다.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - Docker 컨테이너 액션이 macOS·Windows 러너에서도 돈다는 선택지 → Linux 러너만
> - JavaScript 액션이 Docker 액션보다 느리다는 선택지 → JS가 더 빠르다
