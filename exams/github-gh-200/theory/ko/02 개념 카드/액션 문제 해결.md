# 액션 문제 해결

> [!summary] 한 줄 정의
> 액션 실패는 참조(경로·버전), 러너 OS 호환, 입력 전달, 권한, 메타데이터 오류 순으로 확인하고 디버그 로깅으로 세부를 본다.

**English** Troubleshooting action execution

## 시험 트리거
- "Unable to resolve action"
- "Docker 액션이 Windows에서 실패"
- "입력이 비어 있다"

## 핵심
- 참조 확인: owner/repo@ref 오타, 존재하지 않는 태그·SHA, 이름 변경(리디렉션 미지원 → 옛 이름 참조는 실패), 비공개 리포 액션의 접근 설정.
- 로컬 액션(./path)은 먼저 actions/checkout이 필요하다.
- OS: Docker 액션은 Linux만. JS 액션은 러너에 없는 바이너리에 의존하면 실패.
- 입력: 이름 오타는 경고만 날 수 있고, required여도 자동 실패하지 않는다 → 액션 코드에서 검증.
- ACTIONS_STEP_DEBUG로 상세 로그, ::debug:: 메시지 확인. 액션 코드는 ::error::·종료 코드로 실패를 알린다.
- 조직 정책이 그 액션을 막았을 수 있다(허용 목록 밖) → [[조직 Actions 정책]].

## 오답 함정
> [!warning] 액션 리포 이름이 바뀌어도 자동 리디렉션된다는 선택지 → 리디렉션 미지원
