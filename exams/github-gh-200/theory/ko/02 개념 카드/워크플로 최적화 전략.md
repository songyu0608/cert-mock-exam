# 워크플로 최적화 전략

> [!summary] 한 줄 정의
> 캐싱, 필요한 경우에만 실행, 병렬화와 동시성 제어, 적절한 러너 선택, 보존 기간 단축으로 실행 시간과 비용을 줄인다.

**English** Strategies for scaling and optimizing workflows

## 시험 트리거
- "CI가 너무 오래 걸린다"
- "Actions 비용이 늘었다"
- "자체 호스팅 러너가 피크 때 부족"

## 핵심
- 캐시: 의존성 캐싱, setup-* 내장 캐시.
- 불필요한 실행 줄이기: paths·branches 필터, types, 조건 if, concurrency + cancel-in-progress로 오래된 실행 취소.
- 병렬화: 작업 분할과 needs로 의존성 최소화, 매트릭스는 필요한 조합만(exclude), max-parallel로 동시 실행 조절.
- timeout-minutes로 멈춘 작업 비용 차단(기본 360분).
- 러너: 무거운 작업은 더 큰 러너, 대규모·사내망은 자체 호스팅 + ARC 자동 확장, 러너 그룹 동시성 한도.
- 저장 비용: 아티팩트 retention-days 단축, 보존 정책·캐시 한도를 REST API로 일괄 적용, 불필요한 아티팩트 업로드 줄이기.
- 재사용 워크플로·복합 액션으로 중복 제거(유지 비용).
