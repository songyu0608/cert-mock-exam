# 식과 평가 시점

> [!summary] 한 줄 정의
> `${{ }}` 안의 식은 리터럴, 컨텍스트, 연산자, 함수로 값을 계산한다. 러너에 보내기 전 GitHub가 평가해 그 결과를 문자열로 넣는다.

**English** Expressions and evaluation

## 시험 트리거
- "문자열 비교가 대소문자를 무시하나"
- "JSON 문자열을 객체로 바꾸기"
- "식 결과가 run 스크립트에 그대로 들어간다"

## 핵심
- 리터럴: boolean, null, number, string(작은따옴표). 비교는 대소문자 구분 없음.
- 함수: contains, startsWith, endsWith, format, join, toJSON, fromJSON, hashFiles. 상태 함수: success, always, cancelled, failure. 객체 필터 `*`.
- 평가 시점〔해석〕: 워크플로 구문 분석 때 정해지는 값(on, 트리거 필터 등)과 작업·단계가 실행될 때 평가되는 식(if, run 안의 ${{ }}, needs 출력)을 구분한다.
- `run:` 안의 `${{ }}`는 스크립트가 만들어지기 전에 값으로 치환된다 → 신뢰할 수 없는 값이면 인젝션 위험. 환경 변수로 넘긴다.
- 비밀을 식으로 로그에 찍지 않는다. secrets는 자동 마스킹되지만 변형된 값은 가려지지 않을 수 있다.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - 문자열 리터럴에 큰따옴표를 쓴다는 선택지 → 식 안 문자열은 작은따옴표
> - 식 비교가 대소문자를 구분한다는 선택지 → 구분하지 않는다
