# 실패한 실행 진단

> [!summary] 한 줄 정의
> 실패한 실행은 실행 요약(트리거·주석·작업 그래프), 작업 로그, 실행 기록을 차례로 보며 원인을 찾는다.

**English** Diagnosing failed workflow runs

## 시험 트리거
- "어제까지 되던 워크플로가 실패"
- "왜 이 워크플로가 실행됐는지 모르겠다"
- "작업이 대기만 하다 실패"

## 핵심
- 실행 요약: 어떤 이벤트·커밋·행위자가 실행시켰는지(트리거), 작업별 상태, 오류·경고 주석, 아티팩트.
- 로그: 실패한 단계는 자동으로 펼쳐진다. 단계별 소요 시간, 줄 링크, Search logs(펼친 단계만 검색).
- 실행 기록: 같은 워크플로의 이전 성공 실행과 커밋·러너 이미지·의존성 버전을 비교〔해석: 진단 절차는 이 볼트의 정리〕.
- 흔한 원인: 이미지 변경(-latest), 매칭되는 러너 없음(자체 호스팅 24시간 대기 후 실패), 권한 부족(GITHUB_TOKEN), 비밀 미전달(포크 PR), 캐시 키 불일치.
- 정보가 부족하면 디버그 로깅을 켜고 재실행 → [[디버그 로깅]].
- 트리거 해석: on: 설정, 필터(branches·paths·types), 이벤트별 실행 대상 커밋(예: pull_request는 병합 커밋 ref, pull_request_target은 base 브랜치)을 함께 본다.

## 오답 함정
> [!warning] 포크 PR에서 비밀이 비어 실패한 것을 버그로 보는 선택지 → 포크 PR에는 GITHUB_TOKEN 외 비밀이 전달되지 않는 것이 정상
