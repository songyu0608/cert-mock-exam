# 보존 정책

> [!summary] 한 줄 정의
> 로그·아티팩트·캐시를 얼마나 보관할지 정하는 설정이다. UI와 REST API로 리포지토리·조직·엔터프라이즈 수준에서 관리한다.

**English** Retention policies for logs, artifacts, and caches

## 시험 트리거
- "저장 비용을 줄이려 아티팩트를 짧게"
- "조직 전체 보존 기간을 코드로 관리"
- "오래된 실행 로그 정리"

## 핵심
- 로그·아티팩트 기본 90일. 리포지토리·조직·엔터프라이즈에서 기간을 조정한다.
- 2025-07-31 변경 로그: 아티팩트·로그 보존 기간, 포크 PR 승인, 비공개 포크 실행, 리포 수준 러너 생성 허용을 엔터프라이즈·조직·리포 수준 REST API로 관리할 수 있게 됨.
- 캐시: Cache retention 기본 7일·최대 365일, REST `actions/cache/retention-limit`(max_cache_retention_days), `storage-limit`(max_cache_size_gb).
- 개별 정리: 아티팩트 DELETE, 실행 로그 DELETE(/actions/runs/{run_id}/logs), 캐시 키·ID로 DELETE.
- 하위 수준은 상위에서 정한 최대값을 넘을 수 없다〔해석: 일반적인 정책 상속, 이 볼트에서 수치 확인 안 함〕.
