# 자체 호스팅 러너 문제 해결

> [!summary] 한 줄 정의
> 러너 상태(Idle·Active·Offline)를 확인하고, 네트워크 점검(--check), _diag 로그, 서비스 상태, Docker 설치 여부로 원인을 찾는다.

**English** Monitoring and troubleshooting self-hosted runners

## 시험 트리거
- "러너가 Offline"
- "작업이 러너를 못 찾고 대기"
- "docker.sock permission denied"

## 핵심
- 상태: Idle(연결됨·대기), Active(작업 중), Offline(머신 꺼짐, 앱 미실행, GitHub와 통신 불가).
- 네트워크: config 스크립트 `--check --url ... --pat ...` → 결과 PASS/FAIL, 상세는 _diag.
- _diag 로그: Runner_*(앱 시작마다), Worker_*(작업마다), SelfUpdate 로그. 임시 러너는 로그를 외부로 보존해야 한다.
- 서비스: Linux journalctl(systemd), macOS svc.sh(launchctl), Windows services.msc.
- 버전이 임계치보다 낮으면 작업을 처리하지 못한다 → 업데이트.
- 컨테이너 작업: Linux + Docker 필요. docker 명령 not found = 미설치, /var/run/docker.sock permission denied = 서비스 계정 권한.
- 라벨 불일치: runs-on 라벨에 맞는 러너가 없으면 24시간 대기 후 실패.

## 오답 함정
> [!warning] Offline 러너는 GitHub 쪽 장애가 유일한 원인이라는 선택지 → 머신·앱·네트워크 확인
