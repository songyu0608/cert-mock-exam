# 환경 변수와 환경 파일

> [!summary] 한 줄 정의
> `env:`(워크플로·작업·단계)로 변수를 정의하고, 실행 중 값은 `$GITHUB_ENV` 파일에 써서 다음 단계부터 쓴다. GitHub가 기본 변수(GITHUB_SHA 등)를 제공한다.

**English** Environment variables and environment files

## 시험 트리거
- "앞 단계에서 계산한 값을 뒤 단계에서 환경 변수로"
- "도구 경로를 PATH에 추가"
- "같은 이름 env가 여러 수준에 있다"

## 핵심
- 범위가 좁을수록 우선: 단계 env > 작업 env > 워크플로 env.
- `echo "NAME=value" >> "$GITHUB_ENV"` → 같은 작업의 다음 단계부터 적용(쓴 단계에는 적용 안 됨). 여러 줄 값은 `NAME<<DELIM` 구문.
- `echo "/path" >> "$GITHUB_PATH"` → 다음 단계부터 PATH 앞에 추가.
- 기본 변수: GITHUB_SHA, GITHUB_REF, GITHUB_REF_NAME, GITHUB_WORKSPACE, GITHUB_RUN_ID, GITHUB_RUN_NUMBER, GITHUB_RUN_ATTEMPT, GITHUB_EVENT_NAME, GITHUB_ACTOR, RUNNER_OS, RUNNER_TEMP, RUNNER_TOOL_CACHE, CI(true), GITHUB_ACTIONS(true).
- GITHUB_*·RUNNER_* 기본 변수는 덮어쓸 수 없다. 기본 변수는 env 컨텍스트에 없고 대부분 github·runner 컨텍스트에 대응 값이 있다.
- run 안에서는 셸 문법(`$NAME`), 워크플로 식에서는 `${{ env.NAME }}`.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - GITHUB_ENV에 쓴 값이 같은 단계에서 바로 적용된다는 선택지 → 다음 단계부터
> - runs-on에서 env 컨텍스트를 쓸 수 있다는 선택지 → 사용 불가
