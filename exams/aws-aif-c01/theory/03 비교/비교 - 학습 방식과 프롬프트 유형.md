# 비교 - 학습 방식과 프롬프트 유형

> [!summary] 한 줄로
> 학습 방식은 **레이블의 유무**, 프롬프트 유형은 **예시의 개수**로 구분한다.

## 학습 방식
| 방식 | 레이블 | 예 | 대표 알고리즘·서비스 |
|---|---|---|---|
| **지도 학습** | 있음 | 사기 판별, 가격 예측 | 선형·로지스틱 회귀, XGBoost, KNN |
| **비지도 학습** | 없음 | 고객 군집, 이상 탐지, 차원 축소 | K-평균, PCA, RCF |
| **자기 지도 학습** | 데이터가 곧 레이블 | LLM 사전 훈련(다음 단어 예측) | GPT, BERT |
| **강화 학습** | 보상·벌점 | 게임, 자율 주행 | [[AWS DeepRacer]], RLHF의 PPO |
| 전이 학습 | 기존 모델 확장 | 이미지 모델에 자사 로고 | 미세 조정 |

## 분류 vs 회귀 vs 군집
| 문제 | 출력 | 예 |
|---|---|---|
| 분류 | 범주 | 스팸인가, 사기인가 |
| 회귀 | 연속 수치 | 집값, 판매량 |
| 군집 | 그룹(레이블 없음) | 고객 세분화 |

## 프롬프트 유형
| 유형 | 예시 수 | 특징 |
|---|---|---|
| **제로샷** | 0 | 바로 요청 |
| **원샷** | 1 | |
| **퓨샷** | 몇 개 | 형식·기준을 따라 하게 |
| **사고의 사슬** | - | "단계별로 생각해 보세요" |

## 에이전트 워크플로 패턴 → [[Bedrock 에이전트]]
| 패턴 | 설명 |
|---|---|
| 라우팅 | 분류 후 전문 에이전트 하나 |
| 병렬화 | 섹셔닝·투표 |
| 프롬프트 체이닝 | 정해진 단계, 게이트 |
| 평가자-최적화자 | 생성 → 평가 → 반복 |
| 오케스트레이터-워커 | 쪼개서 맡기고 합성 |

## 추론 파라미터
| 파라미터 | 올리면 | 내리면 |
|---|---|---|
| 온도 | 다양·창의적 | **일관·예측 가능** |
| Top P / Top K | 후보 증가 | 후보 감소 |
| 최대 토큰 | 긴 응답 | 짧은 응답 |
