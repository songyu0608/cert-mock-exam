# 플래시카드 P02

> [!info] 이론: [[P02 ML 수명 주기와 MLOps]] · 카드 30장
> Spaced Repetition 플러그인이 있으면 오른쪽 사이드바 "Review"로 복습한다. 플러그인이 없으면 `::` 왼쪽이 질문, 오른쪽이 답이다.

ML 수명 주기 6단계 순서는?::비즈니스 목표 식별 → ML 문제 구성 → 데이터 처리 → 모델 개발 → 배포 → 모니터링

ML 수명 주기는 직선인가?::아니다. 모니터링 결과가 데이터 처리·모델 개발로 돌아가는 순환(피드백 루프)

ML 설계 원칙 중 CI/CD와 CT를 적용하는 원칙은?::자동화 (CT = 지속적 훈련)

ML 문제 구성 단계에서 가장 먼저 따질 질문은?::ML이 정말 맞는 해법인가? 규칙으로 충분하면 ML은 필요 없다

지속 가능성 측면에서 문제 구성 단계의 권장 사항은?::AI 서비스·사전 훈련 모델을 우선 재사용, 지속 가능한 리전 선택

설명 가능성 수준 합의와 공정성 검토에 쓰는 서비스는?::SageMaker Clarify

ML 역할과 책임 정의에 쓰는 서비스는?::SageMaker Role Manager

단계 간 피드백 루프에 쓰는 서비스 세 가지는?::SageMaker Model Monitor, Amazon CloudWatch, Amazon A2I

관리형 데이터 레이블링 서비스는?::SageMaker Ground Truth

민감 데이터 개인정보 보호(S3 PII 탐지) 서비스는?::Amazon Macie

훈련과 추론 사이의 특징 일관성을 보장하는 서비스는?::SageMaker Feature Store

전이 학습 시 성능 문제를 탐지하는 서비스는?::SageMaker Debugger

데이터 중독 위협 방어에 쓰는 것은?::SageMaker Clarify, Model Registry·Feature Store로 롤백

AutoML 서비스는?::SageMaker Autopilot

훈련 비용을 줄이는 관리형 훈련 옵션은?::관리형 스팟 인스턴스, Training Compiler

지속 가능한 하이퍼파라미터 튜닝 방법은?::무작위·그리드 대신 베이지안·Hyperband

클라우드 vs 엣지 배포 평가에 쓰는 서비스는?::SageMaker Neo, IoT Greengrass

호스팅 인스턴스 적정 크기를 추천하는 기능은?::Inference Recommender

모델 훈련용 AWS 칩은?::Trainium (Trn1)

딥 러닝 추론용 AWS 칩은?::Inferentia (Inf2)

CPU 추론용 AWS 칩은?::Graviton3

휴먼 인 더 루프 모니터링 서비스는?::Amazon Augmented AI (A2I)

Model Monitor가 감시하는 4가지는?::데이터 품질, 모델 품질, 편향 드리프트, 특징 기여도 드리프트

지속 가능성을 위한 재훈련 원칙은?::허용 정확도를 벗어날 때만 재훈련

ML 설계 원칙과 모범 사례를 점검하는 도구는?::AWS Well-Architected Tool의 ML 렌즈(JSON 사용자 지정 렌즈)

Well-Architected 6가지 원칙은?::운영 우수성, 보안, 안정성, 성능 효율성, 비용 최적화, 지속 가능성

MLOps란?::DevOps 방식을 ML 수명 주기에 적용한 것. 자동화, 버전 관리, CI/CD/CT, 모델 거버넌스

MLOps 전체 흐름을 자동화하는 SageMaker 기능은?::SageMaker Pipelines

모델 버전과 승인 상태를 관리하는 기능은?::SageMaker Model Registry

ML 모델의 ROI를 시각화하는 서비스는?::Amazon QuickSight
