# Bedrock 에이전트

> [!summary] 한 줄 정의
> LLM이 요청을 **스스로 여러 단계로 나누고 도구(API·Lambda)와 지식 기반을 호출**해 작업을 끝까지 수행하게 하는 기능

## 시험 트리거
| 문제 속 표현 | 정답 |
|---|---|
| 여러 단계 작업 자동 수행, 외부 API 호출 | **에이전트** |
| 에이전트의 도구를 정의하는 단위 | **작업 그룹** (Lambda + OpenAPI 스키마) |
| RAG도 에이전트의 도구 중 하나 | **에이전틱 RAG** |
| 도구가 너무 많거나 로직이 복잡 | **멀티 에이전트** (오케스트레이터·워커) |
| 에이전트를 대규모로 배포·운영 | [[Bedrock AgentCore]] |

## 주요 기능
**구성**
- 메모리(대화 기록·외부 저장소), 계획(문제 분해 지침), 도구(함수)
- 작업 그룹: 언제 쓸지 알려 주는 설명 + Lambda 파라미터(이름·설명·유형·필수)
- **파라미터 설명**이 중요: LLM이 이를 보고 값을 뽑고, 부족하면 사용자에게 되물음
- 지식 기반 연결, 코드 인터프리터(선택)

**워크플로 패턴**
- 라우팅: 한 번 분류해 전문 에이전트 하나 호출
- 병렬화: 섹셔닝(독립 작업 동시) / 투표
- 프롬프트 체이닝: 정해진 단계, 중간 게이트
- 평가자-최적화자: 생성 → 평가 → 피드백 반복
- 관리자(오케스트레이터-워커-합성기)

**메모리**
- 단기: 세션 안 대화 기록 (ElastiCache, MemoryDB, DynamoDB)
- 장기: 선호·사실·세션 요약 등 메모리 레코드 (DynamoDB, AgentCore Memory 등)
