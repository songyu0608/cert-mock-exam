# P09 책임 있는 AI

> [!abstract] 이 파트에서 배우는 것
> 책임 있는 AI의 8가지 차원 → AWS 도구 → Bedrock 모델 평가 → 편향 찾기와 바로잡기(Clarify, Data Wrangler) → 편향 지표 → 설명 가능성(SHAP, PDP) → 모니터링과 거버넌스 → AI 서비스 카드 vs 모델 카드 → 투명성·설명 가능성·해석 가능성 → 인간 중심 설계
> 관련 시험 도메인: **D4 책임 있는 AI 지침(14%)**

## 1. 책임 있는 AI의 8가지 핵심 차원
| 차원 | 뜻 |
|---|---|
| **공정성** | 집단마다 결과가 부당하게 달라지지 않게 |
| **설명 가능성** | 모델이 **왜** 그런 결과를 냈는지 이해 |
| **개인 정보 보호·보안** | 데이터를 적절히 얻고, 쓰고, 보호 |
| **안전성** | 유해한 출력과 오용을 막음 |
| **제어 가능성** | 모델의 행동을 감시하고 조정 |
| **진실성·견고성** | 예상치 못한 입력에도 올바른 출력 |
| **거버넌스** | AI 공급망 전반에 모범 사례 적용 |
| **투명성** | 이해관계자가 AI 사용에 대해 알고 판단 |

## 2. 책임 있는 AI를 위한 AWS 도구
| 도구 | 역할 |
|---|---|
| [[Amazon Bedrock]] 모델 평가 | 자동·인적 평가 |

| [[SageMaker Model Monitor]] | 부정확한 응답이 나오면 알림 |
| [[Amazon Augmented AI]] | 결과를 바로잡도록 **사람**을 검토에 투입 |
| SageMaker ML 거버넌스 | [[SageMaker Role Manager]], [[SageMaker 모델 카드]], 모델 대시보드 |

> [!tip] 시험 포인트
> 편향·설명 가능성 → **Clarify** · 사람 검토 → **A2I** · 모델 문서화 → **모델 카드** · 유해 콘텐츠 차단 → **가드레일**

## 3. Bedrock 모델 평가: 자동 vs 인적
| 자동 평가 | 인적 평가 |
|---|---|
| 미리 정의된 지표로 기계가 채점 | **주관적** 지표를 사람이 평가 (사내 직원 또는 AWS 제공 검토자) |
| 정확도, 견고성, 유해성 | 친근함, 스타일, 정렬, **브랜드 보이스** |

- SageMaker Clarify도 같은 평가 기능 지원

> [!tip] 시험 포인트
> "우리 브랜드 말투와 맞는지" → **인적 평가** · 정확도·유해성 같은 표준 지표 → **자동 평가**

## 4. 편향 찾기(Clarify)와 바로잡기(Data Wrangler)
1. **SageMaker Clarify로 찾기**: 확인할 특징(나이, 성별)을 지정 → 분석해 보고. **균형을 맞추는 일은 사용자 몫**
2. **Data Wrangler로 균형 맞추기**
   - **무작위 언더샘플링**: 많은 쪽을 줄임
   - **무작위 오버샘플링**: 적은 쪽을 복제
   - **SMOTE**: 최근접 이웃으로 소수 클래스의 **새 샘플을 인공 생성**

> [!warning] 헷갈림 주의
> Clarify는 편향을 **찾아서 보고**만 한다. 데이터를 고치는 건 [[SageMaker Data Wrangler]]

## 5. Clarify의 훈련 전 편향 지표
**패싯(facet)** = 비교하려는 인구 집단(성별, 연령대)

| 지표 | 보는 것 |
|---|---|
| **클래스 불균형(CI)** | 한 집단의 훈련 데이터가 다른 집단보다 적음 |
| **레이블 비율 차이(DPL)** | 집단 간 긍정적 결과 비율 차이 |
| KL 발산 · JS 발산 | 집단별 결과 분포가 얼마나 다른가 |
| Lp 노름(LP) | 결과 분포의 p-노름 차이 |
| 총 변동 거리(TVD) | 결과 분포의 L1 노름 차이 |
| 콜모고로프-스미르노프(KS) | 결과 분포 사이의 최대 차이 |
| 조건부 인구 통계 격차(CDD) | 전체와 하위 그룹별 결과 격차 |

## 6. 설명 가능성: SHAP, 섀플리 값, PDP
- **SHAP**(Clarify + Experiments): 특징을 하나씩 빼고 평가해 영향과 **상대적 중요도** 계산
- **섀플리 값**: 게임 이론에서 온 기여도 계산. 특징이 많으면 복잡해 Clarify는 근사인 SHAP 사용. 시계열은 **비대칭 섀플리 값**
- **부분 의존도 플롯(PDP)**: 특징 값이 바뀔 때 예측이 어떻게 달라지는지 + 구간별 데이터 분포

> [!example] 대출 승인 예측의 특징 기여도
> 연 소득 +0.32 · 재직 기간 +0.18 · 부채 비율 −0.22 · 연체 이력 −0.27
> (+는 승인 쪽, −는 거절 쪽으로 밀어낸 정도)

| [[AWS AI 서비스 카드]] | [[SageMaker 모델 카드]] |
|---|---|

| 예: Rekognition(얼굴 인식), Textract AnalyzeID, Transcribe(배치) | |

## 9. 책임 있는 실천
### 책임 있는 모델 선택
- SageMaker·Bedrock 모델 평가 기능 사용
- 사용 사례를 **좁게** 정의: 대상 사용자와 규모, 무엇이 잘못될 수 있나, 완화 수단
- 일반 벤치마크가 아니라 **내 데이터로** 테스트, 모델·데이터 버전별 추이

### 책임 있는 에이전시
- 환경뿐 아니라 사회적·경제적 영향까지, 가치 정렬(이익만이 아닌 사람)
- 적절한 **자율성 수준**: 위험이 크면 사람을 개입시키거나 인적 평가
- 투명성과 책임성: 행동을 설명할 수 있나, 외부 감독이 가능한가

### 책임 있는 데이터 세트 준비
- 데이터 균형 (Data Wrangler, Clarify), 정제·특징 선택·정규화
- **포용적이고 다양한 데이터**: 법 집행·금융 승인처럼 위험이 큰 분야일수록. 적게 대표된 집단은 **데이터 증강**
- 인구 속성만의 문제가 아님 (특정 연령·체중에 치우친 건강 데이터)
- **큐레이션**: 너무 다양해도 문제. 대상이 좁다면 그 집단만 (10대 음악 추천을 50대 취향으로 훈련하지 않기)
- **정기 감사**: 데이터는 드리프트하므로 주기적으로 편향 점검

## 10. 핵심 개념 비교 → [[비교 - 책임 있는 AI 개념과 문서]]
### 투명성(HOW) vs 설명 가능성(WHY)
| | 투명성 | 설명 가능성 |
|---|---|---|
| 질문 | 모델이 **어떻게** 결정하나 | **왜** 그렇게 결정했나 |
| 효과 | 책임성, 신뢰, 감사 가능, 블랙박스가 아님 | 디버깅, 한계 이해, 사용 방법 결정 |
| 구현 | 투명한 문서, UI 안의 설명, 모델 카드, AI 서비스 카드 | SHAP, LIME, **반사실적 설명** / Clarify + Experiments, Clarify 온라인 설명 가능성, Autopilot |
| 단점 | 약점이 악용되기 쉬움, 투명한 모델은 단순해 성능이 낮을 수 있음 | 보안·PII 노출, 악의적 사용자에게 정보, 비용·복잡도 |

### 해석 가능성 · 모델 안전성 · 제어 가능성
- **해석 가능성**: 결정의 원인을 사람이 이해하는 정도. 투명성보다 깊어 **내부 가중치까지** 이해
- **모델 안전성**: 사회적 해, 개인 정보, 보안 측면에서 해를 끼치지 않는 능력. **투명성과 자주 충돌**
- **제어 가능성**: 입력 데이터를 바꿔 모델을 얼마나 제어할 수 있나. 데이터 증강, 훈련 제약으로 높임

> [!warning] 공통 트레이드오프
> 해석·제어가 쉬울수록 성능은 낮아지는 경향
> 해석 쉬움 ← 선형 회귀 · 의사 결정 트리 · 딥 러닝 → 성능 높음(내부 불투명)

## 11. 인간 중심 설계 (HCD)
- **RLHF**가 대표 예 ([[SageMaker Ground Truth]])
- 설명은 명확·유용·이해하기 쉽고·정확·공정해야 함
- **증폭된 의사 결정**: 압박 속 고위험 결정을 기술로 도움. 원칙: 명확성, 단순성, 사용성, 성찰성, 책임성
- **편향 없는 의사 결정**: 편향을 찾아 해결, 공정·투명한 절차, 결정자 교육. 핵심: 투명성, 공정성, 교육
- **사람과 AI의 학습**: 인지적 도제, 개인화, 사용자 중심 설계(장애가 있는 사람 포함)

## 파트 핵심 요약
> [!summary] 시험 직전 체크
> - 편향 찾기 → Clarify · 균형 맞추기 → Data Wrangler(언더·오버샘플링, SMOTE)
> - 특징 기여도 → SHAP(섀플리 값) · 특징 값에 따른 예측 변화 → PDP
> - 내 모델 문서 → 모델 카드 · AWS 서비스 정보 → AI 서비스 카드
> - 지속 모니터링 → Model Monitor · 사람 검토 → A2I · 권한 → Role Manager
> - 투명성 = 어떻게 · 설명 가능성 = 왜 · 해석 가능성 = 내부까지
> - 단순 모델(해석·제어 쉬움) ↔ 복잡 모델(성능 높음) · 안전성 ↔ 투명성
