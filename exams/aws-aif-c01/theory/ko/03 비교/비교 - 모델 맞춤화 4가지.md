# 비교 - 모델 맞춤화 4가지

> [!summary] 한 줄로
> 가중치를 **안 바꾸는** 두 가지(프롬프트, RAG)와 **바꾸는** 두 가지(미세 조정, 지속적인 사전 훈련). 비용은 이 순서로 커진다.

| | 프롬프트 엔지니어링 | RAG ([[Bedrock 지식 기반]]) | 미세 조정 | 지속적인 사전 훈련 |
|---|---|---|---|---|
| 가중치 변경 | 없음 | 없음 | **있음** | **있음** |
| 데이터 | 예시 몇 개 | 외부 문서·DB | **레이블 있는** 프롬프트-응답 쌍 | **레이블 없는** 대량 텍스트 |
| 비용·노력 | 가장 낮음 | 낮음~중간 | 높음 | 가장 높음 |
| 최신 정보 반영 | 프롬프트에 직접 | **DB만 갱신** | 재훈련 필요 | 재훈련 필요 |
| 대표 상황 | 빠르게 품질 개선 | 사내·최신 정보, 출처 제공, 환각 감소 | 특정 작업·말투·형식 | 도메인 용어·지식 자체 |
| Bedrock 호출 | 온디맨드 | 온디맨드 | **프로비저닝된 처리량 필요** | **프로비저닝된 처리량 필요** |

## 문제 속 표현 → 정답
| 표현 | 정답 |
|---|---|
| 가장 빠르고 저렴하게, 재훈련 없이 | 프롬프트 엔지니어링 |
| 자주 바뀌는 사내 문서, 답변 근거 표시 | RAG |
| 레이블이 지정된 예시로 특정 작업 성능 향상 | 미세 조정 |
| 레이블 없는 사내 문서로 도메인에 익숙하게 | 지속적인 사전 훈련 |
| 프롬프트-원하는 출력 쌍으로 지시 처리법 | 지시 튜닝 (미세 조정의 한 형태) |
| 사람이 응답 순위를 매겨 사람 선호에 맞춤 | RLHF ([[SageMaker Ground Truth]]) |

> [!warning] 함정
> - RAG는 **모델을 훈련하지 않는다**. "모델에 지식을 넣는다"는 보기는 미세 조정·사전 훈련
> - 레이블이 없으면 미세 조정이 아니라 지속적인 사전 훈련
