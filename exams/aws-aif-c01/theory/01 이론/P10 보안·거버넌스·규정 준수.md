# P10 보안·거버넌스·규정 준수

> 관련 시험 도메인: **D5 AI 솔루션 보안·규정 준수·거버넌스(14%)**

## 1. 보안, 거버넌스, 규정 준수
| 개념 | 뜻 |
|---|---|
| **보안** | 데이터·정보·인프라의 **기밀성, 무결성, 가용성** 보호 |
| **거버넌스** | 가치를 더하면서 **위험을 관리**할 수 있게 함 |
| **규정 준수** | 조직 내부·외부의 **요구 사항을 지킴** |

## 2. AWS 공동 책임 모델
| AWS의 책임: 클라우드 "자체"의 보안 | 고객의 책임: 클라우드 "안"의 보안 |
|---|---|
| 하드웨어, 소프트웨어, 네트워킹, 시설 | 사실상 나머지 전부. 막을 수 있었던 침해는 고객 책임 |
| | 관리형이 아닌 서비스는 직접 패치 |
| | 최소 권한 원칙, 자격 증명 보호 |

> [!tip] 시험 포인트
> 데이터 암호화 설정, IAM 권한, 모델에 넣는 데이터 관리 → **고객 책임** · 데이터 센터·하드웨어 → **AWS 책임**

## 3. 심층 방어: 7겹의 방어층
여러 겹의 중복된 방어. 생성형 AI에만 해당하지 않는다.

| 층 | 영역 | 서비스 |
|---|---|---|
| 7 | 정책·절차·인식 | 최소 권한, IAM Access Analyzer, 단기 자격 증명 |
| 6 | 위협 탐지·사고 대응 | [[AWS Security Hub]], [[Amazon GuardDuty]], Lambda, EventBridge |
| 5 | 인프라 보호 | IAM, 사용자 그룹, 네트워크 ACL |
| 4 | 네트워크·엣지 보호 | VPC, [[AWS WAF]](Bot Control) |
| 3 | 애플리케이션 보호 | [[AWS Shield]] Advanced, [[Amazon Cognito]] |
| 2 | 아이덴티티·접근 관리 | IAM 사용자·그룹·역할·정책 |
| 1 | 데이터 보호 | [[AWS KMS]], ACM, Private CA, [[AWS PrivateLink]], Network Firewall |

### 데이터 보호
- 저장 시: KMS의 AWS 관리형 키 또는 **고객 관리형 키(CMK)**, S3에서 버전 관리·백업
- 전송 중: AWS Certificate Manager(ACM), AWS Private CA
- VPC(격리된 가상 네트워크), Network Firewall(TLS 트래픽 검사), **PrivateLink**(인터넷 노출 없이 VPC에서 Bedrock으로)

### AWS IAM → [[AWS IAM]]
- 사용자·사용자 그룹: 자체 자격 증명, 비교적 장기적
- **역할**: 보통 임시, 사람이 아닌 서비스(EC2)에도 부여
- **정책**: 사용자·역할에 붙이는 구체적 권한

### 애플리케이션·네트워크·위협 대응
- Shield Advanced: DDoS 방어 (WAF, Firewall Manager 포함) · Cognito: 사용자 인증
- WAF: 웹 트래픽 필터, 계정 탈취 사기 방지, 봇 제어
- Security Hub: 모든 보안 결과를 한 대시보드, 자동 플레이북 · GuardDuty: 위협 탐지 · 대응 자동화: Lambda, EventBridge
- **IAM Access Analyzer**: 권한이 지나친 계정·역할·리소스 찾기

## 4. AI와 관련 깊은 보안 서비스 4가지
| 서비스 | 역할 |
|---|---|
| [[SageMaker Role Manager]] | ML 페르소나 기반 IAM 역할 (데이터 과학자, MLOps, SageMaker 컴퓨팅) |
| [[Amazon Macie]] | ML로 **S3의 민감 데이터**(PII, PHI, 금융 정보) 탐지. DB는 S3 데이터 레이크로 내보내 검사 |
| [[Amazon Inspector]] | 워크로드의 **소프트웨어 취약점**과 의도치 않은 네트워크 노출 스캔 |
| [[Amazon Detective]] | 보안 사고의 **포렌식 조사** |

> [!tip] 시험 포인트
> S3의 PII → **Macie** · 취약점 → **Inspector** · 사고 원인 조사 → **Detective** · 위협 탐지 → **GuardDuty**

- **출처 표기**: 훈련 데이터의 출처, 라이선스·이용 약관·허가 확인
- **데이터 기원**: 수집·큐레이션·정제·전처리·변환 과정 문서화
- 도구: [[SageMaker ML Lineage Tracking]], [[AWS Glue]] Data Catalog, [[SageMaker 모델 카드]]

## 6. 데이터 엔지니어링의 보안
- **데이터 품질**: 완전성, 정확성, 적시성, 일관성. 파이프라인 안 검증·테스트, 프로파일링과 모니터링
- **개인 정보 보호 강화**: 마스킹·난독화, 암호화, **토큰화**. AWS 개인 정보 보호 참조 아키텍처(AWS PRA)
- **데이터 무결성**: 스키마·참조 무결성·비즈니스 규칙 검증, 백업·복구, 트랜잭션 관리(원자성)

## 7. 거버넌스 전략과 규정 준수 표준
### AI 거버넌스 프레임워크
- 편향, 개인 정보, 의도치 않은 위험 완화, 대중의 신뢰 구축
- 명확한 정책·지침(법적·규제적, 윤리적·사회적)
- **AI 거버넌스 위원회**: 법무, 개발자(SME), 규정 준수, 개인 정보 전문가의 교차 기능 조직
- 정책과 절차를 실제로 시행

| 표준 | 내용 |
|---|---|
| NIST 800-53 | 미국 연방 정보 시스템 보호 장치 |
| ENISA | 유럽 연합 사이버 보안청 |
| **ISO/IEC 27001** | 정보 보안 모범 사례. **AWS가 인증을 보유해도 고객이 물려받지는 않음** |
| AWS SOC | AWS에 대한 독립적인 제3자 평가 |
| HIPAA · GDPR · PCI DSS | 의료 정보 · EU 개인 정보 · 카드 결제 정보 |

### 규제 대상 워크로드
- 금융, 의료, 항공우주 등. 스스로 물을 것: 감사 필요? 일정 기간 보관? 제한된 데이터? AI 출력이 새 기록을 만드나?
- 규제 유형: 보고 의무(절차), 대출·신용 승인(결과), 안전이 중요한 시스템, AI 실패 시 책임

### AI 규정 준수는 무엇이 다른가
- **복잡성·불투명성**(LLM은 감사가 어려움), **동적 변화**, **창발적 행동**
- 고유한 위험: 데이터와 사람의 편향, 개인 정보, 허위 정보, 일자리 대체
- 알고리즘 책임법: **EU AI 법**은 투명성, 위험 평가, 사람의 감독을 요구

## 8. AI를 위한 데이터 거버넌스
- **품질과 무결성**: 계보·출처로 변환 이력, 검증·정제
- **보호와 개인 정보**: 접근 제어·암호화, 침해 대응, **데이터 레지던시·주권**
- **수명 주기 관리**: 수집 → 처리 → 저장 → 소비 → 폐기·보관. 분류·목록화, 보존 정책
- **구조와 역할**: 데이터 거버넌스 위원회, 데이터 소유자·관리자
- **공유와 협업**: 교환 협약, 데이터 가상화·페더레이션
- **책임 있는 AI**: 편향·공정성·투명성·책임성, 모니터링과 감사
- 그 밖: 정책의 정기 검토, 다양한 이해관계자 검토, 투명성, 사내 교육과 인증

## 9. 거버넌스를 위한 AWS 서비스 (자주 출제) → [[비교 - 감사·거버넌스 서비스]]
| 서비스 | 하는 일 | 키워드 |
|---|---|---|
| [[AWS Config]] | 리소스 구성, 관계, **시간에 따른 구성 변화** | 구성 이력·변경 추적 |
| [[Amazon Inspector]] | CVE 소프트웨어, 악용 가능한 코드, 약한 암호화, 열린 네트워크 경로 지속 스캔, NVD 기반 위험 점수 | 취약점 스캔 |
| [[AWS Audit Manager]] | 하이브리드·멀티 클라우드 포함 **감사 증거 수집 자동화**, 증거 무결성 | 감사 증거 자동 수집 |
| [[AWS Artifact]] | AWS의 보안·규정 준수 문서(ISO 인증, PCI·SOC 보고서) 즉시 제공 | 규정 준수 보고서 다운로드 |
| [[AWS CloudTrail]] | 콘솔·CLI·SDK·API의 **모든 작업 기록**. "누가 무엇을 망가뜨렸나" | API 호출 기록 |
| [[AWS Trusted Advisor]] | 비용, 성능, 복원력, 보안, 운영 우수성, 서비스 한도 점검·권고 | 모범 사례 점검 |

> [!warning] 헷갈림 주의
> - Artifact = **AWS의** 보고서 / Audit Manager = **내 환경의** 감사 증거
> - CloudTrail = **누가 어떤 API를** / Config = 리소스 **구성이 어떻게 변했나**
> - Inspector = **취약점** / GuardDuty = **위협(이상 행동)**

## 10. 생성형 AI 보안 범위 지정 매트릭스
생성형 AI를 얼마나 직접 소유·통제하느냐에 따라 5단계. 범위가 넓을수록 고객의 책임이 커진다.

| 범위 | 내용 |
|---|---|
| 1 소비자 앱 | 공개 생성형 AI 서비스 사용 |
| 2 기업용 앱 | 생성형 AI 기능이 든 SaaS 사용 |
| 3 사전 훈련 모델 | 기존 FM으로 앱 구축 (예: Bedrock) |
| 4 미세 조정 모델 | 내 데이터로 FM 미세 조정 |
| 5 자체 훈련 모델 | 처음부터 직접 훈련 → **고객 통제·책임 최대** |

살펴볼 분야: 거버넌스·규정 준수, 법률·개인 정보, 위험 관리, 통제, 복원력

## 11. 시험 안내
### 문제 유형 5가지
| 유형 | 설명 |
|---|---|
| 객관식 | 보기 4개 중 정답 1개 |
| 복수 응답 | 5개 이상 중 2개 이상. **부분 점수 없음** |
| 순서 배열(새 유형) | 3~5개를 올바른 순서로. 부분 점수 없음 |
| 연결(새 유형) | 3~7개 항목을 짝지음. 부분 점수 없음 |
| 사례 연구(새 유형) | 한 시나리오로 2문제 이상, 각각 채점 |

- 시험장: 준비물 없음, 메모지·보드·귀마개 제공, 표시(flag) 기능
- 강의는 베타 시험 기준(120분, 85문항)으로 설명. 정식 시험은 **AWS 공식 시험 가이드에서 확인**

### 준비와 응시 전략
- 연습 시험을 충분히 익힌 뒤 예약, 에너지가 좋은 시간대, 충분한 수면
- 무엇을 최적화하는지, 요구 사항, 시스템 전체를 파악
- 한 문제 1~1.5분, 넘어가면 최선의 답 + 표시 후 다시 보기
- **소거법**, 침착하게 (100점 필요 없음)

## 파트 핵심 요약
> [!summary] 시험 직전 체크
> - AWS = 클라우드 자체 · 고객 = 클라우드 안(데이터, IAM, 암호화 설정)
> - PII → Macie · 위협 → GuardDuty · 취약점 → Inspector · 조사 → Detective

> - 비공개 연결 → PrivateLink · 키 → KMS · 웹 공격 → WAF · DDoS → Shield
> - 계보 → ML Lineage Tracking · Glue Data Catalog · 모델 카드
> - 과도한 권한 → IAM Access Analyzer · 서비스에는 역할과 단기 자격 증명
