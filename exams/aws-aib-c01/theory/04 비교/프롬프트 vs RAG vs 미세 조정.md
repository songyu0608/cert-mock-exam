# 프롬프트 vs RAG vs 미세 조정

| | [[프롬프트 엔지니어링]] | [[검색 증강 생성(RAG)]] | [[미세 조정]] |
|---|---|---|---|
| 바꾸는 것 | 지시·예시·형식 | 모델에 주는 **지식** | 모델의 **동작**(가중치) |
| 비용·기간 | 최소·즉시 | 낮음·짧음 | 높음·김 |
| 데이터 업데이트 | 프롬프트 수정 | 지식 기반만 교체 | 재학습 |
| 출처 제시 | - | 가능 | 불가 |
| 맞는 상황 | 우선 저비용 개선 | 최신·사내 정보, 출처 필요 | 일관된 문체·형식, 전문 작업 |
| AWS | (모든 FM) | Bedrock 지식 기반 | Bedrock 모델 사용자 지정, SageMaker AI |

**판별 순서**: ① 프롬프트로 되나? → ② 모델이 모르는 정보가 문제인가(RAG)? → ③ 동작 자체를 바꿔야 하나(미세 조정)? → ④ 그래도 안 되면 지속 사전 학습·자체 모델

> [!question]- "매주 바뀌는 상품 가격표를 근거로 답하고 출처도 보여 달라"
> RAG. 미세 조정은 업데이트마다 재학습이 필요하고 출처를 보여줄 수 없다.

> [!question]- "모든 답을 회사의 법무 문서 형식과 문체로 일관되게"
> 먼저 프롬프트(템플릿·퓨샷). 그래도 부족하면 미세 조정.
