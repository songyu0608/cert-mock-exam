# 책임 있는 AI 차원

> [!summary] 한 줄 정의
> AWS가 정리한 책임 있는 AI의 8차원: 공정성, 설명 가능성, 개인정보 보호 및 보안, 안전, 제어 가능성, 정확성 및 견고성, 거버넌스, 투명성. 시나리오가 어느 차원의 문제인지 짚어낸다.

**일본어** 責任ある AI のディメンション　·　**영어** Dimensions of responsible AI

## 시험 트리거
- "특정 속성의 승인율만 낮다" → 공정성
- "결과의 이유를 설명해 달라" → 설명 가능성
- "AI가 쓴 글임을 사용자가 모른다" → 투명성
- "예상치 못한 입력에 오동작" → 견고성

## 핵심
| 차원 | 의미 | 일본어 |
|---|---|---|
| 공정성 Fairness | 속성에 따른 부당한 차이를 만들지 않는다 | 公平性 |
| 설명 가능성 Explainability | 출력의 이유를 이해·설명할 수 있다 | 説明可能性 |
| 개인정보 보호 및 보안 | 데이터를 적절히 수집·사용·보호 | プライバシーとセキュリティ |
| 안전 Safety | 유해 출력과 오용 방지 | 安全性 |
| 제어 가능성 Controllability | 동작을 모니터링·제어할 수 있다 | 制御可能性 |
| 정확성 및 견고성 Veracity & robustness | 예상 밖 입력에도 올바르게 동작 | 正確性と堅牢性 |
| 거버넌스 Governance | 책임 있는 관행을 조직에 내재화 | ガバナンス |
| 투명성 Transparency | AI 사용·능력·한계를 공개 | 透明性 |

공식 기술 3.1.1의 예시는 **공정성, 설명 가능성, 개인정보 보호, 안전, 투명성, 견고성** 6개. 8차원은 AWS 책임 있는 AI 정리 기준.

**시나리오 → 차원 → 대응**

| 시나리오 | 차원 | 대응 |
|---|---|---|
| 대출 심사에서 특정 속성 승인율만 낮다 | 공정성 | 속성별 결과 측정, 학습 데이터 편향 시정 |
| 고객이 심사 결과 이유를 요구 | 설명 가능성 | 판단에 영향 준 요인을 보여줄 구조 |
| 고객 데이터를 학습에 쓰고 싶다 | 개인정보 보호 | 동의, 목적 제한, 익명화 |
| 챗봇이 부적절한 발언 | 안전 | [[가드레일]], 출력 필터 |
| AI가 쓴 글임을 모른다 | 투명성 | AI 사용 명시 |
| 예상 밖 입력으로 오동작 | 견고성 | 다양한 테스트, 대체 절차 |

## 헷갈리는 개념
| 개념 | 차이 |
|---|---|
| [[투명성 vs 설명 가능성]] | 투명성 = AI를 쓴다는 사실·능력·한계 공개, 설명 가능성 = 개별 출력의 이유 |
