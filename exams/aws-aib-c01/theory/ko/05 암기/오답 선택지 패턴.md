# 오답 선택지 패턴

이 시험은 "그럴듯하지만 비즈니스 판단으로는 틀린" 선택지가 반복된다. 이런 표현이 보이면 먼저 의심한다.

| 오답이 되기 쉬운 선택지 | 정답 쪽 | 노트 |
|---|---|---|
| 최신·최대 모델을 먼저 도입한다 / 기술부터 고른다 | 비즈니스 문제에서 출발 | [[문제 중심 AI 전략]] |
| 처음부터 자체 모델을 학습한다 | 프롬프트 → RAG → 미세 조정 순, 관리형 우선 | [[프롬프트 vs RAG vs 미세 조정]] |
| 자주 바뀌는 정보에 미세 조정 | RAG(지식 기반만 교체) | [[검색 증강 생성(RAG)]] |
| 규칙으로 충분한 업무에 AI | 규칙 기반 자동화 | [[규칙 기반 자동화]] |
| 섀도 AI를 모니터링·안내만으로 대응 | 대체 도구 + 분류 + 절차 + 차단 | [[섀도 AI]] |
| 도입 후에 효과 측정을 시작 | 구현 전 기준 지표 | [[기준 지표]] |
| 파일럿 단계에서 ROI로 계속 여부 판단 | 선행 지표 | [[선행 지표]] |
| 지금까지 투자했으니 계속한다 | 사전 KPI로 판단(매몰 비용 무시) | [[규모 조정·일시 중지·종료]] |
| 비용 = 이용료만 | TCO 전체 | [[총소유비용(TCO)]] |
| 한 번에 전면 전환·전사 일괄 도입(빅뱅) | 병행 운영·단계적·퀵 윈부터 | [[퀵 윈]] |
| 목표를 위해 책임 있는 AI 원칙을 일시적으로 완화 | 위험 비례로 양립 | [[책임 있는 AI 절충]] |
| 출시 직전에 윤리·위험 검토 | 계획 단계부터 | [[설계에 따른 거버넌스]] |
| IT 부서만 / 법무만으로 거버넌스 | 부서 간 대표성 + 책임 소재 | [[AI 거버넌스 위원회]] |
| 모든 AI에 같은 강도의 심사 | 위험 비례 | [[비례적 거버넌스]] |
| 관리형 서비스면 보안·책임은 AWS | 데이터·액세스·사용은 고객 | [[AWS 공동 책임 모델]] |
| 편향은 학습 전 1회 점검으로 충분 | 수명 주기 전체 + 운영 중 모니터링 | [[바이어스 드리프트]] |
| 프로덕션 배포로 프로젝트 완료 | 모니터링·인시던트 대응·롤백까지 | [[프로덕션 위험 모니터링]] |
| 실험 단계 조직에 전사 확산 권고 | 성숙도에 맞는 다음 단계 | [[AI 성숙도 모델]] |
| 문화 문제를 새 도구 배포로 해결 | 리더 행동·평가 제도 변경 | [[문화적 장벽]] |
| 직원 불안에 정보 비공개·확정 후 공지 | 투명한 커뮤니케이션 | [[투명한 커뮤니케이션]] |
| 기술 팀만의 AI 프로젝트 | 부서 간 팀 | [[부서 간 팀]] |
| 전 직원에게 같은 교육 | 역할별 교육 | [[인력 개발 접근 방식]] |
| AI로 사람을 대체해 비용 절감 | 감독·협업으로 역할 전환 | [[인간의 감독과 협업]] |
| 항상 최대 투자 | 산업 성숙도·경쟁 동향에 맞춘 투자 | [[산업 성숙도별 AI 투자]] |

> [!tip] 공통 원리
> 정답은 대체로 **비즈니스 목표에서 출발하고, 작게 시작해 측정하며, 위험에 비례해 통제하고, 사람과 조직을 함께 바꾸는** 선택지다.
