# 프롬프트 엔지니어링

> [!summary] 한 줄 정의
> 모델을 바꾸지 않고 지시·컨텍스트·예시·형식을 설계해 출력을 개선하는 기법. 출력 개선의 첫 수단(저비용·즉효).

**일본어** プロンプトエンジニアリング　·　**영어** Prompt engineering

## 시험 트리거
- "우선 저비용으로 출력을 개선하고 싶다"
- "출력 형식을 맞추고 싶다" → 퓨샷
- "복잡한 판단·계산" → Chain-of-Thought
- "품질 표준화·담당자 의존 방지" → 프롬프트 템플릿

## 핵심
**기본 원칙 6가지**: 명확한 지시 · 컨텍스트(배경·독자·제약) · 역할 지정 · 예시 제시(Few-shot) · 출력 형식 지정 · 단계적 사고(CoT)

| 기법 | 내용 | 적합한 상황 |
|---|---|---|
| 제로샷 | 예시 없이 지시만 | 일반적·단순한 작업 |
| 퓨샷 | 소수의 입출력 예시 | 출력 형식·판단 기준 맞추기 |
| Chain-of-Thought | 추론 과정을 단계별로 | 복잡한 판단·계산 |
| 프롬프트 템플릿 | 정형 프롬프트를 조직에서 공유·재사용 | 품질 표준화 |
| 제약·금지 사항 명시 | 하면 안 되는 일·다루지 않을 주제 | 안전성, 브랜드·정책 준수 |

> [!important] 시험 포인트
> 개선 순서: **프롬프트 → RAG → 미세 조정** (비용·기간·필요 데이터가 오른쪽으로 갈수록 커짐)
