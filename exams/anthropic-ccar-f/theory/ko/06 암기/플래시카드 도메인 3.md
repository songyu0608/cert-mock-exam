# 플래시카드 도메인 3　Claude Code 구성과 워크플로

#flashcards/ccar-f/d3

형식: `질문::답` (Spaced Repetition 플러그인). 플러그인이 없어도 한 줄씩 읽으면 된다.

## 개념 확인
항상 적용할 표준과 필요할 때만 쓰는 워크플로를 각각 어디에 두나?::표준은 CLAUDE.md, 워크플로는 스킬
자연어 설명으로 변환 결과가 일관되지 않을 때 가장 효과적인 방법은?::구체적인 입력/출력 예시 2~3개
서로 영향을 주는 여러 문제는 어떻게 전달하나?::한 번의 자세한 메시지로 함께
인터뷰 패턴이란?::구현 전에 Claude가 질문하게 해 놓친 고려 사항을 드러내는 방법
CI 재리뷰에서 중복 코멘트를 막는 방법은?::이전 리뷰 결과를 컨텍스트에 넣고 새 문제·미해결 문제만 보고하도록 지시
생성된 코드를 리뷰할 때 같은 세션보다 별도 인스턴스가 나은 이유는?::생성 때의 추론 맥락이 없어 자기 결정을 의심할 수 있다
~/.claude/CLAUDE.md의 지시가 팀원에게 적용되나?::아니다. 사용자 수준이라 본인에게만 적용된다
어떤 메모리 파일이 로드됐는지 확인하는 명령은?::/memory
CLAUDE.md에서 패키지별로 필요한 표준 파일만 포함하는 구문은?::@import
코드베이스 곳곳의 테스트 파일에 같은 규칙을 자동 적용하는 가장 유지 보수하기 좋은 방법은?::.claude/rules/ 파일의 YAML frontmatter paths에 glob 패턴(예: **/*.test.tsx)
팀 전원이 쓰는 /review 명령 파일은 어디에 두나?::저장소의 .claude/commands/
스킬 출력이 메인 대화를 오염시키지 않게 하는 frontmatter는?::context: fork
스킬 실행 중 도구를 제한하는 frontmatter는?::allowed-tools
인자 없이 호출했을 때 필요한 값을 안내하는 frontmatter는?::argument-hint
모놀리스를 마이크로서비스로 재구성할 때의 접근은?::플랜 모드로 탐색·설계 후 변경
스택 트레이스가 분명한 단일 파일 버그 수정은?::직접 실행
장황한 탐색 출력으로 메인 컨텍스트가 고갈되는 것을 막는 방법은?::Explore 서브에이전트에 탐색을 맡기고 요약만 받기
세션마다 Claude Code 동작이 다를 때 로드된 메모리 파일을 확인하는 명령은?::/memory
CI에서 Claude Code가 입력을 기다리며 멈출 때 해결책은?::-p(--print) 플래그로 비대화형 실행
CI에서 결과를 기계가 파싱할 수 있게 하는 CLI 플래그 2개는?::--output-format json, --json-schema

## 상황 → 판단
상황: 새 팀원만 규칙을 못 받음 → 정답 방향은?::사용자 수준 → 프로젝트 수준으로
상황: 패키지별로 필요한 표준만 → 정답 방향은?::@import
상황: CLAUDE.md가 너무 큼 → 정답 방향은?::.claude/rules/ 주제별 파일
상황: 세션마다 동작이 다름 → 정답 방향은?::/memory로 로드 파일 확인
상황: 팀 전원이 쓰는 /review → 정답 방향은?::.claude/commands/
상황: 스킬 출력이 메인 대화를 어지럽힘 → 정답 방향은?::context: fork
상황: 스킬 실행 중 파괴적 작업 금지 → 정답 방향은?::allowed-tools
상황: 인자 없이 호출 시 안내 → 정답 방향은?::argument-hint
상황: 항상 적용할 표준 vs 가끔 쓰는 절차 → 정답 방향은?::CLAUDE.md vs 스킬
상황: 흩어진 테스트 파일에 같은 규칙 → 정답 방향은?::.claude/rules/ paths glob
상황: 모놀리스 → 마이크로서비스, 45개+ 파일 마이그레이션 → 정답 방향은?::플랜 모드
상황: 스택 트레이스가 분명한 단일 파일 버그 → 정답 방향은?::직접 실행
상황: 탐색 출력으로 컨텍스트 고갈 → 정답 방향은?::Explore 서브에이전트
상황: 설명해도 변환 결과가 들쭉날쭉 → 정답 방향은?::입출력 예시 2~3개
상황: 낯선 도메인에서 구현 전 → 정답 방향은?::인터뷰 패턴
상황: 서로 얽힌 여러 문제 → 정답 방향은?::한 메시지로 함께
상황: CI가 입력 대기로 멈춤 → 정답 방향은?::-p
상황: CI 결과를 PR 인라인 코멘트로 → 정답 방향은?::--output-format json + --json-schema
상황: 커밋마다 같은 코멘트 → 정답 방향은?::이전 결과를 넣고 새·미해결만
상황: 이미 있는 테스트를 또 제안 → 정답 방향은?::기존 테스트 파일을 컨텍스트에
