# 플래시카드 도메인 5　컨텍스트 관리와 신뢰성

#flashcards/ccar-f/d5

형식: `질문::답` (Spaced Repetition 플러그인). 플러그인이 없어도 한 줄씩 읽으면 된다.

## 개념 확인
점진적 요약에서 특히 뭉개지기 쉬운 정보 4가지는?::수치, 백분율, 날짜, 고객이 말한 기대 사항
그 대책은?::거래 사실을 요약 밖의 사례 사실(case facts) 블록으로 유지해 매 프롬프트에 포함
중간 소실 효과를 줄이는 입력 배치는?::핵심 요약을 맨 앞에, 상세 결과는 명시적 섹션 제목으로 정리
하위 에이전트 컨텍스트 예산이 작을 때 상위 에이전트 출력은 어떻게 바꾸나?::장황한 내용 대신 핵심 사실·인용·관련도 점수 같은 구조화 데이터로
가이드의 에스컬레이션 트리거 3가지는?::고객의 상담원 요청, 정책 예외·공백, 의미 있는 진척 불가
고객이 "사람과 얘기하게 해 달라"고 했다. 먼저 조사부터 하나?::아니다. 즉시 넘긴다
조회 결과 고객이 3명 일치했다. 어떻게 하나?::추가 식별 정보를 요청한다
자체 보고 확신도를 에스컬레이션 기준으로 쓰면 안 되는 이유는?::보정이 나빠 어려운 사례에서도 과신한다
코디네이터 복구를 돕는 구조화된 오류 컨텍스트 4가지는?::실패 유형, 시도한 쿼리, 부분 결과, 가능한 대안
가이드가 안티패턴으로 꼽은 오류 처리 2가지는?::빈 결과를 성공으로 반환해 오류를 숨기기, 한 번의 실패로 전체 워크플로 종료
긴 탐색 세션에서 컨텍스트 저하의 징후는?::답이 일관되지 않고, 앞서 찾은 구체적인 클래스 대신 일반적인 패턴을 말함
멀티 에이전트 장애 복구에서 코디네이터가 재개 시 로드하는 것은?::각 에이전트가 내보낸 상태 매니페스트
전체 정확도 97%만 보고 검토를 줄이면 안 되는 이유는?::특정 문서 유형·필드의 낮은 성능이 가려질 수 있다
확신도 높은 추출의 오류율을 지속 측정하는 방법은?::층화 무작위 표본 추출
필드 수준 확신도의 검토 임계값은 무엇으로 보정하나?::레이블된 검증 세트
서브에이전트 결과에 출처를 보존하려면 무엇을 함께 출력하게 하나?::주장-출처 대응(출처 URL, 문서 이름, 관련 발췌)
신뢰할 만한 두 출처의 통계가 다를 때 처리는?::임의로 고르지 않고 두 값을 출처와 함께 주석으로 남긴다
시점 차이가 모순으로 오해되지 않게 하려면?::발행일·수집일을 구조화된 출력에 포함

## 상황 → 판단
상황: 긴 대화에서 금액·날짜가 뭉개짐 → 정답 방향은?::사례 사실 블록
상황: 합친 결과의 중간이 빠짐 → 정답 방향은?::핵심 요약을 앞에, 섹션 제목
상황: 주문 조회 결과가 너무 김 → 정답 방향은?::관련 필드만 남김
상황: 고객이 상담원을 요구 → 정답 방향은?::즉시 넘김
상황: 정책에 언급이 없는 요청 → 정답 방향은?::넘김
상황: 단순 사례는 넘기고 예외는 혼자 처리 → 정답 방향은?::명시적 기준 + 퓨샷
상황: 고객이 여러 명 일치 → 정답 방향은?::추가 식별 정보 요청
상황: 감정·자체 확신도로 에스컬레이션 → 정답 방향은?::오답
상황: 서브에이전트 타임아웃 보고 → 정답 방향은?::실패 유형·시도·부분 결과·대안
상황: 타임아웃을 빈 결과로 / 전체 종료 → 정답 방향은?::둘 다 안티패턴
상황: 일부 출처를 못 찾음 → 정답 방향은?::커버리지 주석
상황: 긴 탐색 후 일반론만 말함 → 정답 방향은?::스크래치패드, 서브에이전트, 요약 주입, /compact
상황: 에이전트 장애 후 재개 → 정답 방향은?::매니페스트
상황: 전체 정확도 97%라 검토 축소 → 정답 방향은?::문서 유형·필드별로 확인
상황: 확신도 높은 추출의 오류율 측정 → 정답 방향은?::층화 무작위 표본
상황: 검토 인력 배분 → 정답 방향은?::보정된 필드 수준 확신도
상황: 보고서에서 출처가 사라짐 → 정답 방향은?::주장-출처 대응 보존
상황: 두 출처의 통계가 다름 → 정답 방향은?::둘 다 출처와 함께 주석
