# 플래시카드 도메인 4　프롬프트 엔지니어링과 구조화된 출력

#flashcards/ccar-f/d4

형식: `질문::답` (Spaced Repetition 플러그인). 플러그인이 없어도 한 줄씩 읽으면 된다.

## 개념 확인
"보수적으로 판단하라" 지시가 정밀도를 높이지 못하면 대신 무엇을 하나?::보고할 범주와 건너뛸 범주를 구체적으로 정의
거짓 양성이 많은 범주가 개발자 신뢰를 해칠 때 가이드의 대응은?::그 범주를 일시적으로 끄고 프롬프트를 개선
모호한 시나리오용 퓨샷 예시는 몇 개, 무엇을 보여 주나?::2~4개. 그 행동을 고른 이유(대안 대비)까지
형식이 다양한 문서에서 필수 필드가 비어 나올 때 대책은?::형식이 다양한 문서에서 올바르게 추출한 퓨샷 예시 추가
스키마 준수 구조화 출력을 가장 확실하게 얻는 방법은?::JSON 스키마를 단 도구 사용(tool_use)
엄격한 JSON 스키마로도 막을 수 없는 오류는?::의미 오류(합계 불일치, 잘못된 필드 배치)
총액 불일치를 스스로 찾게 하려면 어떤 필드를 함께 추출하나?::stated_total과 calculated_total
원문에 없는 값을 모델이 지어내는 것을 막는 스키마 설계는?::해당 필드를 선택(nullable)으로 설계
확장 가능한 범주를 enum으로 표현하는 패턴은?::"other" + 상세 문자열 필드
검증 실패 후 재요청에 넣어야 할 3가지는?::원문 문서, 실패한 추출 결과, 구체적인 검증 오류
재시도가 효과 없는 대표적인 경우는?::필요한 정보가 원문에 없을 때(예: 제공되지 않은 외부 문서에만 있음)
거짓 양성 패턴을 분석하기 위해 리뷰 결과에 추가하는 필드는?::detected_pattern
병합 전 검사와 야간 기술 부채 보고서 중 배치에 맞는 것은?::야간 기술 부채 보고서만
24시간 배치 처리로 30시간 SLA를 보장하려면 제출 간격은?::4시간
여러 파일을 한 번에 리뷰할 때 결과가 들쭉날쭉한 근본 원인은?::주의 분산
그 해결 구조는?::파일별 로컬 패스 + 별도 파일 간 통합 패스
Message Batches API의 비용·처리 시간·SLA는?::50% 절감, 최대 24시간, 지연 SLA 없음
배치 요청과 응답을 짝짓는 필드는?::custom_id
배치 API에서 할 수 없는 것은?::한 요청 안에서 여러 턴에 걸친 도구 호출
모호한 값을 담는 enum 값의 예는?::"unclear"
Pydantic 검증 실패 후 재요청에 넣을 오류는 일반 메시지인가 구체적 메시지인가?::구체적인 검증 오류

## 상황 → 판단
상황: "보수적으로" 지시에도 거짓 양성 → 정답 방향은?::구체적 범주 기준
상황: 거짓 양성 때문에 개발자가 무시 → 정답 방향은?::해당 범주 일시 비활성화 후 개선
상황: 심각도 분류가 매번 다름 → 정답 방향은?::수준별 코드 예시
상황: 출력 형식이 매번 다름 → 정답 방향은?::퓨샷 예시
상황: 모호한 경우의 판단을 가르치기 → 정답 방향은?::2~4개 예시 + 선택 이유
상황: JSON이 가끔 깨짐 → 정답 방향은?::tool_use + JSON 스키마
상황: 스키마는 통과했는데 합계가 틀림 → 정답 방향은?::의미 오류 → 별도 검증(calculated_total)
상황: 원문에 없는 값을 지어냄 → 정답 방향은?::nullable 필드
상황: 분류가 애매한 값 → 정답 방향은?::enum "unclear" / "other" + 상세
상황: 검증 실패 후 재요청 → 정답 방향은?::원문 + 실패 결과 + 구체적 오류
상황: 외부 문서에만 있는 정보 → 정답 방향은?::재시도 무의미
상황: 기각된 지적의 패턴 분석 → 정답 방향은?::detected_pattern
상황: 병합 전 검사 비용 절감 → 정답 방향은?::동기 유지(배치 불가)
상황: 야간 보고서 비용 절감 → 정답 방향은?::Message Batches API
상황: 배치 일부 실패 → 정답 방향은?::custom_id로 실패분만 고쳐서 재제출
상황: 생성한 세션에 자기 코드 리뷰 → 정답 방향은?::독립 인스턴스
상황: 14개 파일 PR 리뷰가 들쭉날쭉 → 정답 방향은?::파일별 패스 + 통합 패스
