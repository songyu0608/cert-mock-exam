# 오답 선택지 패턴

공식 샘플 문제 해설에서 반복되는 오답 유형. 이런 선택지는 먼저 의심한다.

| 오답이 되기 쉬운 선택지 | 맞는 쪽 | 노트 |
|---|---|---|
| 시스템 프롬프트에 "필수"라고 강조 | 금전·신원 규칙은 코드로 강제 | [[프로그래밍 방식 강제]] |
| 퓨샷 예시를 많이 추가(도구 선택 오류에) | 먼저 도구 설명 보강 | [[도구 설명]] |
| 키워드 파싱 라우팅 레이어 추가 | 과잉 설계. 설명·기준부터 | [[도구 설명]] |
| 별도 분류 모델 학습 | 프롬프트 개선 전에는 과잉 설계 | [[에스컬레이션 트리거]] |
| 자체 보고 확신도 임계값으로 에스컬레이션 | 보정이 나빠 신뢰 불가 | [[감정·자체 확신도 지표의 한계]] |
| 감정 분석으로 에스컬레이션 | 감정은 복잡도와 무관 | [[감정·자체 확신도 지표의 한계]] |
| 더 큰 컨텍스트 윈도우 모델로 교체 | 주의 분산은 안 풀림 → 다중 패스 | [[다중 패스 리뷰]] |
| 같은 리뷰 3회 후 다수결 | 간헐적인 진짜 버그를 놓침 | [[다중 패스 리뷰]] |
| 개발자에게 PR을 쪼개라고 요구 | 시스템 개선 없이 부담 전가 | [[다중 패스 리뷰]] |
| 같은 세션에서 확장 사고로 자체 리뷰 | 독립 인스턴스 | [[독립 리뷰 인스턴스]] |
| 둘 다 배치로 바꾸고 폴링 | 기다리는 작업은 동기 유지 | [[배치 처리 적합성]] |
| 배치 결과 순서 문제 때문에 실시간 유지 | custom_id로 짝지음 | [[Message Batches API]] |
| CLAUDE_HEADLESS 환경 변수 / --batch 플래그 | 없는 기능. -p | [[-p 플래그]] |
| .claude/config.json의 commands 배열 | 없는 기능. .claude/commands/ | [[사용자 지정 슬래시 명령]] |
| ~/.claude/commands/에 팀 명령 | 개인용. 팀은 .claude/commands/ | [[사용자 지정 슬래시 명령]] |
| 하위 디렉터리마다 CLAUDE.md(흩어진 테스트 규칙) | .claude/rules/ paths glob | [[경로별 규칙과 .claude rules]] |
| 파일 유형별 규칙을 스킬로 | 스킬은 호출해야 동작. 경로별 규칙 | [[스킬 vs CLAUDE.md]] |
| 직접 실행으로 시작해 복잡해지면 플랜 모드 | 복잡도가 이미 보이면 처음부터 플랜 모드 | [[플랜 모드]] |
| 타임아웃을 잡아 빈 결과를 성공으로 | 오류 은폐 | [[오류 전파 안티패턴]] |
| 일반적인 "search unavailable" 반환 | 구조화된 오류 컨텍스트 | [[구조화된 오류 컨텍스트]] |
| 한 번의 실패로 워크플로 전체 종료 | 부분 결과로 진행·대안 | [[오류 전파 안티패턴]] |
| 종합 에이전트에 웹 검색 도구 전부 | 범위 좁은 verify_fact | [[도구 배분과 최소 권한]] |
| 하위 에이전트(검색·분석)를 커버리지 부족의 원인으로 | 분해가 좁았으면 코디네이터가 원인 | [[작업 분해 범위]] |
| 반복 횟수 상한을 주된 종료 조건으로 | stop_reason | [[루프 종료 안티패턴]] |
| 필수 필드로 두고 "모르면 추정하라" | nullable | [[nullable 필드와 할루시네이션 방지]] |
| 정보가 원문에 없는데 재시도 반복 | 재시도 무의미 | [[재시도의 한계]] |
| 충돌하는 두 통계 중 최신·권위 있는 것 하나 선택 | 둘 다 출처와 함께 주석 | [[충돌 값과 시간 데이터]] |
