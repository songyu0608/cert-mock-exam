# 플랜 모드

> [!summary] 한 줄 정의
> 대규모·다중 파일·아키텍처 결정이 걸린 작업은 플랜 모드로 탐색·설계부터, 범위가 명확한 단순 변경은 직접 실행.

**English** Plan mode vs direct execution

## 시험 트리거
- "모놀리스를 마이크로서비스로"
- "45개 이상 파일에 걸친 라이브러리 마이그레이션"
- "스택 트레이스가 분명한 단일 파일 버그"

## 핵심
- 플랜 모드: 대규모 변경, **여러 유효한 접근법**, 아키텍처 결정, 여러 파일 수정.
- 직접 실행: 함수 하나에 검사 추가, 단일 파일 버그 수정, 날짜 검증 조건 추가.
- 조합: **조사는 플랜 모드 → 구현은 직접 실행**.
- 복잡도가 요구 사항에 이미 드러나 있으면 처음부터 플랜 모드.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - "직접 실행으로 시작해 복잡해지면 플랜 모드로" → 복잡도가 이미 명시된 경우 틀림
> - "구현하면서 자연스럽게 경계를 찾자" → 늦게 의존성을 발견해 재작업
