# 프로그래밍 강제 vs 프롬프트 안내

| | [[프로그래밍 방식 강제]] (훅·선행 조건 게이트) | 프롬프트 안내 (시스템 프롬프트·퓨샷) |
|---|---|---|
| 준수 | **결정론적**(보장) | 확률적(실패율 > 0) |
| 맞는 상황 | 금전·신원·한도 같은 반드시 지켜야 할 규칙 | 판단·형식·톤처럼 유연해야 하는 부분 |
| 예 | get_customer 전 process_refund 차단, 500달러 초과 환불 차단 | 에스컬레이션 기준 설명, 출력 형식 예시 |
| 구현 | [[Agent SDK 훅]], 선행 조건 검사 코드 | [[퓨샷 프롬프팅]], [[명시적 리뷰 기준]] |

**판별**: 틀렸을 때 **돈·보안·법적 피해**가 있으면 코드로 강제한다.

> [!question]- 12%의 경우 고객 확인 없이 환불까지 간다. 시스템 프롬프트에 "필수"라고 굵게 쓰면 충분한가?
> 아니다. 프롬프트는 확률적이다. get_customer가 검증된 ID를 돌려줄 때까지 후속 호출을 막는 선행 조건을 코드로 둔다.
