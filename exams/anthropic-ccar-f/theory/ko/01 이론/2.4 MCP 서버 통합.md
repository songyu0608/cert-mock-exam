# 태스크 2.4　MCP 서버를 Claude Code와 에이전트 워크플로에 통합한다

**English** Integrate MCP servers into Claude Code and agent workflows  
**日本語** MCPサーバーをClaude Codeとエージェントワークフローに統合する

도메인 2　도구 설계와 MCP 통합 (18%)

MCP 서버를 어디에 구성하고 어떻게 노출할지 묻는다.

> [!tip] 핵심 판단
> - 팀 공용 .mcp.json, 개인 ~/.claude.json
> - 비밀은 ${ENV} 확장, 모든 서버의 도구는 동시에 사용 가능
> - 콘텐츠 카탈로그는 MCP 리소스로, 표준 통합은 커뮤니티 서버

## 알아야 할 지식 (Knowledge of)

1. MCP 서버 범위: 팀 공용 도구는 프로젝트 수준(.mcp.json), 개인·실험용 서버는 사용자 수준(~/.claude.json)
2. 비밀을 커밋하지 않고 자격 증명을 관리하기 위한 .mcp.json의 환경 변수 확장(예: ${GITHUB_TOKEN})
3. 구성된 모든 MCP 서버의 도구는 연결 시점에 발견되어 에이전트가 동시에 사용할 수 있다는 점
4. 탐색성 도구 호출을 줄이기 위해 콘텐츠 카탈로그(예: 이슈 요약, 문서 계층, 데이터베이스 스키마)를 노출하는 수단인 MCP 리소스

> [!quote]- English 공식 가이드 원문
> 1. MCP server scoping: project-level (.mcp.json) for shared team tooling vs user-level (~/.claude.json) for personal/experimental servers
> 2. Environment variable expansion in .mcp.json (e.g., ${GITHUB_TOKEN}) for credential management without committing secrets
> 3. That tools from all configured MCP servers are discovered at connection time and available simultaneously to the agent
> 4. MCP resources as a mechanism for exposing content catalogs (e.g., issue summaries, documentation hierarchies, database schemas) to reduce exploratory tool calls

> [!quote]- 日本語 公式ガイド
> 1. MCPサーバーのスコープ設定：チームで共有するツール向けのプロジェクトレベル（.mcp.json）と、個人用／実験的なサーバー向けのユーザーレベル（~/.claude.json）
> 2. シークレットをコミットせずに認証情報を管理するための、.mcp.jsonでの環境変数の展開（例：${GITHUB_TOKEN}）
> 3. 設定されたすべてのMCPサーバーのツールが接続時に検出され、エージェントから同時に利用可能になること
> 4. 探索的なツール呼び出しを減らすために、コンテンツカタログ（例：課題のサマリー、ドキュメントの階層、データベーススキーマ）を公開する仕組みとしてのMCPリソース

## 할 수 있어야 할 기술 (Skills in)

1. 인증 토큰에 환경 변수 확장을 써서 공용 MCP 서버를 프로젝트 범위 .mcp.json에 구성
2. 개인·실험용 MCP 서버를 사용자 범위 ~/.claude.json에 구성
3. 에이전트가 더 강력한 MCP 도구 대신 내장 도구(Grep 등)를 고르지 않도록 MCP 도구 설명에 기능과 출력을 자세히 쓰기
4. 표준 통합(예: Jira)에는 커뮤니티 MCP 서버를 쓰고, 맞춤 서버는 팀 고유 워크플로에만 쓰기
5. 콘텐츠 카탈로그를 MCP 리소스로 노출해 탐색성 도구 호출 없이도 에이전트가 사용 가능한 데이터를 알게 하기

> [!quote]- English 공식 가이드 원문
> 1. Configuring shared MCP servers in project-scoped .mcp.json with environment variable expansion for authentication tokens
> 2. Configuring personal/experimental MCP servers in user-scoped ~/.claude.json
> 3. Enhancing MCP tool descriptions to explain capabilities and outputs in detail, preventing the agent from preferring built-in tools (like Grep) over more capable MCP tools
> 4. Choosing existing community MCP servers over custom implementations for standard integrations (e.g., Jira), reserving custom servers for team-specific workflows
> 5. Exposing content catalogs as MCP resources to give agents visibility into available data without requiring exploratory tool calls

> [!quote]- 日本語 公式ガイド
> 1. 認証トークン用の環境変数の展開を使用して、プロジェクトスコープの.mcp.jsonで共有MCPサーバーを設定する
> 2. ユーザースコープの~/.claude.jsonで個人用／実験的なMCPサーバーを設定する
> 3. MCPツールの説明を拡充して機能と出力を詳しく説明し、エージェントがより高機能なMCPツールよりも組み込みツール（Grepなど）を優先してしまうのを防ぐ
> 4. 標準的な統合（例：Jira）には、カスタム実装ではなく既存のコミュニティ製MCPサーバーを選択し、カスタムサーバーはチーム固有のワークフローのために取っておく
> 5. 探索的なツール呼び出しを必要とせずにエージェントが利用可能なデータを把握できるように、コンテンツカタログをMCPリソースとして公開する
