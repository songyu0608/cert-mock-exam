# 태스크 1.6　복잡한 워크플로를 위한 작업 분해 전략을 설계한다

**English** Design task decomposition strategies for complex workflows  
**日本語** 複雑なワークフローのためのタスク分解戦略を設計する

도메인 1　에이전트 아키텍처와 오케스트레이션 (27%)

작업을 어떻게 나눌지, 고정 파이프라인과 동적 분해 중 무엇을 쓸지 묻는다.

> [!tip] 핵심 판단
> - 예측 가능한 다면 리뷰 → 프롬프트 체이닝
> - 열린 조사 → 동적 적응형 분해(구조 파악 → 고영향 영역 → 우선순위 계획 → 조정)
> - 큰 리뷰는 파일별 패스 + 통합 패스

## 알아야 할 지식 (Knowledge of)

1. 고정된 순차 파이프라인(프롬프트 체이닝)과 중간 결과에 따라 바뀌는 동적·적응형 분해를 각각 언제 쓰는지
2. 리뷰를 순차 단계로 나누는 프롬프트 체이닝 패턴(예: 파일별 개별 분석 후 파일 간 통합 패스 실행)
3. 단계마다 발견한 내용에 따라 하위 작업을 만들어 내는 적응형 조사 계획의 가치

> [!quote]- English 공식 가이드 원문
> 1. When to use fixed sequential pipelines (prompt chaining) versus dynamic adaptive decomposition based on intermediate findings
> 2. Prompt chaining patterns that break reviews into sequential steps (e.g., analyze each file individually, then run a cross-file integration pass)
> 3. The value of adaptive investigation plans that generate subtasks based on what is discovered at each step

> [!quote]- 日本語 公式ガイド
> 1. 固定の逐次パイプライン（プロンプトチェーン）と、中間的な発見に基づく動的で適応的な分解を、どのような場合に使い分けるか
> 2. レビューを逐次的なステップに分割するプロンプトチェーンのパターン（例：各ファイルを個別に分析してから、ファイル横断の統合パスを実行する）
> 3. 各ステップで発見された内容に基づいてサブタスクを生成する、適応的な調査計画の価値

## 할 수 있어야 할 기술 (Skills in)

1. 워크플로에 맞는 분해 패턴 선택: 예측 가능한 다면 리뷰에는 프롬프트 체이닝, 열린 조사 작업에는 동적 분해
2. 주의 분산을 피하기 위해 큰 코드 리뷰를 파일별 로컬 분석 패스와 별도의 파일 간 통합 패스로 나누기
3. 열린 작업(예: "레거시 코드베이스에 포괄적인 테스트 추가")을 먼저 구조 파악, 영향이 큰 영역 식별, 의존성이 드러날수록 조정되는 우선순위 계획 작성 순서로 분해하기

> [!quote]- English 공식 가이드 원문
> 1. Selecting task decomposition patterns appropriate to the workflow: prompt chaining for predictable multi-aspect reviews, dynamic decomposition for open-ended investigation tasks
> 2. Splitting large code reviews into per-file local analysis passes plus a separate cross-file integration pass to avoid attention dilution
> 3. Decomposing open-ended tasks (e.g., "add comprehensive tests to a legacy codebase") by first mapping structure, identifying high-impact areas, then creating a prioritized plan that adapts as dependencies are discovered

> [!quote]- 日本語 公式ガイド
> 1. ワークフローに適したタスク分解パターンを選択する：予測可能な多面的レビューにはプロンプトチェーン、オープンエンドな調査タスクには動的な分解
> 2. 注意の分散を避けるために、大規模なコードレビューを、ファイルごとのローカル分析パスと、別途実施するファイル横断の統合パスに分割する
> 3. オープンエンドなタスク（例：「レガシーコードベースに包括的なテストを追加する」）を、まず構造を把握し、影響の大きい領域を特定したうえで、依存関係が見つかるたびに適応する優先順位付きの計画を作成することで分解する

## 이 태스크의 카드
- [[작업 분해 범위]] — 코디네이터가 주제를 지나치게 좁게 나누면 서브에이전트가 각자 일을 잘해도 결과 전체가 주제를 덮지 못한다.
- [[프롬프트 체이닝]] — 작업을 미리 정한 순서의 단계로 나눠 차례로 처리하는 고정 파이프라인. 예측 가능한 다면 리뷰에 맞다.
- [[동적 적응형 분해]] — 단계마다 발견한 내용에 따라 하위 작업을 만들어 가는 분해 방식. 열린 조사 작업에 맞다.
- [[다중 패스 리뷰]] — 큰 리뷰를 파일별 로컬 분석 패스와 파일 간 데이터 흐름을 보는 통합 패스로 나눠 주의 분산과 모순된 지적을 막는다.
