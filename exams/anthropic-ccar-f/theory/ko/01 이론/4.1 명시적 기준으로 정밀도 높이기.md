# 태스크 4.1　명시적 기준을 담은 프롬프트로 정밀도를 높이고 거짓 양성을 줄인다

**English** Design prompts with explicit criteria to improve precision and reduce false positives  
**日本語** 精度を高め誤検知を減らすために、明示的な基準を備えたプロンプトを設計する

도메인 4　프롬프트 엔지니어링과 구조화된 출력 (20%)

리뷰·분류 프롬프트에서 거짓 양성을 줄이는 방법을 묻는다.

> [!tip] 핵심 판단
> - "보수적으로" 같은 일반 지시 대신 구체적 범주 기준
> - 거짓 양성이 많은 범주는 잠시 끄고 개선
> - 심각도 수준마다 코드 예시

## 알아야 할 지식 (Knowledge of)

1. 모호한 지시보다 명시적 기준이 중요하다는 점(예: "주석이 정확한지 확인" 대신 "주석이 설명한 동작이 실제 코드 동작과 다를 때만 표시")
2. "보수적으로 판단하라", "확신이 높은 결과만 보고하라" 같은 일반 지시는 구체적인 범주 기준에 비해 정밀도를 높이지 못한다는 점
3. 거짓 양성 비율이 개발자 신뢰에 주는 영향: 거짓 양성이 많은 범주가 정확한 범주에 대한 신뢰까지 떨어뜨린다

> [!quote]- English 공식 가이드 원문
> 1. The importance of explicit criteria over vague instructions (e.g., "flag comments only when claimed behavior contradicts actual code behavior" vs "check that comments are accurate")
> 2. How general instructions like "be conservative" or "only report high-confidence findings" fail to improve precision compared to specific categorical criteria
> 3. The impact of false positive rates on developer trust: high false positive categories undermine confidence in accurate categories

> [!quote]- 日本語 公式ガイド
> 1. 曖昧な指示よりも明示的な基準が重要であること（例：「コメントの正確性を確認する」ではなく「主張されている動作が実際のコードの動作と矛盾する場合にのみコメントを指摘する」）
> 2. 「保守的に判断する」や「確信度の高い指摘事項のみを報告する」といった一般的な指示が、具体的なカテゴリ別の基準と比べて精度の向上につながらない理由
> 3. 誤検知率が開発者の信頼に与える影響：誤検知の多いカテゴリが、正確なカテゴリへの信頼まで損なうこと

## 할 수 있어야 할 기술 (Skills in)

1. 확신도 기반 필터링에 기대지 않고, 보고할 문제(버그, 보안)와 건너뛸 문제(사소한 스타일, 로컬 패턴)를 정의하는 구체적인 리뷰 기준 작성
2. 거짓 양성이 많은 범주를 일시적으로 끄고 개발자 신뢰를 회복하면서 그 범주의 프롬프트를 개선하기
3. 일관된 분류를 위해 심각도 수준마다 구체적인 코드 예시를 붙인 명시적 심각도 기준 정의

> [!quote]- English 공식 가이드 원문
> 1. Writing specific review criteria that define which issues to report (bugs, security) versus skip (minor style, local patterns) rather than relying on confidence-based filtering
> 2. Temporarily disabling high false-positive categories to restore developer trust while improving prompts for those categories
> 3. Defining explicit severity criteria with concrete code examples for each severity level to achieve consistent classification

> [!quote]- 日本語 公式ガイド
> 1. 確信度に基づくフィルタリングに頼るのではなく、報告すべき問題（バグ、セキュリティ）とスキップすべき問題（軽微なスタイル、局所的なパターン）を定義する具体的なレビュー基準を記述する
> 2. 誤検知の多いカテゴリを一時的に無効化し、それらのカテゴリのプロンプトを改善する間に開発者の信頼を回復する
> 3. 一貫した分類を実現するために、重大度レベルごとに具体的なコード例を伴う明示的な重大度基準を定義する
