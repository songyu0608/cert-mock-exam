# 태스크 2.3　에이전트에 도구를 적절히 배분하고 tool_choice를 구성한다

**English** Distribute tools appropriately across agents and configure tool choice  
**日本語** エージェント間でツールを適切に配分し、ツール選択を設定する

도메인 2　도구 설계와 MCP 통합 (18%)

어떤 에이전트에 어떤 도구를 줄지, 도구 호출을 어떻게 강제할지 묻는다.

> [!tip] 핵심 판단
> - 도구는 역할에 필요한 4~5개 정도, 18개처럼 많으면 선택이 흔들림
> - 고빈도 요구만 범위 좁은 교차 역할 도구(verify_fact)
> - tool_choice: "auto" / "any" / 강제 선택

## 알아야 할 지식 (Knowledge of)

1. 에이전트에 도구를 너무 많이 주면(예: 4~5개가 아닌 18개) 결정 복잡도가 높아져 도구 선택 신뢰성이 떨어진다는 원칙
2. 전문 분야 밖의 도구를 가진 에이전트가 이를 오용하는 경향(예: 종합 에이전트가 웹 검색을 시도)
3. 범위가 정해진 도구 접근: 역할에 필요한 도구만 주고, 특정 고빈도 요구에 한해 제한된 교차 역할 도구를 주기
4. tool_choice 구성 옵션: "auto", "any", 강제 도구 선택({"type": "tool", "name": "..."})

> [!quote]- English 공식 가이드 원문
> 1. The principle that giving an agent access to too many tools (e.g., 18 instead of 4-5) degrades tool selection reliability by increasing decision complexity
> 2. Why agents with tools outside their specialization tend to misuse them (e.g., a synthesis agent attempting web searches)
> 3. Scoped tool access: giving agents only the tools needed for their role, with limited cross-role tools for specific high-frequency needs
> 4. tool_choice configuration options: "auto", "any", and forced tool selection ({"type": "tool", "name": "..."})

> [!quote]- 日本語 公式ガイド
> 1. エージェントに多すぎるツール（例：4-5個ではなく18個）へのアクセスを与えると、判断の複雑さが増し、ツール選択の信頼性が低下するという原則
> 2. 専門外のツールを持つエージェントが、それらを誤用しがちである理由（例：統合エージェントがウェブ検索を試みる）
> 3. スコープを限定したツールアクセス：エージェントにはその役割に必要なツールのみを与え、頻度の高い特定のニーズに対しては役割横断のツールを限定的に与える
> 4. tool_choiceの設定オプション："auto"、"any"、強制的なツール選択（{"type": "tool", "name": "..."}）

## 할 수 있어야 할 기술 (Skills in)

1. 서브에이전트마다 역할에 맞는 도구만 허용해 전문 분야 밖 오용 막기
2. 범용 도구를 제약이 있는 대안으로 바꾸기(예: fetch_url을 문서 URL을 검증하는 load_document로 교체)
3. 고빈도 요구에는 범위를 좁힌 교차 역할 도구를 주고(예: 종합 에이전트에 verify_fact 도구), 복잡한 경우는 코디네이터를 거치게 하기
4. tool_choice 강제 선택으로 특정 도구를 먼저 호출하게 하고(예: 보강 도구보다 extract_metadata를 먼저), 이후 단계는 후속 턴에서 처리하기
5. 모델이 대화형 텍스트 대신 반드시 도구를 호출하게 하려면 tool_choice: "any" 설정

> [!quote]- English 공식 가이드 원문
> 1. Restricting each subagent's tool set to those relevant to its role, preventing cross-specialization misuse
> 2. Replacing generic tools with constrained alternatives (e.g., replacing fetch_url with load_document that validates document URLs)
> 3. Providing scoped cross-role tools for high-frequency needs (e.g., a verify_fact tool for the synthesis agent) while routing complex cases through the coordinator
> 4. Using tool_choice forced selection to ensure a specific tool is called first (e.g., forcing extract_metadata before enrichment tools), then processing subsequent steps in follow-up turns
> 5. Setting tool_choice: "any" to guarantee the model calls a tool rather than returning conversational text

> [!quote]- 日本語 公式ガイド
> 1. 各サブエージェントのツールセットをその役割に関連するものに制限し、専門外のツールの誤用を防ぐ
> 2. 汎用的なツールを制約付きの代替ツールに置き換える（例：fetch_urlを、ドキュメントURLを検証するload_documentに置き換える）
> 3. 複雑なケースはコーディネーター経由でルーティングしつつ、頻度の高いニーズに対してはスコープを限定した役割横断のツールを提供する（例：統合エージェント向けのverify_factツール）
> 4. tool_choiceの強制選択を使用して特定のツールが最初に呼び出されるようにし（例：エンリッチメントツールの前にextract_metadataを強制する）、後続のステップはフォローアップのターンで処理する
> 5. モデルが会話テキストを返すのではなく確実にツールを呼び出すように、tool_choice: "any"を設定する
