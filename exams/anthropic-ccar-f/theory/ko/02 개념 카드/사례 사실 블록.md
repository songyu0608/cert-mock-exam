# 사례 사실 블록

> [!summary] 한 줄 정의
> 금액·날짜·주문 번호·상태 같은 거래 사실을 요약된 기록 밖의 고정 블록으로 뽑아 매 프롬프트에 넣는 방법. 점진적 요약이 숫자를 뭉개는 문제를 막는다.

**English** Persistent case facts block

## 시험 트리거
- "긴 대화 끝에 환불 금액을 틀렸다"
- "요약하면서 날짜가 사라졌다"
- "여러 이슈를 동시에 다루는 세션"

## 핵심
- 점진적 요약의 위험: 수치, 백분율, 날짜, **고객이 말한 기대 사항**이 모호한 요약으로 뭉개진다.
- 대책: 거래 사실을 **요약 기록 밖**의 "case facts" 블록으로 유지하고 매 요청에 포함.
- 여러 이슈 세션: 이슈별 구조화 데이터(주문 ID, 금액, 상태)를 **별도 컨텍스트 계층**으로.
- 이후 API 요청에는 **전체 대화 기록**을 보내야 대화 일관성이 유지된다.
