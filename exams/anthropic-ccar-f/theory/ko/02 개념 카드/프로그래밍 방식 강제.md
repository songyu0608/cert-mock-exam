# 프로그래밍 방식 강제

> [!summary] 한 줄 정의
> 훅이나 선행 조건 게이트로 도구 호출 순서·업무 규칙을 코드에서 강제하는 방법. 프롬프트 지시는 확률적이라 실패율이 0이 아니다.

**English** Programmatic enforcement

## 시험 트리거
- "반드시" "항상" "금전 거래" "신원 확인 전에는"
- "12%의 경우 확인 단계를 건너뛴다"
- "보장된 준수"

## 핵심
- **결정론적 준수가 필요한 규칙**(신원 확인 후 환불, 금액 한도)은 프롬프트가 아니라 코드로 막는다.
- 예: get_customer가 검증된 고객 ID를 반환할 때까지 lookup_order·process_refund 호출을 **차단**.
- 훅으로 나가는 호출을 가로채 한도 초과 환불을 막고 사람 에스컬레이션으로 돌린다. → [[Agent SDK 훅]]
- 프롬프트 강화·퓨샷 예시는 확률적 준수일 뿐이다.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - "시스템 프롬프트에 '반드시 먼저 확인'을 강조"하는 선택지 → 금전 영향이 있으면 부족
> - "요청 유형별로 도구 일부만 켜는 라우팅 분류기" → 도구 **가용성** 문제를 풀 뿐 **순서** 문제가 아님
