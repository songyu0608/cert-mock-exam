# 작업 분해 범위

> [!summary] 한 줄 정의
> 코디네이터가 주제를 지나치게 좁게 나누면 서브에이전트가 각자 일을 잘해도 결과 전체가 주제를 덮지 못한다.

**English** Task decomposition scope

## 시험 트리거
- "각 서브에이전트는 성공했는데 보고서가 일부 영역만 다룬다"
- "코디네이터 로그의 하위 작업 목록"

## 핵심
- 근본 원인을 찾을 때 **코디네이터가 무엇을 배정했는지**부터 본다.
- 하위 에이전트가 배정받은 범위 안에서 정확히 일했다면 그들의 잘못이 아니다.
- 대책: 분해 단계에서 주제의 전체 영역을 나열하고 빈틈을 평가하는 [[반복 개선 루프]].

## 오답 함정
> [!warning] 커버리지 부족을 검색 에이전트의 쿼리·분석 에이전트의 필터 탓으로 돌리는 선택지 → 로그상 분해가 좁으면 원인은 코디네이터
