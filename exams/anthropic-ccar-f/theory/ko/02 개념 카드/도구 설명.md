# 도구 설명

> [!summary] 한 줄 정의
> LLM이 도구를 고르는 주된 수단. 설명이 빈약하면 비슷한 도구 사이에서 선택이 흔들린다.

**English** Tool descriptions

## 시험 트리거
- "get_customer와 lookup_order를 자주 헷갈린다"
- "설명이 한 줄뿐"
- "도구 선택 신뢰성을 높이는 첫 단계"

## 핵심
- 설명에 넣을 것: **입력 형식, 예시 쿼리, 엣지 케이스, 경계(비슷한 도구 대신 언제 쓰는지)**, 출력.
- 도구 선택이 틀릴 때 **가장 먼저** 고칠 것은 도구 설명이다(저비용·고효과).
- 시스템 프롬프트의 **키워드 민감 지시**가 잘 쓴 도구 설명을 덮어써 엉뚱한 도구를 연상시킬 수 있다. 시스템 프롬프트도 검토.
- MCP 도구 설명이 빈약하면 에이전트가 더 강력한 MCP 도구 대신 내장 Grep 등을 고른다. → 설명에 기능·출력을 자세히.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - 도구 선택 오류에 "라우팅 레이어로 키워드 파싱 후 도구 미리 선택" → 과잉 설계
> - "두 도구를 lookup_entity 하나로 합치기" → 유효한 설계일 수 있으나 "첫 단계"로는 과함
> - "퓨샷 예시 5~8개 추가" → 근본 원인(설명 부족)을 고치지 않음
