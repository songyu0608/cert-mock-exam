# 構文エラーと意味的エラー

> [!summary] 一行定義
> ツール使用＋厳密なスキーマはJSONの構文エラーをなくすが、合計の不一致やフィールドの取り違えといった意味的なエラーは防げない。

**English** Syntax errors vs semantic errors

## 出題のきっかけ
- 「スキーマは通ったのに明細の合計が総額と合わない」
- 「値が別のフィールドに入っている」

## 要点
- 構文エラー：括弧・引用符など → tool_useで**排除**。
- 意味的エラー：値の合計が合わない、フィールドの誤り → **別途検証が必要**（Pydanticなど）→ [[検証とリトライのループ]]。
- 自己修正の設計：stated_totalと合わせて**calculated_total**を抽出して不一致をフラグ、ソース同士が食い違えば**conflict_detected**。
