# プログラムによる強制とプロンプトによるガイダンス

| | [[プログラムによる強制]]（フック・前提条件のゲート） | プロンプトによるガイダンス（システムプロンプト・few-shot） |
|---|---|---|
| 遵守 | **決定論的**（保証） | 確率的（失敗率 > 0） |
| 向いている場面 | 金銭・本人確認・上限など必ず守るべきルール | 判断・形式・トーンなど柔軟さが必要な部分 |
| 例 | get_customerの前にprocess_refundをブロック、500ドル超の返金をブロック | エスカレーション基準の説明、出力形式の例 |
| 実装 | [[Agent SDKのフック]]、前提条件チェックのコード | [[few-shotプロンプティング]]、[[明示的なレビュー基準]] |

**見分け方**：誤ったときに**金銭・セキュリティ・法的な損害**があるならコードで強制する。

> [!question]- 12%のケースで顧客確認なしに返金まで進む。システムプロンプトに「必須」と太字で書けば十分？
> 不十分。プロンプトは確率的。get_customerが検証済みIDを返すまで後続の呼び出しをブロックする前提条件をコードで置く。
