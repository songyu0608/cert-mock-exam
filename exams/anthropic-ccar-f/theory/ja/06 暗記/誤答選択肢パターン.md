# 誤答選択肢パターン

公式サンプル問題の解説で繰り返し現れる誤答のタイプ。こうした選択肢はまず疑う。

| 誤答になりやすい選択肢 | 正しい方向 | ノート |
|---|---|---|
| システムプロンプトで「必須」と強調 | 金銭・本人確認のルールはコードで強制 | [[プログラムによる強制]] |
| few-shotの例を大量に追加（ツール選択ミスに対して） | まずツールの説明を拡充 | [[ツールの説明]] |
| キーワード解析のルーティング層を追加 | 過剰な設計。説明・基準が先 | [[ツールの説明]] |
| 別の分類器モデルを学習 | プロンプト改善の前では過剰な設計 | [[エスカレーションのトリガー]] |
| 自己申告の確信度のしきい値でエスカレーション | キャリブレーションが不十分で信頼できない | [[感情と自己申告確信度の限界]] |
| 感情分析でエスカレーション | 感情は複雑さと相関しない | [[感情と自己申告確信度の限界]] |
| コンテキストウィンドウの大きいモデルに替える | 注意の分散は解決しない → マルチパス | [[マルチパスレビュー]] |
| 同じレビューを3回実行して多数決 | 断続的に現れる本物のバグを逃す | [[マルチパスレビュー]] |
| 開発者にPRの分割を義務付ける | システムを改善せず負担を転嫁 | [[マルチパスレビュー]] |
| 同じセッションで拡張思考を使って自己レビュー | 独立したインスタンス | [[独立したレビューインスタンス]] |
| 両方をバッチにしてポーリング | 待つ処理は同期のまま | [[バッチ処理の適否]] |
| バッチ結果の順序の問題でリアルタイムを維持 | custom_idで対応付け | [[Message Batches API]] |
| CLAUDE_HEADLESS環境変数／--batchフラグ | 存在しない機能。-p | [[-pフラグ]] |
| .claude/config.jsonのcommands配列 | 存在しない機能。.claude/commands/ | [[カスタムスラッシュコマンド]] |
| ~/.claude/commands/にチームのコマンド | 個人用。チームは.claude/commands/ | [[カスタムスラッシュコマンド]] |
| サブディレクトリごとのCLAUDE.md（散らばったテストの規約） | .claude/rules/のpaths glob | [[パス固有のルールと.claude rules]] |
| ファイル種別ごとの規約をスキルに | スキルは呼び出しが必要。パス固有のルール | [[スキルとCLAUDE.mdの使い分け]] |
| 直接実行で始め、複雑になったらプランモード | 複雑さが既に見えているなら最初からプランモード | [[プランモード]] |
| タイムアウトをキャッチして空の結果を成功として返す | エラーの握りつぶし | [[エラー伝播のアンチパターン]] |
| 汎用的な「検索を利用できません」を返す | 構造化されたエラーコンテキスト | [[構造化されたエラーコンテキスト]] |
| 1回の失敗でワークフロー全体を終了 | 部分的な結果で続行・代替案 | [[エラー伝播のアンチパターン]] |
| 統合エージェントにウェブ検索ツールをすべて与える | スコープを絞ったverify_fact | [[ツールの配分と最小権限]] |
| 下流のエージェント（検索・分析）をカバレッジ不足の原因とする | 分解が狭ければ原因はコーディネーター | [[タスク分解の範囲]] |
| 反復回数の上限を主な終了条件にする | stop_reason | [[ループ終了のアンチパターン]] |
| 必須フィールドにして「わからなければ推定せよ」 | nullable | [[nullableフィールドと捏造の防止]] |
| 情報がソースにないのにリトライを繰り返す | リトライは無意味 | [[リトライの限界]] |
| 矛盾する2つの統計から最新・権威あるものを1つ選ぶ | 両方を情報源とともに注記 | [[矛盾する値と時間的データ]] |
