# フラッシュカード 分野 5　コンテキスト管理と信頼性

#flashcards/ccar-f/d5

形式：`質問::答え`（Spaced Repetitionプラグイン）。プラグインがなくても1行ずつ読めばよい。

## 概念の確認
段階的な要約で特に曖昧になりやすい情報4つは？::数値、パーセンテージ、日付、顧客が述べた期待
その対策は？::取引上の事実を要約の外のケースファクト（case facts）ブロックに保持し、毎回のプロンプトに含める
lost in the middle効果を緩和する入力の並べ方は？::重要な要約を冒頭に置き、詳細は明示的なセクション見出しで整理する
下流エージェントのコンテキスト予算が小さいとき、上流エージェントの出力をどう変える？::冗長な内容ではなく、重要な事実・引用・関連度スコアなどの構造化データにする
ガイドのエスカレーションのトリガー3つは？::顧客による人間の要求、ポリシーの例外・空白、意味のある進展が見込めない
顧客が「人と話したい」と言った。まず調査するか？::しない。即座に引き継ぐ
照会の結果、顧客が3人一致した。どうする？::追加の識別情報を求める
自己申告の確信度をエスカレーション基準に使ってはいけない理由は？::キャリブレーションが不十分で、難しいケースでも過信するため
コーディネーターの復旧を助ける構造化されたエラーコンテキスト4つは？::失敗の種類、試行したクエリ、部分的な結果、考えられる代替アプローチ
ガイドがアンチパターンとするエラー処理2つは？::空の結果を成功として返してエラーを隠す、1回の失敗でワークフロー全体を終了する
長い探索セッションでのコンテキストの劣化の兆候は？::回答が一貫せず、前に見つけた具体的なクラスではなく典型的なパターンに言及する
マルチエージェントのクラッシュ復旧で、コーディネーターが再開時に読み込むものは？::各エージェントがエクスポートした状態のマニフェスト
全体精度97%だけを見てレビューを減らしてはいけない理由は？::特定の文書タイプやフィールドの低い性能が隠れる可能性がある
確信度の高い抽出のエラー率を継続的に測る方法は？::層化無作為抽出
フィールド単位の確信度のレビューしきい値は何でキャリブレーションする？::ラベル付き検証セット
サブエージェントの結果で情報源の帰属を保つには、何を合わせて出力させる？::主張と情報源の対応付け（出典URL、文書名、関連する抜粋）
信頼できる2つの情報源で統計が異なるときの処理は？::恣意的に選ばず、両方の値を情報源の帰属とともに注記して残す
時期の違いが矛盾と誤解されないようにするには？::公開日・収集日を構造化出力に含める

## 状況 → 判断
状況：長い会話で金額・日付があいまいになる → 正解の方向は？::ケースファクトブロック
状況：まとめた結果の中盤が抜ける → 正解の方向は？::重要な要約を冒頭に、セクション見出し
状況：注文検索の結果が長すぎる → 正解の方向は？::関連フィールドだけ残す
状況：顧客が人間の担当者を要求 → 正解の方向は？::すぐに引き継ぐ
状況：ポリシーに記載のないリクエスト → 正解の方向は？::引き継ぐ
状況：単純なケースは引き継ぎ、例外は自力で処理 → 正解の方向は？::明示的な基準＋few-shot
状況：複数の顧客が一致 → 正解の方向は？::追加の識別情報を求める
状況：感情・自己申告の確信度でエスカレーション → 正解の方向は？::誤答
状況：サブエージェントのタイムアウトの報告 → 正解の方向は？::失敗の種類・試行・部分的な結果・代替案
状況：タイムアウトを空の結果に／全体を終了 → 正解の方向は？::どちらもアンチパターン
状況：一部の情報源が見つからない → 正解の方向は？::カバレッジの注記
状況：長い探索の後に一般論しか言わない → 正解の方向は？::スクラッチパッド、サブエージェント、サマリーの注入、/compact
状況：エージェントの障害後に再開 → 正解の方向は？::マニフェスト
状況：全体精度97%なのでレビューを縮小 → 正解の方向は？::文書タイプ・フィールド別に確認
状況：確信度の高い抽出の誤り率を測る → 正解の方向は？::層化無作為抽出
状況：レビュー担当者の配分 → 正解の方向は？::キャリブレーションしたフィールド単位の確信度
状況：レポートから出典が消える → 正解の方向は？::主張と情報源の対応付けを保持
状況：2つの情報源で統計が異なる → 正解の方向は？::両方を情報源とともに注記
