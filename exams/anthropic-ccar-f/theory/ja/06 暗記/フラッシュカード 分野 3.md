# フラッシュカード 分野 3　Claude Codeの設定とワークフロー

#flashcards/ccar-f/d3

形式：`質問::答え`（Spaced Repetitionプラグイン）。プラグインがなくても1行ずつ読めばよい。

## 概念の確認
常に適用する標準と、必要なときだけ使うワークフローをそれぞれどこに置く？::標準はCLAUDE.md、ワークフローはスキル
自然言語の説明で変換結果が一貫しないとき最も効果的な方法は？::具体的な入出力例を2-3件示す
互いに影響し合う複数の問題はどう伝える？::1つの詳細なメッセージでまとめて
インタビューパターンとは？::実装前にClaudeに質問させ、見落としている考慮事項を洗い出す方法
CIの再レビューで重複コメントを防ぐ方法は？::前回のレビュー結果をコンテキストに含め、新規・未対応の問題だけ報告するよう指示
生成したコードのレビューで、同じセッションより別インスタンスがよい理由は？::生成時の推論コンテキストがないため、判断を疑える
~/.claude/CLAUDE.mdの指示はチームメンバーに適用される？::されない。ユーザーレベルなので本人だけ
どのメモリファイルが読み込まれたかを確認するコマンドは？::/memory
CLAUDE.mdでパッケージごとに必要な標準ファイルだけを含める構文は？::@import
コードベース中のテストファイルに同じ規約を自動適用する、最も保守しやすい方法は？::.claude/rules/のファイルのYAMLフロントマターpathsにglobパターン（例：**/*.test.tsx）
チーム全員が使う/reviewコマンドのファイルはどこに置く？::リポジトリの.claude/commands/
スキルの出力がメインの会話を汚さないようにするフロントマターは？::context: fork
スキル実行中のツールを制限するフロントマターは？::allowed-tools
引数なしで呼ばれたときに必要な値を案内するフロントマターは？::argument-hint
モノリスをマイクロサービスに再構築するときのアプローチは？::プランモードで調査・設計してから変更
スタックトレースが明確な単一ファイルのバグ修正は？::直接実行
冗長な探索出力でメインのコンテキストが枯渇するのを防ぐ方法は？::Exploreサブエージェントに探索を任せ、要約だけを受け取る
セッションごとにClaude Codeの動作が違うとき、読み込まれたメモリファイルを確認するコマンドは？::/memory
CIでClaude Codeが入力待ちで止まるときの解決策は？::-p（--print）フラグで非対話モードで実行
CIで結果を機械が解析できるようにするCLIフラグ2つは？::--output-format json、--json-schema

## 状況 → 判断
状況：新しいメンバーだけ規約が適用されない → 正解の方向は？::ユーザーレベル → プロジェクトレベルへ
状況：パッケージごとに必要な標準だけ → 正解の方向は？::@import
状況：CLAUDE.mdが大きすぎる → 正解の方向は？::.claude/rules/のトピック別ファイル
状況：セッションごとに動作が違う → 正解の方向は？::/memoryで読み込まれたファイルを確認
状況：チーム全員が使う/review → 正解の方向は？::.claude/commands/
状況：スキルの出力がメインの会話を散らかす → 正解の方向は？::context: fork
状況：スキル実行中の破壊的な操作を禁止 → 正解の方向は？::allowed-tools
状況：引数なしで呼び出されたときの案内 → 正解の方向は？::argument-hint
状況：常に適用する標準とときどき使う手順 → 正解の方向は？::CLAUDE.mdとスキル
状況：散らばったテストファイルに同じ規約 → 正解の方向は？::.claude/rules/のpaths glob
状況：モノリス → マイクロサービス、45以上のファイルの移行 → 正解の方向は？::プランモード
状況：スタックトレースが明確な単一ファイルのバグ → 正解の方向は？::直接実行
状況：探索の出力でコンテキストが枯渇 → 正解の方向は？::Exploreサブエージェント
状況：説明しても変換結果がばらつく → 正解の方向は？::入出力例2-3件
状況：不慣れなドメインで実装前 → 正解の方向は？::インタビューパターン
状況：相互に関連する複数の問題 → 正解の方向は？::1つのメッセージでまとめて
状況：CIが入力待ちで止まる → 正解の方向は？::-p
状況：CIの結果をPRのインラインコメントに → 正解の方向は？::--output-format json＋--json-schema
状況：コミットのたびに同じコメント → 正解の方向は？::前回の結果を含めて新規・未対応のみ
状況：既にあるテストをまた提案 → 正解の方向は？::既存のテストファイルをコンテキストに
