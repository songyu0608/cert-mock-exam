# フラッシュカード 分野 1　エージェントアーキテクチャとオーケストレーション

#flashcards/ccar-f/d1

形式：`質問::答え`（Spaced Repetitionプラグイン）。プラグインがなくても1行ずつ読めばよい。

## 概念の確認
エージェントループを継続するか終了するかを判断する値は？::stop_reason（"tool_use"なら継続、"end_turn"なら終了）
ツールの実行結果はどこに入れて次のリクエストを送る？::会話履歴（メッセージ一覧）に追加する
ガイドがアンチパターンとして挙げるループ終了方法3つは？::自然言語シグナルの解析、恣意的な反復回数上限を主要な終了手段にする、アシスタントのテキストの有無で完了を判定
ハブアンドスポークでサブエージェント間の通信をコーディネーターに集める理由3つは？::可観測性、一貫したエラー処理、制御された情報フロー
「AIがクリエイティブ産業に与える影響」のレポートがビジュアルアートだけを扱い、コーディネーターがデジタルアート・グラフィックデザイン・写真に分解していた。原因は？::コーディネーターのタスク分解が狭すぎる
サブエージェントはコーディネーターの会話履歴を自動的に継承する？::しない。必要な内容をプロンプトに明示的に含める
エージェント間で情報源の帰属を保って結果を渡すには？::コンテンツとメタデータを構造化された形式で分離して渡す
サブエージェントを並列実行するには、Task呼び出しをどう出す？::コーディネーターの1つの応答の中で複数出す
マルチエージェントの反復的な改善ループで不足を評価するのは誰？::コーディネーター
本人確認なしで返金が進む問題を最も確実に防ぐ方法は？::検証済みの顧客IDが出るまで後続のツール呼び出しをブロックする、プログラムによる前提条件
プロンプトの指示だけで業務の順序を守らせる限界は？::確率的なので失敗率がゼロにならない
構造化されたハンドオフサマリーに含める項目の例4つは？::顧客ID、根本原因、返金額、推奨アクション
複数の問題を含む顧客リクエストの処理順序は？::項目ごとに分解 → 共有コンテキストで並列調査 → 1つの解決策にまとめる
予測可能な多面的コードレビューに向く分解パターンは？::プロンプトチェーン（固定の逐次パイプライン）
「レガシーコードに包括的なテストを追加」のようなオープンエンドなタスクの分解順序は？::構造の把握 → 影響の大きい領域の特定 → 優先順位付きの計画 → 発見に応じて調整
以前のツール結果のほとんどが古いなら、再開と新規開始のどちらがよい？::構造化されたサマリーを注入した新規セッション
stop_reasonが"tool_use"と"end_turn"のときの処理は？::tool_useならツールを実行して継続、end_turnなら終了
コーディネーターがサブエージェントを呼ぶには、allowedToolsに何が必要？::"Task"
AgentDefinitionに含まれる3つは？::説明、システムプロンプト、ツール制限
複数のMCPツールの日付形式を、モデルが見る前に統一するフックは？::PostToolUse
上限額を超える返金を必ず防ぐには？::送信前のツール呼び出しをインターセプトするフックでブロックし、エスカレーションに回す
共通のコードベース分析から2つのテスト戦略を分けて探索するには？::fork_session

## 状況 → 判断
状況：ループをいつ終えるか → 正解の方向は？::stop_reason == "end_turn"
状況：「完了」という言葉・反復回数上限・テキストの有無で終了 → 正解の方向は？::アンチパターン。stop_reasonで判断
状況：サブエージェント同士が直接通信 → 正解の方向は？::コーディネーター経由（ハブアンドスポーク）
状況：サブエージェントはすべて成功したのにレポートが一部の領域だけ → 正解の方向は？::コーディネーターの分解が狭すぎる
状況：統合エージェントが前段の結果を知らない → 正解の方向は？::結果をすべてプロンプトに明示して渡す
状況：コーディネーターがサブエージェントを呼び出せない → 正解の方向は？::allowedToolsに"Task"
状況：サブエージェントを速く実行したい → 正解の方向は？::1つの応答で複数のTask呼び出し
状況：コーディネーターのプロンプトの書き方 → 正解の方向は？::手順ではなく調査の目標・品質基準
状況：本人確認前の返金・上限超えの返金を必ず防ぐ → 正解の方向は？::プログラムによる強制（前提条件・フック）
状況：MCPツールごとに日付・ステータスコードの形式が異なる → 正解の方向は？::PostToolUseフックで正規化
状況：会話履歴を見られない担当者に引き継ぐ → 正解の方向は？::構造化されたハンドオフサマリー（ID、原因、金額、推奨アクション）
状況：1つのメッセージに複数の問題 → 正解の方向は？::分解 → 並列調査 → 統合
状況：予測可能な多面的レビュー → 正解の方向は？::プロンプトチェーン
状況：レガシーコードに包括的なテストを追加 → 正解の方向は？::動的で適応的な分解
状況：昨日の調査を続ける → 正解の方向は？::--resume <session-name>
状況：同じ分析から2つの方法を比較 → 正解の方向は？::fork_session
状況：以前のツールの結果が古い → 正解の方向は？::サマリーを注入した新規セッション
