# タスク 1.7　セッションの状態、再開、フォークを管理する

**English** Manage session state, resumption, and forking

分野 1　エージェントアーキテクチャとオーケストレーション (27%)

セッションを続けるか、分岐させるか、新しく始めるかを選ぶ問題。

> [!tip] 判断の要点
> - --resume <session-name>で続ける、fork_sessionで分岐
> - 再開時は変更されたファイルを具体的に伝える
> - ツールの結果が古ければサマリーを注入した新規セッション

## 必要な知識（Knowledge of）

1. 特定の過去の会話を続行するための、--resume <session-name>を使用した名前付きセッションの再開
2. 共通の分析ベースラインから独立したブランチを作成し、異なるアプローチを探るためのfork_session
3. コード変更後にセッションを再開する際、以前に分析したファイルへの変更をエージェントに伝えることの重要性
4. 古くなったツール結果を抱えたまま再開するよりも、構造化されたサマリーを使って新しいセッションを開始するほうが信頼性が高い理由

> [!quote]- English 公式ガイド原文
> 1. Named session resumption using --resume <session-name> to continue a specific prior conversation
> 2. fork_session for creating independent branches from a shared analysis baseline to explore divergent approaches
> 3. The importance of informing the agent about changes to previously analyzed files when resuming sessions after code modifications
> 4. Why starting a new session with a structured summary is more reliable than resuming with stale tool results

## 必要なスキル（Skills in）

1. セッション名を指定して--resumeを使用し、複数の作業セッションにまたがって名前付きの調査セッションを続行する
2. fork_sessionを使用して並列の探索ブランチを作成する（例：共通のコードベース分析から、2つのテスト戦略やリファクタリングのアプローチを比較する）
3. セッションの再開（以前のコンテキストがおおむね有効な場合）と、サマリーを注入して新たに開始すること（以前のツール結果が古くなっている場合）のいずれかを選択する
4. 全体を再探索させるのではなく、的を絞った再分析のために、再開したセッションに具体的なファイル変更を伝える

> [!quote]- English 公式ガイド原文
> 1. Using --resume with session names to continue named investigation sessions across work sessions
> 2. Using fork_session to create parallel exploration branches (e.g., comparing two testing strategies or refactoring approaches from a shared codebase analysis)
> 3. Choosing between session resumption (when prior context is mostly valid) and starting fresh with injected summaries (when prior tool results are stale)
> 4. Informing a resumed session about specific file changes for targeted re-analysis rather than requiring full re-exploration
