# タスク 2.2　MCPツールの構造化されたエラーレスポンスを実装する

**English** Implement structured error responses for MCP tools

分野 2　ツール設計とMCP統合 (18%)

ツールが失敗したとき、エージェントが復旧方法を決められるよう何を返すかを問う。

> [!tip] 判断の要点
> - isError＋errorCategory＋isRetryable＋説明
> - エラー4種：一時的、検証、ビジネス、権限
> - アクセスの失敗と有効な空の結果を区別し、一時的な失敗はローカルで復旧して必要なものだけ伝播

## 必要な知識（Knowledge of）

1. ツールの失敗をエージェントに伝えるための、MCPのisErrorフラグパターン
2. 一時的なエラー（タイムアウト、サービスの利用不可）、検証エラー（無効な入力）、ビジネスエラー（ポリシー違反）、権限エラーの違い
3. 一律のエラーレスポンス（汎用的な"Operation failed"）では、エージェントが適切な復旧の判断を下せなくなる理由
4. リトライ可能なエラーとリトライ不可能なエラーの違い、および構造化されたメタデータを返すことで無駄なリトライを防ぐ仕組み

> [!quote]- English 公式ガイド原文
> 1. The MCP isError flag pattern for communicating tool failures back to the agent
> 2. The distinction between transient errors (timeouts, service unavailability), validation errors (invalid input), business errors (policy violations), and permission errors
> 3. Why uniform error responses (generic "Operation failed") prevent the agent from making appropriate recovery decisions
> 4. The difference between retryable and non-retryable errors, and how returning structured metadata prevents wasted retry attempts

## 必要なスキル（Skills in）

1. errorCategory（transient/validation/permission）、ブール値のisRetryable、人間が読める説明を含む、構造化されたエラーメタデータを返す
2. エージェントが適切に伝えられるように、ビジネスルール違反に対してretriable: falseフラグと顧客にわかりやすい説明を含める
3. 一時的な失敗についてはサブエージェント内でローカルにエラー復旧を実装し、ローカルで解決できないエラーのみを、部分的な結果および試行した内容とともにコーディネーターに伝播する
4. アクセスの失敗（リトライの判断が必要）と、有効な空の結果（一致するものがなかった成功したクエリを表す）を区別する

> [!quote]- English 公式ガイド原文
> 1. Returning structured error metadata including errorCategory (transient/validation/permission), isRetryable boolean, and human-readable descriptions
> 2. Including retriable: false flags and customer-friendly explanations for business rule violations so the agent can communicate appropriately
> 3. Implementing local error recovery within subagents for transient failures, propagating to the coordinator only errors that cannot be resolved locally along with partial results and what was attempted
> 4. Distinguishing between access failures (needing retry decisions) and valid empty results (representing successful queries with no matches)
