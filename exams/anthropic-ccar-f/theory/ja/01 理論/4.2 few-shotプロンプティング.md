# タスク 4.2　出力の一貫性と品質を高めるためにfew-shotプロンプティングを適用する

**English** Apply few-shot prompting to improve output consistency and quality

分野 4　プロンプトエンジニアリングと構造化出力 (20%)

例を使って出力形式と判断を一貫させる方法を問う。

> [!tip] 判断の要点
> - 曖昧なケースに2-4件の例＋選んだ理由
> - 形式の例（場所、問題、重大度、修正案）
> - 多様な文書構造の例で抽出時のハルシネーション・空のフィールドを減らす

## 必要な知識（Knowledge of）

1. 詳細な指示だけでは一貫しない結果になる場合に、一貫した形式で実用的な出力を得るための最も効果的な手法としてのfew-shotの例
2. 曖昧なケースの扱い方を示すうえでのfew-shotの例の役割（例：曖昧なリクエストに対するツール選択、ブランチレベルのテストカバレッジの不足）
3. few-shotの例によって、モデルが事前に指定されたケースにのみ一致させるのではなく、新しいパターンに判断を一般化できるようになる仕組み
4. 抽出タスクにおけるハルシネーションの低減に対するfew-shotの例の有効性（例：非公式な計量表現や多様な文書構造の処理）

> [!quote]- English 公式ガイド原文
> 1. Few-shot examples as the most effective technique for achieving consistently formatted, actionable output when detailed instructions alone produce inconsistent results
> 2. The role of few-shot examples in demonstrating ambiguous-case handling (e.g., tool selection for ambiguous requests, branch-level test coverage gaps)
> 3. How few-shot examples enable the model to generalize judgment to novel patterns rather than matching only pre-specified cases
> 4. The effectiveness of few-shot examples for reducing hallucination in extraction tasks (e.g., handling informal measurements, varied document structures)

## 必要なスキル（Skills in）

1. 曖昧なシナリオ向けに、妥当と思われる代替案ではなくあるアクションが選ばれた理由の推論を示す、的を絞ったfew-shotの例を2-4個作成する
2. 一貫性を実現するために、求める具体的な出力形式（場所、問題、重大度、修正案）を示すfew-shotの例を含める
3. 許容されるコードパターンと真の問題を区別するfew-shotの例を提示し、一般化を可能にしながら誤検知を減らす
4. few-shotの例を使用して、多様な文書構造（インライン引用と参考文献リスト、方法論のセクションと本文に埋め込まれた詳細）の正しい扱い方を示す
5. 多様な形式の文書からの正しい抽出を示すfew-shotの例を追加し、必須フィールドが空またはnullで抽出される問題に対処する

> [!quote]- English 公式ガイド原文
> 1. Creating 2-4 targeted few-shot examples for ambiguous scenarios that show reasoning for why one action was chosen over plausible alternatives
> 2. Including few-shot examples that demonstrate specific desired output format (location, issue, severity, suggested fix) to achieve consistency
> 3. Providing few-shot examples distinguishing acceptable code patterns from genuine issues to reduce false positives while enabling generalization
> 4. Using few-shot examples to demonstrate correct handling of varied document structures (inline citations vs bibliographies, methodology sections vs embedded details)
> 5. Adding few-shot examples showing correct extraction from documents with varied formats to address empty/null extraction of required fields
