# タスク 4.3　ツール使用とJSONスキーマを用いて構造化出力を強制する

**English** Enforce structured output using tool use and JSON schemas

分野 4　プロンプトエンジニアリングと構造化出力 (20%)

構造化出力を確実に得る方法とスキーマ設計を問う。

> [!tip] 判断の要点
> - tool_use＋JSONスキーマが最も確実（構文エラーは排除、意味的エラーは残る）
> - tool_choice "any"／強制選択
> - nullableフィールド、"unclear"、"other"＋詳細

## 必要な知識（Knowledge of）

1. スキーマに準拠した構造化出力を保証し、JSON構文エラーを排除する最も信頼性の高いアプローチとしての、JSONスキーマを用いたツール使用（tool_use）
2. tool_choice: "auto"（モデルはツールを呼び出さずにテキストを返す場合がある）、"any"（モデルは必ずツールを呼び出すが、どのツールかは選択できる）、強制的なツール選択（モデルは指定された名前の特定のツールを必ず呼び出す）の違い
3. ツール使用による厳密なJSONスキーマは構文エラーを排除するが、意味的なエラー（例：合計と一致しない明細項目、誤ったフィールドに入った値）は防げないこと
4. スキーマ設計上の考慮事項：必須フィールドと任意フィールド、拡張可能なカテゴリのための"other"＋詳細文字列パターンを伴うenumフィールド

> [!quote]- English 公式ガイド原文
> 1. Tool use (tool_use) with JSON schemas as the most reliable approach for guaranteed schema-compliant structured output, eliminating JSON syntax errors
> 2. The distinction between tool_choice: "auto" (model may return text instead of calling a tool), "any" (model must call a tool but can choose which), and forced tool selection (model must call a specific named tool)
> 3. That strict JSON schemas via tool use eliminate syntax errors but do not prevent semantic errors (e.g., line items that don't sum to total, values in wrong fields)
> 4. Schema design considerations: required vs optional fields, enum fields with "other" + detail string patterns for extensible categories

## 必要なスキル（Skills in）

1. JSONスキーマを入力パラメータとする抽出ツールを定義し、tool_useレスポンスから構造化データを抽出する
2. 複数の抽出スキーマが存在し文書の種類が不明な場合に、tool_choice: "any"を設定して構造化出力を保証する
3. tool_choice: {"type": "tool", "name": "extract_metadata"}で特定のツールを強制し、エンリッチメントのステップの前に特定の抽出が確実に実行されるようにする
4. ソース文書に情報が含まれていない可能性がある場合にスキーマのフィールドを任意（null許容）として設計し、モデルが必須フィールドを満たすために値を捏造するのを防ぐ
5. 曖昧なケース用の"unclear"などのenum値や、拡張可能な分類のための"other"＋詳細フィールドを追加する
6. 一貫しないソースの書式に対処するために、厳密な出力スキーマとあわせて形式の正規化ルールをプロンプトに含める

> [!quote]- English 公式ガイド原文
> 1. Defining extraction tools with JSON schemas as input parameters and extracting structured data from the tool_use response
> 2. Setting tool_choice: "any" to guarantee structured output when multiple extraction schemas exist and the document type is unknown
> 3. Forcing a specific tool with tool_choice: {"type": "tool", "name": "extract_metadata"} to ensure a particular extraction runs before enrichment steps
> 4. Designing schema fields as optional (nullable) when source documents may not contain the information, preventing the model from fabricating values to satisfy required fields
> 5. Adding enum values like "unclear" for ambiguous cases and "other" + detail fields for extensible categorization
> 6. Including format normalization rules in prompts alongside strict output schemas to handle inconsistent source formatting

- [[tool_useによる構造化出力]] — JSONスキーマを入力パラメーターとして定義した抽出ツールを呼ばせると、スキーマに準拠した出力を最も確実に得られる（構文エラーを排除）。
- [[構文エラーと意味的エラー]] — ツール使用＋厳密なスキーマはJSONの構文エラーをなくすが、合計の不一致やフィールドの取り違えといった意味的なエラーは防げない。
- [[nullableフィールドと捏造の防止]] — ソースにない可能性のある情報を必須フィールドにすると、モデルは値を捏造する。任意（nullable）フィールドにしてnullを許容する。

- [[JSONスキーマ設計]] — 抽出スキーマの設計要素：必須と任意のフィールド、nullable、enum、"other"＋詳細文字列、strictモード。
