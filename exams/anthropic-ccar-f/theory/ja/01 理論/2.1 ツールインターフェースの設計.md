# タスク 2.1　明確な説明と境界を備えた効果的なツールインターフェースを設計する

**English** Design effective tool interfaces with clear descriptions and boundaries

分野 2　ツール設計とMCP統合 (18%)

モデルが正しくツールを選べるよう、ツールの名前・説明・境界を設計する問題。

> [!tip] 判断の要点
> - ツール選択ミスの**最初の対策はツールの説明の拡充**（入力形式、クエリの例、エッジケース、境界）
> - 重複するツールは名前変更、汎用ツールは目的別に分割
> - システムプロンプト内のキーワード指示がツール選択をゆがめることがある

## 必要な知識（Knowledge of）

1. LLMがツール選択に用いる主要な仕組みとしてのツールの説明。最小限の説明では、類似したツール間での選択の信頼性が低下する
2. ツールの説明に、入力形式、クエリの例、エッジケース、境界の説明を含めることの重要性
3. 曖昧な、または重複するツールの説明が誤ったルーティングを引き起こす仕組み（例：ほぼ同一の説明を持つanalyze_contentとanalyze_document）
4. システムプロンプトの文言がツール選択に与える影響：キーワードに敏感な指示が、意図しないツールの関連付けを生む可能性がある

> [!quote]- English 公式ガイド原文
> 1. Tool descriptions as the primary mechanism LLMs use for tool selection; minimal descriptions lead to unreliable selection among similar tools
> 2. The importance of including input formats, example queries, edge cases, and boundary explanations in tool descriptions
> 3. How ambiguous or overlapping tool descriptions cause misrouting (e.g., analyze_content vs analyze_document with near-identical descriptions)
> 4. The impact of system prompt wording on tool selection: keyword-sensitive instructions can create unintended tool associations

## 必要なスキル（Skills in）

1. 各ツールの目的、想定される入力、出力、および類似の代替ツールではなくそのツールを使うべき場面を明確に区別するツールの説明を作成する
2. 機能の重複をなくすために、ツールの名前を変更し説明を更新する（例：analyze_contentをextract_web_resultsに名前変更し、ウェブに特化した説明を付ける）
3. 汎用的なツールを、入出力の契約が定義された目的別のツールに分割する（例：汎用的なanalyze_documentを、extract_data_points、summarize_content、verify_claim_against_sourceに分割する）
4. 適切に書かれたツールの説明を上書きしてしまう可能性のある、キーワードに敏感な指示がないかシステムプロンプトをレビューする

> [!quote]- English 公式ガイド原文
> 1. Writing tool descriptions that clearly differentiate each tool's purpose, expected inputs, outputs, and when to use it versus similar alternatives
> 2. Renaming tools and updating descriptions to eliminate functional overlap (e.g., renaming analyze_content to extract_web_results with a web-specific description)
> 3. Splitting generic tools into purpose-specific tools with defined input/output contracts (e.g., splitting a generic analyze_document into extract_data_points, summarize_content, and verify_claim_against_source)
> 4. Reviewing system prompts for keyword-sensitive instructions that might override well-written tool descriptions
