# タスク 4.6　マルチインスタンスおよびマルチパスのレビューアーキテクチャを設計する

**English** Design multi-instance and multi-pass review architectures

分野 4　プロンプトエンジニアリングと構造化出力 (20%)

レビューの質を高めるアーキテクチャを問う。

> [!tip] 判断の要点
> - 同じセッションでの自己レビューより独立したインスタンス
> - ファイル単位のローカルパス＋ファイル横断の統合パス
> - コンテキストの大きいモデルに替えても注意の分散は解決しない

## 必要な知識（Knowledge of）

1. セルフレビューの限界：モデルは生成時の推論コンテキストを保持しているため、同じセッション内では自身の判断を疑いにくくなること
2. 独立したレビューインスタンス（以前の推論コンテキストを持たない）は、セルフレビューの指示や拡張思考よりも、微妙な問題を見つけるうえで効果的であること
3. マルチパスレビュー：注意の分散や矛盾した指摘事項を避けるために、大規模なレビューをファイル単位の局所的な分析パスとファイル横断の統合パスに分割すること

> [!quote]- English 公式ガイド原文
> 1. Self-review limitations: a model retains reasoning context from generation, making it less likely to question its own decisions in the same session
> 2. Independent review instances (without prior reasoning context) are more effective at catching subtle issues than self-review instructions or extended thinking
> 3. Multi-pass review: splitting large reviews into per-file local analysis passes plus cross-file integration passes to avoid attention dilution and contradictory findings

## 必要なスキル（Skills in）

1. 生成側の推論コンテキストを持たない、別の独立したClaudeインスタンスを使用して、生成されたコードをレビューする
2. 大規模な複数ファイルのレビューを、局所的な問題に焦点を絞ったファイル単位のパスと、ファイル横断のデータフロー分析のための別個の統合パスに分割する
3. モデルが各指摘事項とあわせて確信度を自己申告する検証パスを実行し、キャリブレーションされたレビューのルーティングを可能にする

> [!quote]- English 公式ガイド原文
> 1. Using a second independent Claude instance to review generated code without the generator's reasoning context
> 2. Splitting large multi-file reviews into focused per-file passes for local issues plus separate integration passes for cross-file data flow analysis
> 3. Running verification passes where the model self-reports confidence alongside each finding to enable calibrated review routing

## このタスクのカード
- [[独立したレビューインスタンス]] — コードを生成したセッションは自分の推論コンテキストを保持しているため、自分の判断を疑いにくい。生成時のコンテキストを持たない別のインスタンスにレビューさせる。
- [[マルチパスレビュー]] — 大きなレビューを、ファイル単位のローカル分析パスと、ファイル間のデータフローを見る統合パスに分け、注意の分散や矛盾した指摘を防ぐ。
