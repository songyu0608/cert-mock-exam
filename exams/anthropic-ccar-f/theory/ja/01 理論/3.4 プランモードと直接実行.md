# タスク 3.4　プランモードと直接実行のどちらを使用するかを判断する

**English** Determine when to use plan mode vs direct execution

分野 3　Claude Codeの設定とワークフロー (20%)

作業の規模と不確実性に応じてプランモードと直接実行のどちらを選ぶかを問う。

> [!tip] 判断の要点
> - 大規模・複数ファイル・複数のアプローチ・アーキテクチャ上の判断 → プランモード
> - 範囲が明確な単純な変更 → 直接実行
> - 冗長な探索はExploreサブエージェント、計画後に直接実行の組み合わせ

## 必要な知識（Knowledge of）

1. プランモードは、大規模な変更、複数の有効なアプローチ、アーキテクチャ上の決定、複数ファイルの修正を伴う複雑なタスク向けに設計されていること
2. 直接実行は、単純で範囲が明確な変更に適していること（例：ある関数に単一のバリデーションチェックを追加する）
3. プランモードでは、変更を確定する前にコードベースの探索と設計を安全に行うことができ、コストのかかる手戻りを防げること
4. 冗長な調査出力を分離し、要約を返すことでメインの会話のコンテキストを保全するExploreサブエージェント

> [!quote]- English 公式ガイド原文
> 1. Plan mode is designed for complex tasks involving large-scale changes, multiple valid approaches, architectural decisions, and multi-file modifications
> 2. Direct execution is appropriate for simple, well-scoped changes (e.g., adding a single validation check to one function)
> 3. Plan mode enables safe codebase exploration and design before committing to changes, preventing costly rework
> 4. The Explore subagent for isolating verbose discovery output and returning summaries to preserve main conversation context

## 必要なスキル（Skills in）

1. アーキテクチャに影響するタスクにプランモードを選択する（例：マイクロサービスの再構成、45+ファイルに影響するライブラリ移行、インフラストラクチャ要件が異なる統合アプローチの選択）
2. 内容が十分に理解されていて範囲が明確な変更に直接実行を選択する（例：スタックトレースが明確な単一ファイルのバグ修正、日付バリデーションの条件分岐の追加）
3. 冗長な調査フェーズにExploreサブエージェントを使用し、複数フェーズのタスクでコンテキストウィンドウが枯渇するのを防ぐ
4. 調査のためのプランモードと実装のための直接実行を組み合わせる（例：ライブラリ移行を計画し、その後、計画したアプローチを実行する）

> [!quote]- English 公式ガイド原文
> 1. Selecting plan mode for tasks with architectural implications (e.g., microservice restructuring, library migrations affecting 45+ files, choosing between integration approaches with different infrastructure requirements)
> 2. Selecting direct execution for well-understood changes with clear scope (e.g., a single-file bug fix with a clear stack trace, adding a date validation conditional)
> 3. Using the Explore subagent for verbose discovery phases to prevent context window exhaustion during multi-phase tasks
> 4. Combining plan mode for investigation with direct execution for implementation (e.g., planning a library migration, then executing the planned approach)
