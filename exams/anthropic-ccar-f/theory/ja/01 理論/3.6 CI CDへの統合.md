# タスク 3.6　Claude CodeをCI/CDパイプラインに統合する

**English** Integrate Claude Code into CI/CD pipelines

分野 3　Claude Codeの設定とワークフロー (20%)

Claude CodeをCI/CDに組み込み、自動レビュー・テスト生成を行う方法を問う。

> [!tip] 判断の要点
> - 非対話での実行は-p（--print）
> - --output-format json＋--json-schemaでPRのインラインコメント
> - 再レビューは前回の結果を含めて新規・未対応のみ、レビューは生成セッションと分離

## 必要な知識（Knowledge of）

1. 自動化されたパイプラインでClaude Codeを非対話モードで実行するための-p（または--print）フラグ
2. CIのコンテキストで構造化出力を強制するための--output-format jsonおよび--json-schemaのCLIフラグ
3. CIから呼び出されるClaude Codeにプロジェクトのコンテキスト（テスト標準、フィクスチャの規約、レビュー基準）を提供する仕組みとしてのCLAUDE.md
4. セッションコンテキストの分離：コードを生成したのと同じClaudeセッションは、独立したレビューインスタンスと比べて、自身の変更をレビューする効果が低い理由

> [!quote]- English 公式ガイド原文
> 1. The -p (or --print) flag for running Claude Code in non-interactive mode in automated pipelines
> 2. --output-format json and --json-schema CLI flags for enforcing structured output in CI contexts
> 3. CLAUDE.md as the mechanism for providing project context (testing standards, fixture conventions, review criteria) to CI-invoked Claude Code
> 4. Session context isolation: why the same Claude session that generated code is less effective at reviewing its own changes compared to an independent review instance

## 必要なスキル（Skills in）

1. CIで-pフラグを付けてClaude Codeを実行し、対話的な入力待ちによるハングを防ぐ
2. --output-format jsonを--json-schemaとともに使用し、PRのインラインコメントとして自動投稿するための、機械で解析可能な構造化された指摘事項を生成する
3. 新しいコミットの後にレビューを再実行する際に、以前のレビューの指摘事項をコンテキストに含め、重複コメントを避けるために新規または未対応の問題のみを報告するようClaudeに指示する
4. 既存のテストファイルをコンテキストに提供し、テスト生成において、テストスイートですでにカバーされている重複シナリオが提案されないようにする
5. テスト標準、価値のあるテストの基準、利用可能なフィクスチャをCLAUDE.mdに文書化し、テスト生成の品質を高め、価値の低いテスト出力を減らす

> [!quote]- English 公式ガイド原文
> 1. Running Claude Code in CI with the -p flag to prevent interactive input hangs
> 2. Using --output-format json with --json-schema to produce machine-parseable structured findings for automated posting as inline PR comments
> 3. Including prior review findings in context when re-running reviews after new commits, instructing Claude to report only new or still-unaddressed issues to avoid duplicate comments
> 4. Providing existing test files in context so test generation avoids suggesting duplicate scenarios already covered by the test suite
> 5. Documenting testing standards, valuable test criteria, and available fixtures in CLAUDE.md to improve test generation quality and reduce low-value test output

## このタスクのカード
- [[CIレビューの重複防止]] — 新しいコミットの後にレビューを再実行するときは前回の指摘をコンテキストに含め、新規または未解決の問題だけを報告させる。テスト生成には既存のテストファイルを渡す。
- [[独立したレビューインスタンス]] — コードを生成したセッションは自分の推論コンテキストを保持しているため、自分の判断を疑いにくい。生成時のコンテキストを持たない別のインスタンスにレビューさせる。
- [[CLAUDE.mdの階層]] — Claude Codeに指示を与えるCLAUDE.mdには、ユーザー・プロジェクト・ディレクトリの3つのレベルがある。
- [[-pフラグ]] — Claude Codeを非対話モードで実行するフラグ。CIで入力待ちにより止まらないようにする。
- [[--output-format jsonと--json-schema]] — CIでClaude Codeの結果を機械が解析できる構造化された形式に強制するCLIフラグ。
