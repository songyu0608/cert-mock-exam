# タスク 1.5　ツール呼び出しのインターセプトとデータ正規化のためにAgent SDKのフックを適用する

**English** Apply Agent SDK hooks for tool call interception and data normalization

分野 1　エージェントアーキテクチャとオーケストレーション (27%)

ツール呼び出しの前後をインターセプトするフックで、データを正規化しルールを強制する方法を問う。

> [!tip] 判断の要点
> - PostToolUseで形式の異なるツール結果を正規化
> - 送信前の呼び出しをインターセプトし、上限超えなどのポリシー違反をブロック → エスカレーション
> - 保証が必要ならフック、プロンプトは確率的

## 必要な知識（Knowledge of）

1. モデルが処理する前にツールの結果をインターセプトして変換するフックパターン（例：PostToolUse）
2. 送信されるツール呼び出しをインターセプトしてコンプライアンスルールを強制するフックパターン（例：しきい値を超える返金のブロック）
3. 決定論的な保証のためにフックを使用することと、確率的な遵守のためにプロンプトの指示に頼ることの違い

> [!quote]- English 公式ガイド原文
> 1. Hook patterns (e.g., PostToolUse) that intercept tool results for transformation before the model processes them
> 2. Hook patterns that intercept outgoing tool calls to enforce compliance rules (e.g., blocking refunds above a threshold)
> 3. The distinction between using hooks for deterministic guarantees versus relying on prompt instructions for probabilistic compliance

## 必要なスキル（Skills in）

1. エージェントが処理する前に、異なるMCPツールから返される不均一なデータ形式（Unixタイムスタンプ、ISO 8601、数値のステータスコード）を正規化するPostToolUseフックを実装する
2. ポリシーに違反するアクション（例：$500を超える返金）をブロックし、代替のワークフロー（例：人間へのエスカレーション）にリダイレクトする、ツール呼び出しインターセプトフックを実装する
3. ビジネスルールで確実な遵守が求められる場合に、プロンプトベースの強制ではなくフックを選択する

> [!quote]- English 公式ガイド原文
> 1. Implementing PostToolUse hooks to normalize heterogeneous data formats (Unix timestamps, ISO 8601, numeric status codes) from different MCP tools before the agent processes them
> 2. Implementing tool call interception hooks that block policy-violating actions (e.g., refunds exceeding $500) and redirect to alternative workflows (e.g., human escalation)
> 3. Choosing hooks over prompt-based enforcement when business rules require guaranteed compliance

## このタスクのカード
- [[プログラムによる強制]] — フックや前提条件ゲートで、ツール呼び出しの順序や業務ルールをコードで強制する方法。プロンプトの指示は確率的で、失敗率はゼロにならない。
- [[Agent SDKのフック]] — ツール呼び出しの前後をインターセプトするコード。結果の正規化（PostToolUse）とポリシー違反の呼び出しのブロックに使い、決定論的な保証を与える。
