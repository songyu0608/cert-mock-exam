# タスク 3.2　カスタムスラッシュコマンドとスキルを作成し設定する

**English** Create and configure custom slash commands and skills

分野 3　Claude Codeの設定とワークフロー (20%)

カスタムスラッシュコマンドとスキルをどこに置き、どう設定するかを問う。

> [!tip] 判断の要点
> - チーム共有のコマンドは.claude/commands/、個人用は~/.claude/commands/
> - スキルのフロントマター：context: fork、allowed-tools、argument-hint
> - 常に適用＝CLAUDE.md、必要なとき＝スキル

## 必要な知識（Knowledge of）

1. .claude/commands/  内のプロジェクトスコープのコマンド（バージョン管理を通じて共有）と、~/.claude/commands/ 内のユーザースコープのコマンド（個人用）の違い
2. context: fork、allowed-tools、argument-hintなどのフロントマター設定をサポートするSKILL.mdファイルを備えた、.claude/skills/内のスキル
3. スキルを分離されたサブエージェントのコンテキストで実行し、スキルの出力がメインの会話を汚染するのを防ぐためのcontext: forkフロントマターオプション
4. 個人用のスキルのカスタマイズ：チームメイトに影響を与えないように、~/.claude/skills/内に別の名前で個人用のバリエーションを作成すること

> [!quote]- English 公式ガイド原文
> 1. Project-scoped commands in .claude/commands/ (shared via version control) vs user-scoped commands in ~/.claude/commands/ (personal)
> 2. Skills in .claude/skills/ with SKILL.md files that support frontmatter configuration including context: fork, allowed-tools, and argument-hint
> 3. The context: fork frontmatter option for running skills in an isolated sub-agent context, preventing skill outputs from polluting the main conversation
> 4. Personal skill customization: creating personal variants in ~/.claude/skills/ with different names to avoid affecting teammates

## 必要なスキル（Skills in）

1. バージョン管理を通じてチーム全体で利用できるように、.claude/commands/内にプロジェクトスコープのスラッシュコマンドを作成する
2. context: forkを使用して、冗長な出力（例：コードベース分析）や探索的なコンテキスト（例：代替案のブレインストーミング）を生成するスキルをメインセッションから分離する
3. スキルのフロントマターでallowed-toolsを設定し、スキル実行中のツールアクセスを制限する（例：破壊的な操作を防ぐためにファイル書き込み操作に限定する）
4. argument-hintフロントマターを使用して、開発者が引数なしでスキルを呼び出したときに必須パラメータの入力を促す
5. スキル（タスク固有のワークフローのためのオンデマンド呼び出し）とCLAUDE.md（常に読み込まれる全体共通の標準）のどちらを使用するかを選択する

> [!quote]- English 公式ガイド原文
> 1. Creating project-scoped slash commands in .claude/commands/ for team-wide availability via version control
> 2. Using context: fork to isolate skills that produce verbose output (e.g., codebase analysis) or exploratory context (e.g., brainstorming alternatives) from the main session
> 3. Configuring allowed-tools in skill frontmatter to restrict tool access during skill execution (e.g., limiting to file write operations to prevent destructive actions)
> 4. Using argument-hint frontmatter to prompt developers for required parameters when they invoke the skill without arguments
> 5. Choosing between skills (on-demand invocation for task-specific workflows) and CLAUDE.md (always-loaded universal standards)
