# タスク 2.5　組み込みツール（Read、Write、Edit、Bash、Grep、Glob）を効果的に選択し適用する

**English** Select and apply built-in tools (Read, Write, Edit, Bash, Grep, Glob) effectively

分野 2　ツール設計とMCP統合 (18%)

Read、Write、Edit、Bash、Grep、Globのどれを選ぶかを問う。

> [!tip] 判断の要点
> - 内容の検索はGrep、パスのパターンはGlob
> - Editの失敗（一意なテキストがない）→ Read＋Write
> - Grepでエントリーポイント → Readで追跡する段階的な探索

## 必要な知識（Knowledge of）

1. コンテンツ検索のためのGrep（関数名、エラーメッセージ、import文などのパターンをファイルの内容から検索する）
2. ファイルパスのパターンマッチングのためのGlob（名前や拡張子のパターンでファイルを見つける）
3. ファイル全体の操作のためのRead/Write。一意のテキストマッチングを使用した的を絞った変更のためのEdit
4. テキストの一致が一意でないためにEditが失敗した場合に、確実なファイル変更のためのフォールバックとしてRead + Writeを使用すること

> [!quote]- English 公式ガイド原文
> 1. Grep for content search (searching file contents for patterns like function names, error messages, or import statements)
> 2. Glob for file path pattern matching (finding files by name or extension patterns)
> 3. Read/Write for full file operations; Edit for targeted modifications using unique text matching
> 4. When Edit fails due to non-unique text matches, using Read + Write as a fallback for reliable file modifications

## 必要なスキル（Skills in）

1. コードベース全体でコードの内容を検索するためにGrepを選択する（例：ある関数のすべての呼び出し元を見つける、エラーメッセージの場所を特定する）
2. 命名パターンに一致するファイルを見つけるためにGlobを選択する（例：**/*.test.tsx）
3. Editが一意のアンカーテキストを見つけられない場合に、Readでファイルの内容全体を読み込んでからWriteを使用する
4. 最初にすべてのファイルを読むのではなく、Grepでエントリーポイントを見つけることから始め、次にReadでimportをたどってフローを追跡することで、コードベースの理解を段階的に構築する
5. まずエクスポートされたすべての名前を特定し、次にコードベース全体で各名前を検索することで、ラッパーモジュールをまたぐ関数の使用箇所を追跡する

> [!quote]- English 公式ガイド原文
> 1. Selecting Grep for searching code content across a codebase (e.g., finding all callers of a function, locating error messages)
> 2. Selecting Glob for finding files matching naming patterns (e.g., **/*.test.tsx)
> 3. Using Read to load full file contents followed by Write when Edit cannot find unique anchor text
> 4. Building codebase understanding incrementally: starting with Grep to find entry points, then using Read to follow imports and trace flows, rather than reading all files upfront
> 5. Tracing function usage across wrapper modules by first identifying all exported names, then searching for each name across the codebase
