# 68. @import와 rules 폴더

이제 팀의 규칙이 프로젝트 CLAUDE.md로 옮겨졌으니, 모든 개발자가 같은 규칙을 로드합니다. 이번 노트에서는 프로젝트가 커져도 이 파일을 작고 읽기 쉽게 유지하는 법을 살펴봅니다. 거대한 파일 하나는 관리하기 어렵고, Claude Code는 세션마다 그 파일 전체를 읽습니다.

## CLAUDE.md가 600줄이 됐다

1년 뒤 ShopAssist 리포지토리에는 패키지가 여러 개 있습니다. 패키지는 자기 폴더와 자기 역할이 있는 코드베이스의 한 부분입니다.

- 환불 서비스
- 스토어 웹사이트의 채팅 창
- 스토어 도구 네 개를 제공하는 MCP 서버

그 1년 동안 새 규칙은 모두 프로젝트 CLAUDE.md에 들어갔습니다. 이제 이 파일은 600줄입니다. 테스트 규칙 옆에 배포 단계가 있고, API 규칙이 채팅 창에 관한 메모와 섞여 있습니다. 어떤 규칙이 아직 유효한지 아무도 모르고, 두 섹션은 서로 반대되는 말을 하기도 합니다.

가장 중요한 원칙은 **지침을 주제별로 나누고, 각 조각을 필요한 곳에서 로드한다**는 것입니다. 이를 위한 도구가 두 가지 있습니다. rules 폴더와 import입니다.

## 1. rules 폴더

리포지토리의 `.claude` 폴더 안에 `rules`라는 폴더를 만듭니다. 그 안의 파일 하나가 주제 하나를 다룹니다.

```text
.claude/
  rules/
    testing.md          # framework, fake payments, test names
    api-conventions.md  # field names, errors
    deployment.md       # release steps
CLAUDE.md               # short overview
```

| 파일 | 내용 |
| --- | --- |
| `testing.md` | 테스트 프레임워크, 가짜 결제 서비스, 테스트 파일 이름 짓는 법 |
| `api-conventions.md` | 엔드포인트의 필드 이름과 오류 반환 방식 |
| `deployment.md` | 릴리스 단계 |

Claude Code는 이 파일들을 프로젝트 메모리의 일부로 읽습니다. 별도 설정이 없는 rules 파일은 프로젝트 CLAUDE.md처럼 모든 세션에서 로드됩니다. 폴더를 커밋하므로 팀 전체가 받습니다.

이제 주제마다 자리가 하나씩 있습니다. 테스트 프레임워크가 바뀌면 짧은 파일 하나만 고칩니다. PR에는 테스트 규칙만 보이므로 리뷰도 빠릅니다. 루트 CLAUDE.md는 짧은 개요로 줄어듭니다. 프로젝트가 무엇인지, 주요 명령, 가장 중요한 팀 규칙입니다.

## 2. import

어떤 표준은 한 패키지에는 중요하고 다른 패키지에는 상관없습니다. 금액 처리 표준은 금액을 센트 단위로 저장하고, 환불 금액은 항상 주문에서 가져온다고 정합니다. 환불 서비스에는 이 표준이 필요하지만 채팅 창에는 필요 없습니다.

그래서 패키지마다 자기 CLAUDE.md를 두고, 그 파일이 필요한 표준을 가져옵니다. 시험에서는 이것을 **@import 구문**이라고 부릅니다. `@` 기호 뒤에 파일 경로를 씁니다.

```text
# CLAUDE.md of the refund service
@standards/money-handling.md
@standards/api-conventions.md

# CLAUDE.md of the chat window
@standards/frontend.md
```

환불 서비스의 CLAUDE.md는 금액 처리 표준과 API 규칙을 가져오고, 채팅 창의 파일은 프런트엔드 표준을 가져옵니다. Claude Code는 CLAUDE.md를 로드할 때 그 파일이 가져오는 파일도 함께 로드합니다.

**import는 누가 정할까요?** 각 패키지의 메인테이너, 즉 그 코드를 맡은 개발자입니다. 메인테이너는 자기 코드가 어떤 표준과 닿는지 압니다. 환불 서비스 담당자는 금액 규칙이 거기에 적용된다는 것을 압니다. 중앙 파일 하나가 그들만큼 잘 알 수는 없습니다.

같은 표준을 패키지마다 CLAUDE.md에 복사하면 안 됩니다. 사본이 세 개가 되고, 서서히 서로 어긋납니다. import를 쓰면 표준은 파일 하나에만 있고, 각 패키지는 그 파일을 가리키기만 합니다.

이 파일들은 **컨텍스트이지 강제 수단이 아니라는 점**도 기억하세요. Claude Code를 안내할 뿐입니다. 500달러 환불 한도처럼 반드시 지켜야 하는 규칙은 여전히 코드와 테스트에 둡니다.

## 정리

- 계속 커지는 CLAUDE.md 하나는 읽기도, 리뷰하기도, 정확하게 유지하기도 어려워집니다.
- `.claude` 안의 rules 폴더에는 테스트, API 규칙, 배포 같은 주제별 파일을 둡니다.
- 별도 설정이 없는 rules 파일은 프로젝트 파일처럼 모든 세션에서 로드됩니다.
- `@` 기호 뒤에 경로를 쓰면 표준 파일을 CLAUDE.md로 가져옵니다.
- 각 패키지의 메인테이너는 자기 코드에 필요한 표준만 가져옵니다. 그래서 모든 표준은 정확히 한 곳에만 있습니다.

주제마다 파일을 따로 두고, 각 패키지가 필요한 것을 가져오게 하세요. 다음 노트에서는 Claude Code가 규칙이 적용되는 파일로 작업할 때만 그 규칙을 로드하게 만드는 법을 살펴보겠습니다.
