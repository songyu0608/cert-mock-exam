# 73. MCP 서버를 안전하게 공유하기

지금까지 팀은 CLAUDE.md, 규칙, 스킬을 리포지토리에 넣었습니다. MCP 서버도 같은 원칙을 따릅니다. 리포지토리 안의 파일은 팀 전체에 닿고, 홈 폴더 안의 파일은 나에게만 닿습니다.

이번 노트에서는 팀이 MCP 서버를 안전하게 공유하려면 어디에 설정해야 하는지 살펴봅니다. 많은 서버에 비밀 정보가 필요하고, **비밀 정보는 절대 리포지토리에 들어가면 안 되기** 때문입니다.

## 모든 개발자에게 서버 두 개가 필요하다

팀은 Claude Code로 ShopAssist를 만들고, 여러 MCP 서버가 그 작업을 돕습니다. 여기서 중요한 서버는 두 개입니다.

| 서버 | 하는 일 |
| --- | --- |
| ShopAssist 백엔드 서버 | 상점 도구 네 개. 개발자들은 테스트용 상점 사본과 함께 씁니다. |
| GitHub 커뮤니티 서버 | 팀 리포지토리가 있는 GitHub에서 Claude Code가 풀 리퀘스트와 이슈를 읽게 합니다. |

모든 개발자에게 두 서버가 다 필요합니다. GitHub 서버에는 **액세스 토큰**도 필요합니다. 액세스 토큰은 누가 호출하는지 증명하는 비밀 값입니다.

가장 중요한 원칙은 **서버 설정은 공유하되, 그 비밀은 절대 공유하지 않는다**는 것입니다. 이번 노트에서는 팀 서버용 프로젝트 파일, 비밀을 위한 변수, 개인 서버용 사용자 파일을 차례로 봅니다.

## 1. 프로젝트 파일

팀 서버는 리포지토리 루트의 `.mcp.json` 파일에 둡니다. 서버마다 이름과, 서버를 시작하는 명령을 적습니다.

```json
{
  "mcpServers": {
    "shopassist": {
      "command": "shopassist-mcp"
    },
    "github": {
      "command": "npx",
      "args": ["-y", "github-mcp-server"]
    }
  }
}
```

이 파일을 다른 변경처럼 커밋합니다. 그러면 리포지토리를 clone하거나 pull하는 모든 사람이 같은 서버를 받습니다. 가장 최근에 합류한 레오도 첫날부터 받습니다. 누구도 레오에게 서버 목록을 보내 줄 필요가 없습니다.

## 2. 비밀

실제 토큰을 `.mcp.json`에 붙여 넣으면 안 됩니다.

- 파일을 커밋하므로 토큰이 리포지토리 기록에 들어갑니다.
- 리포지토리를 읽을 수 있는 누구나 토큰을 읽을 수 있습니다.
- 나중에 그 줄을 지워도 기록에서 사라지지 않으므로, 토큰을 교체해야 합니다.

대신 파일에는 **환경 변수**의 이름을 적습니다. 환경 변수는 리포지토리 밖, 각 개발자의 컴퓨터에 있는 이름 붙은 값입니다. 파일에는 달러 기호와 중괄호 안의 변수 이름을 씁니다. 시험의 예는 `GITHUB_TOKEN`이라는 변수입니다.

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "github-mcp-server"],
      "env": {
        "GITHUB_TOKEN": "${GITHUB_TOKEN}"
      }
    }
  }
}
```

Claude Code는 서버를 시작할 때 그 이름 자리에 개발자 자신의 환경에 있는 값을 넣습니다. 이것을 **환경 변수 확장**이라고 합니다.

1. 개발자가 자기 토큰으로 `GITHUB_TOKEN`을 한 번 설정합니다.
2. Claude Code가 `.mcp.json`을 읽고, 이름을 그 값으로 바꿉니다.
3. GitHub 서버가 실제 토큰으로 시작합니다.

파일에는 이름만 있으므로 커밋해도 안전합니다. 백엔드 서버의 키도 같은 방식으로 다룹니다.

## 3. 개인 서버

레오가 코드에서 다이어그램을 그려 주는 새 커뮤니티 서버를 써 보고 싶어 한다고 해 봅시다. 아직 도움이 되는지는 아무도 모릅니다. 이 서버를 프로젝트 파일에 추가하면 안 됩니다. 그러면 모든 팀원이 이 서버를 시작하게 됩니다.

개인 서버와 실험용 서버는 홈 폴더의 `.claude.json` 파일에 둡니다. 버전 관리는 이 파일을 보지 못합니다. 레오의 서버는 팀 서버 옆에서 레오에게만 실행됩니다. 실험이 성공하면 레오는 풀 리퀘스트로 그 서버를 `.mcp.json`에 옮깁니다. 그러면 팀 전체가 받습니다.

| 파일 | 위치 | 받는 사람 |
| --- | --- | --- |
| `.mcp.json` | 리포지토리 | 팀 전체 |
| `~/.claude.json` | 홈 폴더 | 나만 |

## 제품 참고

| 기준 | 범위 |
| --- | --- |
| 시험 | 두 가지 범위로 답합니다. 팀용은 프로젝트 파일, 개인 서버는 홈 폴더의 파일입니다. |
| 현재 명령 | `claude mcp add`는 세 번째 범위인 local도 제공합니다. 한 프로젝트에서 나만 쓰는 범위입니다(강의 슬라이드 기준). |

## 정리

- 팀 MCP 서버는 리포지토리 안의 `.mcp.json`에 두고, 버전 관리로 공유합니다.
- 개인 서버와 실험용 서버는 홈 폴더의 `.claude.json`에 두고, 나에게만 닿습니다.
- 비밀은 절대 프로젝트 파일에 넣지 않습니다. 파일에는 환경 변수 이름을 적습니다.
- Claude Code는 서버를 시작할 때 각 개발자 자신의 값을 채워 넣습니다.

서버 설정은 커밋하고, 비밀은 모두 각 개발자의 컴퓨터에 두세요. 다음 노트에서는 설정을 마치고 실제 작업이 들어올 때, Claude Code가 언제 실행 전에 계획해야 하는지 정하겠습니다.
