# 80. 세션: 이어 갈까, 새로 시작할까

앞에서는 변경 전에 Claude Code가 우리에게 질문하게 했고, 리뷰에서 나온 문제를 서로 영향을 주는지에 따라 묶었습니다.

이번 노트에서는 며칠에 걸치는 작업을 살펴봅니다. 이전 작업으로 돌아올 때, 옛 세션을 이어 가야 할까요, 새 세션을 시작해야 할까요? 오래된 세션에는 더 이상 사실이 아닌 내용이 남아 있을 수 있기 때문입니다.

| 선택 | 결과 |
| --- | --- |
| 옛 세션 이어 가기 | 이전 메시지와 결과를 모두 유지합니다. |
| 새 세션 시작하기 | 옛 사실 없이 깨끗하게 시작합니다. |

## 금요일의 작업은 한 세션에 담겨 있다

금요일에 ShopAssist 팀의 한 개발자가 Claude Code에 환불 흐름을 분석해 달라고 합니다. Claude Code는 코드를 검색하고, 파일 약 20개를 읽고, 테스트를 실행합니다. 저녁이 되면 환불 금액이 어디서 계산되는지, 500달러 한도가 어디서 확인되는지, 각 경로를 어떤 테스트가 다루는지 압니다.

이 모든 것이 한 세션에 있습니다. **세션**은 Claude Code와의 대화 하나이고, 그 안의 모든 메시지와 모든 도구 결과를 담습니다. Claude Code는 작업하는 동안 세션을 저장하므로 나중에 돌아올 수 있습니다. 월요일에 개발자는 작업을 이어 가려 합니다.

가장 중요한 원칙은 **옛 컨텍스트가 대부분 여전히 사실이면 이어 가고, 옛 도구 결과가 낡았으면 새로 시작한다**는 것입니다. 이번 노트에서는 이름 붙인 세션 이어 가기, 무엇이 바뀌었는지 알려 주기, 요약과 함께 새로 시작하기를 차례로 봅니다.

## 1. 이름으로 이어 가기

금요일에 개발자는 세션에 읽기 쉬운 이름을 붙였습니다. refund analysis입니다. 이름은 긴 세션 ID보다 훨씬 기억하기 쉽습니다. 월요일에 개발자는 resume 플래그와 그 이름으로 Claude Code를 시작합니다.

```bash
# Friday: give the session a name
/rename refund analysis
# Monday: resume it by name
claude --resume "refund analysis"
# Newer versions also accept the ID
claude --resume <session-id>
```

Claude Code는 정확히 그 대화를, 금요일의 조사 결과와 함께 엽니다. 그 사이에 개발자가 다른 일을 했더라도 상관없습니다. 이름이 특정한 조사 하나를 가리키기 때문입니다.

> 제품 참고: 현재 버전은 세션 ID로도 이어 갈 수 있습니다(강의 슬라이드 기준). 시험에서는 **세션 이름과 함께 쓰는 resume 플래그**가 정답입니다.

## 2. 무엇이 바뀌었는지 알려 주기

주말 동안 한 팀원이 풀 리퀘스트를 머지했습니다. 금요일에 Claude Code가 읽은 파일 두 개가 바뀌었습니다. 통화 헬퍼와 환불 테스트 하나입니다. 이어 간 세션은 이 사실을 모릅니다. 세션의 도구 결과에는 여전히 그 파일의 옛 버전이 있습니다. 그래서 Claude Code가 더는 존재하지 않는 코드를 두고 추론할 수 있습니다.

그래서 개발자의 첫 메시지는 변경을 짚어 줍니다.

> 금요일 이후 통화 헬퍼와 환불 금액 테스트가 바뀌었어. 계속하기 전에 그 두 파일을 다시 읽어 줘.

Claude Code는 그 두 파일만 다시 읽습니다. 금요일 분석의 나머지는 여전히 유효하므로 그대로 유지합니다.

| 하면 안 되는 것 | 이유 |
| --- | --- |
| 환불 흐름 전체를 다시 탐색하게 하기 | 하루치 유효한 작업을 버립니다. |
| 아무 말 없이 알아차리길 기대하기 | 옛 버전을 두고 추론할 수 있습니다. |

바뀐 파일을 짚어 주고, Claude Code가 그것만 확인하게 하세요.

## 3. 새로 시작하기

이번에는 다른 월요일을 상상해 봅시다. 주말 동안 팀이 환불 코드를 별도 서비스로 옮겼습니다. 금요일의 파일 대부분이 옮겨지거나 바뀌었습니다. 그래서 옛 도구 결과 대부분이 낡았습니다. **낡았다**(stale)는 것은 더는 없는 코드를 설명한다는 뜻입니다.

이어 간 세션은 그 결과를 모두 그대로 가집니다. Claude Code가 옛 그림과 새 그림을 섞을 수 있고, 거의 모든 것이 바뀌었을 때는 파일 두 개를 짚어 줘도 도움이 되지 않습니다.

그래서 개발자는 새 세션을 시작하고, 맨 앞에 **구조화된 요약**을 넣습니다.

```yaml
goal: explain how refund amounts are calculated
findings:
  - amounts are calculated in one place
  - the 500 dollar limit is checked after that
decisions:
  - keep the limit check as it is
open_questions:
  - do partial refunds use the same limit?
next_step: read the refund service and the tests
```

요약에는 목표, 여전히 사실인 조사 결과, 지금까지의 결정, 미해결 질문, 다음 단계가 들어 있습니다. 옛 파일 내용은 없습니다. Claude Code는 현재 코드를 새로운 눈으로 읽고, 요약이 방향을 잡아 줍니다. **짧고 정확한 요약이 옛 결과로 가득한 긴 기록보다 믿을 만합니다.**

## 정리

- 중요한 세션에는 이름을 붙이고, resume 플래그와 그 이름으로 이어 갑니다.
- 이전 컨텍스트가 대부분 유효하면 이어 갑니다. 그다음 바뀐 파일을 짚어 주어, Claude Code가 그것만 다시 읽게 합니다.
- 이전 도구 결과 대부분이 낡았으면 새 세션을 시작합니다. 목표, 조사 결과, 결정, 다음 단계를 담은 구조화된 요약을 줍니다.

옛 작업을 이어 가기 전에, 그 뒤로 코드가 얼마나 바뀌었는지 물어보세요. 조금만 바뀌었으면 이어 가고 바뀐 것을 짚어 주세요. 많이 바뀌었으면 요약과 함께 새로 시작하세요.

다음 노트에서는 분석을 마친 뒤, 같은 공유 분석에서 출발하는 두 접근법을 비교합니다.
