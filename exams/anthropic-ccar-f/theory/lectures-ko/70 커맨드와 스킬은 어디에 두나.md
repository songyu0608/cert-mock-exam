# 70. 커맨드와 스킬은 어디에 두나

지난 노트에서는 경로별 규칙으로 Claude Code가 테스트 파일에서만 테스트 규칙을 로드하게 만들었습니다.

이번 노트에서는 재사용 워크플로, 즉 커스텀 커맨드와 스킬을 어디에 둘지 살펴봅니다. 같은 파일이라도 팀 전체에 닿을 수도 있고 나에게만 닿을 수도 있기 때문입니다. 그것을 정하는 것은 폴더입니다.

## 요청할 때마다 결과가 다르다

마리아는 ShopAssist 팀의 개발자입니다. 마리아는 풀 리퀘스트를 올리기 전마다 Claude Code에 같은 긴 요청을 입력합니다. 내 변경 사항을 검토하고, 환불 로직, 에스컬레이션, 빠진 테스트에 집중하라는 요청입니다. 지적 사항마다 파일, 위험 수준, 수정안도 함께 달라고 합니다. 다른 개발자들도 이 요청을 저마다 조금씩 다르게 씁니다. 그래서 리뷰 결과도 다르게 나옵니다.

가장 중요한 원칙은 **워크플로를 누가 받을지는 폴더가 정한다**는 것입니다. 리포지토리 안의 폴더는 팀 전체에 닿고, 홈 디렉터리의 폴더는 나에게만 닿습니다.

| 위치 | 공유 방식 | 받는 사람 |
| --- | --- | --- |
| 리포지토리 `.claude/` | 버전 관리로 공유 | 리포지토리를 clone하는 모든 사람 |
| 홈 `~/.claude/` | 버전 관리에 들어가지 않음 | 나만 |

이번 노트에서는 커맨드, 스킬과 그 개인 변형, 스킬과 CLAUDE.md 사이의 선택을 차례로 봅니다.

## 1. 커맨드

**커스텀 슬래시 커맨드**는 이름을 붙여 저장한 프롬프트입니다. 슬래시와 이름을 입력하면 Claude Code가 그 프롬프트를 실행합니다. 커맨드는 일반 텍스트 파일이고, 파일 이름이 커맨드 이름이 됩니다.

마리아의 요청을 `review.md`라는 파일로 만들고, 리포지토리 `.claude` 폴더 안의 `commands` 폴더에 둡니다.

```text
.claude/commands/review.md
```

그리고 다른 변경처럼 이 파일을 커밋합니다. 이제 리포지토리를 clone하거나 pull하는 모든 사람이 `/review` 커맨드를 받습니다. 가장 최근에 합류한 레오도 첫날부터 받습니다.

**개인 커맨드**는 같은 종류의 폴더에 두지만, 위치가 홈 디렉터리입니다. 버전 관리가 보지 못하므로 팀원들은 받지 못합니다. 일일 노트를 써 주는 커맨드처럼 나만의 습관에 씁니다.

팀 커맨드를 프로젝트 CLAUDE.md나 설정 파일 안의 커맨드 목록으로 정의하면 안 됩니다. CLAUDE.md는 지침을 담는 곳이지 커맨드를 정의하는 곳이 아니고, 설정 파일에는 커맨드 목록 자체가 없습니다. **팀 커맨드는 리포지토리 commands 폴더에 있는 파일입니다.**

## 2. 스킬

**스킬**은 프롬프트 하나보다 구조가 더 있는 재사용 워크플로입니다. 스킬마다 `.claude` 안의 `skills` 폴더에 자기 폴더가 있고, 그 폴더에 `SKILL.md` 파일이 있습니다. 파일은 짧은 설명(description)으로 시작하고, 그 뒤에 지침이 옵니다.

```markdown
# SKILL.md in the skill's own folder
---
description: Review changes before a pull request
---
Review my changes. Focus on refund logic,
escalation and missing tests.
Refund checklist:
- refunds never exceed the amount paid
- each finding: file, risk level, fix
```

Claude Code는 스킬이 필요할 때만 로드합니다. 개발자가 이름으로 부를 수도 있고, 설명이 작업에 맞으면 Claude가 골라 쓸 수도 있습니다. 즉 스킬은 **필요할 때 실행**됩니다. 마리아의 리뷰도 환불 코드용 체크리스트를 더 길게 붙여 스킬로 만듭니다.

스킬도 같은 폴더 규칙을 따릅니다.

| 위치 | 받는 사람 |
| --- | --- |
| 리포지토리 `.claude` 폴더의 `skills` 폴더 | 팀 전체 |
| 홈 폴더 | 나만 |

> 제품 참고: 현재 Claude Code에서는 커맨드가 스킬로 통합되었고, `commands` 폴더도 계속 동작합니다. 시험에서는 팀 커맨드가 리포지토리 `commands` 폴더에 있다고 답합니다.

### 레오에게 보안 리뷰가 필요하다

이번에는 레오가 보안만 검토하는 리뷰를 원합니다.

- 팀 스킬을 고치면 안 됩니다. 모든 팀원이 레오의 변경을 받게 됩니다.
- 스킬을 같은 이름으로 홈 폴더에 복사해서도 안 됩니다. 그러면 레오에게는 그 사본이 팀 스킬을 조용히 대신합니다. 레오의 리뷰가 더 이상 팀 체크리스트를 따르지 않는다는 것을 아무도 알 수 없습니다.

대신 레오는 홈 skills 폴더에 `security-review`처럼 **다른 이름으로 개인 변형**을 만듭니다. 팀 스킬은 모두에게 그대로 남습니다.

| 스킬 | 위치 | 받는 사람 |
| --- | --- | --- |
| `review` (팀 스킬) | 리포지토리 | 모두, 같은 체크리스트 |
| `security-review` (개인 변형) | 홈 skills 폴더 | 레오만 |

## 3. 스킬인가, CLAUDE.md인가

| | CLAUDE.md | 스킬 |
| --- | --- | --- |
| 로드 시점 | 항상 | 필요할 때 |
| 담는 내용 | 모든 작업에 적용되는 표준: 테스트 프레임워크, 금액 저장 방식 | 한 종류의 작업을 위한 워크플로: 리뷰, 릴리스 노트 |

마리아의 체크리스트는 길고, 풀 리퀘스트 전에만 중요합니다. CLAUDE.md에 넣으면 모든 세션에서 컨텍스트를 차지하므로 스킬로 만듭니다.

특정 파일을 고칠 때마다 반드시 적용해야 하는 규칙도 있습니다. 이런 규칙은 스킬이 아니라 **경로별 규칙**에 둡니다. 스킬은 누군가 부르거나 Claude가 골랐을 때만 로드되기 때문입니다.

## 정리

- 팀 커맨드는 리포지토리 commands 폴더에 있는 파일이고, 버전 관리로 공유됩니다.
- 개인 커맨드는 홈 디렉터리의 commands 폴더에 둡니다.
- 커맨드 목록을 갖는 설정 파일은 없습니다.
- 스킬은 SKILL.md가 든 자기 폴더가 있고, 필요할 때 실행됩니다.
- 팀 스킬의 개인 변형은 홈 skills 폴더에 다른 이름으로 둡니다.
- CLAUDE.md는 모든 작업에 필요한 것을, 스킬은 한 작업에 필요한 것을 담습니다.

워크플로를 저장하기 전에 누가 받아야 하는지 정하세요. 그리고 정확히 그 사람들에게 닿는 폴더에 두세요. 다음 노트에서는 스킬의 frontmatter로 스킬이 실행되는 방식을 정하겠습니다.
