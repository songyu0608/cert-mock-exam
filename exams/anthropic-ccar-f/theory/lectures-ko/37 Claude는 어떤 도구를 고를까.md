# 37. Claude는 어떤 도구를 고를까?

알렉스는 이미 채팅에서 신원 확인을 마쳤습니다. 주문 번호를 알려 주며 “제 재킷은 어디쯤 왔나요?”라고 묻습니다. 주문을 조회하면 될 텐데, ShopAssist는 그 번호를 고객 검색 도구에 넣습니다. 다른 상담에서는 정반대의 일이 벌어집니다. 처음 온 고객이 이메일 주소만 알려 줬는데 이번에는 그 주소로 주문을 조회합니다. 두 호출 모두 실패합니다.

지난 노트에서는 Claude가 도구를 요청하면 우리 코드가 실행하고, 그 결과를 다시 보내는 루프를 만들었습니다. 이제 ShopAssist에는 고객 확인, 주문 조회, 환불 처리, 상담원 연결을 맡은 네 가지 도구가 있습니다. 루프는 잘 도는데 고객 확인과 주문 조회를 자꾸 혼동한다면, 어디부터 살펴보면 좋을까요?

## Claude가 도구를 고를 때 읽는 것

우리 코드에는 고객을 찾는 함수와 주문을 찾는 함수가 따로 있습니다. 하지만 도구를 제공한다고 해서 Claude에게 그 함수의 Python 코드까지 전달되지는 않습니다. Claude가 받는 것은 지금까지의 대화와 각 도구의 **이름, 입력 스키마, 설명**입니다. 이름은 짧고, 입력 스키마는 어떤 필드에 어떤 타입의 값을 넣을지 알려 줍니다. 이 도구를 **무엇에 쓰고 언제 선택해야 하는지** 가장 자세히 알려 줄 수 있는 곳은 설명입니다.

지금 `get_customer`에는 “고객 정보를 가져옵니다”, `lookup_order`에는 “주문 상세 정보를 가져옵니다”라고만 적혀 있습니다. 이메일 주소와 주문 번호는 둘 다 문자열입니다. 짧은 설명만으로는 어떤 문자열을 받는지, 고객 확인을 이미 마쳤을 때 어디로 가야 하는지 알기 어렵습니다. 이렇게 요청을 엉뚱한 도구에 보내는 일을 **도구 선택 오류**(misrouting)라고 합니다. 시험에는 설명이 거의 같은 `analyze_content`와 `analyze_document`가 비슷한 사례로 나옵니다.

## 두 도구의 설명에 서로의 경계를 적기

도구 설명을 고칠 때는 네 가지 질문에 답해 보세요. 무엇을 하고 어떤 결과를 돌려주나요? 어떤 입력을 받으며 실제 고객은 어떻게 묻나요? 결과가 없거나 여러 개면 어떻게 되나요? 어느 경우에 다른 도구를 써야 하나요? ShopAssist의 두 도구에 이 질문을 적용하면 다음과 같습니다.

| 설명에 담을 내용 | `get_customer` · 고객 확인 | `lookup_order` · 주문 조회 |
| --- | --- | --- |
| 목적과 결과 | 고객을 찾아 신원이 확인된 고객 ID를 돌려줍니다. | 주문 한 건의 상태, 상품, 금액, 배송일과 반품 가능 기간을 돌려줍니다. |
| 입력과 사용 예 | 이메일·전화번호·성명으로 찾습니다. 처음 온 고객이 이메일을 주며 환불을 문의할 때 씁니다. | 스토어 형식의 주문 번호(형식 `ORD-12345678`, 예: `ORD-10482917`)와 확인된 고객 ID가 필요합니다. 알렉스가 번호를 주며 재킷 배송 상태를 물을 때 씁니다. |
| 예외 상황 | 여러 명이 일치하면 후보를 모두 돌려줍니다. ShopAssist는 식별 정보를 하나 더 묻습니다. 일치하는 고객이 없으면 빈 결과를 돌려줍니다. | 주문 번호가 빠졌다면 고객에게 묻습니다. 주문이 다른 고객의 것이면 도구가 조회를 거부합니다. |
| 다른 도구를 쓸 때 | 주문 번호로는 고객을 찾을 수 없습니다. 고객을 확인했고 주문 번호도 있으면 `lookup_order`를 씁니다. | 이메일이나 이름으로 주문을 검색할 수 없습니다. 고객 확인이 필요하면 먼저 `get_customer`를 씁니다. |

이제 처음의 두 상담을 다시 보세요. 알렉스에게는 이미 확인된 고객 ID와 주문 번호가 있으므로 곧바로 주문을 조회할 수 있습니다. 이메일만 준 새 고객에게는 고객 확인부터 진행하고 주문 번호를 물으면 됩니다. 각 설명에 어떤 상황에서 다른 도구로 넘어가며 그때 어느 도구를 쓰는지 적어 둔 덕분입니다.

## 어떤 수정부터 시도할까요?

시스템 프롬프트에 고객 문의 예시를 길게 늘어놓으면 요청할 때마다 그만큼 토큰을 더 씁니다. 어느 도구가 어떤 입력을 받는지는 여전히 도구 설명에서 알아낼 수 없습니다. 요청을 도구에 배분하는 별도 프로그램을 만들거나 두 도구를 하나로 합치는 방법도 있지만, 지금 로그에서 확인한 문제에 비해 큰 변경입니다. 먼저 두 설명을 고치고 같은 문의에서 어떤 도구를 고르는지 확인합니다.

설명은 Claude가 도구를 고를 때 쓰는 지침입니다. **확인된 고객만 자기 주문을 조회할 수 있다**는 스토어 규칙은 도구를 실행하는 코드가 매번 검사합니다. 다음 노트에서는 설명을 고쳤는데도 잘못된 선택이 반복될 때 도구 이름과 시스템 프롬프트에서 무엇을 찾아야 하는지 살펴봅니다.
