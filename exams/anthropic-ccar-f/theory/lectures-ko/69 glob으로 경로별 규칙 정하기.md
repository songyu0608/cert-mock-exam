# 69. glob으로 경로별 규칙 정하기

지난 노트에서는 ShopAssist의 커다란 CLAUDE.md를 rules 폴더의 주제별 파일로 나눴습니다. 각 패키지는 이제 필요한 표준을 가져옵니다. 별도 설정이 없는 rules 파일은 모든 세션에서 로드됩니다.

이번 노트에서는 Claude Code가 규칙이 적용되는 파일로 작업할 때만 그 규칙을 로드하게 만드는 법을 살펴봅니다. 이유는 두 가지입니다. 로드된 규칙은 모두 컨텍스트와 토큰을 씁니다. 그리고 어디서나 로드되는 규칙은 아무 관련 없는 작업 옆에 놓이게 됩니다.

## 테스트 파일은 리포지토리 곳곳에 있다

테스트 규칙은 `testing.md` 파일 하나에 있습니다. 그런데 ShopAssist의 테스트 파일은 한 폴더에 모여 있지 않고, 테스트하는 코드 옆에 있습니다. 환불 서비스에도, MCP 서버에도 테스트가 있습니다. 채팅 창은 컴포넌트마다 옆에 테스트 파일을 둡니다. 테스트 파일이 리포지토리 전체에 흩어져 있는 것입니다. 지금은 테스트 규칙이 모든 세션에서 로드됩니다. 개발자가 릴리스 단계만 바꾸는 세션도 마찬가지입니다.

가장 중요한 원칙은 **rules 파일은 자기가 적용되는 파일을 밝힐 수 있고, Claude Code는 그 파일에 대해서만 규칙을 로드한다**는 것입니다. 이번 노트에서는 paths 필드, glob 패턴, 경로별 규칙과 폴더 CLAUDE.md 사이의 선택을 차례로 봅니다.

## 1. paths 필드

rules 파일은 **YAML frontmatter**라는 짧은 헤더로 시작할 수 있습니다. YAML은 설정을 적는 간단한 형식입니다. 헤더는 파일 맨 위, 대시 세 개로 된 두 줄 사이에 둡니다. 그 안에 `paths`라는 필드를 하나 추가하고, 파일 패턴 목록을 넣습니다.

```markdown
---
paths:
  - "**/*.test.ts"
  - "**/*.test.tsx"
---
# Testing rules
- Name each test after the behaviour it checks.
- Mock external calls, never the network.
```

이제 Claude Code는 이 파일을 모든 세션에서 로드하지 않습니다. 테스트를 고칠 때처럼, 패턴 중 하나와 일치하는 파일로 작업할 때 로드합니다. 릴리스 단계에 관한 세션에서는 테스트 규칙이 컨텍스트에 들어가지 않습니다. 그 세션의 토큰을 쓰지 않고, 작업과 섞이지도 않습니다.

| 세션 | 테스트 규칙 |
| --- | --- |
| 테스트 수정 | 일치하므로 로드 |
| 릴리스 단계 변경 | 일치하지 않으므로 제외 |

## 2. glob 패턴

**glob**은 파일 경로와 일치시키는 짧은 패턴입니다.

```text
*              any part of a file name
**             any folder, at any depth
**/*.test.tsx  any file ending in .test.tsx

chat/Cart.test.tsx        matches
chat/Header.test.tsx      matches
new-folder/Order.test.tsx matches too
```

- 별표 하나(`*`)는 파일 이름의 어느 부분과도 일치합니다.
- 별표 두 개(`**`)는 깊이와 상관없이 어느 폴더와도 일치합니다.
- 그래서 `**/*.test.tsx`는 리포지토리의 어느 폴더에 있든 이름이 `.test.tsx`로 끝나는 모든 파일을 뜻합니다.

이 패턴은 채팅 창의 모든 테스트 파일을, 어디에 있든 다룹니다. 위치가 아니라 **파일 유형**으로 파일을 찾기 때문입니다. 다음 주에 개발자가 새 폴더에 새 테스트를 추가해도 그 테스트가 일치하므로, 아무도 무언가를 고칠 필요가 없습니다.

패턴은 한 폴더와 그 아래 전부를 다룰 수도 있습니다. 팀은 서버 구성을 `terraform` 폴더에 적습니다. Terraform은 설정 파일로 서버를 구성하는 도구입니다. 배포 규칙은 `terraform/**/*` 패턴을 쓸 수 있고, 그러면 Claude Code가 그 폴더의 파일을 고칠 때만 로드됩니다.

```yaml
# testing rule
paths:
  - "**/*.test.tsx"

# deployment rule
paths:
  - "terraform/**/*"
```

한 패턴은 파일 유형을, 다른 패턴은 폴더 하나와 그 아래 전부를 다룹니다.

## 3. 경로별 규칙인가, 폴더 CLAUDE.md인가

팀에는 테스트 규칙을 둘 방법이 두 가지 더 있었습니다.

| 방법 | 문제 |
| --- | --- |
| 루트 CLAUDE.md의 테스트 섹션 | 모든 세션에서 로드되고, 지금 고치는 파일에 어느 섹션이 맞는지 Claude Code가 스스로 판단해야 합니다. |
| 테스트가 있는 폴더마다 CLAUDE.md | 디렉터리 파일은 한 폴더에 속하므로 같은 테스트 규칙의 사본이 여러 개 생기고, 시간이 지나며 서로 어긋납니다. 새 폴더마다 사본도 필요합니다. |

그래서 이렇게 고릅니다.

| 규칙의 범위 | 둘 곳 | 예 |
| --- | --- | --- |
| 디렉터리 하나 | 그 디렉터리의 CLAUDE.md | 환불 폴더 자체의 규칙 |
| 여러 폴더에 흩어진 한 파일 유형 | rules 폴더의 경로별 규칙 | 모든 테스트 파일 |

이 규칙들은 **컨텍스트이지 강제 수단이 아니라는 점**을 기억하세요. Claude Code를 안내할 뿐입니다. 반드시 통과해야 하는 테스트는 여전히 CI에서 실행됩니다.

## 정리

- rules 폴더의 규칙 파일은 `paths` 필드가 있는 YAML frontmatter로 시작할 수 있습니다.
- 이 필드에는 glob 패턴 목록이 들어갑니다.
- 규칙은 Claude Code가 일치하는 파일로 작업할 때만 로드되므로, 다른 세션은 그 규칙에 컨텍스트를 쓰지 않습니다.
- `**`는 어느 폴더와도 일치하므로, 패턴 하나로 어디에 있든 모든 테스트 파일을 다룰 수 있습니다.
- 한 폴더에 속하는 규칙은 디렉터리 CLAUDE.md에, 여러 폴더에 흩어진 파일의 규칙은 경로별 규칙에 둡니다.

규칙이 적용되는 곳을 밝히고, Claude Code가 거기서만 로드하게 하세요. 다음 노트에서는 팀의 커스텀 명령과 스킬을 어디에 둘지 정하겠습니다.
