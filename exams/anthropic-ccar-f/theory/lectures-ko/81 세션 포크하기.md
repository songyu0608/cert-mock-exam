# 81. 세션 포크하기

지난 노트에서는 이름 붙인 세션을 이어 가서 한 작업 줄기를 계속했습니다.

이번 노트에서는 세션 **포크**를 살펴봅니다. 포크는 대화 하나를 독립된 사본 두 개로 만들어, 같은 출발점에서 두 접근법을 시도하는 것입니다. 공정하게 비교하려면 두 접근법이 같은 사실에서 출발해야 하기 때문입니다.

## 분석은 하나, 설계 선택지는 둘

환불 분석이 끝났습니다. Claude Code는 환불 흐름을 읽고 금액이 계산되는 곳을 찾았습니다. 각 경로를 다루는 테스트도 정리했습니다. 거의 하루가 걸렸습니다.

이제 팀은 코드 구조를 바꾸는 방법 두 가지를 봅니다.

| 접근법 | 내용 |
| --- | --- |
| 제자리에 두기 | 환불 계산을 현재 모듈에 두고, 빠진 검사를 거기에 추가합니다. |
| 새 모듈 | 계산을 새 별도 모듈로 옮기고, 모든 환불 경로가 그 모듈을 호출합니다. |

팀은 고르기 전에 둘 다 보고 싶어 합니다.

가장 중요한 원칙은 **포크는 지금까지의 대화를 복사하고, 그다음 각 사본은 따로 이어진다**는 것입니다. 이번 노트에서는 왜 포크하는지, 어떻게 포크하는지, 똑같이 fork라고 불리는 서로 다른 두 기능을 차례로 봅니다.

## 1. 왜 포크하나

포크 대신 쓸 수 있는 방법은 두 가지인데, 둘 다 문제가 있습니다.

| 방법 | 문제 |
| --- | --- |
| 분석 세션에서 첫 접근법을 시도하고, 같은 세션에서 두 번째를 시도 | 두 번째 시도가 공정하지 않습니다. Claude Code가 첫 설계와 그 문제, 논거를 기억하고, 그 생각이 두 번째 설계로 새어 듭니다. |
| 새 세션 두 개 시작 | 세션마다 하루치 분석을 통째로 반복해야 합니다. |

포크는 두 문제를 모두 피합니다. 공유 분석이 **기준선**입니다. 각 분기는 그 기준선에서 출발하고, 어느 분기도 다른 분기를 보지 못합니다.

## 2. 어떻게 포크하나

**Claude Code에서는** 이름 붙인 세션 refund analysis를 이어 가면서 fork session 플래그를 더합니다. Claude Code는 새 세션 ID로 새 세션을 열고, 그 세션은 기록 전체를 가집니다. 원래 세션은 그대로 남습니다. 진행 중인 세션 안에서는 `/branch` 커맨드가 같은 일을 합니다.

아래 명령은 스크립트 설명에 맞춘 예시입니다(강의 슬라이드에는 SDK 코드만 있습니다).

```bash
claude --resume "refund analysis" --fork-session
```

접근법마다 한 번씩, 두 번 포크합니다. 첫 분기에서는 작은 변경을, 두 번째 분기에서는 별도 모듈을 요청합니다.

**Agent SDK에서는** 세션 ID로 세션을 이어 가면서 fork session을 true로 설정합니다. 시험은 이 이름을 씁니다.

```python
# Agent SDK (Python): resume by ID and fork
options = ClaudeAgentOptions(
    resume=session_id,
    fork_session=True,
)
```

### 세부 사항 하나: 포크는 파일을 복사하지 않는다

포크는 대화를 복사하지, 디스크의 파일을 복사하지 않습니다. 두 분기는 같은 폴더에서 일합니다. 그래서 먼저 각 분기에 수정이 아니라 **계획**을 요청합니다.

1. 각 분기가 바꿀 파일, 위험, 실행할 테스트를 돌려줍니다.
2. 두 답을 나란히 비교합니다.
3. 접근법 하나를 골라, 그것만 구현합니다.

## 3. 두 가지 포크

스킬도 frontmatter에서 `context`를 `fork`로 설정할 수 있습니다. 같은 이름이지만 반대되는 기능입니다.

| 기능 | 대화 기록 | 용도 |
| --- | --- | --- |
| 스킬의 `context: fork` | 기록 없는 서브에이전트에서 실행 | 노이즈가 많은 작업을 메인 대화 밖에 둠 |
| 세션 포크 | 기록 전체를 유지 | 이미 해 둔 작업에서 출발 |

하나는 깨끗하게 시작하고, 다른 하나는 앞선 내용을 알고 시작합니다.

## 정리

- resume은 한 세션을 계속합니다. 포크는 세션 기록을 새 독립 분기로 복사합니다.
- 접근법마다 한 번씩 포크합니다. 그러면 모든 분기가 같은 분석에서 출발하고, 서로를 보지 못합니다.
- Claude Code에서는 resume 플래그에 fork session 플래그를 더하거나, `/branch` 커맨드를 씁니다.
- SDK에서는 세션 ID로 이어 가면서 fork session을 설정합니다.
- 스킬의 context fork는 기록 없이 시작하고, 세션 포크는 기록을 유지합니다.

좋은 선택지가 두 개라면, 분석을 포크하고 계획을 비교한 뒤, 고른 것 하나만 구현하세요. 다음 노트에서는 긴 탐색이 모호한 답을 내기 시작할 때 또렷하게 유지하는 법을 봅니다.
