# 22. 실습: 첫 도구 호출을 처음부터 끝까지 따라가기

> 이 주문으로 산 재킷을 아직 반품할 수 있나요?

지금까지의 ShopAssist라면 “반품 기한은 배송 후 30일입니다”라고 답할 수 있습니다. 하지만 고객이 알고 싶은 건 **자기 재킷의 반품 기한이 남았는지**입니다. 주문 번호를 함께 알려 줘도 ShopAssist가 배송일을 조회할 수 있어야 답이 나옵니다. 이번 노트에서는 주문을 조회하는 도구를 하나 만들고, 고객 질문 한 건이 최종 답변이 되기까지 따라가 보겠습니다.

## 우리 코드가 실행할 함수와 Claude가 읽을 설명 준비하기

빈 파일 `tool_call.py`를 엽니다. 이전 대화 실습처럼 `.env`에서 API 키를 읽고 클라이언트와 모델 이름을 준비합니다. 시스템 프롬프트에는 ShopAssist의 역할, 30일 반품 규칙, 짧게 답하라는 지침을 둡니다. 이번에는 `json`도 가져옵니다. 나중에 주문 조회 결과를 Claude에 보낼 때 씁니다.

먼저 **우리 코드에서 실행할 함수**를 만듭니다. 실제 스토어라면 데이터베이스를 조회하겠지만, 이번에는 `ORDERS`라는 Python 딕셔너리에 주문 한 건을 넣어 둡니다. 키는 주문 ID입니다. 그 ID로 찾을 수 있는 상품은 재킷이고, 배송이 완료됐으며, 배송 후 20일이 지났습니다. `lookup_order(order_id)`는 `ORDERS.get(...)`으로 주문을 찾습니다. 일치하는 주문이 없으면 주문을 찾을 수 없다는 오류를 담은 딕셔너리를 돌려줍니다.

Claude를 호출하기 전에 함수부터 확인해 보세요. 등록된 ID로 한 번, 없는 ID로 한 번 호출해 결과를 출력합니다. 첫 줄에 재킷의 배송 정보가, 둘째 줄에 조회 오류가 나오면 함수가 의도대로 동작한 겁니다. 확인용 출력 두 줄은 이제 지워도 됩니다.

다음은 **Claude가 읽을 도구 설명**입니다. Claude는 우리 Python 함수를 보지 못합니다. Claude에 보내는 것은 `TOOLS` 목록에 담은 도구 정의입니다. `name`에는 Claude가 호출을 요청할 때 쓸 이름인 `lookup_order`를 적습니다. `description`에는 주문 ID로 조회하면 상품, 배송 상태, 배송 후 며칠이 지났는지를 알 수 있다고 씁니다. Claude는 이 설명을 읽고 도구를 언제 쓸지 정하므로 신경 써서 씁니다. 마지막으로 `input_schema`에서 입력을 객체로 정하고, 그 안에 문자열 `order_id`가 꼭 있어야 한다고 지정합니다. 필드 설명에 ID의 예도 하나 넣어 두면 Claude가 입력 모양을 이해하기 쉽습니다.

## 첫 번째 API 요청에서 돌아오는 것은 무엇일까요?

`messages` 목록에 고객 질문을 `user` 메시지로 넣습니다. 질문 끝에는 조회할 주문 ID도 적습니다. `client.messages.create(...)`에 모델, `max_tokens=300`, 낮은 `effort`, 시스템 프롬프트와 대화 기록을 넘깁니다. 이번에 더하는 인자는 `tools=TOOLS`입니다. 이 목록을 받아야 Claude가 주문 조회를 요청할 수 있습니다.

응답의 `stop_reason`을 출력해 보세요. 원문의 실행 결과는 `tool_use`입니다. 이 시점에 주문을 조회한 횟수는 **0회**입니다. Claude가 “이 ID로 주문을 찾아 주세요”라고 요청하고 우리 코드에 차례를 넘겼기 때문입니다.

`response.content`의 블록을 하나씩 읽고 `block.type`이 `tool_use`인 블록을 찾습니다. 도구 이름과 입력을 출력하면 Claude가 고른 `lookup_order`와 주문 ID가 보입니다. 이 실습에서 제공한 도구는 하나이므로 해당 블록에서 `result = lookup_order(**block.input)`을 실행합니다. Python의 `**`는 딕셔너리의 키와 값을 이름 붙은 인자로 풀어 줍니다. 그래서 `order_id`가 함수의 같은 이름 매개변수로 들어갑니다. 이제 `result`를 출력하면 배송 후 20일이 지난 재킷이 나옵니다. 이 결과는 아직 우리 프로그램 안에만 있습니다.

## 두 번째 요청에서 조회 결과 돌려주기

같은 `messages`에 메시지 두 개를 차례로 추가합니다.

1. **Claude가 보낸 요청을 보관합니다.** 역할은 `assistant`, 내용은 첫 응답의 `response.content` 전체입니다. 도구 이름과 입력만 골라서 새 메시지를 만들면 원래 호출 ID를 잃을 수 있으므로 받은 내용을 그대로 넣습니다.
2. **그 요청에 대한 결과를 붙입니다.** 역할은 `user`이고, 내용은 `tool_result` 블록 하나를 담은 목록입니다. 여기서 `user`는 애플리케이션 쪽에서 보낸 메시지라는 뜻입니다. 새로 고객에게 입력을 받는 단계는 없습니다. 블록의 `tool_use_id`에는 방금 받은 `block.id`를, `content`에는 `json.dumps(result)`로 문자열로 바꾼 조회 결과를 넣습니다. API는 이 ID로 바로 앞 메시지의 어느 도구 호출에 답했는지 확인합니다.

같은 모델과 도구 정의로 `client.messages.create(...)`를 다시 호출합니다. 이번 대화 기록에는 **고객 질문, Claude의 도구 호출 요청, 우리 코드의 조회 결과**가 순서대로 들어 있습니다. 두 번째 응답의 종료 사유는 `end_turn`입니다. 텍스트 블록을 읽으면 이번에는 고객의 주문에 맞는 답이 나옵니다. 배송 후 20일이 지났으니 30일 기한까지 약 열흘이 남았습니다.
