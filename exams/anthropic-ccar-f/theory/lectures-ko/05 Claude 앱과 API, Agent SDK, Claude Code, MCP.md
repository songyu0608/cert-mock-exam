# 5. Claude 앱과 API, Agent SDK, Claude Code, MCP

Claude가 한 번의 요청에서 볼 수 있는 것은 그 요청에 담긴 내용입니다. 이 개념이 낯설다면 강의 후반의 선택 강의인 103강 ‘요청을 받으면 Claude에는 무엇이 보일까?’를 참고하세요. 이번에는 그 요청이 어떤 경로로 Claude에 도달하는지 살펴보겠습니다.

시험의 시나리오에도 앞으로의 강의에도 다섯 가지 이름이 계속 나옵니다. 이름을 구분하려면 **누가 어떤 일을 하려고 쓰는가?**를 생각해 보세요.

| 이름 | 누가, 무슨 일에 쓰나요? |
| --- | --- |
| Claude 앱 | 사람이 채팅창에서 글쓰기, 분석, 조사 같은 자기 일을 합니다. |
| Claude API | 애플리케이션이 코드로 Claude에 요청을 보내고 응답을 받습니다. |
| Claude Agent SDK | 개발자가 제품 안에 여러 단계로 일하는 에이전트를 넣습니다. |
| Claude Code | 개발팀이 코드베이스에서 코드를 작성하고 검토합니다. CI에서도 실행합니다. |
| MCP | 도구와 데이터 소스를 제공하는 시스템과 이를 사용하는 프로그램이 공통 규약으로 통신합니다. |

## 사람이 채팅하는 앱, 프로그램이 호출하는 API

Claude 앱은 브라우저, 데스크톱, 휴대전화에서 직접 쓰는 제품입니다. 메시지를 입력하면 Claude가 그 채팅창에서 답합니다. 앱의 프로젝트(Projects)에는 한 주제에 필요한 지침과 파일을 모아 둘 수 있습니다. 파일을 올리거나 공유 드라이브, 이메일처럼 사용 중인 다른 서비스를 앱에 연결할 수도 있습니다.

글을 쓰거나 자료를 분석하고 조사하는 사람에게 어울리는 환경입니다. 하지만 고객 알렉스가 반품하려고 여는 것은 스토어 웹사이트입니다. 우리가 작성한 ShopAssist의 서비스 코드가 Claude 앱 안에서 돌아가는 것은 아닙니다.

스토어의 채팅창 뒤에서는 **우리 애플리케이션이 Claude API를 호출**합니다. 요청에 지침과 대화 내용을 넣고, 필요하면 사용할 수 있는 도구의 정의도 넣습니다. 응답으로는 텍스트나 구조화된 데이터, 또는 도구를 사용하겠다는 요청이 돌아옵니다.

ShopAssist에서 호출을 보낼 때마다 대화 기록과 고객 계정을 관리하고, 필요한 검사를 실행하고, 스토어 규칙을 적용하는 쪽은 우리 애플리케이션입니다. API는 그 코드가 Claude와 대화하는 접점입니다.

## 제품에 에이전트를 넣는 Agent SDK

SDK는 개발자가 자신의 프로그램에 추가해서 쓰는 코드 라이브러리입니다. 왜 필요할까요? 고객 문의 하나를 해결하려면 Claude가 도구를 요청하고, 우리 코드가 실행 결과를 돌려주고, Claude가 그 결과를 읽어 다음 행동을 정해야 할 때가 많습니다. 일이 끝날 때까지 이 과정을 반복하는 것이 **에이전트 루프**입니다. API를 직접 쓰면 이 루프도 직접 작성합니다.

Claude Agent SDK는 그 루프를 대신 실행합니다. 파일을 읽거나 명령을 실행하는 내장 도구를 제공하고, 에이전트가 보조 작업을 맡을 서브에이전트를 시작할 수도 있습니다. 도구 호출 전후에 우리 코드가 개입하도록 하는 **훅(hook)**도 있습니다. 훅에서 호출을 검사하거나 변경할 수 있습니다. 이 밖에도 나중에 대화를 이어 갈 수 있도록 세션을 관리하고 MCP 서버와 연결해 줍니다. ShopAssist도 뒤에 가면 Agent SDK로 전환합니다.

## 개발팀이 사용하는 Claude Code

Claude Code는 코드베이스 안에서 파일을 읽고 코드를 편집하며, 테스트와 명령을 실행해 코딩 작업을 단계적으로 수행합니다. 개발자는 터미널이나 코드 편집기(IDE)에서 이 도구를 사용합니다.

코드가 바뀔 때마다 자동 검사를 실행하는 지속적 통합(CI) 환경에서도 사용할 수 있습니다. 여기에는 키보드 앞에서 다음 지시를 입력할 사람이 없습니다. 그래서 비대화형으로 실행합니다. 작업을 하나 받아 수행하고, 결과를 출력한 뒤 종료합니다.

Claude Code도 Agent SDK와 비슷한 에이전트 루프로 작동합니다. 쓰임새를 구분해 보세요. 스토어가 **고객에게 제공하는 에이전트**에는 Agent SDK를 쓰고, **그 에이전트의 코드를 작성하고 리뷰하는 개발팀**은 Claude Code를 씁니다.

## 도구와 데이터를 연결하는 MCP

MCP는 Model Context Protocol의 약자입니다. 프로토콜이란 두 프로그램이 통신할 때 따르는 공통 규약입니다. MCP를 사용하면 시스템이 도구와 데이터 소스를 표준 방식으로 Claude에 연결할 수 있습니다.

스토어가 MCP 서버를 통해 도구를 한 번 제공하면 MCP를 지원하는 여러 프로그램에서 그 도구를 쓸 수 있습니다. Claude 앱이나 Claude Code, Agent SDK로 만든 에이전트가 그런 프로그램입니다. MCP가 맡는 역할은 Claude와 외부 시스템을 연결하는 일입니다. 서버가 구체적으로 무엇을 제공하는지는 뒤에서 살펴보겠습니다.

## ShopAssist에 대입해 보기

알렉스가 스토어 웹사이트에 질문을 입력합니다. 백엔드가 API를 통해 Claude에 요청을 보냅니다. 여러 단계가 필요한 문의에서는 Agent SDK가 루프를 실행합니다. 고객을 확인하는 `get_customer`나 주문을 조회하는 `lookup_order` 같은 도구는 스토어의 MCP 서버가 제공합니다. 이 시스템을 만드는 개발자들은 각자의 개발 환경과 CI에서 Claude Code를 사용합니다.

시험의 여섯 시나리오에도 같은 구분이 적용됩니다. 고객 지원 에이전트는 Agent SDK로 만들고 도구는 MCP로 제공합니다. 멀티 에이전트 리서치 시스템도 Agent SDK로 만듭니다. 개발자 생산성 도구는 Agent SDK에 내장 도구와 MCP 서버를 연결합니다. 반면 코드 생성 시나리오에서는 팀이 Claude Code를 직접 쓰고, CI 시나리오에서는 파이프라인이 Claude Code를 실행합니다. 문서에서 데이터를 추출하는 시나리오에서는 애플리케이션이 API를 호출합니다.

문제에서 제품 이름이 나오면 먼저 누가 그 일을 하는지 짚어 보세요. 다음 강의에서는 답변을 작성하던 프로그램이 실제로 주문을 조회하고 환불 업무까지 수행하려면 무엇이 더 필요한지 살펴보겠습니다.
