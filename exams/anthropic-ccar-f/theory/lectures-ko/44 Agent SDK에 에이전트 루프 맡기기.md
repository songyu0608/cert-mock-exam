# 44. Agent SDK에 에이전트 루프 맡기기

지난 노트에서는 Claude Code가 스토어의 MCP 서버에 주문을 조회하고 그 결과로 고객에게 답하는 과정을 살펴봤습니다. 이제 우리가 만드는 고객 지원 에이전트에도 같은 서버를 연결해 보겠습니다. 그때마다 도구를 실행하고 결과를 돌려주는 루프를 처음부터 작성해야 할까요?

시험에 나오는 고객 지원 에이전트, 리서치 시스템, 개발자 도구는 모두 Claude Agent SDK를 사용합니다. 이 SDK에 ShopAssist의 루프를 맡겨 보면 개발자가 여전히 결정해야 할 두 가지가 보입니다. 고객 지원에 어떤 도구가 필요한지, 그 도구가 실행될 때 어떤 규칙을 적용할지입니다.

## 재킷 주문 한 건을 끝까지 따라가기

고객이 “재킷이 언제 배송됐나요?”라고 묻습니다. 직접 작성한 루프에서는 대화를 Claude에 보내고 응답의 종료 사유를 읽었습니다. 도구 호출 요청이면 함수를 실행하고, 결과를 대화에 추가해 다시 보냈습니다. 이제 고객의 메시지와 실행 옵션을 SDK의 `query`에 전달해 보세요.

1. Claude가 주문 내역이 필요하다고 판단해 `lookup_order`를 요청합니다. 직접 작성한 루프에서 보았던 `tool_use`에 해당합니다.
2. SDK가 설정에 따라 호출을 처리하고 서버가 돌려준 주문 내역을 같은 대화에 추가합니다. Claude는 다음 라운드에서 고객의 질문과 도구 결과를 함께 볼 수 있습니다.
3. Claude가 “재킷은 20일 전에 배송됐습니다”라고 답하고 턴을 마칩니다. 직접 작성한 루프의 `end_turn`에 해당합니다. 애플리케이션은 SDK가 전달하는 메시지에서 중간 단계와 최종 결과를 읽어 상담 기록을 남길 수 있습니다.

여기서 주문 조회를 고른 쪽은 여전히 Claude입니다. 한 라운드의 결과를 다음 라운드에 전달하는 일을 SDK가 맡았기 때문에, 개발자는 요청을 보낼 때마다 같은 코드를 작성할 필요가 없습니다.

## 고객 지원에 필요한 도구 고르기

개발자를 돕는 에이전트라면 파일을 읽고 쓰거나, 코드에서 텍스트를 찾거나, 셸 명령을 실행할 수 있어야 합니다. 램프 환불을 상담하는 ShopAssist에는 그런 기능을 쓸 일이 없습니다. 사용할 내장 도구 집합을 비워 두고 스토어의 MCP 서버를 연결합니다. 서버가 제공할 도구는 고객 확인(`get_customer`), 주문 조회(`lookup_order`), 환불 처리(`process_refund`), 상담원 연결(`escalate_to_human`)입니다. 이렇게 하면 Claude가 고객 문의에 필요한 도구 중에서 고를 수 있습니다. 도구가 하나 늘 때마다 Claude의 선택도 어려워지므로, 에이전트에는 그 일에 필요한 도구만 주고 그 이상은 주지 않습니다.

이때 **도구를 제공하는 설정**과 **호출을 미리 승인하는 설정**을 구분해 보세요. SDK의 `tools`는 내장 도구의 범위를 정합니다. `allowedTools`(Python에서는 `allowed_tools`)는 별도 확인 없이 호출하도록 승인할 도구를 정합니다. 이 목록에 네 가지 이름만 적어도 다른 모든 도구가 자동으로 사라지는 것은 아닙니다. 연결할 서버와 제공할 도구를 먼저 정하고, 그중 어떤 호출을 미리 승인할지 설정합니다. [Agent SDK 권한 문서](https://code.claude.com/docs/en/agent-sdk/permissions)

## 환불이 실행되기 전에 규칙 적용하기

고객이 600달러짜리 주문의 환불을 요청합니다. 시스템 프롬프트에 “500달러를 초과하면 상담원에게 넘기세요”라고 쓰면 Claude가 다음 행동을 고를 때 참고할 수 있습니다. 그런데 Claude가 그대로 `process_refund`를 요청했다면 어디에서 멈출 수 있을까요?

**훅(hook)**은 루프가 정해진 지점에 도달했을 때 SDK가 호출하는 함수입니다. 환불에는 실행 전과 실행 후의 차이가 중요합니다.

| 훅 | 실행 시점 | ShopAssist에서 할 수 있는 일 |
| --- | --- | --- |
| `PreToolUse` | 도구 호출을 요청한 뒤, 실행하기 전 | 입력을 검사하거나 바꾸고 호출을 허용하거나 차단합니다. 600달러 환불은 이때 차단해 상담원에게 넘기도록 합니다. |
| `PostToolUse` | 도구가 성공적으로 실행된 뒤, Claude가 결과를 보기 전 | MCP 도구가 돌려준 결과에서 고객에게 필요 없는 내부 정보를 덜어 냅니다. |

600달러가 이미 고객 계좌로 돌아간 뒤에는 결과 메시지를 고쳐도 환불을 막을 수 없습니다. 그래서 금액 검사는 환불 **전**에 둡니다. Claude가 어떤 표현으로 답하든, 환불 호출이 들어올 때마다 같은 코드가 한도를 확인합니다. 프롬프트는 텍스트라서 Claude가 대부분 따르지만 매번 따르지는 않습니다. 프롬프트는 Claude를 안내하고, 훅은 규칙을 강제합니다. [Agent SDK 훅 문서](https://code.claude.com/docs/en/agent-sdk/hooks)

## 일을 나누거나 나중에 이어 가기

SDK에는 **서브에이전트**와 **세션**도 있습니다. 서브에이전트에는 어떤 일을 맡길 수 있는지 설명을 붙이고 그 일을 수행할 프롬프트를 줍니다. 더 큰 작업 중 일부를 맡길 때 메인 에이전트가 이 서브에이전트를 부릅니다. 세션은 대화를 보관하므로 나중에 같은 작업을 이어 가거나, 한 지점에서 별도 사본으로 갈라져 다른 방향을 시도할 수 있습니다.

ShopAssist에 새 규칙을 넣을 때는 이렇게 물어보세요. **Claude가 다음 행동을 고를 때 알아야 할 내용인가요? 도구를 실행하기 전에 매번 확인해야 할 조건인가요?** SDK가 루프를 맡아도 이 판단은 스토어에 남습니다. 다음 노트에서는 고객의 신원을 확인하기 전에는 주문에 접근할 수 없도록 이 원칙을 적용해 보겠습니다.
