# 89. 다중 패스 리뷰

지난 노트에서는 새 컨텍스트의 두 번째 Claude 인스턴스가 Claude Code가 쓴 코드를 리뷰했습니다. 이번 노트에서는 그 변경이 클 때 무슨 일이 일어나는지 살펴봅니다. 리뷰가 완전해 보여도 얕을 수 있고, 그러면 놓친 버그가 고객에게 닿기 때문입니다.

## 파일 24개를 한 번에 보면 잘못된다

부분 환불 기능이 커졌습니다. 풀 리퀘스트는 이제 파일 24개를 바꿉니다. 환불 서비스, 환불 훅, 지원팀으로의 핸드오프, 그리고 이 모든 것의 테스트입니다.

독립적인 리뷰어가 파일 24개를 한 번의 패스로 읽습니다.

- 앞쪽 파일 몇 개에 대한 코멘트는 자세하지만, 나머지는 한 줄씩입니다.
- 한 파일에서는 반올림 패턴을 문제로 지적하고, 다른 파일에서는 같은 코드를 승인합니다.
- 실제 버그도 하나 놓칩니다. 이 버그는 곧 다시 봅니다.

가장 중요한 원칙은 **많은 파일을 한 번에 보면 모델의 주의가 너무 얇게 퍼지므로, 리뷰를 단계로 나눈다**는 것입니다.

| 패스 | 보는 것 |
| --- | --- |
| 파일별 패스 | 각 파일의 국소적 문제 |
| 통합 패스 | 파일 사이를 오가는 데이터 |
| 검증 패스 | 의심스러운 지적 사항을 라우팅 |

원인에는 이름이 있습니다. **주의력 희석**(attention dilution)입니다. 파일마다 주의의 작은 몫만 받으므로, 지적 사항이 얕아지고 때로는 서로 어긋납니다. 이것을 더 큰 모델이나 더 큰 컨텍스트 창으로 고치면 안 됩니다. 파일은 이미 다 들어갑니다. 문제는 공간이 아니라 주의입니다.

## 1. 파일별 패스

CI 코드가 바뀐 파일을 하나씩 따로 리뷰어에게 보냅니다. 요청마다 그 파일의 diff와 팀의 리뷰 기준이 들어갑니다. 각 패스는 **국소적 문제**, 즉 그 파일 하나 안에서 보이는 문제만 찾습니다. 빈 날짜에 대한 확인이 빠진 것이 한 예입니다. 각 패스는 파일과 줄이 담긴 짧고 구조화된 지적 사항을 돌려줍니다.

이제 모든 파일이 같은 깊이로 검토됩니다. 모든 패스가 같은 기준을 쓰므로, 같은 패턴은 같은 판정을 받습니다.

## 2. 통합 패스

어떤 버그는 파일 사이에 있어서, 파일별 패스로는 볼 수 없습니다.

한 번의 패스가 놓친 버그가 바로 이것입니다. 환불 서비스는 이제 금액을 센트로 반환합니다. 핸드오프 코드는 여전히 그 값을 달러로 읽습니다. 각 파일은 그 자체로는 맞습니다. 하지만 합쳐지면 620달러를 6만 2,000달러로 환불하라고 사람에게 알립니다.

```text
환불 서비스 ── amount: 62000 (cents) ──> 핸드오프 코드 ── 환불 $62,000 ──> 지원 담당자
```

그래서 통합 패스는 파일별 지적 사항과, 각 파일이 다른 파일에 무엇을 넘기는지 정리한 짧은 지도를 받습니다. 그리고 질문 하나를 합니다. **데이터가 한 파일에서 다음 파일로 옮겨 갈 때 의미를 유지하는가?** 그 질문이 센트 버그를 찾습니다.

형태에 주목하세요. 코드가 단계를 정해진 순서로 실행합니다. 모든 파일을 먼저, 그다음 통합 패스입니다. 앞에서 본 정해진 파이프라인인 **프롬프트 체이닝**을 리뷰에 쓴 것입니다.

전체 리뷰를 세 번 실행하고, 두 번 이상 나온 지적 사항만 남기면 안 됩니다. 한 번의 실행만 잡은 실제 버그가 사라집니다.

## 3. 검증 패스

큰 리뷰는 지적 사항을 많이 내고, 그중 일부는 의심스럽습니다. 그래서 마지막 패스가 각 지적 사항을 코드와 대조하고 **신뢰도 점수**를 붙입니다.

점수가 지적 사항이 갈 곳을 정합니다.

| 신뢰도 | 처리 |
| --- | --- |
| 높음 | 일반 코멘트로 게시 |
| 낮음 | 사람이 먼저 자세히 봄. 버리는 것은 없음 |

점수는 모델 스스로의 주장일 뿐이라는 점을 기억하세요. 그래서 임계값은 증거로 정합니다. 과거 점수를 개발자가 확인하거나 기각한 지적 사항과 비교합니다. **신뢰도는 지적 사항을 라우팅할 뿐, 무엇이 사실인지 정하지 않습니다.**

## 정리

- 많은 파일을 한 번에 보면 주의력 희석 때문에 얕고 서로 어긋나는 지적 사항이 나옵니다.
- 파일별 패스는 모든 곳에서 같은 깊이로 국소적 문제를 잡습니다.
- 통합 패스는 파일 사이를 오가는 데이터를 확인합니다.
- 이 단계들을 정해진 순서로 실행하는 것이 프롬프트 체이닝입니다.
- 검증 패스는 각 지적 사항에 신뢰도를 붙이고, 의심스러운 것은 버리지 않고 사람에게 보냅니다.

한 번에 꼼꼼히 읽기에 너무 큰 변경이면 나누세요. 파일마다 한 패스, 그다음 파일 전체를 가로지르는 한 패스입니다. 다음 노트에서는 이 리뷰를 키보드 앞에 아무도 없는 CI에서 실행합니다.
