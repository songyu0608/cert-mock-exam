# 67. CLAUDE.md 레벨: 누가 어떤 지침을 받을까

지난 섹션에서 스토어의 리서치 어시스턴트는 주장을 출처에 묶어 두는 법을 익혔습니다. 이제 ShopAssist를 만드는 팀과, 그 팀이 매일 쓰는 도구로 넘어갑니다.

이번 노트에서는 **CLAUDE.md** 파일과, 팀의 각 사람이 실제로 그 안의 어떤 지침을 받는지 살펴봅니다. 같은 코드에서 같은 도구를 써도 두 개발자가 서로 다른 결과를 얻을 수 있기 때문입니다.

## 새로 온 개발자의 테스트만 이상하다

지난 몇 달 동안 ShopAssist 리포지토리가 커졌습니다. 에이전트, 도구, 훅, 많은 테스트가 들어 있습니다. 팀은 이 리포지토리에서 Claude Code로 일합니다. Claude Code는 파일을 읽고, 코드를 고치고, 명령을 실행하는 코딩 도구입니다. 네이티브 설치 프로그램으로 설치합니다.

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

이번 주에 레오라는 개발자가 팀에 합류합니다. 레오는 첫날 Claude Code에 환불 한도 테스트를 추가해 달라고 합니다. 돌아온 테스트는 스타일이 다릅니다. 다른 테스트 프레임워크를 쓰고, 우리가 쓰는 가짜 결제 서비스(결제하는 척만 하는 대체 서비스)가 아니라 실제 결제 서비스를 호출합니다. 다른 팀원들의 Claude Code는 절대 이렇게 하지 않습니다.

가장 중요한 원칙은 **CLAUDE.md 파일은 그 파일을 로드하는 Claude Code를 쓰는 사람에게만 닿는다**는 것입니다. 이번 노트에서는 세 가지 레벨, 레오에게 팀 규칙이 빠진 이유, 세션이 무엇을 로드했는지 확인하는 법을 차례로 봅니다.

## 1. 세 가지 레벨

CLAUDE.md는 지침을 적은 일반 텍스트 파일입니다. Claude Code는 세션이 시작될 때 이 파일을 읽으므로, 같은 규칙을 프롬프트마다 반복할 필요가 없습니다. 시험에서는 이 파일들을 **메모리 파일**이라고 부릅니다. 메모리 파일은 세 레벨에 둘 수 있습니다.

| 레벨 | 위치 | 적용 범위 | 담을 내용 |
| --- | --- | --- | --- |
| 사용자 | 홈 폴더의 숨김 폴더 `.claude` 안: `~/.claude/CLAUDE.md` | 내가 여는 모든 프로젝트, 나에게만 | 짧은 설명을 원한다 같은 개인 취향 |
| 프로젝트 | 리포지토리 루트의 `CLAUDE.md`, 또는 리포지토리의 `.claude` 폴더 안 | 리포지토리를 clone하거나 pull하는 모든 사람 | 테스트 프레임워크, 가짜 결제 서비스, “환불 금액은 항상 주문에서 가져온다” 같은 팀 규칙 |
| 디렉터리 | 리포지토리 안 더 깊은 폴더의 `CLAUDE.md`, 예: `refund/CLAUDE.md` | 그 폴더의 파일로 작업할 때 | 그 코드에만 중요한 규칙 |

- **사용자 레벨** 파일은 리포지토리에 속하지 않으므로, 버전 관리로 팀원에게 공유되지 않습니다.
- **프로젝트 레벨** 파일은 다른 파일처럼 커밋합니다.
- **디렉터리 레벨** 파일은 Claude Code가 그 폴더의 파일로 작업할 때 로드됩니다.

Claude Code는 적용되는 파일을 모두 합칩니다. 더 구체적인 파일이 일반적인 파일에 내용을 더합니다.

## 2. 레오의 문제

추측하지 말고, 레오가 `/memory` 명령을 실행합니다. 이 명령은 이번 세션에 로드된 메모리 파일을 나열하고, 각 파일을 열어 편집할 수 있게 해 줍니다.

```text
> /memory
Memory files loaded in this session:
  Project    ./CLAUDE.md
# Select a file to open it for editing
# The test rules are not in this file
```

레오에게는 프로젝트 파일이 보이지만, 팀의 테스트 규칙은 그 안에 없습니다. 이번에는 팀원 한 명이 오래된 노트북에서 같은 명령을 실행합니다. 그 목록에는 사용자 레벨 파일도 있고, 테스트 규칙이 그 안에 있습니다. 프로젝트를 시작할 때 팀의 규칙을 그 개인 파일에 적었던 것입니다. 그 노트북의 Claude Code는 늘 규칙을 따랐습니다. 하지만 그 파일은 리포지토리에 들어간 적이 없으므로 레오의 Claude Code는 한 번도 그 규칙을 본 적이 없습니다.

**해결책은 팀 규칙을 프로젝트 CLAUDE.md로 옮기는 것입니다.** 이 변경도 다른 변경처럼 풀 리퀘스트로 진행합니다. 머지된 뒤에는 리포지토리를 pull하는 모든 사람이 같은 규칙을 받습니다. 다음에 올 신규 입사자도 마찬가지입니다. 개인 취향은 사용자 레벨 파일에 남깁니다.

레오에게 개인 파일 사본을 보내 홈 폴더에 두게 하면 안 됩니다. 두 사본은 서서히 어긋나고, 다음 신규 개발자도 같은 문제를 겪습니다. **팀 규칙은 버전 관리에 둡니다.**

## 3. 세션마다 다르게 동작할 때

`/memory`는 Claude Code가 한 세션에서는 규칙을 따르고 다음 세션에서는 무시할 때도 도움이 됩니다. “금액은 주문에서 가져온다” 규칙이 환불 폴더의 CLAUDE.md에만 있다고 가정해 보세요.

- 환불 코드를 고치는 세션에서는 Claude Code가 규칙을 따릅니다.
- 환불 금액도 다루는 결제(checkout) 코드로 작업하는 세션에서는 규칙이 사라진 것처럼 보입니다.

`/memory`를 보면 이 세션은 환불 폴더의 파일을 로드하지 않았습니다. 디렉터리 파일은 자기 폴더 안의 작업에만 닿습니다. 모든 곳에 적용되어야 하는 규칙이라면 프로젝트 파일로 올리세요.

## 제품 참고: `/memory`와 `/context`

| 명령 | 하는 일 |
| --- | --- |
| `/memory` | 시험에서 로드된 메모리 파일을 확인하는 명령입니다. 현재 버전에서는 파일을 나열하고 하나씩 엽니다. |
| `/context` | 지금 세션에 로드된 모든 것을 보여 줍니다. |

## 정리

- 사용자 레벨 파일은 홈 폴더에 있고, 나에게만 닿습니다.
- 프로젝트 파일은 리포지토리에 있고, 버전 관리로 팀 전체에 공유됩니다.
- 디렉터리 파일은 한 폴더에 규칙을 더하고, Claude Code가 그 폴더에서 작업할 때만 로드됩니다.
- 새 팀원에게 팀 지침이 빠져 있다면 먼저 사용자 레벨을 보고, 그 지침을 프로젝트 파일로 옮깁니다.
- `/memory` 명령으로 세션이 실제로 로드한 파일을 확인합니다.

각 규칙은 그 규칙이 필요한 사람이 로드하는 곳에 두세요. 팀 규칙은 리포지토리에, 나만의 습관은 홈 폴더에 둡니다. 다음 노트에서는 프로젝트 파일이 커져서 주제별로 나누는 법을 살펴보겠습니다.
