# 42. MCP 서버의 도구와 리소스

지난 노트에서는 주문을 찾지 못했을 때와 반품 기한이 지났을 때 도구가 어떤 답을 돌려줘야 하는지 살펴봤습니다. 이제 스토어 개발자가 Claude Code에서도 같은 주문을 조회하고 싶어 합니다. ShopAssist에는 반품이나 배송에 관한 정책 문서를 읽는 기능도 필요합니다. 프로그램마다 주문 조회 함수를 복사하고, 문서가 늘어날 때마다 연결 코드를 새로 짜야 할까요?

## 한 서버의 도구를 여러 프로그램에서 쓰기

MCP(Model Context Protocol)를 사용하면 스토어는 **서버** 하나를 통해 제공할 기능을 정할 수 있습니다. 그 기능을 쓰려고 접속하는 프로그램을 **클라이언트**라고 합니다. Claude Code, Claude 앱, Agent SDK로 만든 ShopAssist가 모두 클라이언트가 될 수 있습니다. 주문 시스템과 고객 데이터베이스의 내부 구조가 달라도 클라이언트가 기능을 알아보고 호출하는 방식은 같습니다.

클라이언트가 연결되면 서버가 어떤 도구를 제공하는지 알아봅니다. Claude가 그중 하나를 골라 호출을 요청하면 클라이언트가 요청을 전달하고 서버가 함수를 실행합니다. 스토어가 주문 조회 기능만 공개했다면 Claude는 이 연결을 통해 주문을 조회할 수 있습니다. 주문을 삭제하려면 서버에 그에 해당하는 기능이 따로 있어야 합니다.

## 주문 한 건을 조회할 때와 정책 문서를 찾을 때

| 서버가 제공하는 것 | ShopAssist에서 쓰는 예 | 알 수 있는 내용 |
| --- | --- | --- |
| 도구(tool) | 주문 번호를 넣어 `lookup_order`를 호출합니다. | 지금 이 주문에 어떤 상품이 있고 언제 배송됐는지 확인합니다. |
| 리소스(resource) | 클라이언트가 정책 문서 목록을 읽어 에이전트에 제공합니다. | 반품, 배송, 가격 조정, 파손 상품 중 어느 문서를 읽을지 알 수 있습니다. |

검색 도구만 있다고 해 보세요. Claude가 ‘반품’을 검색하고, 결과가 모자라면 ‘환불 규정’으로 다시 검색한 뒤 문서를 열어 봅니다. 찾는 동안에도 호출이 오가고 토큰이 듭니다. 반면 문서마다 다루는 주제가 적힌 목록을 먼저 읽으면 필요한 문서를 바로 고를 수 있습니다. 시험에 나오는 이슈 요약 목록, 문서의 목차, 데이터베이스 스키마도 같은 역할을 합니다.

## Claude Code가 실제 주문 대신 테스트 파일을 읽은 이유

스토어의 백엔드 서버와 개발팀의 이슈 관리 서버를 Claude Code에 함께 연결해 보겠습니다. 클라이언트는 연결한 서버마다 제공하는 도구를 확인합니다. 개발자는 서버를 번갈아 선택할 필요 없이 두 서버의 도구와 Claude Code의 내장 도구를 한 대화에서 쓸 수 있습니다.

> 알렉스의 램프 주문은 왜 환불이 거절됐나요?

이 질문에 Claude Code가 파일 안의 텍스트를 찾는 `Grep`을 선택했다고 해 보세요. 리포지토리에서 램프가 들어간 오래된 테스트 주문을 찾아내고, 그 데이터로 실제 고객에게 일어난 일을 추측합니다. 이때 먼저 볼 곳은 주문 조회 도구의 설명입니다. “주문 세부 정보를 가져옵니다”라는 한 줄로는 어느 시스템의 어떤 주문을 읽는지 알기 어렵습니다.

설명을 이렇게 바꿔 보세요. “실제 고객 주문에 대한 질문에 사용합니다. 스토어 주문 시스템에서 현재 상태, 상품, 금액, 배송일, 반품 기한을 읽어 옵니다. 리포지토리 파일에는 코드와 테스트 데이터만 들어 있습니다.” 이제 Claude는 답의 근거를 어디에서 찾아야 할지 알 수 있습니다. 개발자가 코드 속 테스트를 찾을 때는 여전히 `Grep`이 유용하므로 그대로 둡니다. 선택을 강제하려고 `Grep`을 없애면 진짜 원인이 가려지고 다른 작업이 망가집니다. 선택받지 못한 도구의 설명을 고치세요.

## 어떤 서버를 직접 만들까요?

개발팀이 쓰는 이슈 관리 시스템은 Jira입니다. Jira용 커뮤니티 MCP 서버가 이미 있으므로 팀은 그 서버를 연결합니다. 이런 표준 시스템용 서버를 직접 만들면 다른 사람들이 이미 최신으로 유지하는 것을 만들고 유지하는 데 시간을 쓰게 됩니다. ShopAssist의 백엔드는 사정이 다릅니다. 고객 신원을 먼저 확인하고, 500달러를 초과하는 환불은 상담원에게 넘기며, 거절 사유는 스토어가 정한 형식으로 돌려줘야 합니다. 이런 업무에는 우리 규칙을 담은 서버를 직접 만듭니다.

도구를 연결하고 나면 실제 고객 질문으로 확인해 보세요. **설명만 읽고도 어떤 데이터에서 무엇을 가져오는지 알 수 있나요?** 다음 노트에서는 지난 실습의 주문 조회와 반품 접수를 MCP 서버에 올리고, Claude Code에서 호출해 보겠습니다.
