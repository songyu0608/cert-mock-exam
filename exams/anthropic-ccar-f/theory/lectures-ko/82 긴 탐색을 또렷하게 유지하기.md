# 82. 긴 탐색을 또렷하게 유지하기

지난 노트에서는 세션을 포크해서, 공유 분석 하나에서 출발하는 두 접근법을 비교했습니다.

이번 노트에서는 한 세션 안의 긴 탐색이 서서히 초점을 잃는 문제를 살펴봅니다. 답은 여전히 확신에 차 있습니다. 그래서 답이 더 이상 내 코드에 관한 것이 아니게 돼도 아무도 알아차리지 못합니다.

## 첫 한 시간과 세 시간째

ShopAssist에 사진 없이 도착한 파손 상품을 확인하는 검사를 추가하려 합니다. 먼저 코드에서 환불과 에스컬레이션이 어떻게 동작하는지 알아야 합니다. 그래서 Claude Code에 탐색을 맡깁니다.

**첫 한 시간**에는 답이 정확합니다.

- 환불 한도는 `RefundPolicy`라는 클래스에서 확인됩니다.
- 금액은 통화 헬퍼에서 반올림됩니다.

**두 시간과 파일 약 60개를 거친 뒤**, 새 검사를 어디에 넣어야 하는지 묻습니다.

- 답: "검증 로직은 보통 서비스 레이어에 둡니다." 우리 코드의 클래스는 하나도 언급하지 않습니다.
- 몇 분 뒤: "환불 한도는 보통 컨트롤러에서 확인합니다." 첫 한 시간에 찾은 것과 정반대입니다.

가장 중요한 원칙은 **중요한 조사 결과가 대화 안에만 있어서는 안 된다**는 것입니다. 이번 노트에서는 증상과 원인, 스크래치패드 파일, compact 커맨드와 그것을 실행할 때를 차례로 봅니다.

## 1. 증상과 원인

이 문제를 **컨텍스트 저하**(context degradation)라고 합니다. 징후는 두 가지입니다.

| 징후 | 내용 |
| --- | --- |
| 답이 일반론이 된다 | 이 코드베이스에서 앞서 찾은 클래스가 아니라 흔한 패턴을 이야기합니다. |
| 답이 서로 어긋난다 | 첫 한 시간에 찾은 사실이 나중에 바뀝니다. |

원인은 컨텍스트입니다. Claude Code가 받은 모든 검색 결과와 읽은 모든 파일이 아직 대화에 있습니다. 초기 조사 결과는 이제 수천 줄의 탐색 출력 아래, 한참 뒤에 있습니다. 긴 입력의 중간에 있는 사실은 놓치기 쉽습니다. 그래서 Claude Code는 빈틈을 코드가 보통 어떤 모습인지로 채웁니다.

같은 질문을 다시 하거나 "구체적으로 답해"를 덧붙이면 안 됩니다. 조사 결과는 여전히 묻혀 있으므로, 다음 답도 일반론입니다.

## 2. 스크래치패드

**스크래치패드 파일**은 프로젝트 안, 대화 밖에 있는 평범한 메모 파일입니다. 탐색을 시작할 때 Claude Code에 이 파일을 유지하라고 합니다. 중요한 것을 찾을 때마다 짧은 항목을 하나 추가합니다. 항목에는 클래스나 함수, 파일, 그것이 하는 일을 적습니다. 미해결 질문도 이 파일에 넣습니다.

```markdown
# Exploration notes
- RefundPolicy: decides eligibility, checks the refund limit
- CurrencyHelper: rounds amounts to the currency
- EscalationRouter: sends large refunds to a human agent
- Open: where do damaged-item claims enter the flow?
## Rule
Before answering a question about the code, read this file first.
```

지침의 뒷부분도 똑같이 중요합니다. Claude Code는 코드에 관한 나중 질문에 답하기 전에, **스크래치패드를 먼저 읽습니다.** 이제 새 검사에 관한 질문에 구체적인 답이 나옵니다. 메모에 `RefundPolicy`가 적격 여부를 정한다고 적혀 있으므로, 검사는 거기에 들어갑니다.

파일은 채팅이 아니라 디스크에 있습니다. 그래서 줄어든 대화나 새 세션 같은 컨텍스트 경계를 넘어 살아남습니다. 항목은 짧게 씁니다. 긴 설명이 아니라 이름, 파일, 사실입니다.

## 3. compact 커맨드

`/compact` 커맨드는 대화 기록을 짧은 요약으로 바꿉니다. 검색 결과나 파일 전체 내용 같은 긴 탐색 출력으로 컨텍스트가 찼을 때 공간을 비워 줍니다.

하지만 요약은 텍스트를 줄입니다. 정확한 이름, 경로, 숫자가 가장 먼저 빠집니다. **핵심 조사 결과가 대화 안에만 있을 때는 compact를 실행하면 안 됩니다.**

그래서 순서는 이렇습니다.

1. 스크래치패드를 갱신합니다.
2. compact를 실행합니다.
3. Claude Code가 스크래치패드를 다시 읽고, 정확한 조사 결과가 작은 공간에 돌아옵니다.

compact 커맨드에 요약이 무엇을 남겨야 하는지 짧은 지침을 덧붙일 수도 있습니다. 아래는 그 형태의 예시입니다.

```text
/compact keep the class names, file paths and open questions
```

시험에서는 긴 코드 탐색에 스크래치패드와 compact가 좋은 답입니다. Claude Code에서도, Agent SDK로 만든 개발자 에이전트에서도 마찬가지입니다.

## 정리

- 긴 세션에서는 답이 흔한 패턴으로 흐르고, 앞선 조사 결과와 어긋납니다. 이것이 컨텍스트 저하이고, 다시 물어도 고쳐지지 않습니다.
- 스크래치패드 파일은 핵심 조사 결과를 대화 밖에 기록합니다. Claude Code는 나중 질문에 답하기 전에 그 파일을 읽습니다.
- compact는 탐색 출력이 컨텍스트를 채웠을 때 공간을 비웁니다. 스크래치패드가 최신일 때만 실행합니다.

조사 결과를 먼저 적어 두고, 그다음에야 대화가 짧아지게 하세요. 다음 노트에서는 작업이 한 세션에 담기에 너무 길어져서, 단계로 나눕니다.
