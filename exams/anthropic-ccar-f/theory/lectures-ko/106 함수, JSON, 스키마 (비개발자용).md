# 106. 함수, JSON, 스키마 (비개발자용)

이번 노트는 프로그램이 데이터와 행동을 어떻게 기술해서 Claude와 애플리케이션이 그것에 대해 합의하는지 다룹니다.

ShopAssist는 말만 하는 것이 아니기 때문에 중요합니다. 주문에 대해 행동하려면, 프로그램이 읽을 수 있는 데이터와 요청할 수 있는 행동이 필요합니다.

코드를 쓰지 않는 분을 위한 선택 강의입니다.

> 가장 중요한 점: 스키마는 계약입니다. 데이터가 어떤 모양이어야 하는지 양쪽에 알려 줍니다.

세 가지를 살펴봅니다. 첫째, 데이터의 형식인 JSON. 둘째, 그 데이터의 규칙인 스키마. 셋째, 행동인 함수와 도구.

## 첫째: JSON

스토어의 고객 Alex가 이렇게 씁니다. "지난 주문에서 산 재킷을 반품하고 싶어요. 단추 하나가 깨졌어요."

사람은 이 문장을 바로 이해합니다. 프로그램은 그렇지 않습니다. 프로그램에는 각 정보가 이름 붙은 자기 자리에 있어야 합니다. 이것을 **구조화된 데이터**라고 합니다. **JSON**은 그것의 가장 흔한 형식입니다. JavaScript Object Notation의 줄임말이지만, JSON을 읽는 데 JavaScript를 알 필요는 없습니다.

Alex의 요청을 JSON으로 쓰면 필드를 감싸는 중괄호가 **객체**를 표시합니다. 객체는 필드의 묶음이라고 생각하면 됩니다. 각 필드에는 이름과 값이 있습니다. `reason`이라는 필드의 값은 "broken button"이고, `refund_requested`라는 필드의 값은 true입니다.

> 아래는 스크립트 설명에 맞춘 예시이며, 강의 화면의 JSON과 필드 이름이 다를 수 있습니다.

```json
{
  "order_id": "ORD-12345678",
  "item": "jacket",
  "price": 89.9,
  "reason": "broken button",
  "problems": ["broken button", "missing belt"],
  "refund_requested": true
}
```

값에는 타입이 있습니다.

| 타입 | 설명 | 예 |
| --- | --- | --- |
| 문자열(string) | 따옴표로 감싼 텍스트 | `"broken button"` |
| 숫자(number) | 따옴표 없이 씀 | 재킷 가격 |
| 불리언(boolean) | true나 false, 그 밖에는 없음 | `true` |
| 배열(array) | 대괄호 안의 목록 | 깨진 단추와 빠진 벨트, 두 문제를 담은 문자열 배열 |

많은 사람이 놀라는 세부 사항이 하나 있습니다. 주문 번호는 숫자처럼 보이지만 문자열로 저장합니다. 글자와 대시가 들어 있습니다. 아무도 주문 번호로 계산하지 않습니다. 그리고 실제 숫자로 저장하면 맨 앞의 0이 사라집니다. 그래서 주문 번호나 고객 ID 같은 **식별자는 문자열**입니다.

## 둘째: 스키마

JSON은 실제 값을 담습니다. **스키마**는 그 값의 규칙을 기술합니다. 어떤 필드가 있고, 각 필드가 어떤 타입인지 말합니다. 어떤 필드가 필수인지도 말합니다.

- **필수 필드**는 항상 있어야 합니다. 예를 들어 반품 요청에는 항상 사유가 있어야 합니다.
- **선택 필드**는 없어도 됩니다. 고객이 덧붙인 코멘트 같은 것입니다.

스키마에는 고객 데이터가 전혀 들어 있지 않습니다. 모든 요청이 가져야 할 모양을 기술할 뿐입니다.

왜 도움이 될까요? Claude가 "고객은 아마 환불을 원하는 것 같습니다"라는 문장으로 답한다고 상상해 보세요. 그러면 애플리케이션은 무엇을 저장할지 추측해야 합니다. 스키마가 있으면 애플리케이션은 각 값이 어디 있는지 압니다. 코드로 결과를 확인할 수 있습니다. 필수 필드가 모두 있나? 가격이 정말 숫자인가? `refund_requested`가 정말 true나 false인가? 뭔가 틀렸다면 애플리케이션은 어떤 일이 일어나기 전에 그것을 잡아냅니다.

앞서 말했듯이 API는 Claude의 출력이 스키마를 따르게 만들 수 있습니다. 하지만 스키마는 데이터의 모양을 확인할 뿐, 사실이 맞는지는 확인하지 않습니다.

## 셋째: 함수와 도구

**함수**는 프로그램 안의 이름 붙은 행동입니다. 입력을 받아 어떤 일을 하고 출력을 돌려줍니다. `lookup_order`를 예로 들어 봅니다. 이름이 하는 일을 말해 줍니다. 입력은 주문 번호와 확인된 고객 ID입니다. 출력은 주문입니다. 상품, 상태, 배송일이 담겨 있습니다.

**도구**는 애플리케이션이 Claude에게 기술해 주는 함수입니다. 기술은 세 부분으로 이루어집니다.

1. **이름**
2. 도구가 무엇을 하고 언제 쓰는지 말하는 **짧은 설명**
3. **입력 스키마**: 같은 종류의 계약이지만, 이번에는 도구의 입력에 대한 것입니다. `lookup_order`의 입력 스키마는 주문 번호가 필수 문자열이라고 말합니다.

Claude는 이 기술을 읽습니다. 그 뒤의 코드는 절대 보지 않습니다. 그다음 Claude는 도구 호출을 요청할 수 있습니다. 애플리케이션이 함수를 실행하고 결과를 돌려보냅니다. Claude는 무엇이 필요한지 정하고, 애플리케이션이 일을 합니다.

## 정리

- JSON은 데이터를 이름과 값이 있는 필드로 저장합니다.
- 값은 문자열, 숫자, true나 false, 또는 배열일 수 있습니다.
- 주문 번호 같은 식별자는 문자열입니다.
- 스키마는 계약입니다. 어떤 필드가 있고, 어떤 타입이며, 어떤 것이 필수인지 정합니다.
- 도구는 이름, 설명, 입력 스키마로 Claude에게 기술한 함수입니다.

그러니 Claude와 애플리케이션이 합의해야 할 때는 그 합의를 스키마로 적어 두세요.

이 강좌에서 도구를 다루는 첫 실습은 도구 호출 하나를 처음부터 끝까지 따라갑니다.
