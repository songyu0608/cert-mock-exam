# 10. 실습: 코드로 첫 요청 보내기

이번에는 ShopAssist의 첫 Python 스크립트를 작성합니다. 고객이 “재킷을 산 지 20일이 지났는데 반품할 수 있나요?”라고 물으면 스크립트가 Claude API에 질문을 보내고 응답을 읽습니다. Claude를 사용하는 애플리케이션의 기능은 이 호출 한 번에서 시작합니다.

## 키를 읽고 클라이언트 준비하기

먼저 API 키가 필요합니다. 우리 스크립트가 Claude API를 사용할 수 있게 해 주는 비밀번호 같은 값입니다. 스크립트와 같은 폴더에 있는 `.env` 파일에 `ANTHROPIC_API_KEY`라는 이름으로 자신의 키를 한 줄에 저장합니다. 키를 공유하거나 소스 코드에 붙여 넣지 마세요.

이제 `.env`를 닫고 빈 파일 `first_request.py`를 엽니다. `dotenv`에서 `load_dotenv`를, Anthropic 공식 Python 라이브러리에서 `Anthropic`을 가져옵니다. `load_dotenv()`를 호출하면 프로그램이 환경 변수에서 키를 읽을 수 있습니다. 이어서 `client = Anthropic()`으로 클라이언트를 만듭니다. 라이브러리가 `ANTHROPIC_API_KEY`라는 이름을 찾아 읽으므로 여기에서 키를 다시 넘길 필요가 없습니다.

모델 이름은 상수 `MODEL`에 한 번만 적습니다. 나중에 모델을 바꿀 때도 이 한 줄만 고치면 됩니다. 이 실습에서는 성능과 효율의 균형을 고려해 Sonnet을 사용합니다.

## 질문과 반품 정책을 한 메시지에 담기

요청은 `client.messages.create(...)`로 보내고, 반환값은 `response`에 담습니다. `model`에는 앞에서 정한 `MODEL`을 넣고 `max_tokens`는 300으로 설정합니다. Claude가 이번 응답에서 생성할 수 있는 토큰의 상한입니다. `output_config` 안의 `effort`는 `low`로 둡니다. 얼마나 깊이 생각해서 답할지 정하는 설정이고 답변의 길이에도 영향을 줍니다. 이번 질문은 간단합니다.

`messages`에는 지금까지의 대화를 목록으로 넘깁니다. 첫 요청에는 우리 쪽에서 보낸 `user` 메시지 하나만 있습니다. 그 메시지의 `content`에 세 가지를 함께 적습니다.

> 재킷을 산 지 20일이 지났는데 반품할 수 있나요? 스토어에서는 30일 이내에 반품을 받습니다. 두 문장으로 답해 주세요.

실습 코드에서는 읽기 좋도록 이 텍스트를 여러 줄의 짧은 문자열로 적습니다. Python은 괄호 안에 나란히 적은 문자열을 하나로 이어 붙입니다. 메시지와 목록, 메서드 호출의 괄호를 닫으면 요청이 완성됩니다.

## 첫 응답에서 무엇을 읽을까?

처음에는 응답 전체를 출력해 보겠습니다. `response`는 Python 객체이므로 `response.model_dump_json(indent=2, exclude_none=True)`으로 읽기 쉬운 JSON 텍스트를 만듭니다. 두 칸씩 들여 쓰고 값이 `None`인 필드는 생략합니다.

스크립트를 실행하면 키를 읽고 요청을 보낸 뒤 응답을 기다립니다. Anthropic 서버에서 답을 작성하면 다음과 같은 메시지가 돌아옵니다.

| 응답에서 볼 곳 | 이번 실행에서 알 수 있는 것 |
| --- | --- |
| `content` | 응답을 구성하는 블록의 목록입니다. 이번에는 텍스트 블록 하나이므로 `response.content[0].text`가 고객에게 보여 줄 답입니다. |
| `role` | Claude가 작성한 메시지이므로 `assistant`입니다. |
| `stop_reason` | 생성을 멈춘 이유입니다. 이번에는 Claude가 답을 마쳐서 `end_turn`입니다. |
| `usage` | 입력 토큰과 출력 토큰을 각각 셉니다. 첫 실행에서 보낸 입력은 53토큰이었습니다. |

이제 큰 JSON 전체를 출력하던 자리를 세 줄로 바꿉니다. 첫 줄에는 답변 텍스트, 둘째 줄에는 종료 사유, 셋째 줄에는 `usage.input_tokens`와 `usage.output_tokens`를 출력합니다. 다시 실행하면 같은 질문이라도 표현은 조금 달라질 수 있습니다. 원문의 실행 예시에서는 답이 자연스럽게 끝났고, 종료 사유는 `end_turn`, 입력은 53토큰, 출력은 약 75토큰이었습니다.

## 상한을 300에서 20으로 낮추면

같은 질문을 두고 `max_tokens`만 20으로 낮춰 다시 실행해 보세요. 몇 단어가 나온 뒤 문장 중간에서 끊깁니다. 이번에는 종료 사유가 **`max_tokens`**이고, 출력 토큰 수도 설정한 상한과 같은 20입니다.

API 호출 자체는 성공했습니다. 하지만 고객에게 이 텍스트를 그대로 보내면 쓰다 만 문장을 보여 주게 됩니다. 그래서 ShopAssist는 **답을 사용하기 전에 종료 사유를 확인**해야 합니다. 이 실습에서 `end_turn`은 답을 마쳤다는 뜻이고, `max_tokens`는 상한에 걸려 잘렸다는 뜻입니다. 후자라면 상한을 높여 다시 요청하거나, 애플리케이션에서 잘린 답을 따로 처리하세요.
