# 3. 시험 형식

Claude Certified Architect – Foundations 시험은 어떤 방식으로 진행될까요? 강의에서 소개하는 시험은 **60문항에 120분**입니다. 한 문제에 쓸 수 있는 시간은 평균 2분 정도입니다.

## 같은 시나리오에서 여러 문제 풀기

단일 선택 문제에서는 주어진 선택지 중 가장 적절한 답 하나를 고릅니다. 복수 선택 문제에서는 답을 여러 개 골라야 합니다. 몇 개를 고를지는 문제에 표시됩니다.

시험을 보면 실제 업무를 바탕으로 만든 시나리오 여섯 개 중 무작위로 뽑힌 네 개를 받습니다. 여섯 가지 주제는 고객 지원 에이전트, Claude Code를 활용한 코드 생성, 멀티 에이전트 리서치 시스템, Claude를 활용한 개발자 생산성 향상, 지속적 통합(CI) 파이프라인에서의 Claude Code 활용, 구조화된 데이터 추출입니다.

시나리오 하나에 여러 문제가 딸려 나올 수 있습니다. 따라서 개별 지식을 외우는 것만으로는 답을 고르기 어렵습니다. 팀이 어떤 상황에 놓여 있는지, 반드시 충족해야 할 요구사항은 무엇인지, 어떤 제약 안에서 해결해야 하는지 읽어내야 합니다.

## 출제 비중과 점수 읽는 법

| 도메인 | 출제 비중 |
| --- | ---: |
| 에이전트 아키텍처와 오케스트레이션 | 27% |
| 도구 설계와 Model Context Protocol(MCP) 통합 | 18% |
| Claude Code 설정과 워크플로 | 20% |
| 프롬프트 엔지니어링과 구조화된 출력 | 20% |
| 컨텍스트 관리와 신뢰성 | 15% |

시험은 **100~1,000점의 환산 점수**를 사용하고, 합격선은 **720점**입니다. 그렇다고 정확히 72%를 맞혀야 한다는 뜻은 아닙니다. 시험 버전에 따라 난이도가 조금씩 달라도 결과를 비교할 수 있도록 점수를 환산합니다.

시험이 끝나면 합격 여부와 환산 점수가 나옵니다. 성적표에는 각 도메인에서 몇 퍼센트를 맞혔는지도 표시됩니다. 이 수치로 어느 영역에 강하고 약한지 알 수 있습니다. 각 영역의 정답률로 합격 여부를 따로 결정하지는 않습니다.

## 등록부터 갱신까지

아래 비용과 일정은 강의 원문에서 안내한 기준입니다. 실제로 접수할 때는 등록 화면에서 본인에게 적용되는 금액과 규정을 확인하세요.

기본 응시료는 응시할 때마다 미화 125달러입니다. 등록은 Anthropic Partner Academy에서 시작하고, 시험은 Pearson VUE를 통해 치릅니다.

Claude Partner Network에 참여하는 회사에 다닌다면 Partner Academy에 접속하고 시험에 등록할 때 회사 이메일을 쓰는 편이 좋습니다. 그래야 취득한 자격이 소속 파트너사와 연결됩니다. 개인 이메일을 쓰면 나중에 계정이나 등록 정보를 수정해야 할 수 있습니다.

회사의 파트너 등급에 따라 첫 응시료 할인이 적용될 수도 있습니다. 해당하는 할인은 결제 단계에 표시됩니다. 기본 응시료를 결제하기 전에 회사가 파트너 네트워크에 참여하는지, 회사와 연결된 계정으로 로그인했는지 확인하세요.

등록 후에는 안내에 따라 Pearson VUE 계정을 만들거나 기존 계정에 로그인해 일정을 예약합니다. 온라인 감독 방식으로 응시하거나 지정된 Pearson VUE 시험장을 선택할 수 있습니다.

취소하거나 일정을 바꾸려면 예약 시각보다 **최소 48시간 전**에 처리해야 합니다. 남은 시간이 48시간 미만이면 취소나 변경이 불가능하며, 응시료를 돌려받지 못할 수 있습니다.

불합격한 뒤에는 다시 응시할 수 있지만 대기 기간이 있습니다. 첫 번째 불합격 후에는 **14일**, 두 번째는 **30일**, 세 번째는 **90일**을 기다립니다. 어느 시점을 기준으로든 연속된 12개월 동안 같은 시험에 응시할 수 있는 횟수는 최대 네 번이고, 응시료는 매번 냅니다.

합격한 자격의 유효기간은 12개월입니다. 만료 전에 무료로 제공되는 비감독 방식의 갱신 평가를 마치면 자격을 연장할 수 있습니다. 갱신 전에 자격이 만료되면 정규 시험에 다시 응시하고 응시료 전액을 내야 합니다.

문제를 풀 때 한 가지 기억해 두세요. 선택지 중에는 기술적으로 가능한 방법이 여럿 있을 수 있습니다. 그럴 때는 시나리오로 돌아가세요. 문제의 원인을 해결하지 못하는 선택지, 불필요하게 복잡한 선택지, 명시된 요구사항을 어기는 선택지를 차례로 지워 보면 **이 상황에 가장 잘 맞는 해결책**이 남습니다. 시험에서 평가하는 실무 아키텍처 판단이 바로 이것입니다.
