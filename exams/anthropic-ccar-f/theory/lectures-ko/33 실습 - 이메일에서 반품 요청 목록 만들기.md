# 33. 실습: 이메일에서 반품 요청 목록 만들기

지원 메일함에 반품 이메일 다섯 통이 들어왔습니다. 한 고객은 파란 재킷이 너무 작다며 주문 번호를 적었고, 다른 고객은 신발이 파손됐다고만 썼습니다. 헤드폰을 산 고객이 적은 번호는 하이픈 뒤가 네 자리뿐입니다. 이번 노트에서는 메일을 하나씩 읽어 지원팀이 사용할 목록을 만들어 보겠습니다. 번호가 없는 고객의 요청도 이 목록에 남아야 합니다.

## 이메일을 파일 이름순으로 읽기

지원 메일함은 각 이메일을 `emails` 폴더에 텍스트 파일로 저장합니다. 새 Python 스크립트에서 결과를 저장할 `json`, 파일과 폴더를 다룰 `pathlib.Path`, 그리고 `validate.py`의 `extract` 함수를 가져옵니다. [[25 실습 - 주문 번호를 검증하고 오류와 함께 다시 요청하기|25번 노트]]에서 만든 함수입니다. 이메일 한 통을 Claude에 보내 주문 ID, 상품, 반품 사유를 받고, 코드 검사에 걸리면 오류를 알려 주고 다시 요청합니다.

빈 목록 `requests`를 준비하고 `sorted(Path("emails").glob("*.txt"))`로 파일을 하나씩 꺼냅니다. `glob`은 확장자가 `.txt`인 파일을 찾고, `sorted`는 다시 실행해도 파일을 같은 순서로 읽게 해 줍니다. 루프 안에서는 `read_text`로 본문을 읽어 `extract`에 넘깁니다. 이번 실습은 폴더의 여러 파일에 기존 함수를 차례로 호출하므로 이메일 한 통마다 적어도 한 번의 API 요청이 나갑니다.

## 지원팀이 원본을 찾고 검토할 수 있게 하기

추출한 세 필드에 우리 코드가 두 가지를 더합니다. 하나는 원본 이메일을 다시 열 수 있는 **파일 이름**이고, 다른 하나는 지원팀이 확인할 건을 고를 **처리 상태**입니다. 주문 ID가 있으면 `ok`, 없으면 `needs_review`로 표시하고 완성한 레코드를 목록에 넣습니다.

터미널에도 파일 이름, 주문 ID, 상품, 반품 사유, 상태를 한 줄씩 출력합니다. 여기서 주문 ID를 `str(order_id)`로 바꾸는 이유는 무엇일까요? 값이 없으면 Python에서는 `None`인데, 여기에 문자열처럼 열 너비를 지정하면 출력할 때 오류가 납니다. 출력할 때만 문자로 바꾸면 열을 맞춰 읽을 수 있고, 저장할 데이터에는 여전히 값이 없다는 사실이 남습니다.

원문의 실행에서는 다섯 통 모두에서 추출 결과를 받았습니다. 이 함수는 재시도를 모두 소진하면 결과 전체로 `None`을 돌려줄 수도 있습니다. 그때는 딕셔너리에서 필드를 꺼내기 전에 추출 실패를 확인하고, 담당자가 원본을 찾도록 파일 이름과 검토 상태를 남깁니다. 추출은 성공했고 주문 ID만 빈 경우에는 상품과 반품 사유를 그대로 쓸 수 있습니다.

## 다섯 통 중 왜 두 통이 검토 대상일까요?

| 이메일의 상품 | 실행 결과 | 상태 |
| --- | --- | --- |
| 파란 재킷 | 고객이 주문 번호를 적었고 반품 사유는 ‘너무 작음’입니다. | `ok` |
| 신발 | 파손됐다는 설명은 있지만 주문 번호가 없습니다. | `needs_review` |
| 백팩 | 필요한 값이 모두 들어 있습니다. | `ok` |
| 헤드폰 | 네 자리 번호가 검사에서 거부됐습니다. 오류를 알려 주고 다시 추출하자 주문 ID가 빈 값으로 돌아왔습니다. | `needs_review` |
| 램프 | 필요한 값이 모두 들어 있습니다. | `ok` |

헤드폰을 읽을 때는 터미널에 한 줄이 더 보입니다. 첫 번째 번호가 거부됐다는 검증 메시지입니다. 한 통의 이메일을 두 번 처리했어도 목록에 넣는 반품 요청은 한 건입니다.

마지막으로 `json.dumps(requests, indent=2)`로 목록을 읽기 좋게 들여쓴 JSON 텍스트로 바꾸고, `write_text`로 `return_requests.json`에 저장합니다. 원문에서는 `head -n 12 return_requests.json`으로 앞 열두 줄을 열어 확인합니다. 두 번째 레코드인 신발의 주문 ID에는 JSON의 `null`이 들어 있습니다. 화면에 출력한 글자 `"None"`을 저장한 것이 아니라, Python의 빈 값이 JSON에서 어떻게 표현되는지 확인할 수 있습니다.

저장한 건수는 목록의 길이로, 검토 건수는 상태가 `ok`가 아닌 레코드를 세어 구합니다. 이번 결과는 **반품 요청 5건 저장, 그중 2건 검토**입니다. 신발과 헤드폰의 주문 번호를 억지로 채우면 지원팀은 오히려 어느 고객에게 다시 물어야 하는지 놓칩니다. 번호를 비워 두고 원본 파일과 상태를 남겨야 담당자가 두 요청을 이어서 처리할 수 있습니다.
