# 95. 핵심 구분: 에이전트, 도구, 컨텍스트

ShopAssist가 완성됐고, 팀이 만든 리뷰 봇도 완성됐습니다. 이제 그 전부를 시험의 눈으로 돌아봅니다.

이번 강의는 시험이 오답 선택지로 바꾸는 에이전트, 도구, 컨텍스트의 구분을 다룹니다. 이 오답 선택지가 엉뚱한 경우는 드물기 때문에 중요합니다. 각 선택지는 실제 기법을 말하지만, 그 기법을 틀린 레이어나 틀린 일에 씁니다.

> 가장 중요한 점: 각 쌍에서 한 선택지는 신중해 보이고, 다른 선택지는 원인을 고칩니다.

세 그룹을 차례로 봅니다. 첫째, 루프와 그 규칙. 둘째, 도구. 셋째, 에스컬레이션과 컨텍스트. 이 셋을 합치면 시험의 첫 번째, 두 번째, 다섯 번째 도메인을 다룹니다.

## 첫 번째 그룹: 루프와 그 규칙

### 첫 번째 쌍: 중지 신호 대 라운드 카운터

루프는 stop reason이 `tool_use`인 동안 계속되고, `end_turn`에서 끝납니다. 오답 선택지는 Claude의 말이나 응답 속 아무 텍스트를 보고 루프를 멈추거나, 정해진 라운드 수가 지나면 멈춥니다. 라운드 한도는 안전망일 뿐입니다. 한도에 걸렸다면 뭔가 고장 난 것이므로 케이스를 사람에게 넘깁니다.

```text
애플리케이션 → Claude: request
Claude → 애플리케이션: stop_reason: tool_use
애플리케이션 → 도구: run the tool
애플리케이션 → Claude: tool_result
Claude → 애플리케이션: stop_reason: end_turn
```

### 두 번째 쌍: 프롬프트, 게이트, 훅

이 쌍에는 세 면이 있습니다.

| 수단 | 하는 일 |
| --- | --- |
| 프롬프트 | Claude를 이끌지만 가끔 실패함 |
| 전제 조건 게이트 | 단계 순서를 고정함. 예: 주문 작업 전에 먼저 고객 확인 |
| 훅 | 도구 호출 하나를 실행 전에 잡음 |

그래서 항상 지켜져야 하는 규칙은 코드에 둡니다. 실행 전에 잡는 훅은 예를 들어 500달러를 넘는 환불을 막고, 케이스를 `escalate_to_human`으로 돌립니다. `PostToolUse` 훅은 타임스탬프나 상태 코드 같은 데이터 형태를 고칩니다.

```python
def post_tool_use(result):
    result["date"] = to_iso(result["date"])
    result["status"] = STATUS_NAMES[result["status"]]
    return result
```

오답 선택지 하나를 더 조심하세요. 어떤 도구가 있는지 제한하면 쓸 수 있는 것이 바뀔 뿐, 호출 순서는 바뀌지 않습니다.

### 세 번째 쌍: 코디네이터를 거친 라우팅 대 서브에이전트 간 직접 호출

멀티 에이전트 시스템에서는 서브에이전트 사이의 모든 메시지가 코디네이터를 거칩니다. 그래야 모든 단계를 볼 수 있습니다. 오류는 어디서나 같은 방식으로 처리되고, 어떤 정보가 어디로 갈지 제어할 수 있습니다.

- `verify_fact`처럼 자기 전용의 좁은 도구를 부르는 서브에이전트는 코디네이터를 우회하는 것이 아닙니다.
- 하지만 모든 검색 도구를 가진 종합 에이전트는 도구가 너무 많고, 다른 에이전트의 일을 하기 시작합니다.
- 서브에이전트는 빈 상태로 시작합니다. 그래서 코디네이터는 프롬프트마다 완전한 조사 결과를 넘깁니다.

## 두 번째 그룹: 도구

### 첫 번째 쌍: 더 나은 설명 대 더 큰 변경

Claude가 틀린 도구를 고르면 첫 번째 해결책은 도구 설명입니다. 설명마다 도구가 무엇을 하고 무엇을 돌려주는지 말합니다. 입력, 예외 경우, 그리고 언제 이웃 도구를 써야 하는지를 밝힙니다. 첫 단계로서는 few-shot 예시, 라우팅 레이어, 도구 합치기가 오답입니다.

```python
get_order = {
    "name": "get_order_status",
    "description": (
        "Looks up one order by ID and returns its status. "
        "Input: order_id, for example ORD-12345678. "
        "Edge case: an unknown ID returns found=false. "
        "For all orders of a customer, use list_orders."
    ),
}
```

설명만으로 부족하면 겹치는 도구의 이름을 바꾸고, 범용 도구를 나눕니다. 그다음 시스템 프롬프트에 키워드 트리거가 있는지 확인합니다. 그리고 에이전트가 더 나은 MCP 도구 대신 Grep을 고른다면, 그 MCP 도구의 설명을 고칩니다. Grep은 그대로 둡니다.

### 두 번째 쌍: 빈 결과 대 실패

아무것도 찾지 못한 검색은 성공한 것입니다. 답이 비어 있을 뿐입니다. 타임아웃은 접근 실패입니다. `isError` 플래그, 범주, `isRetryable` 플래그를 함께 보냅니다. 오답 선택지는 실패를 빈 성공으로 숨기거나, 그냥 "operation failed"만 돌려줍니다.

일시적 오류만 재시도할 가치가 있습니다. 비즈니스 오류에는 다시 시도하는 대신 고객에게 안전한 설명을 줍니다. 에이전트 사이에서는 실패 보고가 실패 유형, 질의, 부분 결과, 가능한 대안을 담습니다. 작업은 계속되고, 최종 보고서는 빈틈을 밝힙니다.

```python
failure_report = {
    "type": "timeout",
    "query": "return policy for jackets",
    "partial_results": ["policy-2025.pdf"],
    "alternatives": ["try the help-center search"],
}
```

## 세 번째 그룹: 에스컬레이션과 컨텍스트

### 첫 번째 쌍: 실제 트리거 대 트리거처럼 보이기만 하는 신호

| 지금 에스컬레이션 | 에스컬레이션하지 않음 |
| --- | --- |
| 고객이 사람을 요청함 | 화난 말투 |
| 정책 예외 요청 | 스스로 보고한 신뢰도 점수 |
| 정책 공백 | 복잡해 보이기만 하는 케이스 |
| 진전이 불가능함 | |

일치하는 고객이 여러 명이면 ShopAssist는 다른 식별자를 묻습니다. 에스컬레이션이 어느 방향으로든 어긋나면, 해결책은 몇 가지 예시를 붙인 명확한 기준입니다. 케이스를 분류하도록 학습시킨 별도 모델이나 감정 분석은 오답입니다.

```python
SYSTEM_PROMPT = """
Several customers match? Ask for another identifier.
Escalate if the customer asks for a person,
or asks for a policy exception.
Example: "Let me talk to a person" → escalate
Example: "This is the third time!" → keep helping
"""
```

### 두 번째 쌍: 케이스 정보 블록 대 요약

요약은 정확한 금액, 날짜, 약속을 모호한 말로 바꿉니다. 더 꼼꼼하게 요약해도 이 점은 달라지지 않습니다. 정확한 사실은 요약 밖의 블록에 이슈마다 항목 하나씩 둡니다. 도구 결과는 중요한 필드만 남기고, 긴 입력에서는 핵심 조사 결과를 맨 앞에 둡니다.

```python
case_facts = [
    {
        "issue": "refund",
        "order": "ORD-12345678",
        "amount": "74.50 USD",
        "promise": "call before Friday",
    },
]
```

### 세 번째 쌍: 출처가 붙은 주장 대 압축된 조사 결과

서브에이전트는 주장-출처 레코드를 돌려주고, 종합은 그것을 버리지 않고 합칩니다. 신뢰할 만한 두 출처가 서로 다를 때는 두 값을 모두 남기고, 각 값에 출처와 날짜를 붙입니다. 그 차이를 어떻게 다룰지는 코디네이터가 정합니다. 날짜가 있으면 그 차이가 충돌이 아니라 추세라는 것도 드러납니다.

```python
claims = [
    {"claim": "Return window: 30 days",
     "source": "return-policy.pdf", "date": "2025-03"},
    {"claim": "Return window: 14 days",
     "source": "help-page", "date": "2026-09"},
]
```

## 정리

- stop reason이 루프를 끝내고, 한도는 버그만 잡습니다.
- 프롬프트는 이끌고, 게이트와 훅은 강제합니다.
- 서브에이전트 사이의 모든 메시지는 코디네이터를 거칩니다.
- 잘못된 도구 선택은 설명부터 고치고, 실패는 절대 빈 결과처럼 보여서는 안 됩니다.
- 실제 트리거에서만 에스컬레이션하고, 사실과 출처는 요약 밖에서 정확하게 지킵니다.
