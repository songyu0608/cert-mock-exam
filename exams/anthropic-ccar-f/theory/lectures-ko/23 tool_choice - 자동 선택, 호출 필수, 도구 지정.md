# 23. tool_choice: 자동 선택, 호출 필수, 도구 지정

지난 노트에서는 Claude가 주문 조회를 요청하고, ShopAssist가 함수를 실행해 결과를 돌려줬습니다. 이번에는 고객 지원 이메일에 첨부된 문서를 처리해 봅시다. 청구서 한 장을 보냈더니 Claude가 “3월에 발행된 청구서로 보입니다”라고 친절하게 설명합니다. 사람은 이해할 수 있지만, 우리 코드가 저장하려던 필드는 어디 있을까요?

팀은 청구서, 반품 신청서, 배송 전표에 각각 다른 **추출 도구**를 준비했습니다. 주문을 조회하는 도구와 달리, 이 도구들이 하는 일은 Claude가 문서에서 읽은 값을 정해진 필드로 받는 것입니다. 받고 싶은 필드의 모양을 도구의 `input_schema`에 정의하고, 코드가 호출 입력을 받아 저장합니다. 이 단계에서는 글로만 답하고 끝내면 저장할 데이터가 없습니다.

## 이 요청에서 도구를 꼭 써야 할까요?

`tool_choice`는 **이번 API 요청에서 Claude가 도구를 어떻게 선택할 수 있는지** 정하는 설정입니다. 원문의 시험 시나리오에서는 다음 세 가지를 구분합니다.

| 설정 | Claude에 맡기는 선택 | ShopAssist에서 쓰는 상황 |
| --- | --- | --- |
| `{"type": "auto"}` | 글로 답하거나, 필요하면 도구를 고릅니다. 도구를 제공할 때의 기본값입니다. | 알렉스가 반품 정책을 물으면 바로 답하고, 재킷 배송 상태를 물으면 주문을 조회합니다. |
| `{"type": "any"}` | 제공한 도구 중 하나 이상을 호출해야 합니다. 어떤 도구인지는 Claude가 고릅니다. | 첨부 문서의 종류를 모릅니다. 청구서·반품 신청서·배송 전표 중 맞는 추출 도구로 필드를 받습니다. |
| `{"type": "tool", "name": "extract_metadata"}` | 이름으로 지정한 도구를 호출해야 합니다. | 첨부 파일에서 문서 유형, 날짜, 주문 번호부터 추출해야 합니다. |

알렉스와 대화할 때는 주문을 조회할 필요가 없는 질문도 많습니다. 그래서 `auto`가 자연스럽습니다. 반면 세 종류의 첨부 파일을 같은 경로로 받아 처리하는 시험 지문에서는 문서에 맞는 도구를 Claude가 골라야 하고, 텍스트만 돌려주면 안 됩니다. 이 조건에 대응하는 답이 `any`입니다. 질문에 주로 나오는 세 설정 외에 **이번 요청에서는 도구를 쓰지 못하게 하는** `{"type": "none"}`도 있습니다.

## 첫 도구를 정한 뒤에는 누가 다음 단계를 고를까요?

팀에서 “다른 시스템에서 정보를 가져오기 전에 문서 자체에 적힌 정보부터 뽑자”고 정했다고 해 보세요. 문서 유형이나 작성일, 언급된 주문 번호처럼 문서를 설명하는 정보를 **메타데이터**라고 합니다. 뽑아 낸 주문 번호로 스토어의 주문 내역을 조회해 정보를 보태는 일은 **보강**(enrichment)입니다.

이 순서를 묻는 시험 문제에서는 첫 요청에 `extract_metadata`를 이름으로 지정합니다. Claude가 호출을 요청하면 코드가 도구를 실행하고 그 결과를 대화 기록에 붙입니다. 여기까지가 첫 단계입니다. 결과를 Claude에 돌려보낼 때는 [[22 실습 - 첫 도구 호출을 처음부터 끝까지 따라가기|22번 노트]]에서처럼 **새 API 요청**을 보냅니다. 대화 기록은 이어져도 `tool_choice`는 요청마다 정합니다. 후속 요청에서는 `auto`로 바꿉니다. 이제 Claude는 주문 상세 정보가 더 필요하면 `lookup_order`를 요청하고, 이미 충분하다면 고객에게 답할 수 있습니다. 강제 지정은 첫 단계만 고정하므로, 도구 하나를 강제해 두고 그 도구가 이후 단계 전체를 이끌 거라고 기대하면 안 됩니다.

## 시험에서 고른 설정을 코드에 쓸 수 있는지 확인하기

원본 과정에서 예로 든 **Opus 5.5, Sonnet 5.5, Fable 5.1**은 `any`와 이름을 지정한 `tool`을 보내면 API가 400 오류를 반환합니다. 이 모델에서는 `auto`와 `none`을 쓸 수 있습니다. 실제 코드에서는 사용할 모델 버전의 지원 범위를 먼저 확인하세요. [Anthropic 도구 선택 문서](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools)

그렇다면 이 모델에서 첨부 문서의 필드를 어떻게 받을까요? 원문은 두 방법을 소개합니다.

1. **도구 호출로 받을 때**는 `tool_choice`를 `auto`로 두고, 도구 정의에 `strict: true`를 설정합니다. 지침에는 “모든 첨부 파일에 `extract_metadata`를 호출하세요”처럼 도구 이름을 적습니다. 호출이 일어나면 입력은 스키마를 따릅니다. 다만 `auto`에서는 텍스트로만 답할 수도 있으므로 코드는 응답에 해당 `tool_use` 블록이 실제로 들어 있는지 확인한 뒤 값을 꺼냅니다.
2. **응답 자체를 데이터로 받을 때**는 원하는 스키마를 출력 형식으로 지정합니다. 이렇게 구조화된 출력(structured outputs)을 사용하면 도구 입력에서 필드를 꺼낼 필요 없이 응답을 직접 읽을 수 있습니다. 다음 노트에서 반품 이메일로 이 방법을 실습합니다.

시험 지문을 읽을 때는 요청 하나를 놓고 물어보세요. **글로 답해도 되는가? 어떤 도구든 꼭 써야 하는가? 첫 번째로 실행할 도구까지 정해져 있는가?** 세 질문을 구분하면 첨부 문서의 종류에 따라 도구를 고르는 문제와, 메타데이터를 먼저 추출하는 문제를 가를 수 있습니다.
