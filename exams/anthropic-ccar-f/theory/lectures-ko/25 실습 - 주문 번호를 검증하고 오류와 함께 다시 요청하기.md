# 25. 실습: 주문 번호를 검증하고 오류와 함께 다시 요청하기

지난 노트에서는 반품 이메일에서 주문 ID, 상품, 반품 사유를 꺼냈습니다. 신발을 반품하려는 고객은 주문 번호를 쓰지 않았는데, 응답에는 `unknown`이 들어 있었습니다. 이제 헤드폰을 반품하려는 고객이 주문 번호를 쓰기는 했지만 뒤에 숫자를 네 자리만 적었다고 해 보세요. 스토어의 주문 번호는 `ORD-` 뒤에 숫자 여덟 자리가 붙습니다. 두 이메일을 어떻게 처리하면 좋을까요?

이번 노트에서는 [[24 실습 - 스키마에 맞는 응답 받기|24번 노트]]의 추출 코드를 `validate.py`로 옮깁니다. 기존의 재킷과 신발 이메일에 헤드폰 이메일을 더합니다. 세 이메일을 실행하는 부분은 `if __name__ == "__main__":` 아래에 둡니다. 이렇게 하면 이 파일을 직접 실행할 때만 테스트가 돌아갑니다. 다른 파일에서 `extract` 함수를 가져와 쓸 때마다 테스트 메일까지 API로 보내는 일을 막을 수 있습니다.

## 주문 번호를 모르면 무엇을 반환할까요?

세 이메일을 한 통씩 보내 보면 재킷에서는 고객이 적은 주문 번호가 나옵니다. 신발에서는 `unknown`, 헤드폰에서는 숫자가 네 자리뿐인 번호가 나옵니다. 셋 다 문자열이라서 지금의 스키마를 통과합니다. 이대로 저장하면 나중에 주문을 조회할 때에야 문제가 드러납니다.

먼저 번호를 쓰지 않은 고객부터 생각해 보겠습니다. 지금은 주문 ID 필드가 필수이고 값은 문자열이어야 합니다. 필드는 그대로 두되, `type`을 `["string", "null"]`로 바꾸고 설명에 “이메일에 주문 번호가 없으면 `null`을 사용하세요”라고 적습니다. 다시 실행하면 신발의 주문 ID는 Python에서 `None`으로 출력됩니다. JSON의 `null`을 Python으로 읽은 값입니다. 이제 메일에 번호가 없다는 사실을 그대로 기록할 수 있습니다. 다만 헤드폰에서는 여전히 짧은 번호가 나옵니다.

## 코드에서 주문 번호의 형식 검사하기

`is_valid` 함수는 주문 ID 하나를 받아 `True` 또는 `False`를 반환합니다. `None`은 방금 허용했으니 통과시킵니다. 문자열이면 주문 번호의 형식을 확인합니다. 원문의 실습은 `ORD-`로 시작하는지, 전체 길이가 12자인지를 검사합니다. 이것만으로도 헤드폰 사례는 걸러지지만, 글자가 섞인 여덟 자리도 통과할 수 있습니다. 스토어 규칙까지 검사하려면 다음처럼 쓸 수 있습니다.

```python
import re

def is_valid(order_id):
    return order_id is None or re.fullmatch(r"ORD-[0-9]{8}", order_id) is not None
```

추출한 주문 ID를 이 함수에 넣고 실패하면 값을 출력해 보세요. 이번에는 헤드폰 번호 옆에 거부됐다는 메시지가 찍힙니다. 그래도 `extract`가 호출자에게 돌려준 값은 처음과 같습니다. 잘못된 번호가 저장되지 않게 하려면 검사 자체를 `extract` 안으로 옮겨야 합니다.

## 실패한 응답과 오류를 다음 요청에 담기

기존 함수에서 API를 호출하는 부분을 `ask_claude(messages)`로 분리합니다. 이 함수는 이메일 한 통 대신 지금까지의 메시지 목록을 받아 API에 넘기고, 응답 텍스트를 그대로 돌려줍니다. 그러면 `extract`가 응답을 JSON으로 읽을 수도 있고, Claude에게 자신이 방금 쓴 답을 그대로 보여 줄 수도 있습니다.

1. `extract`는 추출 지침과 고객 이메일을 합쳐 첫 `user` 메시지를 만듭니다. 이 목록으로 `ask_claude`를 호출합니다.
2. 돌아온 텍스트를 `json.loads`로 읽고 주문 ID를 검사합니다. 통과하면 딕셔너리를 바로 반환합니다.
3. 실패하면 시도 횟수와 거부한 값을 출력합니다. 대화에는 방금 받은 응답을 `assistant` 메시지로, 구체적인 오류와 수정 요청을 `user` 메시지로 덧붙입니다. 예를 들어 “추출한 주문 번호는 하이픈 뒤가 네 자리입니다. 여덟 자리 번호가 원문에 있는지 확인하고, 유효한 번호가 없으면 `null`을 쓰세요”라고 알려 줍니다. 다음 시도에는 이 목록 전체를 보냅니다.

최초 요청을 포함해 이메일 한 통당 최대 세 번 시도합니다. 모두 실패하면 `extract`는 `None`을 반환합니다. 여기서 **추출 결과 전체가 없는 경우**와 **추출에는 성공했지만 주문 ID만 없는 경우**를 구별하세요. 후자에서는 상품과 반품 사유가 든 딕셔너리를 사용할 수 있습니다.

원문의 실행에서 재킷과 신발은 첫 시도에 통과했습니다. 헤드폰은 첫 응답에서 네 자리 번호가 거부됐고, 두 번째 응답에서 주문 ID가 `null`로 바뀌어 통과했습니다. 같은 이메일을 한 번 더 보내기만 했다면 Claude는 왜 다시 읽어야 하는지 알기 어려웠을 겁니다. 어느 값이 어떤 검사에서 걸렸는지 알려 주면, 원문을 다시 볼 때 어디를 확인해야 하는지 분명해집니다.
