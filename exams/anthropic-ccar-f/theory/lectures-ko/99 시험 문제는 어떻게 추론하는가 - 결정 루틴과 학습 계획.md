# 99. 시험 문제는 어떻게 추론하는가: 결정 루틴과 학습 계획

지난 세 노트에서는 ShopAssist, 팀의 Claude Code 설정, 그리고 프롬프트를 돌아봤습니다. 시험이 보는 방식 그대로 봤습니다.

이번 노트는 그 모든 것을 어떤 시나리오 문제에도 쓸 수 있는 루틴 하나로 묶습니다. 시험의 오답 선택지는 실제 기법을 이름으로 대기 때문에 중요합니다. 기법을 아는 것만으로는 부족합니다. 그중에서 고르는 방법도 필요합니다.

> 가장 중요한 점: 선택지를 읽기 전에 문제 지문이 무엇을 요구하는지 정하세요. 문제 지문(stem)은 문제에서 상황을 설명하는 부분입니다.

## 여섯 단계 루틴

루틴은 여섯 단계이고, 두 그룹으로 나뉩니다.

| 단계 | 할 일 |
| --- | --- |
| 1. 제약 | 스토어에 필요한 것을 찾음 |
| 2. 실패 | 로그가 실제로 보여 주는 것을 찾음 |
| 3. 레이어 | 어디서 고장 났는지 찾음 |
| 4. 보장인가? | 지문이 보장을 요구하는지, 첫 단계를 요구하는지 정함 |
| 5. 최소 수정 | 충분하되 그 이상은 아닌 수정을 고름 |
| 6. 나머지는 탈락 | 다른 선택지마다 왜 지는지 이유 하나씩 댐 |

앞의 세 단계는 상황을 읽고, 뒤의 세 단계는 답을 고릅니다.

루틴 다음에는 정답이 여러 개인 문제와 학습 계획을 살펴봅니다.

## 루틴 적용하기

상황은 이렇습니다. ShopAssist의 로그에 한 패턴이 보입니다. 일부 고객이 30일 반품 기간이 지났는데도 반품을 요청합니다. 이런 경우 10건 중 1건쯤 ShopAssist가 직접 반품을 승인한다고 해 봅시다. 문제는 가장 효과적인 첫 단계를 묻습니다.

선택지는 네 개입니다.

- **A. 더 강한 프롬프트**: 대문자로 "절대 예외를 허용하지 말 것"이라고 쓴 줄.
- **B. 기준**: 예외 요청을 사람에게 보내는 몇 가지 예시가 붙은 명확한 에스컬레이션 기준.
- **C. 별도 모델**: 케이스를 에스컬레이션할지 해결할지 분류하도록 학습시킨 모델.
- **D. 신뢰도**: Claude가 낸 신뢰도 점수가 임계값 아래면 에스컬레이션.

**1단계, 제약.** 스토어의 목표는 첫 문의에서 80%를 해결하면서, 언제 에스컬레이션할지 아는 것입니다. 그러니 에스컬레이션을 너무 많이 해도 실패이고, 너무 적게 해도 실패입니다.

**2단계, 실패.** 로그가 실제로 말하는 것을 보세요. ShopAssist는 맞는 고객과 맞는 주문을 찾았습니다. 도구 호출도 맞았습니다. 누가 예외를 승인할 수 있는지에 대한 결정이 틀렸습니다.

**3단계, 레이어.** 이것은 판단의 문제이므로 실패한 레이어는 프롬프트입니다. ShopAssist에게는 정책 질문과 예외 요청 사이에 명확한 선이 없었습니다.

**4단계, 보장인가 첫 단계인가.** 지문은 "첫 단계"라고 말하고, 규칙이 매번 지켜져야 한다고 요구하는 부분은 없습니다. 그러니 프롬프트 레이어의 수정이 허용됩니다.

**5단계, 충분한 최소 수정.** 두 번째 선택지 B입니다. 추론 과정을 보여 주는 몇 가지 예시가 붙은 명확한 기준입니다.

**6단계, 나머지가 지는 이유.**

- 대문자는 Claude가 이미 가끔만 따르는 규칙을 되풀이합니다.
- 별도로 학습시킨 모델은 프롬프트를 고치기도 전에 새 인프라를 만듭니다.
- 신뢰도 점수는 Claude 스스로의 주장입니다. ShopAssist는 이 예외를 승인할 때도 이미 확신하고 있었습니다.

## 지문의 한 문장 바꾸기

이제 지문의 한 문장을 바꿔 봅니다. 지문이 "스토어의 법무팀은 에이전트가 기간이 지난 반품을 절대 승인하지 않을 것을 요구한다"고 말한다고 해 봅시다.

1~3단계는 그대로입니다. 4단계가 바뀝니다. "절대"는 보장을 요구하는 말이고, 프롬프트는 가끔 실패합니다. 그래서 답이 코드로 옮겨 갑니다. `process_refund`가 실행되기 전에 검사가 주문의 배송일과 반품 기간을 비교합니다. 예를 들어 40일째라면 30일을 넘으므로 호출을 막습니다.

실패는 같지만 지문이 다르고, 그래서 답도 다릅니다. 4단계가 선택지를 보기 전에 오는 이유가 이것입니다.

> **규칙**: 보장은 코드에 둡니다. 첫 단계는 보통 프롬프트나 도구 설명에서 시작합니다.

## 복수 선택 문항

복수 선택 문항은 몇 개를 골라야 하는지 적혀 있습니다. 함께 있으면 좋아 보이는 선택지 쌍을 찾지 마세요. 루틴으로 선택지마다 따로 판단합니다. 실패한 레이어를 고치는가? 지문이 요구하는 것을 충족하는가?

보장 버전에 "두 개 고르기"를 다시 적용해 봅니다.

| 선택지 | 판단 |
| --- | --- |
| 코드 검사 | 정답. 규칙을 강제함 |
| 기준 + 예시 | 정답. Claude가 예외 요청을 스스로 에스컬레이션하게 하므로 차단되는 호출이 드물어짐 |
| 대문자 | 오답. 프롬프트는 가끔 실패함 |
| 신뢰도 점수 | 오답. Claude 스스로의 주장 |

답의 개수는 처음이 아니라 마지막에 세세요.

## 루틴 요약

- 선택지보다 제약과 관찰된 실패를 먼저 읽습니다.
- 실패한 레이어의 이름을 댑니다. 코드, 도구 설명, 프롬프트, 또는 Claude가 받은 컨텍스트입니다.
- 지문이 보장을 요구하는지 첫 단계를 요구하는지 정합니다. 보장은 코드로 가고, 첫 단계는 보통 프롬프트나 설명에서 시작합니다.
- 충분한 최소 수정을 고르고, 다른 선택지마다 지는 이유를 댑니다.
- 복수 선택 문항에서는 선택지마다 따로 판단합니다.

## 마지막 몇 주의 학습 계획

시험에는 도메인이 다섯 개 있고, 비중은 다음과 같습니다.

| 도메인 | 비중 | 10시간 중 학습 시간 |
| --- | --- | --- |
| Agentic Architecture and Orchestration | 27% | 약 3시간 |
| Claude Code Configuration and Workflows | 20% | 약 2시간 |
| Prompt Engineering and Structured Output | 20% | 약 2시간 |
| Tool Design and MCP Integration | 18% | 약 2시간 |
| Context Management and Reliability | 15% | 약 1.5시간 |

컨텍스트와 신뢰성은 비중이 가장 작지만, 신뢰성은 많은 시나리오 문제 안에 등장합니다.

그러니 학습 시간을 이 비중대로 나누세요. 학습할 때마다 일부 시간은 시나리오 문제에 쓰고, 매번 여섯 단계를 돌려 보세요.

시험은 120분 동안 60문항이므로 문제마다 약 2분이 있습니다. 시험 날까지 루틴이 자동으로 나와야 합니다. 그러니 비중대로 공부하고, 시나리오로 연습하고, 모든 문제에서 답을 고르기 전에 지문이 무엇을 요구하는지 정하세요.
