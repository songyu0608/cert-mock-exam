예시: Alex의 재킷

타입이 유효해도 틀릴 수 있다

extraction = {
    "order_number": "ORD-12345678",
    "item": "jacket",
    "order_date": "2026-09-12",
    "delivery_date": "Sept 3rd",
    "reason": "wrong size",
}

# check 1: delivery_date is before order_date → FAIL
# check 2: delivery_date is not YYYY-MM-DD → FAIL

날짜가 서로 바뀌었고 하나는 형식이 틀렸습니다. 스키마는 둘 다 받아들이고, 우리 검사만 이것을 잡아냅니다.

원문 제목: Valid types can still be wrong (EXAMPLE: ALEX'S JACKET). 코드(영문 유지) 의미: 추출 결과 - 주문일 2026-09-12, 배송일 "Sept 3rd", 사유 사이즈 불일치. 검사 1: 배송일이 주문일보다 앞섬 → 실패 / 검사 2: 배송일이 YYYY-MM-DD 형식이 아님 → 실패. 캡션: The dates are swapped and one is badly written. The schema accepts both; only our own checks catch it.
