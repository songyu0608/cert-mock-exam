둘째: 단계 요약

요약이 모든 프롬프트의 첫머리에 온다

Context from discovery:
modules: refund_service, refund_rules, payouts
depends_on: orders, payments, notifications
tests: refund test files, listed by name
risks: the $500 limit is checked in two places,
       and only one of them has a test
open_questions: who sends the refund emails?

Task: decide where the new service begins and ends.

설계 서브에이전트를 시작하는 한 가지 방법: 탐색 기록 전체가 아니라 요약을 먼저 줍니다.

원문 제목: The summary opens every prompt (SECOND: THE PHASE SUMMARY). 프롬프트(영문 유지) 의미: 탐색 단계의 컨텍스트 - 모듈 refund_service, refund_rules, payouts / 의존 대상 orders, payments, notifications / 테스트 파일 이름 목록 / 위험: $500 한도가 두 곳에서 확인되는데 그중 하나에만 테스트가 있음 / 미해결: 환불 이메일은 누가 보내나? 과제: 새 서비스가 어디서 시작하고 끝나는지 정할 것. 캡션: One way to start a design subagent: the summary first, not the full discovery transcripts.
