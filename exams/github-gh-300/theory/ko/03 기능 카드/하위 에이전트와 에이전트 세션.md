# 하위 에이전트와 에이전트 세션

> [!summary] 한 줄 정의
> 하위 에이전트는 자기 컨텍스트에서 위임받은 작업을 하고 결과만 메인 에이전트에 돌려줘 메인 컨텍스트를 아낀다. 에이전트 세션은 에이전트 작업의 대화와 활동 단위다.

**English** Agent sessions and sub-agents

## 시험 트리거
- "긴 조사 작업으로 메인 대화 컨텍스트가 넘친다"
- "여러 관점 리뷰를 병렬로"
- "진행 중인 에이전트 작업을 추적"

## 핵심
- 하위 에이전트(VS Code): 자기 컨텍스트에서 일하고 집중된 결과를 메인 에이전트에 반환. 중간 작업이 메인 대화에 쌓이지 않는다.
- 메인 대화 기록을 물려받지 않으므로 목표·컨텍스트·허용 행동·기대 결과를 위임 내용에 담아야 한다. 호출마다 상태가 없다(stateless). 하위 에이전트는 다른 하위 에이전트를 만들 수 없다.
- 위임은 사용량과 조율 비용을 늘리므로 작은 작업은 직접 요청이 낫다.
- 사용자 지정 에이전트: `.github/agents/`의 `.agent.md` 같은 파일로 특화 에이전트를 정의해 위임에 쓴다.
- 에이전트 세션: 에이전트 작업의 대화와 활동. GitHub에서는 세션 로그로 작업·도구 사용을 확인하고, 내가 시작한 세션만 조회할 수 있다. 쓰기 권한이 없으면 세션은 읽기 전용.
- VS Code의 Sessions 뷰와 Agents 창에서 세션을 본다(세부 UI는 변동 정보).

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - 하위 에이전트는 메인 대화 기록을 그대로 물려받는다는 선택지 → 물려받지 않으므로 위임 내용에 필요한 정보를 담는다
> - 하위 에이전트를 쓰면 항상 비용이 줄어든다는 선택지 → 사용량·조율 비용이 늘 수 있다. 이점은 메인 컨텍스트 절약
