# 도메인 4　프롬프트 엔지니어링과 컨텍스트 구성

**English** Domain 4: Apply prompt engineering and context crafting  
**한국어 공식 안내서** 프롬프트 엔지니어링 및 컨텍스트 제작 적용

도메인 4 (10–15%) · 목표 6개

프롬프트 구조와 컨텍스트, 제로샷·퓨샷, 프롬프트 작성 모범 사례, 프롬프트 처리 흐름과 채팅 기록 사용을 다룬다.

## 목표 4.1

**프롬프트 구조와 컨텍스트를 설명한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Describe prompt structure and context
>
> 프롬프트 구조 및 컨텍스트 설명

프롬프트는 목표·맥락·요구사항·예시로 구성하고, 4S(Single, Specific, Short, Surround)를 따른다.

관련 카드: [[사용자 지정 지침]] · [[프롬프트 작성 원칙(4S)]] · [[컨텍스트 결정 방식]]

## 목표 4.2

**컨텍스트가 어떻게 결정되는지 이해한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Understand how context is determined
>
> 컨텍스트가 결정되는 방식 이해

자동 수집 컨텍스트(커서 주변, 열린 탭 등)와 명시 컨텍스트(#file, #selection, @참가자), 지침·Spaces·MCP가 컨텍스트를 정한다.

관련 카드: [[컨텍스트 결정 방식]]

## 목표 4.3

**제로샷과 퓨샷 프롬프팅을 사용한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Use zero-shot and few-shot prompting
>
> 제로 샷 및 몇 샷 프롬프트 사용

제로샷은 예시 없이, 원샷은 예시 하나, 퓨샷은 여러 예시로 패턴을 따르게 한다. 모델은 다시 학습하지 않는다.

관련 카드: [[제로샷·원샷·퓨샷 프롬프팅]]

## 목표 4.4

**프롬프트 작성 모범 사례를 적용한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Apply best practices for prompt crafting
>
> 프롬프트 작성에 대한 모범 사례 적용

docs 8전략: 넓게 시작해 구체화, 예시, 작업 분할, 모호함 회피, 관련 코드 지정, 실험·반복, 기록 관리, 좋은 코딩 관행.

관련 카드: [[프롬프트 엔지니어링 모범 사례]]

> [!abstract] 성능을 위한 프롬프트 설계

## 목표 4.5

**프롬프트 엔지니어링 원칙을 설명한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Explain prompt engineering principles
>
> 프롬프트 엔지니어링 원칙 설명

명확성, 충분한 맥락, 예시, 단언하고 반복(assert and iterate), 역할 프롬프팅 같은 원칙으로 성능을 높인다.

관련 카드: [[프롬프트 작성 원칙(4S)]] · [[프롬프트 엔지니어링 모범 사례]]

## 목표 4.6

**프롬프트 처리 흐름과 채팅 기록 사용을 설명한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Describe prompt process flow and chat history usage
>
> 프롬프트 프로세스 흐름 및 채팅 기록 사용 설명

프롬프트는 컨텍스트 수집 → 필터 → 모델 → 후처리를 거치고, 채팅 기록이 다음 요청의 컨텍스트가 된다. 길어진 기록은 요약·초기화한다.

관련 카드: [[프롬프트 처리 흐름]] · [[채팅 기록과 체인 프롬프팅]]

## 요약
- 4S: Single · Specific · Short · Surround.
- 새 작업 = 새 스레드.
- 퓨샷 ≠ 파인튜닝.

## 이 도메인의 카드
- [[프롬프트 작성 원칙(4S)]] — 좋은 프롬프트는 한 가지 작업에 집중하고(Single), 구체적이며(Specific), 간결하고(Short), 주변 컨텍스트를 갖춘다(Surround). Microsoft Learn 모듈의 원칙이다.
- [[컨텍스트 결정 방식]] — Copilot은 커서 주변 코드, 열린 탭, 파일 이름·유형, 프로젝트 구조, 사용자가 명시한 #·@ 참조, 지침 파일 등으로 컨텍스트를 정한다.
- [[제로샷·원샷·퓨샷 프롬프팅]] — 예시 없이 요청하면 제로샷, 예시 하나를 주면 원샷, 여러 예시를 주면 퓨샷이다. 예시가 많을수록 원하는 패턴·규칙을 따르기 쉽다.
- [[프롬프트 엔지니어링 모범 사례]] — GitHub 문서의 Copilot 프롬프트 전략: 넓게 시작해 구체화, 예시 제공, 복잡한 작업 분할, 모호함 회피, 관련 코드 지정, 실험·반복, 기록 관리, 좋은 코딩 관행.
- [[채팅 기록과 체인 프롬프팅]] — Copilot Chat은 대화 기록을 컨텍스트로 쓴다. 단계적으로 요청을 이어 가면(체인 프롬프팅) 정밀해지지만 기록이 길어지면 비용과 혼선이 커진다.
