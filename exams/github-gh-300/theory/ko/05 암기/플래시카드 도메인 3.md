## 개념 확인
Business·Enterprise에서 GitHub.com Copilot Chat 프롬프트 기본 보존 기간은?::최대 28일
IDE 코드 제안 프롬프트는 제안 후 어떻게 되나?::폐기(학습용으로 보존하지 않음)
Learn 모듈의 인바운드 단계 순서는?::안전한 전송·컨텍스트 수집 → 프록시 필터 → 유해성 필터 → LLM 생성
Copilot이 커서 앞뒤 코드를 함께 쓰는 전처리 기법은?::Fill-in-the-Middle(FIM)
후처리의 코드 품질 검사 예 두 가지는?::XSS, SQL 인젝션
제안이 파일에 반영되는 시점은?::사용자가 명시적으로 수락할 때
GitHub가 Copilot 파인튜닝에 쓴 방법은?::LoRA(Low-Rank Adaptation)
새롭거나 드문 기술에서 Copilot의 한계는?::제안 정확도·관련성이 낮을 수 있다

## 상황 → 판단
상황: 우리 코드가 학습에 쓰이나(Business) → 정답은?::IDE 제안 프롬프트는 폐기, 학습 미사용
상황: GitHub.com 채팅 기록 보존 → 정답은?::최대 28일(Business·Enterprise 기본)
상황: 프롬프트 조작·해킹 시도 → 정답은?::프록시 필터
상황: 생성 코드의 SQL 인젝션 패턴 → 정답은?::후처리 코드 품질 검사
상황: 커서 앞뒤 코드를 함께 사용 → 정답은?::Fill-in-the-Middle(FIM)
상황: 새 라이브러리 API를 잘못 씀 → 정답은?::LLM 한계(학습 데이터) → 문서·예시 제공
