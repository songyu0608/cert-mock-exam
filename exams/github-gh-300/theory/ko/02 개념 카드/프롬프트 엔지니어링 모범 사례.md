# 프롬프트 엔지니어링 모범 사례

> [!summary] 한 줄 정의
> GitHub 문서의 Copilot 프롬프트 전략: 넓게 시작해 구체화, 예시 제공, 복잡한 작업 분할, 모호함 회피, 관련 코드 지정, 실험·반복, 기록 관리, 좋은 코딩 관행.

**English** Prompt engineering best practices for Copilot

## 시험 트리거
- "한 번에 전체 앱을 만들어 달라고 했더니 엉망"
- "'이거 고쳐 줘'라고 했더니 엉뚱한 함수 수정"
- "첫 결과가 마음에 안 든다"

## 핵심
- ① 넓게 시작한 뒤 구체화: 목표·시나리오를 먼저, 이어서 세부 요구사항.
- ② 예시 제공: 입력·출력 샘플, 구현, 단위 테스트.
- ③ 복잡한 작업을 작은 작업으로 나눠 하나씩.
- ④ 모호함 회피: "이것" 대신 함수·파일 이름을 명시, 드문 라이브러리는 설명하거나 import.
- ⑤ 관련 코드 지정: 관련 파일 열기, 무관한 파일 닫기, 코드 선택.
- ⑥ 실험과 반복: 결과가 틀리면 프롬프트를 고쳐 다시.
- ⑦ 기록을 관련 있게: 새 작업은 새 스레드, 쓸모없는 요청은 삭제.
- ⑧ 좋은 코딩 관행: 일관되고 읽기 쉬운 이름·주석·모듈화·테스트가 응답 품질을 높인다.
- Learn: 단언하고 반복(assert and iterate) — 처음부터 다시 하지 말고 주석을 보강해 재요청. 역할 프롬프팅 — "보안 전문가로서…"처럼 전문가 역할 지정.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - 좋은 결과를 위해 한 프롬프트에 모든 요구사항을 한꺼번에 넣는다는 선택지 → 작은 작업으로 나눈다
> - 결과가 나쁘면 대화를 계속 이어 붙인다는 선택지 → 무관한 기록은 정리하고, 새 작업은 새 스레드
