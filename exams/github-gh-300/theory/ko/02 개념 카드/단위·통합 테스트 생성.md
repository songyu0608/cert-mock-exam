# 단위·통합 테스트 생성

> [!summary] 한 줄 정의
> Copilot Chat의 /tests나 자연어 요청으로 단위·통합 테스트를 만들고, 엣지 케이스와 어설션을 명시적으로 요청한다. 생성된 테스트도 검토가 필요하다.

**English** Generating tests, edge cases, and assertions

## 시험 트리거
- "선택한 메서드의 단위 테스트를 성공·실패·엣지 케이스까지"
- "테스트 프레임워크가 아직 없다"
- "음수와 0 입력도 테스트"

## 핵심
- /tests: Agent 모드에서는 적절한 테스트 파일에 바로 쓰고, 기존 테스트 프레임워크와 스타일을 감지해 맞춘다.
- /setupTests: 프레임워크가 없을 때 추천·구성(Agent 모드).
- Ask 모드: 파일을 바꾸지 않고 테스트 케이스 비교, 프레임워크·어설션 스타일 추천, 예시 확인.
- 엣지 케이스: 명시적으로 요청하거나 Ask 모드로 시나리오 목록부터 받는다(예: "음수와 0").
- 통합 테스트: "데이터 접근 계층의 통합 테스트를 만들어 줘"처럼 자연어로.
- 컨텍스트: #selection, #codebase, #editor 등.
- 어설션 규칙: 사용자 지정 지침(예: `applyTo: tests/**`의 *.instructions.md)으로 Arrange-Act-Assert 같은 관례를 지정.
- 검토: diff를 보고 Keep·Undo, 빌드·실행으로 확인. 생성 테스트가 모든 시나리오를 덮지는 않는다.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - Copilot이 만든 테스트가 통과하면 커버리지가 충분하다는 선택지 → 모든 시나리오를 덮지 못하므로 검토 필요
> - Ask 모드에서 /tests를 쓰면 테스트 파일이 바로 생성된다는 선택지 → 파일에 쓰는 것은 Agent 모드
