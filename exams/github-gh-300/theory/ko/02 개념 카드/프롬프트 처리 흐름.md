# 프롬프트 처리 흐름

> [!summary] 한 줄 정의
> 사용자 프롬프트는 안전한 전송과 컨텍스트 수집 → 프록시 필터 → 유해성 필터 → LLM 생성 → 후처리·검증 → 전달의 단계를 거친다(Microsoft Learn 모듈).

**English** Copilot prompt process flow (inbound and outbound)

## 시험 트리거
- "Copilot이 프롬프트에 무엇을 붙여 보내나"
- "부적절한 요청은 어디서 걸러지나"
- "응답이 사용자에게 오기 전 검사"

## 핵심
- 인바운드 ① 안전한 전송(HTTPS)과 컨텍스트 수집: 커서 앞뒤 코드, 파일 이름·유형, 인접한 열린 탭, 프로젝트 구조·경로, 언어·프레임워크. Fill-in-the-Middle(FIM)로 전처리.
- ② 프록시 필터: 프롬프트를 조작해 시스템을 해킹하거나 생성 방식을 캐내려는 시도를 차단.
- ③ 유해성 필터: 혐오·공격적·부적절한 내용과 개인 데이터(이름, 주소, 식별 번호)를 거른다.
- ④ LLM이 코드 제안 생성.
- 아웃바운드 ⑤ 후처리·응답 검증: 유해성 필터, 코드 품질 검사(XSS, SQL 인젝션 같은 흔한 버그·취약점), 선택적 공개 코드 일치 필터(약 150자). 통과하지 못하면 잘리거나 폐기.
- ⑥ 모든 필터를 통과한 응답만 전달 → 피드백 루프(수락·수정·거절) → ⑦ 반복.
- 공식 docs(책임 있는 사용)도 같은 큰 흐름을 설명한다: 커서 주변 코드 + 열린 탭 → 전처리 → LLM → 콘텐츠 필터(유해·불안전 코드) → 공개 코드 차단 또는 참조 표시 → 수락 시 적용.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - 공개 코드 필터가 항상 켜져 있다는 선택지 → 선택(관리자·사용자가 설정)
> - 프록시 필터가 LLM 응답 품질을 검사하는 단계라는 선택지 → 프록시 필터는 입력 쪽 조작·해킹 시도 차단, 품질 검사는 후처리
