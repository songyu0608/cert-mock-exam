# 리포지토리 모범 사례

> [!summary] 한 줄 정의
> README·LICENSE·CONTRIBUTING 같은 표준 파일, 브랜치와 PR 중심 흐름, 보호 규칙, 레이블·템플릿, 정리(보관)를 갖춰 협업하기 쉬운 리포지토리를 유지한다.

**English** Best practices for repository maintenance and collaboration

## 시험 트리거
- "새 기여자가 어디서 시작할지 모른다"
- "기본 브랜치가 자주 깨진다"
- "오래된 프로젝트를 정리"

## 핵심
- 문서: README(소개·시작 방법), LICENSE(사용 조건), CONTRIBUTING(기여 방법), SECURITY(취약점 보고) → [[커뮤니티 상태 파일]].
- 흐름: 기본 브랜치에 직접 커밋하지 않고 브랜치 + PR + 리뷰(GitHub 플로). 짧고 설명적인 브랜치 이름.
- 보호: 기본 브랜치에 리뷰·상태 확인 필수 → [[브랜치 보호 규칙과 룰셋]]. 책임자 지정 → [[CODEOWNERS]].
- 정리: 레이블·이슈 템플릿으로 분류, 병합된 브랜치 삭제, 유지하지 않는 리포지토리는 보관.
- 재사용: 같은 구조로 시작할 땐 템플릿 리포지토리.
- 〔해석〕 이 카드는 위 공식 문서들의 권장 사항을 모은 정리다.
