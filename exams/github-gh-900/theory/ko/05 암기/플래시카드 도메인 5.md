# 플래시카드 도메인 5　GitHub로 프로젝트 관리

#flashcards/gh-900/d5

형식: `질문::답` (Spaced Repetition 플러그인). 플러그인이 없어도 한 줄씩 읽으면 된다.

## 개념 확인
Projects의 세 가지 레이아웃은?::테이블, 보드, 로드맵
스프린트 같은 기간 단위를 표현하는 필드 유형은?::반복(iteration) 필드
새 프로젝트에서 기본으로 켜진 내장 워크플로 2개는?::이슈·PR 닫힘 → Done, PR 병합 → Done
신규 기여자용 이슈를 표시하는 기본 레이블은?::good first issue
마일스톤 페이지에서 보이는 진행 지표는?::마감일과 완료율(열린·닫힌 수)
저장된 답글은 어디에 속하고 몇 개까지?::개인 계정, 최대 100개
이슈·PR당 최대 담당자 수는?::10명
프로젝트 인사이트의 기본 과거 차트는?::번업(Burn up) 차트

## 상황 → 판단
상황: 칸반으로 진행 상황 보기 → 정답은?::Projects 보드 레이아웃
상황: 마감일 기준 타임라인 → 정답은?::Projects 로드맵 레이아웃
상황: 스프린트 단위 계획 → 정답은?::반복(iteration) 필드
상황: PR 병합 시 상태를 Done으로 → 정답은?::내장 워크플로(기본 켜짐)
상황: 릴리스까지 남은 작업 비율 → 정답은?::마일스톤(완료율)
상황: 같은 안내 답변을 반복 입력 → 정답은?::저장된 답글
상황: 이 이슈의 책임자를 분명히 → 정답은?::담당자 지정
상황: 완료 대 남은 작업 추이 → 정답은?::프로젝트 인사이트 번업 차트

## 목표 번호

목표 5.2의 내용은?::프로젝트, 레이블, 마일스톤, 워크플로를 구성하는 방법을 설명한다
목표 5.3의 내용은?::저장된 답글과 담당자로 소통을 간소화하는 방법을 식별한다
목표 5.4의 내용은?::프로젝트 인사이트로 진행 상황과 생산성을 추적하는 방법을 설명한다
