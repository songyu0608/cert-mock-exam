# 플래시카드 도메인 7　GitHub 커뮤니티 살펴보기

#flashcards/gh-900/d7

형식: `질문::답` (Spaced Repetition 플러그인). 플러그인이 없어도 한 줄씩 읽으면 된다.

## 개념 확인
개인 계정으로 후원할 때 GitHub 수수료는?::없음(조직 후원은 최대 6%)
GitHub Sponsors의 후원 방식 두 가지는?::일회성, 매월(등급 선택)
공개 리포지토리에서 기본으로 켜지는 무료 보안 기능 2가지는?::코드 스캐닝, 비밀 스캐닝
공개 리포지토리에서 표준 GitHub 호스트 러너 사용 요금은?::무료
사람·조직을 팔로우하면 활동이 어디에 보이나?::개인 대시보드(공개 활동만)
리포지토리 릴리스만 알림으로 받으려면?::워치 → 사용자 지정(Custom) → Releases
GitHub Marketplace에서 찾을 수 있는 두 가지는?::Actions와 Apps
Marketplace에서 앱을 판매할 수 있는 소유자는?::조직(유료 요금제는 게시자 확인 필요)
InnerSource를 한 줄로?::조직 내부 소프트웨어에 오픈 소스 관행 적용("방화벽 안의 오픈 소스")
엔터프라이즈 구성원 전원이 읽을 수 있게 하는 공개 범위는?::내부(internal)
쓰기 권한 없는 프로젝트에 변경을 제안하는 흐름은?::포크 → 수정 → 원본으로 풀 리퀘스트
포크와 클론의 차이는?::포크는 GitHub 상의 사본 리포지토리, 클론은 로컬 사본
신규 기여자에게 적합한 이슈를 찾는 레이블 두 가지는?::good first issue, help wanted
프로젝트가 활발히 유지되는지 보려면?::Insights → Pulse

## 상황 → 판단
상황: 메인테이너를 금전적으로 후원 → 정답은?::GitHub Sponsors
상황: 어떤 개발자의 공개 활동을 계속 보기 → 정답은?::팔로우
상황: 리포지토리 릴리스 알림만 → 정답은?::워치 → Custom → Releases
상황: 워크플로에 쓸 기존 액션 찾기 → 정답은?::GitHub Marketplace
상황: 팀 간 코드 재사용·기여를 사내에서 → 정답은?::InnerSource(internal 리포지토리)
상황: 쓰기 권한 없는 프로젝트에 수정 제안 → 정답은?::포크 → PR
상황: 초보 기여자용 이슈 찾기 → 정답은?::good first issue 레이블

## 목표 번호
목표 7.1의 내용은?::오픈 소스와 GitHub Sponsors의 이점을 설명한다
목표 7.2의 내용은?::GitHub가 오픈 소스 프로젝트를 지원하고 발전시키는 방식을 설명한다
목표 7.3의 내용은?::사용자와 조직을 팔로우해 활동 소식을 받는 방법을 식별한다
목표 7.4의 내용은?::GitHub Marketplace와 그 용도를 설명한다
목표 7.5의 내용은?::InnerSource가 조직 안에서 오픈 소스 원칙을 적용하는 방식을 설명한다
목표 7.6의 내용은?::협업을 촉진하려면 포크, 템플릿, 검색 가능한 리포지토리를 언제 쓰는지 안다
