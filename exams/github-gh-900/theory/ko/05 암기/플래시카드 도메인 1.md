# 플래시카드 도메인 1　Git과 GitHub 기본 이해

#flashcards/gh-900/d1

형식: `질문::답` (Spaced Repetition 플러그인). 플러그인이 없어도 한 줄씩 읽으면 된다.

## 개념 확인
분산 버전 관리 시스템의 특징은?::모든 개발자가 프로젝트와 전체 이력의 완전한 사본을 가진다
버전 관리가 기록해 보여 주는 네 가지는?::무엇이, 누가, 언제, 왜 바뀌었는지
Git과 GitHub의 차이를 한 줄로?::Git은 버전 관리 도구, GitHub는 Git 리포지토리 호스팅 + 협업 기능 플랫폼
풀 리퀘스트는 Git과 GitHub 중 어디의 기능인가?::GitHub
스테이징한 변경을 이력에 스냅샷으로 저장하는 명령은?::git commit
로컬 커밋을 원격 브랜치로 올리는 명령은?::git push
원격 변경을 가져와 현재 브랜치에 적용하는 명령은?::git pull
조직 계정에 로그인할 수 있나?::없다. 구성원은 각자의 사용자 계정으로 로그인한다
여러 조직의 정책·결제를 중앙에서 관리하는 계정은?::엔터프라이즈 계정
SAML SSO와 internal 리포지토리를 쓰려면 필요한 요금제는?::GitHub Enterprise
99.9% 월간 가동률 SLA와 EMU를 제공하는 요금제는?::GitHub Enterprise Cloud
GitHub 플로 6단계 순서는?::브랜치 만들기 → 변경·커밋 → PR 만들기 → 리뷰 반영 → 병합 → 브랜치 삭제
병합한 브랜치를 삭제하는 이유는?::작업 완료를 알리고 오래된 브랜치를 실수로 재사용하지 않게
작업 목록(체크박스) 문법은?::- [ ] 할 일 / - [x] 완료
팀 전체를 멘션하는 문법은?::@조직이름/팀이름
경고 블록 5종은?::NOTE, TIP, IMPORTANT, WARNING, CAUTION
GitHub Desktop이 특히 맞는 사용자(공식 문서)는?::Git·GitHub 초보자(변경을 시각화), 문법을 외우지 않으려는 숙련자
GitHub Mobile이 보안에 쓰이는 두 가지 방식은?::2FA 수단, 새 기기 로그인 시도 확인

## 상황 → 판단
상황: 파일 이전 버전으로 되돌리고 누가 바꿨는지 알아야 함 → 정답은?::버전 관리(Git)
상황: 인터넷 없이 로컬에서 이력 조회·커밋 → 정답은?::Git(분산형, 전체 이력 사본)
상황: 이슈·PR 리뷰·호스팅이 필요 → 정답은?::GitHub
상황: 여러 사람이 리포지토리를 공유·소유하고 팀으로 권한 관리 → 정답은?::조직(Organization)
상황: 여러 조직의 정책·청구를 중앙에서 관리 → 정답은?::엔터프라이즈 계정
상황: 변경을 main에 반영하기 전 리뷰 → 정답은?::브랜치 → PR → 리뷰 → 병합(GitHub 플로)
상황: 아직 작업 중인 변경을 공유하고 피드백 → 정답은?::초안(draft) 풀 리퀘스트
상황: 이슈에 체크 가능한 할 일 목록 → 정답은?::작업 목록 - [ ]
상황: 경고·주의 문구를 눈에 띄게 → 정답은?::> [!WARNING] 등 경고(alerts) 문법
상황: Git 명령 없이 GUI로 커밋·푸시 → 정답은?::GitHub Desktop
상황: 이동 중 알림 분류·PR 리뷰·2FA 승인 → 정답은?::GitHub Mobile
