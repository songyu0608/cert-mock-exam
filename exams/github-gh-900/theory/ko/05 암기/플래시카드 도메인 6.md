# 플래시카드 도메인 6　개인정보 보호, 보안, 관리 이해

#flashcards/gh-900/d6

형식: `질문::답` (Spaced Repetition 플러그인). 플러그인이 없어도 한 줄씩 읽으면 된다.

## 개념 확인
비밀번호와 2FA 요구를 한 번에 만족하는 로그인 수단은?::패스키
2FA를 잃었을 때 쓰는 것은?::설정 때 받은 복구 코드(또는 추가 복구 수단)
조직 소유자가 2FA를 요구할 수 있는 대상은?::구성원, 결제 관리자, 외부 협업자
코드 쓰기 없이 이슈·PR을 정리하는 최소 역할은?::Triage
공개 범위 변경·리포지토리 삭제가 가능한 역할은?::Admin
개인 계정 리포지토리의 권한 단계는?::소유자와 협업자 두 단계
구성원이 아닌데 일부 리포지토리에 접근하는 사람의 역할은?::외부 협업자(outside collaborator)
권장 최소 조직 소유자 수는?::2명
모든 리포지토리의 보안 알림을 보고 보안 설정을 관리하는 역할은?::보안 관리자(security manager)
중첩 팀에서 자식 팀이 받는 것은?::부모 팀의 접근 권한 상속
중첩할 수 없는 팀 유형은?::secret 팀
EMU에서 계정을 만들고 관리하는 주체는?::외부 ID 공급자(IdP)
EMU 관리형 계정이 할 수 없는 것 2가지는?::공개 콘텐츠 생성, 엔터프라이즈 밖 협업
Copilot 조직 정책을 설정할 수 있는 사람은?::Copilot Business·Enterprise 조직의 소유자
엔터프라이즈 정책과 조직 정책이 다르면?::엔터프라이즈 정책이 우선(조직이 덮어쓸 수 없음)
엔터프라이즈 구성원 전체가 읽을 수 있는 공개 범위는?::내부(internal)
공개 범위를 바꾸면 공통으로 사라지는 것은?::스타와 워처
여러 룰셋이 같은 브랜치에 적용되면?::규칙이 합쳐지고 가장 엄격한 버전이 적용
병합 커밋을 막아 squash·rebase만 허용하는 설정은?::선형 이력 필수(Require linear history)
비밀이 든 커밋의 푸시를 막는 기능은?::푸시 보호(Secret Protection)
공개 리포지토리에서 기본으로 켜진 무료 보안 기능 2가지는?::코드 스캔, 비밀 검색

## 상황 → 판단
상황: 비밀번호와 2FA를 한 번에 → 정답은?::패스키
상황: 2FA 기기를 잃어버림 → 정답은?::복구 코드(Support는 복구해 주지 않음)
상황: 코드 쓰기 없이 이슈 레이블·닫기·할당만 → 정답은?::Triage 역할
상황: 리포지토리 설정 일부(토픽 등) 관리, 보호 규칙은 불가 → 정답은?::Maintain 역할
상황: 외부 컨설턴트에게 특정 리포지토리만 → 정답은?::외부 협력자(Outside collaborator)
상황: 보안 경고 열람·보안 설정만 맡는 팀 → 정답은?::보안 관리자(Security manager)
상황: 회사 IdP로 계정을 만들고 지우며 외부 활동 차단 → 정답은?::EMU
상황: 조직에서 Copilot 기능·모델을 제한 → 정답은?::Copilot 정책(Settings → Copilot → Policies)
상황: 사내 전원만 보이게 → 정답은?::internal 공개 범위
상황: main 병합 전 승인 2명·테스트 통과 강제 → 정답은?::브랜치 보호 규칙 또는 룰셋
상황: 규칙 여러 개를 겹쳐 적용 → 정답은?::룰셋
상황: 하위 팀이 상위 팀 권한을 물려받게 → 정답은?::중첩 팀(부모-자식)

## 목표 번호
목표 6.1의 내용은?::2단계 인증(2FA)과 패스키로 계정을 보호하는 방법을 설명한다
목표 6.2의 내용은?::리포지토리와 조직의 접근 권한과 역할을 식별한다
목표 6.3의 내용은?::EMU(Enterprise Managed Users)와 조직 전체 Copilot 정책 관리의 목적을 설명한다
목표 6.4의 내용은?::리포지토리 공개 범위 옵션, 표시 설정, 브랜치 보호 규칙을 설명한다
목표 6.5의 내용은?::조직 설정, 팀, 역할을 관리하는 방법을 안다
