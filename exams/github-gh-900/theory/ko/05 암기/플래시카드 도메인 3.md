# 플래시카드 도메인 3　GitHub로 협업하기

#flashcards/gh-900/d3

형식: `질문::답` (Spaced Repetition 플러그인). 플러그인이 없어도 한 줄씩 읽으면 된다.

## 개념 확인
큰 이슈를 작게 나누는 기능은?::하위 이슈(sub-issues)
이슈 간 막힘 관계를 표시하는 기능은?::이슈 종속성(blocked by / blocking)
PR 리뷰의 세 가지 결정은?::Comment, Approve, Request changes
PR의 모든 커밋을 하나로 합쳐 병합하는 방법은?::Squash and merge
병합 커밋 없이 선형 이력을 만드는 방법은?::Rebase and merge
디스커션에서 질문의 답을 표시할 수 있는 카테고리 형식은?::Q&A
디스커션을 켜는 사람은?::리포지토리 또는 조직 관리자
닫기 키워드가 동작하는 조건은?::PR이 기본 브랜치를 대상으로 할 때
다른 리포지토리 이슈를 닫는 문법은?::Fixes 소유자/리포지토리#번호
이슈 템플릿 폴더 위치는?::기본 브랜치의 .github/ISSUE_TEMPLATE
필수 입력 칸이 있는 이슈 양식의 파일 형식은?::YAML(.yml)
승인된 PR만 보는 한정자는?::review:approved
특정 사용자가 만든 것만 제외하는 문법은?::-author:사용자
알림을 나중에 보려고 보관하는 동작과 필터는?::Save, is:saved
저장하지 않은 알림의 보관 기간은?::3개월
비밀 gist를 볼 수 있는 사람은?::URL을 아는 누구나(목록·검색에만 안 나옴)
gist의 정체는?::포크·클론·이력이 있는 Git 리포지토리
검색 엔진이 위키를 색인하는 조건은?::스타 500개 이상이고 공개 편집을 막은 위키
사용자 사이트 리포지토리 이름은?::<사용자 이름>.github.io
프로젝트 사이트 주소 형식은?::<소유자>.github.io/<리포지토리>

## 상황 → 판단
상황: 버그·기능 요청 추적 → 정답은?::이슈
상황: 질문·아이디어·공지 같은 열린 대화 → 정답은?::디스커션
상황: PR 병합 시 이슈 자동 닫기 → 정답은?::PR 본문에 Closes #번호(기본 브랜치 대상)
상황: 이슈 작성 시 필수 항목 강제 → 정답은?::이슈 양식(YAML issue form)
상황: 나에게 리뷰 요청된 열린 PR만 → 정답은?::is:pr is:open review-requested:@me
상황: 리뷰 요청 알림만 보고 싶다 → 정답은?::reason:review-requested 필터
상황: 설정 파일 조각을 리포지토리 없이 공유 → 정답은?::Gist
상황: 프로젝트 장문 문서를 리포지토리 안에 → 정답은?::위키
상황: 프로젝트 문서 웹사이트를 무료 호스팅 → 정답은?::GitHub Pages
