# 플래시카드 도메인 2　GitHub 리포지토리 다루기

#flashcards/gh-900/d2

형식: `질문::답` (Spaced Repetition 플러그인). 플러그인이 없어도 한 줄씩 읽으면 된다.

## 개념 확인
README가 여러 위치에 있을 때 우선순위는?::.github → 루트 → docs
프로필 README를 만드는 방법은?::사용자 이름과 같은 이름의 공개 리포지토리 루트에 README 작성
라이선스가 없는 공개 리포지토리를 다른 사람이 할 수 있는 것은?::보기와 포크(이용 약관). 복제·배포·파생 저작물 권리는 없다
취약점 보고 방법을 안내하는 파일은?::SECURITY.md
조직 기본 커뮤니티 상태 파일을 두는 곳은?::조직의 공개 .github 리포지토리
CODEOWNERS에서 여러 패턴이 같은 파일에 맞으면?::마지막으로 일치한 패턴이 우선
코드 소유자 리뷰를 필수로 만드는 방법은?::브랜치 보호 규칙 또는 룰셋에서 코드 소유자 리뷰 필수 설정
템플릿에서 만든 리포지토리가 원본으로 PR을 보낼 수 없는 이유는?::이력이 관련 없기(unrelated histories) 때문
템플릿 리포지토리 설정 권한은?::리포지토리 관리자(admin)
브라우저 업로드 파일 크기 한도는?::파일당 25MiB
100MiB를 넘는 파일을 저장하려면?::Git LFS(Large File Storage)
리포지토리 활동을 기간별로 요약하는 인사이트는?::Pulse
스타의 세 가지 용도는?::북마크, 감사(지지) 표시, 추천·순위(Explore)에 반영
SLA와 지원이 제공되는 출시 단계는?::GA(일반 공급)
종속성 그래프에서 내보낼 수 있는 의존성 목록 형식은?::SBOM(소프트웨어 자재 명세서)
보관된 리포지토리를 다시 수정하려면?::보관 해제(unarchive) 후 수정
유지하지 않는 리포지토리를 지우지 않고 정리하는 방법은?::보관(archive)해 읽기 전용으로

## 상황 → 판단
상황: 프로젝트를 처음 본 사람이 무엇인지 알아야 함 → 정답은?::README
상황: 다른 사람이 코드를 재사용할 수 있게 → 정답은?::LICENSE 추가
상황: 특정 경로 변경 시 담당 팀에 리뷰 자동 요청 → 정답은?::CODEOWNERS
상황: 취약점을 공개 이슈 대신 어떻게 보고하나 → 정답은?::SECURITY.md
상황: 조직의 모든 리포지토리에 같은 CONTRIBUTING → 정답은?::.github 리포지토리의 기본 커뮤니티 상태 파일
상황: 같은 폴더 구조로 새 리포지토리를 반복 생성 → 정답은?::템플릿 리포지토리
상황: 200 MiB 파일을 리포지토리에 넣어야 함 → 정답은?::Git LFS
상황: 최근 기간의 병합 PR·이슈 활동 요약 → 정답은?::Insights → Pulse
상황: 프로젝트를 나중에 다시 찾으려 표시 → 정답은?::스타
상황: 얼리 액세스 기능을 켜 보고 싶다 → 정답은?::기능 미리 보기(Feature preview)
상황: 어떤 패키지에 의존하고 취약점이 있는지 → 정답은?::종속성 그래프 + Dependabot 경고
상황: 더 이상 유지하지 않는 리포지토리를 읽기 전용으로 → 정답은?::보관(Archive)

목표 2.2의 내용은?::템플릿과 브랜치로 리포지토리를 만들고 정리하고 유지하는 방법을 식별한다
목표 2.3의 내용은?::리포지토리에 파일을 추가하고 관리하는 방법을 설명한다
목표 2.4의 내용은?::가시성을 높이는 리포지토리 인사이트, 스타, 기능 미리 보기, 리포지토리 지표 대시보드, 종속성 인사이트를 설명한다
목표 2.5의 내용은?::리포지토리 유지 관리와 협업의 모범 사례를 안다
