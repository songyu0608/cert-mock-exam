# 판단 패턴 역색인

문제 속 상황에서 정답 기능을 거꾸로 찾는 표. 가운데 열을 가리고 말해 본다. 표의 상황은 이 볼트가 공식 문서를 바탕으로 만든 예다.

## 도메인 1　Git과 GitHub 기본 이해

| 문제 속 상황 | 정답 방향 | 노트 |
|---|---|---|
| 파일 이전 버전으로 되돌리고 누가 바꿨는지 알아야 함 | 버전 관리(Git) | [[버전 관리]] |
| 인터넷 없이 로컬에서 이력 조회·커밋 | Git(분산형, 전체 이력 사본) | [[Git과 GitHub의 차이]] |
| 이슈·PR 리뷰·호스팅이 필요 | GitHub | [[Git과 GitHub의 차이]] |
| 여러 사람이 리포지토리를 공유·소유하고 팀으로 권한 관리 | 조직(Organization) | [[GitHub 계정 유형]] |
| 여러 조직의 정책·청구를 중앙에서 관리 | 엔터프라이즈 계정 | [[GitHub 계정 유형]] |
| 변경을 main에 반영하기 전 리뷰 | 브랜치 → PR → 리뷰 → 병합(GitHub 플로) | [[GitHub 플로]] |
| 아직 작업 중인 변경을 공유하고 피드백 | 초안(draft) 풀 리퀘스트 | [[GitHub 플로]] |
| 이슈에 체크 가능한 할 일 목록 | 작업 목록 - [ ] | [[Markdown 작성법]] |
| 경고·주의 문구를 눈에 띄게 | > [!WARNING] 등 경고(alerts) 문법 | [[Markdown 작성법]] |
| Git 명령 없이 GUI로 커밋·푸시 | GitHub Desktop | [[GitHub Desktop]] |
| 이동 중 알림 분류·PR 리뷰·2FA 승인 | GitHub Mobile | [[GitHub Mobile]] |

## 도메인 2　GitHub 리포지토리 다루기

| 문제 속 상황 | 정답 방향 | 노트 |
|---|---|---|
| 프로젝트를 처음 본 사람이 무엇인지 알아야 함 | README | [[README]] |
| 다른 사람이 코드를 재사용할 수 있게 | LICENSE 추가 | [[LICENSE]] |
| 특정 경로 변경 시 담당 팀에 리뷰 자동 요청 | CODEOWNERS | [[CODEOWNERS]] |
| 취약점을 공개 이슈 대신 어떻게 보고하나 | SECURITY.md | [[커뮤니티 상태 파일]] |
| 조직의 모든 리포지토리에 같은 CONTRIBUTING | .github 리포지토리의 기본 커뮤니티 상태 파일 | [[커뮤니티 상태 파일]] |
| 같은 폴더 구조로 새 리포지토리를 반복 생성 | 템플릿 리포지토리 | [[템플릿 리포지토리]] |
| 200 MiB 파일을 리포지토리에 넣어야 함 | Git LFS | [[파일 추가와 관리]] |
| 최근 기간의 병합 PR·이슈 활동 요약 | Insights → Pulse | [[리포지토리 인사이트]] |
| 프로젝트를 나중에 다시 찾으려 표시 | 스타 | [[스타]] |
| 얼리 액세스 기능을 켜 보고 싶다 | 기능 미리 보기(Feature preview) | [[기능 미리 보기]] |
| 어떤 패키지에 의존하고 취약점이 있는지 | 종속성 그래프 + Dependabot 경고 | [[종속성 그래프]] |
| 더 이상 유지하지 않는 리포지토리를 읽기 전용으로 | 보관(Archive) | [[리포지토리 보관]] |

## 도메인 3　GitHub로 협업하기

| 문제 속 상황 | 정답 방향 | 노트 |
|---|---|---|
| 버그·기능 요청 추적 | 이슈 | [[이슈]] |
| 질문·아이디어·공지 같은 열린 대화 | 디스커션 | [[디스커션]] |
| PR 병합 시 이슈 자동 닫기 | PR 본문에 Closes #번호(기본 브랜치 대상) | [[PR과 이슈 연결]] |
| 이슈 작성 시 필수 항목 강제 | 이슈 양식(YAML issue form) | [[이슈·PR 템플릿]] |
| 나에게 리뷰 요청된 열린 PR만 | is:pr is:open review-requested:@me | [[이슈·PR 필터와 검색]] |
| 리뷰 요청 알림만 보고 싶다 | reason:review-requested 필터 | [[알림]] |
| 설정 파일 조각을 리포지토리 없이 공유 | Gist | [[Gist]] |
| 프로젝트 장문 문서를 리포지토리 안에 | 위키 | [[위키]] |
| 프로젝트 문서 웹사이트를 무료 호스팅 | GitHub Pages | [[GitHub Pages]] |

## 도메인 4　최신 개발 방식 적용

| 문제 속 상황 | 정답 방향 | 노트 |
|---|---|---|
| PR마다 자동 테스트 | GitHub Actions(pull_request 이벤트) | [[GitHub Actions]] |
| 새 이슈에 자동으로 레이블 | GitHub Actions(issues 이벤트) | [[GitHub Actions]] |
| IDE에서 여러 파일 수정·터미널 명령까지 AI가 진행 | Copilot 에이전트 모드 | [[GitHub Copilot 기능]] |
| 이슈를 AI에 맡겨 PR을 받고 싶다 | Copilot 클라우드 에이전트(이슈를 Copilot에 할당) | [[GitHub Copilot 기능]] |
| 조직이 직원 Copilot을 중앙 관리 | Copilot Business 이상 | [[GitHub Copilot 요금제]] |
| 새 팀원이 곧바로 같은 개발 환경 | Codespaces + devcontainer.json | [[GitHub Codespaces]] |
| 브라우저에서 오타만 빠르게 수정 | github.dev(. 키) | [[github.dev]] |
| 브라우저에서 코드 실행·디버그 | Codespaces | [[Codespaces vs github.dev]] |

## 도메인 5　GitHub로 프로젝트 관리

| 문제 속 상황 | 정답 방향 | 노트 |
|---|---|---|
| 칸반으로 진행 상황 보기 | Projects 보드 레이아웃 | [[GitHub Projects]] |
| 마감일 기준 타임라인 | Projects 로드맵 레이아웃 | [[GitHub Projects]] |
| 스프린트 단위 계획 | 반복(iteration) 필드 | [[GitHub Projects]] |
| PR 병합 시 상태를 Done으로 | 내장 워크플로(기본 켜짐) | [[프로젝트 자동화]] |
| 릴리스까지 남은 작업 비율 | 마일스톤(완료율) | [[레이블과 마일스톤]] |
| 같은 안내 답변을 반복 입력 | 저장된 답글 | [[저장된 답글]] |
| 이 이슈의 책임자를 분명히 | 담당자 지정 | [[담당자]] |
| 완료 대 남은 작업 추이 | 프로젝트 인사이트 번업 차트 | [[프로젝트 인사이트]] |

## 도메인 6　개인정보 보호, 보안, 관리 이해

| 문제 속 상황 | 정답 방향 | 노트 |
|---|---|---|
| 비밀번호와 2FA를 한 번에 | 패스키 | [[2단계 인증과 패스키]] |
| 2FA 기기를 잃어버림 | 복구 코드(Support는 복구해 주지 않음) | [[2단계 인증과 패스키]] |
| 코드 쓰기 없이 이슈 레이블·닫기·할당만 | Triage 역할 | [[리포지토리 역할]] |
| 리포지토리 설정 일부(토픽 등) 관리, 보호 규칙은 불가 | Maintain 역할 | [[리포지토리 역할]] |
| 외부 컨설턴트에게 특정 리포지토리만 | 외부 협력자(Outside collaborator) | [[조직 역할]] |
| 보안 경고 열람·보안 설정만 맡는 팀 | 보안 관리자(Security manager) | [[조직 역할]] |
| 회사 IdP로 계정을 만들고 지우며 외부 활동 차단 | EMU | [[EMU(Enterprise Managed Users)]] |
| 조직에서 Copilot 기능·모델을 제한 | Copilot 정책(Settings → Copilot → Policies) | [[Copilot 정책 관리]] |
| 사내 전원만 보이게 | internal 공개 범위 | [[리포지토리 공개 범위]] |
| main 병합 전 승인 2명·테스트 통과 강제 | 브랜치 보호 규칙 또는 룰셋 | [[브랜치 보호 규칙과 룰셋]] |
| 규칙 여러 개를 겹쳐 적용 | 룰셋 | [[브랜치 보호 규칙 vs 룰셋]] |
| 하위 팀이 상위 팀 권한을 물려받게 | 중첩 팀(부모-자식) | [[팀]] |
