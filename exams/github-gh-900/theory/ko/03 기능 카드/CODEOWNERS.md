# CODEOWNERS

> [!summary] 한 줄 정의
> 파일·경로별 책임자(사용자·팀)를 지정해, 해당 파일을 바꾸는 PR에 자동으로 리뷰를 요청하는 파일.

**English** About code owners

## 시험 트리거
- "특정 폴더 변경은 보안팀이 꼭 리뷰해야 한다"
- "리뷰어를 매번 수동 지정하기 번거롭다"
- "여러 패턴이 같은 파일에 맞는다"

## 핵심
- 위치: .github/, 루트, docs/ 순으로 처음 찾은 파일 사용. 브랜치마다 따로 적용된다.
- 문법: gitignore와 비슷한 패턴 + @사용자, @조직/팀, 이메일. 여러 패턴이 맞으면 마지막 패턴이 우선.
- 해당 파일을 바꾸는 PR이 열리면 코드 소유자에게 리뷰가 자동 요청된다(초안 PR은 준비 완료로 바뀔 때).
- 브랜치 보호·룰셋으로 "코드 소유자 리뷰 필수"를 켜면 소유자 중 1명의 승인이 필요 → [[브랜치 보호 규칙과 룰셋]].
- 소유자는 리포지토리 쓰기 권한이 필요하다(팀은 visible + 쓰기). 파일은 3MB 미만.
- 요금제: Free는 공개 리포지토리, Pro·Team·Enterprise는 공개·비공개 모두.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - CODEOWNERS만 두면 코드 소유자 승인이 필수가 된다는 선택지 → 자동 요청만. 필수화는 브랜치 보호·룰셋
> - 여러 패턴이 맞으면 첫 번째가 우선이라는 선택지 → 마지막 패턴
