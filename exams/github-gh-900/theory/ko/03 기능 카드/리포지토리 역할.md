# 리포지토리 역할

> [!summary] 한 줄 정의
> 조직 리포지토리는 Read → Triage → Write → Maintain → Admin 5단계 역할로 권한을 준다. 개인 계정 리포지토리는 소유자와 협업자 두 단계뿐이다.

**English** Repository roles and permissions

## 시험 트리거
- "코드는 못 바꾸지만 이슈 정리는 해야 한다"
- "리포지토리 설정은 관리하되 삭제는 못 하게"
- "외부 디자이너에게 보기만 허용"

## 핵심
- Read: 보고 토론(비코드 기여자).
- Triage: 쓰기 없이 이슈·PR 관리(레이블 적용, 닫기·다시 열기·할당, 마일스톤 적용, 리뷰 요청).
- Write: 코드 푸시, PR 병합, 필수 리뷰 승인, 레이블 생성·삭제, Actions 워크플로 생성·실행.
- Maintain: 민감·파괴적 작업 없이 리포지토리 운영(설명·토픽·병합 옵션·디스커션 켜기). 브랜치 보호·룰셋·웹훅·배포 키·공개 범위·삭제는 불가.
- Admin: 접근 관리, 브랜치 보호·룰셋, 설정·공개 범위, 웹훅, 보관·삭제, 이슈 삭제, 보안 기능 등 전체.
- 개인 계정 리포지토리: 소유자(전체 제어)와 협업자(쓰기). 비공개 리포지토리에서 협업자에게 읽기 전용을 줄 수 없다.
- 사용자 지정 리포지토리 역할은 GitHub Enterprise Cloud에서만.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - Maintain 역할로 브랜치 보호 규칙을 바꾼다는 선택지 → Admin
> - 이슈 분류만 하는 사람에게 Write를 준다는 선택지 → Triage가 최소 권한
