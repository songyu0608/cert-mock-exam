# 풀 리퀘스트

> [!summary] 한 줄 정의
> 브랜치의 변경을 다른 브랜치(보통 기본 브랜치)에 병합하자고 제안하고, 리뷰·토론·자동 검사를 거쳐 병합하는 협업 단위.

**English** Pull requests

## 시험 트리거
- "변경을 리뷰받고 병합"
- "아직 작업 중이지만 의견을 먼저 받고 싶다"
- "커밋을 하나로 합쳐 병합"

## 핵심
- 초안(draft) PR: 병합할 수 없고 코드 소유자 자동 요청도 없다. 준비 완료로 바꾸면 리뷰 요청.
- 리뷰 결정 3가지: Comment(일반 의견), Approve(승인), Request changes(변경 요청). 줄 단위로 수정 제안(suggested changes).
- 읽기 권한이 있으면 리뷰·코멘트 가능. 관리자는 병합 전 승인을 필수로 만들 수 있다. 병합에는 쓰기 권한 필요.
- 병합 방법: Create a merge commit(모든 커밋 + 병합 커밋), Squash and merge(커밋 하나로), Rebase and merge(병합 커밋 없이 선형 이력). 리포지토리에서 허용한 방법만 쓸 수 있다.
- 포크 기반 PR: 원본에 쓰기 권한이 없어도 포크에서 PR을 보낸다 → [[포크]]. Checks 탭에 자동 검사 결과.
- 한국어 공식 안내서는 PR을 "끌어오기 요청"으로 표기.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - 초안 PR도 승인되면 바로 병합할 수 있다는 선택지 → 초안은 병합 불가, 준비 완료로 바꿔야 한다
> - 선형 이력을 원하는데 merge commit을 고르는 선택지 → squash 또는 rebase
