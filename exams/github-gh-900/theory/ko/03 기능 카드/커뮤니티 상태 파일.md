# 커뮤니티 상태 파일

> [!summary] 한 줄 정의
> CONTRIBUTING(기여 방법), SECURITY(취약점 보고 방법), CODE_OF_CONDUCT(행동 강령), SUPPORT 등 건강한 기여를 돕는 표준 파일. 조직 기본값을 .github 리포지토리에 둘 수 있다.

**English** Community health files (CONTRIBUTING, SECURITY, etc.)

## 시험 트리거
- "기여자가 PR을 잘못된 형식으로 보낸다"
- "취약점을 공개 이슈로 올리지 않게 하고 싶다"
- "조직의 모든 리포지토리에 같은 기여 안내"

## 핵심
- CONTRIBUTING: 기여 방법과 기대치. 이슈·PR을 만들 때 링크가 표시된다. 위치 .github → 루트 → docs 우선.
- SECURITY.md: 지원 버전과 취약점 보고 방법. Security 탭 > Security policy에서 만든다.
- 지원 파일: ACCESSIBILITY, CODE_OF_CONDUCT, CONTRIBUTING, FUNDING.yml, SECURITY, SUPPORT, 이슈·PR 템플릿, 디스커션 양식 등.
- 기본값: 조직·계정의 공개 .github 리포지토리에 두면, 그 파일이 없는 리포지토리에 적용된다. 리포지토리 자체 파일이 우선.
- 이슈 템플릿은 전부 아니면 전무: 리포지토리에 자체 템플릿이 있으면 기본 템플릿은 하나도 쓰이지 않는다. LICENSE는 기본값 불가.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - .github 기본값 리포지토리를 비공개로 둘 수 있다는 선택지 → 공개여야 한다
> - 리포지토리에 CONTRIBUTING이 있어도 조직 기본값이 덮어쓴다는 선택지 → 리포지토리 파일이 우선
