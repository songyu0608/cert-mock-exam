# GitHub Projects

> [!summary] 한 줄 정의
> 이슈와 PR을 바탕으로 테이블·보드·로드맵 레이아웃과 사용자 지정 필드로 작업을 계획·추적하는 도구. 이슈와 양방향으로 동기화된다.

**English** GitHub Projects and layouts

## 시험 트리거
- "칸반 보드로 진행 상황을 보고 싶다"
- "마감일 기준 타임라인"
- "스프린트(반복) 단위로 계획"

## 핵심
- 레이아웃: 테이블(조밀한 표), 보드(칸반), 로드맵(타임라인).
- 항목은 추가한 이슈·PR에서 오고 양방향 동기화: 프로젝트에서 담당자를 바꾸면 이슈도 바뀐다. 초안 이슈(draft issue)도 만들 수 있다.
- 사용자 지정 필드: 텍스트, 숫자, 날짜, 단일 선택, 반복(iteration). 내장 필드 포함 최대 50개.
- 자동화: 내장 워크플로, 그리고 GraphQL API·GitHub Actions → [[프로젝트 자동화]].
- 조직 템플릿에 뷰, 필드, 초안 이슈, 워크플로(자동 추가 제외), 인사이트를 담을 수 있다. 상태 업데이트(예: At risk, 시작·목표 날짜).
- 한국어 공식 안내서는 "GitHub 프로젝트"로 표기.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - 프로젝트에서 바꾼 담당자가 원래 이슈에는 반영되지 않는다는 선택지 → 양방향 동기화
> - 타임라인 보기를 위해 별도 도구가 필요하다는 선택지 → 로드맵 레이아웃
