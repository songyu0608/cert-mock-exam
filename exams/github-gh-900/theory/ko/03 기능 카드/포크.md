# 포크

> [!summary] 한 줄 정의
> 다른 리포지토리를 내 계정·조직으로 복사한 GitHub 상의 리포지토리. 쓰기 권한이 없는 프로젝트에 변경을 제안하거나 내 아이디어의 출발점으로 쓴다.

**English** Forks

## 시험 트리거
- "쓰기 권한이 없는 오픈 소스에 수정을 제안"
- "원본 프로젝트를 바탕으로 내 버전을 시작"
- "원본의 최신 변경을 내 사본에 반영"

## 핵심
- 포크 → 내 포크에서 수정 → 원본(upstream)으로 풀 리퀘스트: 포크 앤 풀(fork and pull) 모델 → [[풀 리퀘스트]].
- 동기화: 웹의 Sync fork 또는 upstream 원격을 추가해 가져온다.
- 구분: 클론은 로컬 사본, 브랜치는 한 리포지토리 안의 개발 줄기, 포크는 GitHub 상의 별도 리포지토리.
- 비공개 리포지토리는 소유자가 허용할 때만 포크할 수 있다. Free 사용자는 비공개 리포지토리를 조직으로 포크할 수 없다.
- 포크는 원본과 이력을 공유하므로 PR을 보낼 수 있다. 템플릿에서 만든 리포지토리는 이력이 무관해 PR을 보낼 수 없다 → [[템플릿 리포지토리]].
- 공개 범위를 바꾸면 포크가 분리될 수 있다 → [[리포지토리 공개 범위]].

## 헷갈리는 개념
| 개념 | 차이 |
|---|---|
| [[템플릿 리포지토리]] | 이력 공유·PR 가능 vs 새 이력의 시작점 |
| [[Git 핵심 개념]] | 포크(GitHub 상 복사) vs 클론(로컬 복사) vs 브랜치(같은 리포지토리 안) |

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - 쓰기 권한이 없으면 오픈 소스에 기여할 수 없다는 선택지 → 포크 후 PR
> - 템플릿으로 만든 리포지토리에서 원본으로 PR을 보낸다는 선택지 → 이력이 무관해서 불가, PR이 목적이면 포크
