# 포크·템플릿·검색 가능성 비교

| | [[포크]] | [[템플릿 리포지토리]] | [[오픈 소스 프로젝트 탐색\|검색 가능한 리포지토리]] |
|---|---|---|---|
| 무엇 | 원본의 GitHub 상 사본 | 구조·파일을 복사한 새 리포지토리 | 다른 사람이 찾고 참여할 수 있게 공개·정리한 리포지토리 |
| 이력 | 원본과 공유 | 새 이력(관련 없는 이력) | 해당 없음 |
| 원본으로 PR | 가능(포크 앤 풀) | 불가 | 해당 없음 |
| 맞는 상황 | 쓰기 권한 없는 프로젝트에 기여, 원본 기반 변형 | 같은 구조로 새 프로젝트를 반복 시작 | 기여자를 모으고 재사용을 늘림 |
| 준비 | 포크 버튼(비공개는 소유자 허용 시) | 관리자가 Settings에서 템플릿 지정 | public, 토픽·설명, README·LICENSE·CONTRIBUTING, good first issue |

**판별**: 원본에 변경을 돌려보낼 것인가? → 포크. 원본과 무관한 새 프로젝트의 뼈대가 필요한가? → 템플릿. 사람들이 찾아오게 하고 싶은가? → 검색 가능하게 정리.

> [!question]- 사내 표준 마이크로서비스 구조로 새 서비스를 계속 만든다. 포크와 템플릿 중?
> 템플릿. 원본 이력이 필요 없고 원본으로 PR을 보낼 일도 없다.

> [!question]- 오픈 소스 라이브러리의 버그를 고쳐 원본에 반영하고 싶다. 쓰기 권한은 없다.
> 포크 → 수정 → 원본으로 풀 리퀘스트.

〔해석〕 "검색 가능한 리포지토리" 열은 안내서 문구(discoverable repositories)를 공식 문서의 탐색 기능에 맞춰 정리한 것이다.
