# 브랜치 보호 규칙 vs 룰셋

| | 브랜치 보호 규칙 | 룰셋 |
|---|---|---|
| 한 브랜치에 여러 개 | 불가(하나만) | 가능, 겹치면 가장 엄격한 규칙 적용 |
| 대상 | 브랜치 | 브랜치·태그, 푸시(파일 경로·확장자·크기) |
| 상태 전환 | 상태 개념 없음 | 활성(Active)·비활성(Disabled), 삭제하지 않고 끄고 켬 |
| 우회 | "Do not allow bypassing" 설정으로 관리자 포함 여부 결정 | 우회 목록(bypass list) |
| 열람 | 문서에 따로 명시 없음 | 읽기 권한자도 활성 룰셋 열람 |
| 조직 단위 | 없음 | Enterprise에서 조직 전체 리포지토리에 적용 |
| 수량 | 브랜치 패턴별 | 리포지토리당 최대 75개 |

공통: 승인 리뷰 수, 상태 확인 필수, 서명 커밋, 선형 이력, 강제 푸시 금지 같은 보호를 강제한다. 요금제 조건은 둘 다 Free 공개 리포지토리, Pro·Team·Enterprise 비공개 리포지토리.

> [!question]- 보안팀 규칙(승인 2명)과 플랫폼팀 규칙(승인 3명)을 같은 브랜치에 동시에 적용하고 싶다.
> 룰셋. 둘 다 적용되고 더 엄격한 3명이 요구된다.

> [!question]- 개발자가 어떤 규칙이 걸려 있는지 직접 확인할 수 있어야 한다.
> 룰셋은 읽기 권한자도 볼 수 있다.
