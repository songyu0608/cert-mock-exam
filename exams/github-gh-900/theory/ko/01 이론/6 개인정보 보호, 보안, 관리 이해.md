# 도메인 6　개인정보 보호, 보안, 관리 이해

**English** Domain 6: Understand privacy, security, and administration  
**한국어 공식 안내서** 개인 정보 보호, 보안 및 관리 이해

도메인 6 (10–15%) · 목표 5개

계정 보안(2FA·패스키), 리포지토리·조직 역할, EMU와 Copilot 정책, 공개 범위와 브랜치 보호, 조직·팀 관리를 다룬다.

> [!abstract] 보안과 접근 관리
> Security and access management · 보안 및 액세스 관리

## 목표 6.1

**2단계 인증(2FA)과 패스키로 계정을 보호하는 방법을 설명한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Describe how to secure accounts with two-factor authentication (2FA) and passkeys
>
> 2FA(2단계 인증) 및 암호로 계정을 보호하는 방법 설명

2FA 방법(TOTP 앱, SMS, 보안 키, GitHub Mobile, 패스키)과 복구 코드. 패스키는 비밀번호와 2FA를 한 번에 충족한다. 코드 기여자는 2FA가 필수다.

관련 카드: [[GitHub Mobile]] · [[2단계 인증과 패스키]]

## 목표 6.2

**리포지토리와 조직의 접근 권한과 역할을 식별한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Identify access permissions and roles for repositories and organizations
>
> 리포지토리 및 조직에 대한 액세스 권한 및 역할 식별

리포지토리 역할 Read < Triage < Write < Maintain < Admin과 조직 역할(소유자, 구성원, 중재자, 결제 관리자, 보안 관리자, 외부 협력자)을 구분한다.

관련 카드: [[리포지토리 역할]] · [[조직 역할]]

## 목표 6.3

**EMU(Enterprise Managed Users)와 조직 전체 Copilot 정책 관리의 목적을 설명한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Explain the purpose of Enterprise Managed Users (EMUs) and organization-wide Copilot policy management
>
> EMU(Enterprise Managed Users) 및 조직 전체의 Copilot 정책 관리의 목적 설명

EMU는 IdP가 계정을 만들고 관리해 회사가 계정 수명 주기를 통제한다(공개 콘텐츠·외부 협업 불가). 조직 소유자는 Copilot Business·Enterprise에서 기능·모델·MCP 등의 정책을 설정한다.

관련 카드: [[EMU(Enterprise Managed Users)]] · [[Copilot 정책 관리]]

## 목표 6.4

**리포지토리 공개 범위 옵션, 표시 설정, 브랜치 보호 규칙을 설명한다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Describe repository privacy options, visibility settings, and branch protection rules
>
> 리포지토리 개인 정보 옵션, 표시 유형 설정 및 분기 보호 규칙 설명

공개 범위(public, private, internal)와 변경의 영향, 브랜치 보호 규칙·룰셋으로 리뷰·상태 확인을 강제하는 방법을 안다.

관련 카드: [[CODEOWNERS]] · [[종속성 그래프]] · [[리포지토리 공개 범위]] · [[브랜치 보호 규칙과 룰셋]] · [[GitHub Advanced Security]]

## 목표 6.5

**조직 설정, 팀, 역할을 관리하는 방법을 안다**

> [!quote]- 공식 원문 (English / 한국어 공식 안내서)
> Recognize how to manage organization settings, teams, and roles
>
> 조직 설정, 팀 및 역할을 관리하는 방법 인식

조직 설정, 팀(공개·비밀, 중첩, 권한 상속), 역할 부여, 2FA 요구 같은 조직 관리 방법을 안다.

관련 카드: [[GitHub 계정 유형]] · [[조직 역할]] · [[팀]]

## 요약
- 역할 순서: Read < Triage < Write < Maintain < Admin.
- 소유자는 2명 이상 권장.
- internal = 엔터프라이즈 구성원 전원 읽기.
- 한 브랜치에 보호 규칙은 하나, 룰셋은 여러 개 겹침.

## 이 도메인의 카드
- [[2단계 인증과 패스키]] — 비밀번호 외에 두 번째 인증 수단(TOTP 앱, SMS, 보안 키, GitHub Mobile)을 요구하는 2FA와, 비밀번호와 2FA를 한 번에 만족하는 패스키로 계정을 보호한다.
- [[리포지토리 역할]] — 조직 리포지토리는 Read → Triage → Write → Maintain → Admin 5단계 역할로 권한을 준다. 개인 계정 리포지토리는 소유자와 협업자 두 단계뿐이다.
- [[조직 역할]] — 조직 단위 역할: 소유자, 구성원, 중재자, 결제 관리자, 보안 관리자, GitHub App 관리자, 외부 협업자.
- [[팀]] — 조직 구성원을 묶어 리포지토리 권한을 한 번에 주고, @멘션·리뷰 요청·CODEOWNERS에 쓰는 단위. 부모-자식으로 중첩된다.
- [[EMU(Enterprise Managed Users)]] — 엔터프라이즈가 외부 IdP로 GitHub 사용자 계정의 생성·인증·프로필·조직 멤버십·리포지토리 접근을 직접 관리하는 Enterprise Cloud 기능.
- [[Copilot 정책 관리]] — Copilot Business·Enterprise 조직의 소유자가 Copilot 기능, 모델, MCP 서버, 미리 보기 기능을 조직 전체에 켜고 끄는 정책. 엔터프라이즈 정책이 우선한다.
- [[리포지토리 공개 범위]] — 공개(누구나), 비공개(권한 받은 사람), 내부(엔터프라이즈 구성원 전체 읽기) 세 가지. 바꾸면 포크·스타·기능에 영향이 있다.
- [[브랜치 보호 규칙과 룰셋]] — 중요 브랜치에 PR 리뷰 승인, 상태 확인 통과, 서명 커밋, 선형 이력 등을 강제하는 규칙. 룰셋은 여러 개를 겹쳐 적용할 수 있는 더 유연한 방식이다.
- [[GitHub Advanced Security]] — 코드 스캔(CodeQL), 비밀 검색, 푸시 보호, 종속성 리뷰 등을 제공하는 보안 제품군. Secret Protection과 Code Security 두 유료 제품으로 나뉘고, 공개 리포지토리는 일부를 무료로 쓴다.
