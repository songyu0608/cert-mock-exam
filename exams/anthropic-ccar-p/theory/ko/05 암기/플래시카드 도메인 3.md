# 플래시카드 도메인 3　통합

#flashcards/ccar-p/d3

형식: `질문::답` (Spaced Repetition 플러그인). 플러그인이 없어도 한 줄씩 읽으면 된다.

## 개념 확인
공식 샘플 1에서 최소 권한에 맞는 변경은?::역할에 필요 없는 환불·삭제 도구를 에이전트 구성에서 완전히 제거
도구 선택 정확도가 떨어지기 시작하는 도구 수(도구 검색 문서)는?::30~50개 초과
list_users·list_events·create_event 대신 공식 글이 권하는 도구 설계는?::schedule_event처럼 워크플로 단위의 도구 하나
Claude Code의 도구 응답 기본 제한은?::25,000토큰
인증과 인가의 차이는?::인증은 신원 확인, 인가는 허용된 행동 범위 결정
MCP 커넥터가 인증 서버 연결에 지원하는 방식은?::OAuth Bearer 토큰
지연을 줄이는 공식 방법 5가지는?::기준선 측정, 맞는 모델 선택, 프롬프트·출력 간결화, max_tokens 제한, 스트리밍
정확도를 해치지 않고 TTFT와 비용을 함께 줄이는 레버는?::정적 내용 앞 배치 + 프롬프트 캐싱
멀티 에이전트 글이 에이전트 실패 원인을 진단한 방법은?::전체 프로덕션 트레이싱
실행 중인 에이전트를 깨뜨리지 않는 배포 방식은?::레인보 배포(구·신 버전 동시 운영 후 트래픽 점진 전환)
RAG 없이 전체 지식 베이스를 넣어도 되는 기준(공식 글)은?::약 200,000토큰(약 500쪽) 미만
샘플 3에서 먼저 조사할 곳은?::검색/인덱싱 단계가 무관하거나 오래된 청크를 반환하는지
청크가 원래 맥락을 잃는 문제를 공식 글은 어떻게 해결하나?::청크마다 50~100토큰의 맥락 설명을 붙여 임베딩·BM25 인덱싱(컨텍스트 기반 검색)
컨텍스트 임베딩 + 컨텍스트 BM25의 실패율 감소폭은?::49%(5.7%→2.9%)
재랭킹까지 결합했을 때는?::67%(5.7%→1.9%)
정확한 식별자(예: TS-999) 검색에 강한 방식은?::BM25(어휘·키워드 일치)
하이브리드 검색 결과를 좁히는 마지막 단계는?::재랭킹
Messages API MCP 커넥터의 두 가지 제한은?::MCP 기능 중 도구 호출만 지원, 공개 HTTP 서버만 연결(로컬 STDIO 불가)
Claude Code의 하이브리드 전략은?::CLAUDE.md는 처음부터 넣고, 파일은 glob·grep으로 필요할 때 탐색
코드 실행 + MCP의 점진적 공개로 줄어든 토큰(공식 글 예)은?::150,000 → 2,000토큰(98.7% 절감)
도구 검색이 줄이는 도구 정의 토큰 비율은?::보통 85% 이상(필요한 3~5개만 로드)
처음에 로드하지 않을 도구를 표시하는 속성은?::defer_loading: true
프로그래밍 방식 도구 호출의 토큰 절감(공식 발표)은?::37%(43,588→27,297)
코드 실행 + MCP의 공식 글 예시 토큰 절감은?::150,000→2,000토큰(98.7%)
이 방식의 대가는?::샌드박스·자원 제한·모니터링 등 운영·보안 부담
MCP의 한 줄 정의(공식 글)는?::AI 에이전트를 외부 시스템에 연결하는 오픈 표준
MCP 커넥터가 지원하는 MCP 기능은?::도구 호출만
MCP 커넥터의 ZDR 적격 여부는?::적격 아님(표준 보존 정책)

## 상황 → 판단
상황: 역할에 필요 없는 위험 도구가 붙어 있음 → 정답 방향은?::구성에서 제거(최소 권한)
상황: 도구 30~50개 초과로 선택 오류 → 정답 방향은?::도구 검색·도구 정리
상황: API 엔드포인트별 도구가 많음 → 정답 방향은?::워크플로 단위 도구로 통합
상황: 에이전트가 서비스 계정 권한으로 전체 데이터 접근 → 정답 방향은?::인가를 도구·데이터 계층에서 강제
상황: 정확도를 올리려 단계·추론 추가 → 정답 방향은?::지연 증가를 측정해 SLA와 비교
상황: 에이전트 실패 원인을 알 수 없음 → 정답 방향은?::전체 프로덕션 트레이싱
상황: 실행 중 에이전트를 깨지 않고 배포 → 정답 방향은?::레인보 배포
상황: 지식 베이스 200,000토큰 미만 → 정답 방향은?::RAG 없이 전체 투입 + 캐싱
상황: 청크가 원래 맥락을 잃음 → 정답 방향은?::컨텍스트 기반 검색(50~100토큰 설명)
상황: 정확한 오류 코드·ID 검색 → 정답 방향은?::BM25 결합(하이브리드)
상황: 여러 앱이 같은 사내 시스템 사용 → 정답 방향은?::MCP
상황: 로컬 STDIO 서버를 API에 연결 → 정답 방향은?::MCP 커넥터 불가(원격 HTTP만)
상황: 도구 정의가 수만 토큰 → 정답 방향은?::점진적 탐색(도구 검색·코드 실행)
