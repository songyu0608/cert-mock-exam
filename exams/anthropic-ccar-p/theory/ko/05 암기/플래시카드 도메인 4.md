# 플래시카드 도메인 4　평가, 테스트, 최적화

#flashcards/ccar-p/d4

형식: `질문::답` (Spaced Repetition 플러그인). 플러그인이 없어도 한 줄씩 읽으면 된다.

## 개념 확인
안내서 4.1의 평가 지표 5개 축은?::정확도, 지연, 비용, 안전성, 보안
평가 설계 원칙 3가지(공식 문서)는?::과제 특화, 가능하면 자동화, 질보다 양
멀티 에이전트 리서치 시스템이 평가를 시작한 질의 수는?::약 20개
가장 빠르고 신뢰할 수 있는 채점 방식은?::코드 기반 채점
사람 채점에 대한 공식 문서의 평가는?::가장 유연하고 품질이 높지만 느리고 비싸므로 가능하면 피한다
LLM 채점 팁 3가지는?::상세하고 명확한 루브릭, 경험적·구체적 출력, 채점 전 추론
A/B 테스트에서 원인을 알기 위한 원칙(해석)은?::한 번에 한 변수만 바꾼다
프롬프트 수정 하나로 성공률이 크게 오른 사례(멀티 에이전트 글)는?::30%에서 80%
샘플 3의 증상과 정답은?::문서 갱신 뒤 확신에 찬 오답(모델·지연 불변) → 검색/인덱싱이 무관하거나 오래된 청크를 반환하는지 먼저 조사
진단의 첫 질문(해석)은?::무엇이 바뀌었는가(문서·프롬프트·모델·도구) — 변화와 증상을 연결한다
할루시네이션 기본 완화 기법 3가지는?::"모른다" 허용, 직접 인용으로 근거 확보, 인용으로 검증(근거 없으면 철회)
Best-of-N 검증에서 할루시네이션 신호는?::같은 프롬프트의 여러 출력 사이의 불일치
Message Batches API의 할인율은?::모든 토큰 50%(캐싱 할인과 중첩 가능)
지연·비용을 함께 줄이면서 품질 손실이 없는 대표 레버는?::정적 접두사 + 프롬프트 캐싱
배치 한 개의 한도는?::요청 100,000건 또는 256MB 중 먼저 닿는 쪽
배치 결과 보관 기간은?::생성 후 29일
cited_text는 출력 토큰으로 과금되나?::아니요, 출력 토큰에 포함되지 않는다
인용과 함께 쓸 수 없는 기능은?::구조화된 출력

## 상황 → 판단
상황: 정확도만 보고 배포 결정 → 정답 방향은?::정확도·지연·비용·안전성·보안 함께
상황: 평가셋이 클 때까지 평가 보류 → 정답 방향은?::약 20개 실제 질의로 즉시 시작
상황: 정답이 명확한 분류 채점 → 정답 방향은?::코드 기반 채점
상황: 자유 서술 대량 채점 → 정답 방향은?::LLM 채점(루브릭, 신뢰성 검증 후)
상황: 여러 요소를 한꺼번에 바꿈 → 정답 방향은?::한 번에 한 변수(A/B)
상황: 문서 갱신 뒤 확신에 찬 오답 → 정답 방향은?::검색/인덱싱 먼저 조사
상황: 없는 사실을 지어냄 → 정답 방향은?::"모른다" 허용·직접 인용·인용 검증
상황: 즉시 응답 불필요한 대량 처리 → 정답 방향은?::Message Batches API(50%)
상황: 도구 중간 결과가 컨텍스트를 채움 → 정답 방향은?::프로그래밍 방식 도구 호출
