# 플래시카드 도메인 1　솔루션 설계와 아키텍처

#flashcards/ccar-p/d1

형식: `질문::답` (Spaced Repetition 플러그인). 플러그인이 없어도 한 줄씩 읽으면 된다.

## 개념 확인
좋은 성공 기준의 4가지 성질(공식 문서)은?::구체적, 측정 가능, 달성 가능, 관련성
"응답 품질이 좋아야 한다"를 성공 기준으로 고치면?::측정 가능한 수치와 대상을 정한다. 예: 테스트셋 N건에서 정확도·F1 몇 이상
엔드투엔드 아키텍처의 4요소(안내서 표기)는?::입력 → 처리 → 출력 → 피드백 루프
에이전트가 진행 상황을 판단하는 근거로 공식 글이 강조하는 것은?::각 단계에서 환경으로부터 받는 실제 결과(도구 호출 결과·코드 실행 결과 등)
증강 LLM을 만드는 세 가지 증강은?::검색(retrieval), 도구(tools), 메모리(memory)
워크플로와 에이전트를 가르는 기준(공식 정의)은?::워크플로는 미리 정한 코드 경로, 에이전트는 LLM이 스스로 절차와 도구 사용을 정함
에이전트형 시스템이 성능을 얻는 대가는?::지연과 비용 증가(오류 누적 위험 포함)
프롬프트 체이닝이 맞는 작업 조건은?::고정된 하위 작업으로 깔끔하게 나뉘는 작업
체이닝의 트레이드오프는?::지연을 더 쓰고 정확도를 얻는다
라우팅으로 비용을 줄이는 공식 예시는?::쉬운·흔한 질문을 더 작고 비용 효율적인 모델로 보낸다
병렬화의 두 변형은?::섹셔닝(독립 하위 작업 병렬 실행), 투표(같은 작업 여러 번 실행)
가드레일을 병렬화로 구현할 때 공식 글의 권장은?::응답 생성 인스턴스와 별도의 검사 인스턴스를 둔다
오케스트레이터-워커와 병렬화의 핵심 차이는?::하위 작업이 미리 정해지지 않고 오케스트레이터가 입력에 따라 동적으로 정한다
평가자-최적화자가 효과적인 두 조건은?::명확한 평가 기준이 있고, 반복 개선이 측정 가능한 가치를 줄 때
멀티 에이전트 시스템의 토큰 사용량은 채팅 대비 약 몇 배(리서치 시스템 글)?::약 15배(단일 에이전트는 약 4배)
멀티 에이전트에 덜 맞는 작업의 특징은?::모든 에이전트가 같은 컨텍스트를 공유해야 하거나 에이전트 간 의존성이 많은 작업
고정 분해와 동적 분해의 대표 패턴은?::고정: 프롬프트 체이닝·섹셔닝 / 동적: 오케스트레이터-워커·에이전트
안내서가 든 비즈니스 가치 축 5개는?::효율성, 변혁, 생산성, 비용, 성능 SLA

## 상황 → 판단
상황: 성공 기준 없이 "AI 도입"만 요구 → 정답 방향은?::측정 가능한 성공 기준부터 정한다
상황: 단계가 고정되고 예측 가능해야 함 → 정답 방향은?::워크플로
상황: 필요한 단계 수를 미리 알 수 없음 → 정답 방향은?::에이전트
상황: 단일 호출 + 검색 + 예시로 충분 → 정답 방향은?::에이전트를 만들지 않는다(가장 단순한 해법)
상황: 고정 하위 작업 + 중간 검사 → 정답 방향은?::프롬프트 체이닝(게이트)
상황: 쉬운 질문은 작은 모델로 → 정답 방향은?::라우팅
상황: 응답 생성과 부적절 콘텐츠 검사 → 정답 방향은?::병렬화(섹셔닝): 별도 인스턴스
상황: 하위 작업을 입력에 따라 동적으로 → 정답 방향은?::오케스트레이터-워커
상황: 명확한 기준 + 반복 개선 가치 → 정답 방향은?::평가자-최적화자
상황: 넓은 병렬 탐색, 가치 높은 작업 → 정답 방향은?::멀티 에이전트(토큰 약 15배 감수)
상황: 의존성 큰 코딩을 서브에이전트로 쪼갬 → 정답 방향은?::멀티 에이전트 부적합
