## 개념 확인
사용자 입력 사전 검사(harmlessness screen)에 공식 문서가 권하는 방식은?::가벼운 모델로 구조화된 출력의 단순 분류를 먼저 실행
반복 우회 시도 사용자에 대한 공식 권장은?::응답 조정, 제한·차단 고려, 정책 위반 안내
신뢰할 수 없는 서드파티 콘텐츠를 넣을 위치(공식 권장)는?::tool_result 블록(system·일반 user 텍스트가 아님)
내 지시를 tool_result 안에 넣으면 안 되는 이유는?::Claude가 도구 결과를 신뢰할 수 없는 데이터로 취급해 무시하거나 인젝션으로 의심할 수 있다
에이전트 디버깅이 어려운 이유(멀티 에이전트 글)는?::같은 프롬프트에도 실행마다 비결정적으로 다른 결정을 내린다
토큰이 늘수록 정확도가 떨어지는 실패 모드는?::context rot(컨텍스트 열화)
공식 문서가 실행 전 확인을 권하는 행동은?::되돌리기 어려운 행동(삭제, 강제 푸시, 외부 게시 등)
에이전트가 사람 피드백을 받으려 멈추는 시점(공식 글)은?::체크포인트나 막히는 지점
PHI를 넣으면 안 되는 곳(공식 문서)은?::JSON 스키마 정의(속성 이름, enum, const, pattern)
FedRAMP 환경이 필요할 때의 경로(2026-11 공공 부문 FAQ)는?::Amazon Bedrock(GovCloud) 또는 Google Vertex(Assured Workloads)
멀티 에이전트 글에서 사람 테스터가 발견한 편향은?::권위 있는 출처보다 SEO 콘텐츠 팜을 고르는 출처 선택 편향
샘플 1에서 로깅과 확인 프롬프트는 각각 무슨 통제인가?::로깅은 탐지 통제, 확인 프롬프트는 보완 통제(둘 다 권한 제거가 아님)
ZDR 조직이 브라우저에서 API를 직접 호출할 수 없는 이유는?::API가 CORS 요청을 거부한다(백엔드 경유 필요)
HIPAA 준비의 전제 조건은?::서명된 BAA와 HIPAA 활성 조직
