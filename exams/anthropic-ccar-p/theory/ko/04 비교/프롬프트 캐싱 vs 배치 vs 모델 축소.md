# 프롬프트 캐싱 vs 배치 vs 모델 축소

| | [[프롬프트 캐싱]] | [[Message Batches API]] | 작은 모델로 교체 |
|---|---|---|---|
| 줄이는 것 | 반복 접두사 비용 + TTFT | 모든 토큰 비용 50% | 단가·지연 |
| 품질 영향 | 없음 | 없음 | 있을 수 있음(평가 필요) |
| 지연 | 줄어듦 | 늘어남(비동기, 대부분 1시간 내) | 대개 줄어듦 |
| 조건 | 정적 내용 앞, 최소 길이 이상 | 즉시 응답 불필요 | 작업 적합성을 평가로 확인 |
| 함께 쓰기 | 배치와 중첩 가능 | 캐싱과 중첩 가능 | 라우팅과 결합 |

**판별 순서**: ① 같은 긴 접두사가 반복되나? → 캐싱 ② 결과를 바로 안 써도 되나? → 배치 ③ 평가에서 작은 모델로도 기준을 넘나? → 모델 축소·라우팅

> [!question]- 실시간 챗봇에서 매 요청 8,000토큰 정책 문서를 보낸다. 지연과 비용을 함께 줄이려면?
> 정책을 앞에 두고 프롬프트 캐싱(공식 샘플 2). 배치는 실시간에 맞지 않고, 무작정 모델 축소는 품질 위험.
