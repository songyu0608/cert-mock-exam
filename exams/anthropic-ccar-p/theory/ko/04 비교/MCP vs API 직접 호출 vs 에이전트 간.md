# MCP vs API 직접 호출 vs 에이전트 간

| | [[MCP(모델 컨텍스트 프로토콜)\|MCP]] | API/CLI 직접(사용자 정의 도구) | 에이전트 간(A2A) |
|---|---|---|---|
| 강점 | 표준·재사용, 여러 클라이언트 | 세밀한 제어·검증, 단순 | 독립 에이전트에게 위임 |
| 맞는 상황 | 같은 시스템을 여러 앱·에이전트가 사용 | 한 앱에서 몇 개 API만 | 팀·조직 경계를 넘는 작업 위임 |
| 주의 | 도구 정의 비대화, 커넥터 제약(도구 호출만·원격 HTTP만) | 통합마다 코드 중복 | 신뢰 경계·인증·결과 검증(해석) |

**판별 순서**: ① 여러 클라이언트가 재사용하나? → MCP ② 한 앱의 소수 호출이고 세밀한 게이트가 필요한가? → 사용자 정의 도구 ③ 다른 에이전트의 자율적 처리가 필요한가? → A2A

> [!warning] A2A 세부는 Anthropic 공식 문서에서 이번에 확인하지 못했다. A2A 열은 일반적인 아키텍처 해석이다.

> [!question]- 로컬에서만 도는 STDIO MCP 서버를 Messages API에 붙이려 한다.
> MCP 커넥터는 공개 HTTP 서버만 연결한다. 원격으로 공개하거나, 앱 쪽 MCP 클라이언트·사용자 정의 도구로 연결한다.
