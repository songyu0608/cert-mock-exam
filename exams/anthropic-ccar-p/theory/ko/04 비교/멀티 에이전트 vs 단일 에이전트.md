# 멀티 에이전트 vs 단일 에이전트

| | 단일 에이전트(또는 워크플로) | [[멀티 에이전트 도입 판단\|멀티 에이전트]] |
|---|---|---|
| 토큰(채팅 대비) | 약 4배 | 약 15배 |
| 맞는 작업 | 의존성이 크고 컨텍스트를 공유해야 함(대부분의 코딩) | 넓고 병렬화되는 탐색, 단일 컨텍스트를 넘는 정보 |
| 위험 | 컨텍스트 한도 | 조율 실패, 중복 작업, 오류 누적, 비용 |
| 설계 포인트 | 컨텍스트 관리, 도구 | 하위 작업마다 목표·출력 형식·도구·경계 명시 |

**판별 순서**: ① 작업 가치가 약 15배 토큰을 정당화하나? ② 하위 작업이 서로 독립적인가? ③ 둘 다 예일 때만 멀티 에이전트.

> [!question]- 여러 모듈이 서로 강하게 얽힌 리팩터링을 서브에이전트 5개에 나눠 맡기려 한다.
> 맞지 않는다. 에이전트 간 의존성이 크고 같은 컨텍스트를 공유해야 하는 작업은 멀티 에이전트의 효과가 낮다.
