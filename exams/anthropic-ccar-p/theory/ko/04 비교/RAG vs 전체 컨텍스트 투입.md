# RAG vs 전체 컨텍스트 투입

| | [[RAG 파이프라인 설계\|RAG]] | 전체 투입 + 캐싱 |
|---|---|---|
| 지식 크기 | 큼(200,000토큰 이상) | 작음(약 200,000토큰·500쪽 미만) |
| 갱신 | 재인덱싱 필요 | 프롬프트만 교체 |
| 장애 지점 | 청킹·인덱스·검색 | 컨텍스트 열화, 비용 |
| 품질 개선 | 컨텍스트 기반 검색, 하이브리드, 재랭킹 | 긴 문서 위·질문 끝, 인용 먼저 |

**판별 순서**: ① 지식 베이스가 200,000토큰 미만인가? → 전체 투입 + 캐싱 ② 크거나 계속 늘어나나? → RAG ③ 탐색형 질의인가? → 에이전트의 점진적 탐색 고려

> [!question]- 사내 규정 문서 전체가 약 300쪽이고 거의 바뀌지 않는다.
> 약 200,000토큰 미만이면 RAG 없이 전체를 프롬프트에 넣고 캐싱하는 편이 단순하다(Contextual Retrieval 글의 기준). 분량을 토큰 카운팅으로 확인한다.
