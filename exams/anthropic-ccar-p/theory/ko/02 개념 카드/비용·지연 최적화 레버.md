# 비용·지연 최적화 레버

> [!summary] 한 줄 정의
> 품질을 지키며 토큰·지연·비용을 줄이는 레버: 캐싱, 배치, 모델·effort 조정, 라우팅, 출력·컨텍스트 축소, 스트리밍.

**日本語** トークン使用量、レイテンシ、コストとパフォーマンス　·　**English** Optimizing token usage, latency and cost-performance

## 시험 트리거
- "월 API 비용이 예산을 넘었다"
- "야간 대량 문서 처리"
- "응답 시작이 늦다"

## 핵심
- 프롬프트 캐싱: 반복 접두사 재사용으로 비용과 TTFT를 함께 줄인다 → [[프롬프트 캐싱]].
- Message Batches API: 즉시 응답이 필요 없는 대량 작업을 50% 할인. 캐싱 할인과 중첩된다 → [[Message Batches API]].
- 모델·effort: effort 조정이 모델 교체보다 나은 경우가 많다. 라우팅으로 쉬운 요청을 작은 모델로 → [[라우팅]].
- 토큰 축소: 간결한 프롬프트·출력, max_tokens, 도구 응답 페이지네이션, 도구 검색, 프로그래밍 방식 도구 호출(−37%).
- 지연: 스트리밍은 체감 지연(첫 출력까지)을 줄인다. 기준선 측정이 먼저다.
