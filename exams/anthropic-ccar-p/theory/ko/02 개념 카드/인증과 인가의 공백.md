# 인증과 인가의 공백

> [!summary] 한 줄 정의
> 누가 요청하는지(인증)와 무엇을 할 수 있는지(인가)를 에이전트·도구·데이터 경계마다 확인해, 에이전트가 사용자 권한보다 넓게 행동하는 공백을 찾는다.

**日本語** 認証と認可　·　**English** Authentication and authorization gaps

## 시험 트리거
- "에이전트가 서비스 계정 권한으로 모든 고객 데이터에 접근한다"
- "MCP 서버 인증 방식"
- "프롬프트에 API 키를 넣었다"

## 핵심
- 〔해석〕 인증(authentication) = 신원 확인, 인가(authorization) = 허용된 행동 범위. 공백은 대개 인가 쪽에서 생긴다.
- 〔해석〕 점검 질문: 에이전트는 누구의 권한으로 도구를 호출하나? 사용자별 데이터 경계가 도구 계층에서 강제되나? 비밀은 프롬프트 밖에 있나?
- 프롬프트 인젝션 대응 문서: 필요 없는 비밀에 접근시키지 말고, 권한 범위를 최소로(최소 권한) → [[프롬프트 인젝션]].
- MCP 커넥터는 인증이 필요한 서버에 OAuth Bearer 토큰을 지원한다 → [[MCP 커넥터]].
- Claude Code 팀 환경: 로그인 방식·조직 제한은 관리형 설정(forceLoginMethod, forceLoginOrgUUID)으로 강제한다 → [[Claude Code 설정 우선순위]].
