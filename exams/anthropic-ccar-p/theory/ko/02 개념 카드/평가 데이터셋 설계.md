# 평가 데이터셋 설계

> [!summary] 한 줄 정의
> 실제 과제 분포와 엣지 케이스를 담은 평가셋을 만들고, 자동 채점·LLM 채점·사람 검토를 섞어(혼합 방법론) 테스트한다.

**日本語** 評価データセットとテストフレームワーク　·　**English** Designing evaluation datasets and test frameworks

## 시험 트리거
- "평가 케이스를 수백 개 모을 때까지 평가를 미룬다"
- "엣지 케이스에서만 실패한다"
- "평가 방법을 하나로 정하기 어렵다"

## 핵심
- 평가 설계 원칙 3가지(공식 문서): 과제 특화(실제 분포 + 엣지 케이스), 가능하면 자동화, 질보다 양(자동 채점 문항을 많이).
- 엣지 케이스 예: 무관하거나 없는 입력, 지나치게 긴 입력, 유해·무관한 사용자 입력, 사람도 판단이 갈리는 모호한 사례.
- 멀티 에이전트 글: 실제 사용을 대표하는 약 20개 질의로 바로 시작했다. 초기에는 효과 크기가 커서 소수 케이스로도 변화가 보인다.
- 혼합 방법론: 코드 채점(정확 일치), LLM 채점(루브릭), 사람 검토(자동화가 놓치는 엣지 케이스 발견)를 함께 쓴다.
- 도구 평가 글: 과적합을 피하려 보류(held-out) 테스트셋으로 성능을 확인한다.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - "수백 건의 대규모 평가셋이 생길 때까지 평가를 미룬다" → 공식 글은 소수 케이스로 즉시 시작하라고 한다
> - "사람이 손으로 채점한 소수 문항이 자동 채점 다수보다 낫다" → 공식 문서는 질보다 양을 권한다
