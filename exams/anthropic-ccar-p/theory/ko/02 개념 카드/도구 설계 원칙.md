# 도구 설계 원칙

> [!summary] 한 줄 정의
> 에이전트용 도구는 API를 그대로 감싸기보다 고효과 워크플로 단위로 적게 만들고, 이름·응답·오류를 에이전트가 쓰기 쉽게 설계한다.

**日本語** ツールの設計　·　**English** Writing effective tools for agents

## 시험 트리거
- "API 엔드포인트마다 도구를 하나씩 만들었다"
- "도구 응답이 너무 길어 컨텍스트를 채운다"
- "에이전트가 잘못된 파라미터로 계속 호출한다"

## 핵심
- 도구가 많다고 결과가 좋아지지 않는다. 기존 API를 단순히 감싼 도구가 흔한 실수다. 예: list_users·list_events·create_event 대신 schedule_event 하나.
- 네임스페이스: 서비스·리소스별 접두사(asana_search, jira_search)로 도구 경계를 나눈다.
- 토큰 효율: 긴 응답에는 페이지네이션·범위 선택·필터·잘라내기를 기본값과 함께 둔다. Claude Code는 도구 응답을 기본 25,000토큰으로 제한한다.
- 오류 응답은 올바른 입력 형식을 알려 주는 도움이 되는 메시지로 만든다.
- 도구도 평가한다: 실제 사용에 기반한 평가 과제, 정확도 외에 호출 수·토큰·오류를 수집하고 보류(held-out) 세트로 확인한다.
