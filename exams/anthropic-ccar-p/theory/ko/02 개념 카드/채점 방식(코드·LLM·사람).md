# 채점 방식(코드·LLM·사람)

> [!summary] 한 줄 정의
> 평가 채점은 가장 빠르고 신뢰할 수 있고 확장 가능한 방법을 고른다. 코드 채점 → LLM 채점 → 사람 채점 순으로 검토한다.

**日本語** 採点方法　·　**English** Grading: code-based, LLM-based, human

## 시험 트리거
- "자유 서술 답변을 대량으로 채점"
- "분류 결과가 정답과 같은지"
- "채점 LLM을 믿어도 되나"

## 핵심
- 코드 채점: 가장 빠르고 신뢰할 수 있으며 확장성이 높다. 복잡한 판단의 뉘앙스는 부족하다(정확 일치, 문자열 포함).
- 사람 채점: 가장 유연하고 품질이 높지만 느리고 비싸다. 가능하면 피한다.
- LLM 채점: 빠르고 유연하며 복잡한 판단에 맞다. 먼저 신뢰성을 테스트한 뒤 확장한다.
- LLM 채점 팁: 상세하고 명확한 루브릭, 경험적·구체적 출력(정답/오답, 1~5점), 채점 모델이 점수 전에 추론하도록(thinking).
- 멀티 에이전트 글: 루브릭(사실 정확도, 인용 정확도, 완전성, 출처 품질, 도구 효율)으로 단일 LLM 호출이 0.0~1.0 점수와 합격/불합격을 내는 방식이 가장 일관되었다.

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - LLM 채점기를 검증 없이 바로 대규모로 쓰는 선택지 → 공식 문서는 신뢰성 테스트 후 확장을 권한다
> - 정답이 명확한 분류 과제에 LLM 채점을 쓰는 선택지 → 코드 채점(정확 일치)이 더 빠르고 신뢰할 수 있다
