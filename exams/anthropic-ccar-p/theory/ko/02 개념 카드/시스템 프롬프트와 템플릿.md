# 시스템 프롬프트와 템플릿

> [!summary] 한 줄 정의
> 시스템 프롬프트로 역할·규칙·맥락을 정하고, 고정 부분과 변수(입력)를 분리한 템플릿으로 재사용한다.

**日本語** システムプロンプト、テンプレート　·　**English** System prompts and templates

## 시험 트리거
- "응답의 톤과 범위를 일관되게"
- "지시·맥락·예시·입력이 섞여 오해가 생긴다"
- "같은 프롬프트를 여러 요청에 재사용"

## 핵심
- 역할 부여: 시스템 프롬프트에 역할을 정하면 한 문장만으로도 동작과 톤이 사용 사례에 맞춰진다(공식 문서).
- XML 태그로 지시(<instructions>)·맥락(<context>)·입력(<input>)을 나누면 오해가 줄어든다.
- 명확하고 구체적으로: 공식 문서는 Claude를 "규범과 작업 방식을 모르는 유능한 신입 직원"으로 생각하라고 한다.
- 〔해석〕 템플릿 = 고정 부분(역할·규칙·예시) + 변수(요청마다 바뀌는 입력). 고정 부분을 앞에 두면 캐싱에 유리하다 → [[프롬프트 캐싱]].
- 보안 정책은 시스템 프롬프트에 두고, 신뢰할 수 없는 내용은 도구 결과로 분리한다 → [[프롬프트 인젝션]].
