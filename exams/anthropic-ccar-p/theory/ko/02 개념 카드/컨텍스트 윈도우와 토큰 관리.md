# 컨텍스트 윈도우와 토큰 관리

> [!summary] 한 줄 정의
> 컨텍스트 창은 모델이 응답을 만들 때 참조하는 작업 기억이다. 클수록 좋은 것이 아니라, 무엇을 넣을지 관리해야 한다.

**日本語** コンテキストウィンドウ、トークン使用量　·　**English** Context windows and token usage

## 시험 트리거
- "대화가 길어지면서 정확도가 떨어진다"
- "요청 하나에 얼마나 토큰이 드는지 미리 알고 싶다"
- "긴 대화를 계속 이어가야 한다"

## 핵심
- 컨텍스트에 포함되는 것: 시스템 프롬프트, 모든 메시지(도구 결과·이미지·문서), 도구 정의, 그리고 생성되는 출력(사고 포함).
- 토큰이 늘면 정확도와 회상률이 떨어진다(context rot). 얼마나 넣느냐만큼 무엇을 넣느냐가 중요하다.
- 응답의 usage 필드로 사용량을 확인하고, 보내기 전에는 토큰 카운팅 API로 추정한다. 캐싱을 쓰면 input_tokens·cache_read_input_tokens·cache_creation_input_tokens로 나뉜다.
- 장시간 대화·에이전트에서는 서버 측 컴팩션이 기본 전략이다 → [[컨텍스트 압축과 메모리]].
- 2026-11 문서 기준 주요 최신 모델은 1M 토큰 창, 요청당 최대 128k 출력 토큰(변동 정보).

## 오답 함정
> [!warning] "컨텍스트 창이 크니 관련 문서를 전부 넣는다" → context rot과 비용 증가. 고신호 정보만 고른다
