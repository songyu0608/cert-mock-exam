# 워크플로 vs 에이전트

> [!summary] 한 줄 정의
> 워크플로는 미리 정한 코드 경로로 LLM과 도구를 조율하고, 에이전트는 LLM이 스스로 절차와 도구 사용을 정한다.

**日本語** ワークフローとエージェント型　·　**English** Workflows vs agents

## 시험 트리거
- "단계가 고정되어 있고 예측 가능해야 한다" → 워크플로
- "필요한 단계 수를 미리 알 수 없다" → 에이전트
- "가장 단순한 해법"

## 핵심
- 공식 글: 가장 단순한 해법을 먼저 찾고, 필요할 때만 복잡도를 높인다. 단일 LLM 호출 + 검색 + 예시로 충분한 경우가 많다.
- 에이전트형 시스템은 더 나은 과제 성능을 얻는 대신 지연과 비용을 더 쓴다. 이 트레이드오프가 타당한지 판단해야 한다.
- 워크플로: 잘 정의된 작업에서 예측 가능성과 일관성. 에이전트: 유연성과 모델 주도 판단이 대규모로 필요할 때.
- 에이전트는 비용이 높고 오류가 누적될 수 있으므로 샌드박스 테스트와 가드레일이 필요하다.
- 원칙 3가지: 단순성, 계획 단계의 투명성, 도구 문서화·테스트(에이전트-컴퓨터 인터페이스, ACI).

## 오답 함정
> [!warning] 오답이 되기 쉬운 선택지
> - "항상 자율 에이전트가 더 낫다" → 고정 절차·예측 가능성이 중요하면 워크플로가 정답
> - "프레임워크를 먼저 도입한다" → 공식 글은 LLM API를 직접 쓰는 것부터 시작하라고 권한다
