# 엔드투엔드 아키텍처와 피드백 루프

> [!summary] 한 줄 정의
> 입력 → 처리 → 출력에 피드백 루프(평가·모니터링·사용자 피드백)를 붙여, 운영 결과가 다시 설계 개선으로 돌아오게 만드는 전체 구조.

**日本語** エンドツーエンドのアーキテクチャ　·　**English** End-to-end architecture (input → processing → output → feedback loops)

## 시험 트리거
- "출시 후 품질이 떨어져도 알 수 없었다"
- "사용자 피드백을 어디에 반영할지"
- "입력부터 출력까지 전체 흐름을 설계"

## 핵심
- 입력: 사용자 요청, 문서, 도구 결과. 들어오는 신뢰할 수 없는 콘텐츠는 이 단계에서 구분한다 → [[프롬프트 인젝션]].
- 처리: 프롬프트·검색·도구 호출·워크플로/에이전트 → [[워크플로 vs 에이전트]].
- 출력: 형식 검증, 가드레일, 필요 시 사람 검토 → [[가드레일 계층]] · [[휴먼 인 더 루프]].
- 피드백 루프: 에이전트는 각 단계에서 환경으로부터 실제 결과(도구 실행 결과, 코드 실행 결과)를 받아 진행을 판단해야 한다고 공식 글은 설명한다.
- 운영 피드백: 트레이싱·평가·사용자 피드백을 모아 프롬프트·검색·모델을 다시 조정한다 → [[관측 가능성과 모니터링]].
- 〔해석〕 안내서는 이 네 단계를 목표 문구로만 제시한다. 각 단계의 구체 구성은 Anthropic 공식 글을 근거로 한 해석이다.
