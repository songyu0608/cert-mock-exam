# 시스템 문제 진단

> [!summary] 한 줄 정의
> 증상과 무엇이 바뀌었는지를 근거로 원인 층(프롬프트·검색·모델·도구·데이터)을 좁힌다.

**日本語** システムの問題（プロンプトの失敗、ハルシネーション、モデルの不適合）　·　**English** Diagnosing system issues (prompt failure, hallucinations, model mismatch)

## 시험 트리거
- "문서 갱신 뒤 갑자기 확신에 찬 오답"
- "특정 유형 질문에서만 형식이 깨진다"
- "작은 모델로 바꾼 뒤 복잡한 추론이 실패"

## 핵심
- 공식 샘플 3: 문서 갱신 직후 확신에 찬 오답 + 지연·모델 버전 변화 없음 → 검색/인덱싱이 무관하거나 오래된 청크를 반환하는지 먼저 본다. 다른 선택지는 문서 갱신으로 특별히 유발되지 않는다.
- 〔해석〕 프롬프트 실패 신호: 지시 누락·형식 불일치·특정 입력에서만 실패 → 프롬프트·예시를 고친다.
- 〔해석〕 할루시네이션 신호: 근거 없는 사실·출처 불일치 → 근거 제공·인용·"모른다" 허용 → [[할루시네이션 완화]].
- 〔해석〕 모델 부적합 신호: 과제 난도에 비해 모델·effort가 낮음, 지연 요구에 비해 과함 → [[모델 선택 트레이드오프]].
- 진단 도구: 트레이싱으로 검색어·출처·도구 실패를 확인(멀티 에이전트 글) → [[관측 가능성과 모니터링]].
