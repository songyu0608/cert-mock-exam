# 도메인 1　솔루션 설계와 아키텍처

**English** Domain 1: Solution Design & Architecture  
**日本語** 分野1：ソリューション設計とアーキテクチャ

도메인 1 (17%) · 목표 6개

Claude로 무엇을 어떤 구조로 만들지 정하는 도메인이다. 성공 기준을 먼저 정하고, 단일 호출 → 워크플로 → 에이전트 → 멀티 에이전트 순으로 필요한 만큼만 복잡도를 올리는 판단이 중심이다.

## 목표 1.1

**Claude 기반 AI 솔루션으로 비즈니스 문제를 전환한다**

> [!quote]- 공식 원문 (English / 日本語)
> Translate business problems into Claude-based AI solutions
>
> ビジネス課題をClaudeベースのAIソリューションに落とし込む

업무 문제와 측정 가능한 성공 기준을 먼저 정하고, 가장 단순한 해법(단일 호출 + 검색 + 예시)부터 검토한다.

관련 카드: [[비즈니스 문제 정의와 성공 기준]] · [[워크플로 vs 에이전트]] · [[구조화된 디스커버리]]

## 목표 1.2

**엔드투엔드 아키텍처(입력 → 처리 → 출력 → 피드백 루프)를 설계한다**

> [!quote]- 공식 원문 (English / 日本語)
> Design end-to-end architectures (input → processing → output → feedback loops)
>
> エンドツーエンドのアーキテクチャ（入力 → 処理 → 出力 → フィードバックループ）を設計する

입력·처리·출력 각 단계의 책임과, 평가·모니터링·사용자 피드백이 설계로 돌아오는 루프를 함께 설계한다.

관련 카드: [[엔드투엔드 아키텍처와 피드백 루프]]

## 목표 1.3

**적절한 아키텍처 패턴(워크플로, 에이전트형, 증강 LLM)을 선택한다**

> [!quote]- 공식 원문 (English / 日本語)
> Select appropriate architectural patterns (workflow, agentic, augmented LLM)
>
> 適切なアーキテクチャパターン（ワークフロー、エージェント型、拡張LLM）を選択する

고정 절차면 워크플로, 단계 수를 예측할 수 없으면 에이전트. 둘 다 증강 LLM(검색·도구·메모리)을 기본 블록으로 쓴다.

관련 카드: [[증강 LLM]] · [[워크플로 vs 에이전트]] · [[프롬프트 체이닝]] · [[라우팅]] · [[병렬화(섹셔닝·투표)]] · [[평가자-최적화자]]

## 목표 1.4

**멀티 에이전트 시스템과 오케스트레이션 전략을 설계한다**

> [!quote]- 공식 원문 (English / 日本語)
> Design multi-agent systems and orchestration strategies
>
> マルチエージェントシステムとオーケストレーション戦略を設計する

넓고 병렬화되는 탐색에는 멀티 에이전트가 맞지만 토큰을 약 15배 쓴다. 컨텍스트 공유·의존성이 큰 작업에는 맞지 않는다.

관련 카드: [[오케스트레이터-워커]] · [[멀티 에이전트 도입 판단]]

## 목표 1.5

**복잡한 문제 해결에 분해 기법을 적용한다**

> [!quote]- 공식 원문 (English / 日本語)
> Apply decomposition techniques for complex problem solving
>
> 複雑な問題解決のために分解の手法を適用する

고정 분해(체이닝·섹셔닝)와 동적 분해(오케스트레이터-워커)를 구분한다. 분해는 정확도를 올리지만 지연과 비용이 는다.

관련 카드: [[프롬프트 체이닝]] · [[병렬화(섹셔닝·투표)]] · [[오케스트레이터-워커]] · [[문제 분해 기법]]

## 목표 1.6

**솔루션을 비즈니스 가치 축(효율성, 변혁, 생산성, 비용, 성능 SLA)에 맞춘다**

> [!quote]- 공식 원문 (English / 日本語)
> Align solutions to business value pillars (efficiency, transformation, productivity, cost, performance SLAs)
>
> ソリューションをビジネス価値の柱（効率性、変革、生産性、コスト、パフォーマンスSLA）に整合させる

안내서가 든 5개 가치 축에 솔루션을 맞추고, 비용·SLA는 측정 가능한 지표와 기술 레버로 연결한다.

관련 카드: [[비즈니스 가치 축과 SLA]] · [[비용·지연 최적화 레버]] · [[기대치 정렬과 SLA 관리]]

## 요약
- 문제·성공 기준 → 가장 단순한 해법 → 필요할 때만 복잡도 증가
- 워크플로(고정 경로) vs 에이전트(LLM이 절차 결정)
- 멀티 에이전트: 넓은 병렬 탐색에 유리, 토큰 약 15배

## 이 도메인의 카드
- [[비즈니스 문제 정의와 성공 기준]] — LLM을 쓰기 전에 해결할 문제와 측정 가능한 성공 기준을 먼저 정한다. 기준이 없으면 설계도 평가도 할 수 없다.
- [[엔드투엔드 아키텍처와 피드백 루프]] — 입력 → 처리 → 출력에 피드백 루프(평가·모니터링·사용자 피드백)를 붙여, 운영 결과가 다시 설계 개선으로 돌아오게 만드는 전체 구조.
- [[증강 LLM]] — 검색(retrieval)·도구(tools)·메모리(memory)로 기능을 늘린 LLM. 워크플로와 에이전트를 만드는 기본 구성 요소다.
- [[워크플로 vs 에이전트]] — 워크플로는 미리 정한 코드 경로로 LLM과 도구를 조율하고, 에이전트는 LLM이 스스로 절차와 도구 사용을 정한다.
- [[프롬프트 체이닝]] — 작업을 고정된 순서의 하위 단계로 나눠 각 LLM 호출이 앞 단계 결과를 처리하게 하는 워크플로. 중간에 프로그램 검사(게이트)를 둘 수 있다.
- [[라우팅]] — 입력을 분류해 전문화된 후속 처리(프롬프트·도구·모델)로 보내는 워크플로.
- [[병렬화(섹셔닝·투표)]] — 여러 LLM 호출을 동시에 실행하고 결과를 프로그램으로 합치는 워크플로. 독립 하위 작업으로 나누는 섹셔닝과, 같은 작업을 여러 번 돌리는 투표가 있다.
- [[오케스트레이터-워커]] — 중심 LLM이 작업을 동적으로 쪼개 워커 LLM에 맡기고 결과를 종합하는 워크플로.
- [[평가자-최적화자]] — 한 LLM이 응답을 만들고 다른 LLM이 평가·피드백을 주는 루프를 반복하는 워크플로.
- [[멀티 에이전트 도입 판단]] — 여러 에이전트를 병렬로 쓰면 넓은 탐색 작업의 성능이 오르지만 토큰을 훨씬 많이 쓴다. 작업의 가치와 구조로 도입 여부를 정한다.
- [[문제 분해 기법]] — 복잡한 문제를 LLM이 다루기 쉬운 하위 작업으로 나누는 방법. 고정 분해(체이닝·섹셔닝)와 동적 분해(오케스트레이터·에이전트)를 구분한다.
- [[비즈니스 가치 축과 SLA]] — 솔루션을 효율성·변혁·생산성·비용·성능 SLA라는 가치 축에 맞춰 설계하고 설명한다(안내서의 5개 축).
