# 도메인 2　Claude 모델, 프롬프팅, 컨텍스트 엔지니어링

**English** Domain 2: Claude Models, Prompting & Context Engineering  
**日本語** 分野2：Claudeモデル、プロンプト作成、コンテキストエンジニアリング

도메인 2 (13%) · 목표 5개

모델 선택과 프롬프트·컨텍스트 설계 도메인이다. 공식 샘플 2(정적 내용 먼저 + 프롬프트 캐싱)가 이 도메인에 속한다.

## 목표 2.1

**트레이드오프에 따라 적절한 Claude 모델을 선택한다**

> [!quote]- 공식 원문 (English / 日本語)
> Select appropriate Claude models based on trade-offs
>
> トレードオフに基づいて適切なClaudeモデルを選択する

능력·속도·비용·effort를 보고, 자기 사용 사례의 평가셋으로 고른다. effort 조정이 모델 교체보다 나은 경우가 많다.

관련 카드: [[라우팅]] · [[모델 선택 트레이드오프]]

## 목표 2.2

**시스템 프롬프트, 템플릿, 가드레일을 설계한다**

> [!quote]- 공식 원문 (English / 日本語)
> Design system prompts, templates, and guardrails
>
> システムプロンプト、テンプレート、ガードレールを設計する

시스템 프롬프트에 역할·정책을 두고 XML 태그로 구조화한다. 템플릿은 고정 부분과 변수를 나눈다. 가드레일은 프롬프트만으로 끝내지 않는다.

관련 카드: [[시스템 프롬프트와 템플릿]] · [[긴 문서 배치 순서]] · [[가드레일 계층]]

## 목표 2.3

**프롬프트 엔지니어링 기법(제로샷, 퓨샷, 사고의 연쇄)을 적용한다**

> [!quote]- 공식 원문 (English / 日本語)
> Apply prompt engineering techniques (zero-shot, few-shot, chain-of-thought)
>
> プロンプトエンジニアリングの手法（ゼロショット、few-shot、思考の連鎖）を適用する

제로샷부터 시작해, 형식이 흔들리면 3~5개 예시(퓨샷), 추론이 필요하면 사고의 연쇄·thinking을 쓴다.

관련 카드: [[퓨샷 프롬프팅]] · [[사고의 연쇄와 확장 사고]]

## 목표 2.4

**컨텍스트 윈도우를 최적화하고 토큰 사용량을 관리한다**

> [!quote]- 공식 원문 (English / 日本語)
> Optimize context windows and manage token usage
>
> コンテキストウィンドウを最適化し、トークン使用量を管理する

컨텍스트는 클수록 좋은 것이 아니다(context rot). 고신호 정보만 넣고, 긴 문서는 위·질문은 끝, 장시간 작업은 컴팩션.

관련 카드: [[컨텍스트 윈도우와 토큰 관리]] · [[컨텍스트 엔지니어링]] · [[긴 문서 배치 순서]] · [[컨텍스트 압축과 메모리]] · [[점진적 탐색 vs 일괄 컨텍스트]]

## 목표 2.5

**프롬프트 재사용 전략(캐싱, 모듈형 프롬프트, 스킬)을 구현한다**

> [!quote]- 공식 원문 (English / 日本語)
> Implement prompt reuse strategies (caching, modular prompts, Skills)
>
> プロンプトの再利用戦略（キャッシング、モジュール型プロンプト、スキル）を実装する

반복 접두사는 캐싱, 공통 부품은 모듈형 프롬프트, 필요할 때만 부르는 지식·절차는 스킬로 재사용한다.

관련 카드: [[프롬프트 캐싱]] · [[모듈형 프롬프트]] · [[Agent Skills]]

## 요약
- effort 조정 > 모델 교체인 경우가 많다
- 퓨샷 3~5개(관련성·다양성·구조화)
- 정적 내용 앞 + 캐싱 = 지연·비용 동시 절감(샘플 2)
- [[공식 샘플 문제 3문항]]

## 이 도메인의 카드
- [[모델 선택 트레이드오프]] — 능력·속도·비용·effort를 함께 보고, 자기 사용 사례의 평가셋으로 모델을 고른다.
- [[시스템 프롬프트와 템플릿]] — 시스템 프롬프트로 역할·규칙·맥락을 정하고, 고정 부분과 변수(입력)를 분리한 템플릿으로 재사용한다.
- [[퓨샷 프롬프팅]] — 예시 없이 지시만 주는 제로샷과 달리, 잘 만든 예시 몇 개를 주어 형식·톤·구조를 안정시키는 기법.
- [[사고의 연쇄와 확장 사고]] — 답하기 전에 추론 과정을 거치게 해 복잡한 문제의 정확도를 높이는 기법. 현재 모델은 API의 thinking과 effort로 추론량을 조정한다.
- [[컨텍스트 윈도우와 토큰 관리]] — 컨텍스트 창은 모델이 응답을 만들 때 참조하는 작업 기억이다. 클수록 좋은 것이 아니라, 무엇을 넣을지 관리해야 한다.
- [[컨텍스트 엔지니어링]] — 원하는 결과를 낼 가능성이 가장 높은, 가장 작은 고신호 토큰 집합을 골라 컨텍스트를 구성하는 일.
- [[긴 문서 배치 순서]] — 긴 문서는 프롬프트 위쪽에, 질문·지시는 끝에 둔다. 관련 부분을 먼저 인용하게 하면 초점이 잡힌다.
- [[컨텍스트 압축과 메모리]] — 긴 작업에서 컨텍스트가 차면 요약(컴팩션)하거나 오래된 도구 결과를 지우고, 중요한 정보는 컨텍스트 밖 노트에 남긴다.
- [[프롬프트 캐싱]] — 요청마다 반복되는 접두사(prefix)를 캐시해 재사용하는 기능. 정적 내용을 앞에, 동적 내용을 뒤에 두어야 효과가 난다.
- [[모듈형 프롬프트]] — 역할·정책·예시·작업 지시 같은 프롬프트 부품을 나눠 관리하고, 여러 애플리케이션·요청에서 재사용하는 전략.
- [[Agent Skills]] — 지시·메타데이터·스크립트·리소스를 폴더로 묶어 Claude가 필요할 때만 불러 쓰는 모듈형 기능. 점진적 공개로 컨텍스트를 아낀다.
