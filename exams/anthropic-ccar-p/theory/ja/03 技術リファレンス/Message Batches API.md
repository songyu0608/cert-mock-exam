# Message Batches API

> [!summary] 一行定義
> 即時の応答が不要な大量のリクエストを非同期で処理し、すべてのトークンが50%割引になるAPI。

**English** Message Batches API

## 試験のトリガー
- 「夜間に数万件のドキュメントを分類」
- 「結果をすぐに受け取る必要がない」
- 「評価セットを大量に実行する」

## 要点
- すべての使用量（入力・出力・特殊トークン）が標準価格の50%割引。プロンプトキャッシングの割引と重ねて適用される。
- ほとんどは1時間以内に終わるが、24時間以内に終わらなければ期限切れになる（期限切れのリクエストは課金されない）。24時間はSLAではない。
- 1つのバッチは、リクエスト100,000件または256MBのいずれか先に達する方まで。結果は作成後29日間取得できる。
- バッチは5分を超えることがあるため、キャッシングを使うなら1時間のキャッシュTTLを検討する。
- サーバーツール（Web検索、コード実行、MCPコネクタ、ツール検索など）はバッチでも動作する。〔解釈〕ユーザー定義ツールは結果を返すたびに新しいリクエストが必要になるため、リアルタイムのツールループには向かない。

## 誤答の落とし穴
> [!warning] ユーザーが待っているリアルタイムの応答にバッチを使う選択肢 → 非同期処理なので合わない
