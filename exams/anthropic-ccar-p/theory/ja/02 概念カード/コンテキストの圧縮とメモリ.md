# コンテキストの圧縮とメモリ

> [!summary] 一行定義
> 長いタスクでコンテキストが埋まったら要約（コンパクション）するか古いツール結果を消し、重要な情報はコンテキストの外のメモに残す。

**English** Compaction, context editing and memory

## 試験のトリガー
- 「長時間のエージェントがコンテキストの上限に達する」
- 「数十回のツール呼び出しの後で初期の決定を忘れる」
- 「セッションをまたいで進捗を保つ」

## 要点
- コンパクション：会話が上限に近づいたら内容を要約して新しいコンテキストで続ける。何を残すか（決定事項、未解決の問題）が要点。
- 最も軽い形は古いツール結果の消去（tool result clearing）。
- 構造化されたメモ：エージェントがコンテキストの外にメモを残し、後で再び取り込む（例：To-Doリスト、NOTESファイル）。
- サブエージェント：クリーンなコンテキストで細かい作業をし、圧縮した要約だけを返す。
- 公式ドキュメント：長時間の会話やエージェントには、サーバー側のコンパクションが基本戦略。

## 誤答の落とし穴
> [!warning] コンパクションが情報を失わずにすべてを保持するという選択肢 → 要約なので残す内容を選ぶ必要がある
