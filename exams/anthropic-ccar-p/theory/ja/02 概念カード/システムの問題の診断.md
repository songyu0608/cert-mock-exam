# システムの問題の診断

> [!summary] 一行定義
> 症状と何が変わったかを根拠に、原因の層（プロンプト・検索・モデル・ツール・データ）を絞り込む。

**English** Diagnosing system issues (prompt failure, hallucinations, model mismatch)

## 試験のトリガー
- 「文書の更新後に突然、確信に満ちた誤答」
- 「特定の種類の質問だけ形式が崩れる」
- 「小さいモデルに替えたら複雑な推論が失敗」

## 要点
- 公式サンプル3：文書の更新直後に確信に満ちた誤答＋レイテンシ・モデルのバージョンは変化なし → 検索／インデックス作成が関連のない、または古いチャンクを返していないかを先に見る。他の選択肢は文書の更新を特にきっかけとして起こるものではない。
- 〔解釈〕プロンプトの失敗のシグナル：指示の欠落・形式の不一致・特定の入力だけで失敗 → プロンプトや例を直す。
- 〔解釈〕ハルシネーションのシグナル：根拠のない事実・情報源との不一致 → 根拠の提供・引用・「わからない」の許可 → [[ハルシネーションの低減]]。
- 〔解釈〕モデルの不適合のシグナル：タスクの難しさに対してモデル・effortが低い、またはレイテンシ要件に対して過剰 → [[モデル選択のトレードオフ]]。
- 診断ツール：トレーシングで検索クエリ・情報源・ツールの失敗を確認する（マルチエージェントの記事）→ [[オブザーバビリティとモニタリング]]。

## 誤答の落とし穴
> [!warning] 誤答になりやすい選択肢
> - 「モデルの重みが気づかないうちに変更された」→ サンプル3の誤答（A）
> - 「temperatureが低すぎる」→ サンプル3の誤答（C）
> - 「コンテキストウィンドウが縮小した」→ サンプル3の誤答（D）
