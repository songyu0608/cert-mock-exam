# マルチエージェントとシングルエージェント

| | シングルエージェント（またはワークフロー） | [[マルチエージェントの導入判断\|マルチエージェント]] |
|---|---|---|
| トークン（チャット比） | 約4倍 | 約15倍 |
| 合うタスク | 依存関係が大きくコンテキストを共有する必要がある（ほとんどのコーディング） | 広く並列化できる探索、単一のコンテキストを超える情報 |
| リスク | コンテキストの上限 | 調整の失敗、重複作業、誤りの累積、コスト |
| 設計のポイント | コンテキスト管理、ツール | サブタスクごとに目的・出力形式・ツール・境界を明示 |

**判別の順序**：① タスクの価値が約15倍のトークンに見合うか？ ② サブタスクは互いに独立しているか？ ③ 両方「はい」のときだけマルチエージェント。

> [!question]- 複数のモジュールが強く絡み合ったリファクタリングを、5つのサブエージェントに分担させようとしている。
> 合わない。エージェント間の依存関係が大きく、同じコンテキストを共有する必要があるタスクでは、マルチエージェントの効果は低い。
