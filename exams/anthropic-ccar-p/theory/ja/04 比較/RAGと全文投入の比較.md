# RAGと全文投入の比較

| | [[RAGパイプラインの設計\|RAG]] | 全文投入＋キャッシング |
|---|---|---|
| 知識のサイズ | 大きい（200,000トークン以上） | 小さい（約200,000トークン・500ページ未満） |
| 更新 | 再インデックスが必要 | プロンプトを差し替えるだけ |
| 障害ポイント | チャンキング・インデックス・検索 | コンテキストの劣化、コスト |
| 品質の改善 | コンテキスト検索、ハイブリッド、リランキング | 長文ドキュメントは上・質問は末尾、先に引用 |

**判別の順序**：① ナレッジベースは200,000トークン未満か？ → 全文投入＋キャッシング ② 大きい、または増え続けるか？ → RAG ③ 探索型のクエリか？ → エージェントによる段階的ディスカバリーを検討

> [!question]- 社内規程の文書全体が約300ページで、ほとんど変わらない。
> 約200,000トークン未満なら、RAGなしで全体をプロンプトに入れてキャッシングする方が単純である（Contextual Retrievalの記事の基準）。分量はトークンカウントで確認する。

根拠：Contextual retrieval
