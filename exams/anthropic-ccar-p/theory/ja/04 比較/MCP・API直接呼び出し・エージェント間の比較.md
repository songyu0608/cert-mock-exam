# MCP・API直接呼び出し・エージェント間の比較

| | [[MCP（モデルコンテキストプロトコル）\|MCP]] | API/CLIの直接呼び出し（ユーザー定義ツール） | エージェント間（A2A） |
|---|---|---|---|
| 強み | 標準・再利用、複数のクライアント | きめ細かい制御・検証、単純 | 独立したエージェントへの委任 |
| 合う状況 | 同じシステムを複数のアプリ・エージェントが使う | 1つのアプリで数個のAPIだけ | チーム・組織の境界を越える作業の委任 |
| 注意点 | ツール定義の肥大化、コネクタの制約（ツール呼び出しのみ・リモートHTTPのみ） | 統合ごとのコードの重複 | 信頼境界・認証・結果の検証（解釈） |

**判別の順序**：① 複数のクライアントが再利用するか？ → MCP ② 1つのアプリの少数の呼び出しで、細かいゲートが必要か？ → ユーザー定義ツール ③ 他のエージェントによる自律的な処理が必要か？ → A2A

> [!warning] A2Aの詳細は、今回Anthropicの公式ドキュメントで確認できなかった。A2Aの列は一般的なアーキテクチャの解釈である。

> [!question]- ローカルでのみ動くSTDIOのMCPサーバーをMessages APIにつなごうとしている。
> MCPコネクタは公開されたHTTPサーバーにしか接続できない。リモートで公開するか、アプリ側のMCPクライアント・ユーザー定義ツールで接続する。
