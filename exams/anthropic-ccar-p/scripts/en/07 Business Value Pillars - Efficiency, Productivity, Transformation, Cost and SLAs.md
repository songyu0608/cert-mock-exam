# 7. Business Value Pillars: Efficiency, Productivity, Transformation, Cost and SLAs

We have split the support team's request into parts for the model, for code and for people. Now someone has to say why DemoShop should pay for it.

That person is DemoShop's chief operating officer, or COO, the sponsor of ShopAssist. The COO pays for it and decides whether the project goes on. The COO wants a lower cost for each support case. The COO fears a missed promise to customers and an incident in the press.

This lesson answers one question: what value does a solution bring, and how do we show it?

A value pillar is one kind of value a business expects from a project. The exam names five pillars. A good design names the one pillar it moves most, and the number that measures it.

Three things make this work: the five pillars, what is not a pillar, and a short test we run on every solution.

First, the five pillars.

The first pillar is efficiency. The same work gets done with less time and effort for each case. At DemoShop, an order question that took a person several minutes gets a correct answer from ShopAssist in seconds.

The second is productivity. People do more of their valuable work in the same hour. Here the AI helps a person instead of replacing a step. When ShopAssist hands a case to the support team with a clear summary, nobody reads the whole chat again.

The third is transformation. The business works in a new way that was not possible before. A customer can finish something alone, at any hour, that always needed a person.

The fourth is cost: the money the business spends for each unit of work. In support, that unit is a resolved case. So we measure cost per resolved case, which is what support spends, divided by the cases it closes. A chat that ShopAssist passes to a person does not count as resolved by ShopAssist. Our assumption for DemoShop is about four dollars when a person resolves a case. The target with ShopAssist is about one dollar.

The fifth is performance SLAs. An SLA, or service level agreement, is a promised level of service, stated as a number. For example, the first answer arrives within a few seconds. A later lesson turns promises like this into exact numbers.

Second, what is not a pillar.

Quality and customer experience matter a lot. But they are not on the exam's list of five. They are results, and they show up inside the pillars.

Think of a customer who wants to return a jacket. A faster correct answer is efficiency for DemoShop. For the customer, it is also a better experience.

So when a proposal says "our value is a better experience", we ask two things. Through which pillar? Measured by which number?

Third, the test.

For each solution we ask: which one pillar does it move most, and which number will show the change? Let's run the test on two parts of ShopAssist.

The first part is the automatic answer about order status. Our assumption is that about 40 percent of contacts ask where an order is. ShopAssist reads the order and answers. The customer gets the same answer as before, with much less work behind it. So the pillar is efficiency: much less work for each case. Less work shows up as money, so the number for the COO is cost per resolved case.

The second part is self-service returns. The customer writes that the jacket does not fit. ShopAssist finds the order, and code checks the return window. The customer starts and finishes the return in the chat, late in the evening, without waiting for a person. Before, every return needed someone from support. Now the customer does it alone. That is a new way of working, so the pillar is transformation. Its number is different: the share of returns that customers finish on their own.

A common mistake is to promise all five at once. The proposal says ShopAssist will cut cost, raise productivity, transform returns and beat every SLA. Nobody can measure that.

There is a second reason to choose one: moving one pillar up can push another one down. Say we want more correct answers, so we choose a larger model. Fewer cases come back to people, and that helps efficiency. But a larger model costs more, so the cost pillar gets worse. It also answers more slowly, so the SLA pillar gets worse too.

So we pick one main pillar for each part. The other pillars become limits we watch. For the returns feature, the limit could be: cost per resolved case must not go up.

Let's go over the main points.

A value pillar is one kind of value a business expects. The exam names five: efficiency, productivity, transformation, cost and performance SLAs. Quality and customer experience are results that show up inside those pillars. For each solution, we name the one pillar it moves most and the number that measures it. The automatic order answer is efficiency, measured by cost per resolved case. Self-service returns are transformation, measured by the share of returns customers finish alone. On the exam, be careful with an answer that adds quality as a sixth pillar, or promises all five at once.

The practical rule: one main pillar, one number, and the other pillars as limits you watch.
